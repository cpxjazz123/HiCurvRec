# Measurability review — PCTR revision 2

## Verdict: REVISE

I reviewed the single mechanism declared in `candidate.md`: prefix-internal tangent residual ordering (PCTR). Its operator is the signed tangent inner product correction described there. I did not review or infer a second candidate, a signed area, or a second score term; those are not the proposed operator. The stated protocol and strict conjunctive task thresholds are treated as frozen.

## Can the artifact alone verify the effect?

**In principle, largely yes; as currently specified, not decisively.** The proposed `assignment_audit.jsonl` plus manifest is unusually comprehensive: it calls for exact operands, batch/group membership, lambda-zero and candidate assignments, comparison/tie data, clamp flags, counts, and recomputation without model inference. If these fields are actually emitted losslessly and with unambiguous semantics, an independent consumer could recompute most operator-level quantities and the assignment diagnostics from the artifact alone.

However, this is a declaration of a future artifact, not an artifact or a concrete schema. No `assignment_audit.emit` implementation/call site or output is present in the staged workspace. The document explicitly says the outputs do not exist. Thus there is presently no artifact-based verification, and the named emit point is not itself evidence that the required records are produced.

## Missing items needed for decisive falsifiers

1. **A normative, machine-readable schema and executable consumer.** Define field names, types, nullability, units, integer encoding, array order, exact float/bit encoding, and record kinds. Supply/version the independent validator and its conformance tests. “One record per sample/comparison” is ambiguous about cardinality and how sample operands are joined to the many comparison records.
2. **A complete coverage contract for eligibility and comparisons.** Emit the full eligible code set and the exact reason each code/comparison is present or excluded at each level and parent. State how unavailable/empty candidate sets and samples with no within-parent alternative enter each denominator. The rule referring to “levels 0–2 as applicable” needs a mechanically checkable definition. Ensure IDs are unique and every expected sample/comparison has exactly one record; a count alone cannot establish this.
3. **Resolve level/protocol naming against the frozen inputs.** The declaration specifies three integer SID tokens and diagnostics for levels 0–2, while `frozen_artifacts.json` reports `level0`–`level3` and 781 distinct codes at level3. Identify explicitly which frozen level is outside the three-token mechanism, and provide a mapping for all relevant arrays/IDs. The stated 24,587 denominator is acceptable only with a row-by-row reconciliation to the actual evaluation ID set.
4. **Make the control comparison independently reconstructible.** The artifact must contain or losslessly reference the exact frozen control assignments and candidate eligibility, along with stable IDs and hashes for the underlying frozen files. A claimed `lambda=0` stream is not enough unless the consumer can verify its inputs match the candidate stream and frozen control. Include a validator check for one-to-one joins, duplicate IDs, and eligibility equality.
5. **Fully specify the metric evidence.** “Metric inputs/results” is not sufficient for independent recomputation. Include exact ER anchor/positive/negative IDs and labels, negative sampling/order and scoring inputs, plus the exact per-query Stage3 relevance labels, ranked item IDs/scores (or equivalent sufficient inputs), exclusions, denominators, and metric implementation/configuration. State how these are joined to the frozen populations and how floating-point comparisons to the strict thresholds are performed. The prose asks for some of these elsewhere, but the artifact contract must require them explicitly.
6. **Define the activity and tie accounting unambiguously.** For activity, specify the reference ordering at `lambda=0`, comparison population, direction/treatment of ties, and whether a pair counts once per sample/code set. For tie share, define exactly which candidate scores form eligible unordered pairs and how the first-representative bucket rule is applied across values. Emit sufficient raw values and deterministic ordered pair IDs to reproduce both numerators and denominators.
7. **Make clamp-rate accounting auditable.** Enumerate the precise attempted-operation denominator for each clamp type (including per-point/per-vector multiplicity and identity-neighborhood behavior), and prevent double-counting or omission. Emit operation IDs or sufficient indexed flags so the consumer can independently derive per-type counts and the aggregate ratio. Clarify whether the `max(1,...)` arcosh adjustment is counted for every argument below one and how this relates to the stated domain rejection check.
8. **Prove artifact completeness and provenance.** Specify canonical serialization, shard ordering, hash algorithm, manifest finalization, and a tamper-evident link between records and manifest. Include exact source/config/data/control hashes and the reference implementation/device-math identity. Define how the validator detects truncation, duplicate/reordered shards, and a completion marker copied from another run. Hashes establish identity only if the expected trusted hashes are available to the reviewer.
9. **Reconcile the staged latent evidence.** `frozen_artifacts.json` describes the latents as shape `[24587, 768]`, whereas the mechanism describes 32-dimensional Lorentz points. This may be a legitimate Stage2 projection, but the artifact contract must include its exact source/transform provenance and point coordinates as claimed, and identify the frozen Stage2 input file/hash so an auditor can verify the 32-D values without rerunning inference.

## Decision

The stated falsifiers are plausible and many are well chosen, but current wording leaves enough freedom in population construction, denominator accounting, and metric evidence that two consumers could reach different pass/fail outcomes from the same run. More fundamentally, the named artifact and call site are not staged, so no current evidence demonstrates the proposed audit is emitted. **REVISE**: make the schema, population/denominator definitions, metric payload, and validator normative and testable, then provide a completed artifact before considering approval for JOIN E. The strict thresholds remain unchanged; no pass is inferred here.
