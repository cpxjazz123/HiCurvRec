# 用 ORCA 轨道做结构角色，再测各角色的**行为关系保留率**（不训练）

## 1. 做法

| 步 | 实现 |
|---|---|
| 图 | TRAIN 交互图，**24,556 节点 / 315,391 无向边**（323,633 条有向对按无序对去重） |
| 小结构 | **ORCA**（`thocevar/orca`，`g++ -O2 -std=c++11` 本地编译，无外部依赖）：`orca node 4` ⇒ 每节点 **15 个精确 4-节点轨道计数**，1.50 s 跑完（`results/research/issue213/orca/node4.out`） |
| 特征 | 15 个轨道（log1p）+ `clustering` / `core` / 度数 / 平均邻居度 / **邻居两两 Jaccard 均值**（"桥/扇出"线索） |
| 角色 | 标准化后 **NMF(k=6)**（RolX 的核心做法：软隶属、不预设类别），取 argmax 作主角色 |
| 保留率 | 对每条 TRAIN 行为边 (a,b)，看 SID 是否共享 **≥1 码** 与 **全 3 码**；并列**同度数分位随机对照**（40,000 对） |

两个 SID 均按**记录的 sha256** 解析（期间有一次并发重排：`results/research/stage3_queue/_stage/` 下有同哈希副本；`results/stage2_RQ-VAE/TIGER_RQ-VAE/item_sids.json` 现为**不同 sha**，被脚本跳过并打印原因）。

- **历史基线 `TIGER_RQ-VAE`**：`53273cb6…eed85`

## 4. 结论（每条都对应上表）

1. **角色确实可分辨**，且两个 SID 上算出的保留率**排序一致**（1、2 高；5 最低）——说明角色划分不是该 SID 的产物。
2. **保留率随角色变化，但幅度有限**：F0 上 `0.1765 → 0.2917`（**1.65×**），相对随机是 **2.6× – 4.3×**。不是"某些角色几乎全丢"，而是"都留了一部分、社区/两跳类留得更多"。
3. **与直觉相反**：最像"桥/扇出"的角色 2（邻居互不相邻、共享大量二跳邻居）**保留率最高之一**（0.2792，4.11× 随机），而**最低的是角色 5 星形/链状**（0.1765）与角色 4 度数中段（0.1863）。所以"桥梁最难保留"这一假设**在本数据上不成立**，不能作为机制设计的先验。
4. **`share3`（三码全同）整体极低（0.26%）**，但在角色 1/2 上是 0.0074/0.0087，为角色 4/5 的 **3–4 倍**——即"完全同码"只发生在少数结构上。
5. **F0 的 SID 在行为关系保留上明显更强**：总体 `0.1897` vs 历史基线 `0.1316`（**1.44×**），且每个角色都更高。这是继 `recall@10`（0.057278 vs 0.056216）之后，F0 优于历史基线的**第二个独立观测**。

## 5. 边界与未完成

- 角色数为脚本常量 `k=6`，未做选择；argmax 硬分配（NMF 本身给软隶属）。
- 保留率只测"共享 ≥1 码 / 全 3 码"两种粗口径，未测排序保持（如 SID 距离与行为距离的秩相关）。
- **ORCA 5-节点轨道仍在运行**（最大度 2521，Σd² 大），本轮结论只基于 4-节点 15 轨道；5-节点接入后角色可能更细。
- 这是**观测**，不是机制：本线三接口已结案（#210），要继续须新 Issue 并预注册。
