## 4. 结论（每条都对得上表）

1. **角色可分辨且稳定**：只用 4-节点 15 轨道与用 4+5 节点 88 轨道，两版给出的排序一致——{社区内部、两跳/扇出} 最高，稠密/星形最低；说明排序不是某一组轨道的产物。
2. **保留率差异是 1.79×**（F0：0.1650 → 0.2960），相对随机是 **2.4×–4.4×**。不是"某些角色几乎全丢"，而是"都保住一部分、社区/两跳类多留约 1.5 倍"。
3. **与直觉相反，且比 4-节点版更锐利**：接入 5-节点轨道后，**最差的是"稠密 hub"角色 0（0.1650，0.87× 总体）**——而最像"桥/扇出"的角色 2 反而高（0.2797，1.47×）。所以"桥梁最难保留"在本数据上**不成立**；最难的是**稠密高核区**。
4. **`share3`（三码全同）整体仅 0.26%**，但在角色 1/2 上是 0.0102/0.0079，为角色 0/5 的 **4–8 倍**。
5. **F0 的 SID 在每个角色上都强于历史基线**：总体 `0.1897` vs `0.1316`（**1.44×**），角色级也一致（如角色 1：0.2960 vs 0.2075）。这是 F0 优于历史基线的**第二个独立观测**（第一个是 recall@10 0.057278 vs 0.056216）。

## 4b. 只算 4-节点 vs 加上 5-节点：结论差在哪

两版用同一张图、同一个 `ROLES = 6`、同一套保留率口径，只在特征里差 73 个 5-节点轨道（`--only-4` 可复现第一版）。

| 项 | 4-节点（15 轨道） | 4+5-节点（88 轨道） |
|---|---|---|
| 角色成员 | 3,679 / 1,144 / 2,895 / 2,081 / 6,917 / 7,840 | 3,515 / 1,386 / 2,574 / 3,835 / 875 / 12,371 |
| 最高 `share≥1` | 社区内部 0.2917（1.54× 总体） | 社区内部 0.2960（1.56×） |
| 最低 `share≥1` | 星形/链状 0.1765（**0.93×** 总体） | **稠密 hub 0.1650（0.87× 总体）** |
| 极差 | 1.65× | 1.79× |
| 稠密区 | 0.1858 ≈ 总体，**看不出劣势** | 唯一显著低于总体的角色（−13%） |
| `share3` 集中度 | 角色 1/2 为其余的 2.5–3× | 角色 1/2 为角色 0 的 8× |
| 独有角色 | — | 875 人的环/长路径簇，保留率恰为总体 |

**不变**：保留率的高低排序（社区、两跳 > 度数中段 > 稠密、星形）、F0 在每个角色上都强于历史基线、以及"最像桥的角色反而保留得多"这一反直觉结论。**改变**：4-节点只能看到"最低与总体相差 7%"——一个几乎无信号的差异；接上 5-节点后，被系统性压缩的是**稠密 hub**（11.1 万条边，低于总体 13%），并且多分出一个 4-节点不可分的角色。

跨版本可比的是**极值排序与幅度**，不是角色编号：分区不一一对应（角色 5 从 7,840 变成 12,371），`ROLES = 6` 是常数、不是选出来的。

## 4c. 两版的角色能不能对应上

角色编号只在一次运行内有效；按质心的前三个特征逐个比对，六个角色里**三个有同名对应、三个没有**：

| 4-节点角色 | 成员 | 4+5-节点角色 | 成员 | 对应关系 |
|---|---|---|---|---|
| clustering 2.215（社区内部） | 1,144 | clustering 2.144 | 1,386 | **同一种**，保留率 0.2917 → 0.2960（Δ0.004） |
| overlap 10.885（两跳/扇出） | 2,895 | overlap 10.837 | 2,574 | **同一种**，0.2792 → 0.2797（Δ0.0005） |
| o4_14/o4_13/core（稠密） | 3,679 | o5_71/72/69（稠密 hub） | 3,515 | 成员数接近，**但边数 24,783 → 111,727**，保留率 0.1858 → 0.1650 |
| o4_12/01/08（混合） | 2,081 | log_degree/o4_00（度数中段） | 3,835 | **不是同一个** |
| log_degree/o4_00（度数中段） | 6,917 | o5_68/60/63（环/长路径） | 875 | **不是同一个**（差 8 倍） |
| mean_nbr_deg/o4_06（星形/链状） | 7,840 | o5_22/o4_06（星形/链状） | 12,371 | 同类，规模 +58% |

结论：**高分段的两个角色几乎不变（Δ ≤ 0.004），低分段整个重排**——4-节点把三个角色压在 0.186 附近（跨度 0.010），5-节点把它们摊成 0.1650/0.1819/0.1900/0.2212（跨度 0.056）。所以"数据差别大不大"的答案是分层的：高分段没变，低分段的排序与幅度都变了。

逐节点的 ARI/NMI **未测量**：两次运行的 JSON 只存了质心与逐角色保留率，没有存每个节点的角色归属，无法从落盘产物反推；要这个数就必须再跑一次分区比对（已被明确要求不重复跑）。

## 5. 边界与未完成

- 角色数为脚本常量 `k=6`，未做选择；argmax 硬分配（NMF 本身给软隶属）。
- 保留率只测"共享 ≥1 码 / 全 3 码"两种粗口径，未测排序保持（如 SID 距离与行为距离的秩相关）。
- 5-节点轨道已接入（951 s 完成，73 轨道）；4-节点版结果保留在 `graphlet_roles_4node.json` 作为稳定性对照。
- 这是**观测**，不是机制：本线三接口已结案（#210），要继续须新 Issue 并预注册。

## 6. 复现（轨道文件不入库，一条命令重建）

```bash
cd results/research/issue213/orca
git clone --depth 1 https://github.com/thocevar/orca .    # 第三方源码，不入库
g++ -O2 -std=c++11 -o orca orca.cpp
cd ../../.. && python3 results/research/issue213/make_orca_input.py
cd results/research/issue213/orca
./orca node 4 graph.in node4.out     # 1.5 s
./orca node 5 graph.in node5.out     # 951 s
cd ../../.. && python3 results/research/issue213/graphlet_roles.py
```

`graph.in` / `node4.out` / `node5.out` 由上述步骤确定性重建（同一 TRAIN 图、无随机性），因此不入库；`graphlet_roles.json` 是本次运行的输出，已入库。
