METRIC: hyp_code_mi_gain
TITLE: Size-matched hyperbolic information gain of the full SID partition about the frozen reference's target distribution
FORMULA:
Let V be the N=24587 items. Work in the Poincare ball B^3={x in R^3 : ||x||<1} with fixed curvature K=-1 and distance dP(x,y)=arcosh(1+2||x-y||^2/((1-||x||^2)(1-||y||^2))). The frozen Issue #126 reference gives, per item v, a source vector s_v in B^3, a target vector r_v in B^3, and its temperature tau. For each item i let H(i) be its training-split history (set of training items) and h_i the Karcher (Frechet) barycentre of {s_j : j in H(i)} in (B^3,dP), computed by the standard iteration h <- exp_h( mean_{j in H(i)} log_h(s_j) ). Define the reference predictive distribution
  p_i(v) = exp(-dP(h_i, r_v)/tau) / sum_{w in V} exp(-dP(h_i, r_w)/tau).
Let code(v) be the FULL SID tuple of v (all levels 1..L), partitioning V into C cells c with sizes n_c, sum_c n_c = N. Define
  P_i(c) = sum_{v : code(v)=c} p_i(v),   H_i = - sum_c P_i(c) ln P_i(c)   (0 ln 0 := 0).
Null: for r=1..R (R=8, fixed a priori), draw a uniformly random partition of V into cells with the SAME size multiset (random permutation of V, first n_1 items to cell 1, next n_2 to cell 2, ...), recompute P_i^(r)(c) and H_i^(r); set H_i^0 = (1/R) sum_r H_i^(r).
Let Q be the systematic sample of every 6th item id, |Q| = floor(N/6) = 4096. The metric is
  M = (1/|Q|) sum_{i in Q} [ H_i^0 - H_i ]   (nats; M=0 if H_i^0=H_i=0 for all i).
Higher M is better. tau = the reference's frozen temperature; if only distances are exported, tau = median over training pairs (a,b) of dP(s_a, r_b), frozen before any recall is read.

INPUTS: (1) the exported SID table, item id -> integer code per level; (2) the frozen Issue #126 reference arrays s_v and r_v for all items plus its temperature tau; (3) the training split, used only to build each item's history H(i). Nothing else.

GEOMETRY: curvature K=-1 enters twice. First, h_i is a Karcher barycentre in the ball, computed with exp/log maps; it is not a Euclidean mean of s_j, because the Poincare conformal factor weights points near the boundary differently. Second, the softmax is over the Poincare distance dP(h_i,r_v), which saturates as points approach the boundary, so the logit ordering and spacing are curvature-dependent. A flat-limit run at K=-1e-3 is the stated control, not a tuning knob.

WHY IT SHOULD TRACK RECALL: Stage-3 beam search over codes succeeds when, given a query, the reference's plausible targets concentrate on few SID codes. M is exactly the excess entropy that the real code removes from the reference's full predictive distribution, relative to a random partition of identical granularity. It uses the entire distribution over all 24587 candidates (not a mean over ten negatives), the whole history barycentre as the query (not a single anchor), and all SID levels at once. Over Q_H it adds: (i) the full negative distribution instead of a summary; (ii) all levels without an informativeness mask, because the size-matched null absorbs depth automatically; (iii) an information-theoretic rather than prefix-ranking target. Over HBAA it is not an item-wise positive-vs-negative contrast at all; it is a partition-level mutual-information statistic. The null makes collapse unprofitable by construction: one cell gives H=0 for both terms; N unique codes give the same permutation of the p_i values under both terms; a random relabelling is the null and scores ~0.

COMPUTE: about 4096 x 24587 = 1.0e8 Poincare distances, plus R=8 scatter-add passes of the same size via reduceat after sorting items by cell id; roughly 20-40 s in chunked float32 numpy (or a few seconds on GPU), peaking near 1 GB with 256-query chunks. Well under a minute.

RISKS: if the frozen reference's softmax is nearly flat for most histories, H_i and H_i^0 both approach the same value and M ties near 0 across tables; small tau makes M noisy on very fine cells; the R=8 Monte Carlo null adds sampling noise; if the reference is effectively Euclidean (its reps far from the boundary), the hyperbolic and flat versions will agree and the curvature adds little; sparse histories make h_i close to s_i and reduce the query-side signal.

FAILURE MODE: it must be worst on an anti-clustered table whose codes are assigned to split each reference neighbourhood as evenly as possible across cells, e.g. level-1 code = (rank of the item within its reference nearest-neighbour block) mod C. There H_i > H_i^0, so M < 0. The two degenerate ends are neutral, not rewarded: a single-cell table and an all-unique-code table both give M = 0, and a randomly relabelled table gives M = 0 by definition.
END METRIC
