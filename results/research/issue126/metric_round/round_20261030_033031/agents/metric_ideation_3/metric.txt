METRIC: hyp_geodesic_pmi_l1
TITLE: Entropy-normalised pointwise mutual information between the level-1 SID code and the history, measured with Poincare geodesics at the history's Frechet barycentre.
FORMULA:
 Ball B^d = {x in R^d : ||x||_2 < 1}, constant sectional curvature -1, c_curv = 1.
 Item map: p_i = s_i / (1 + ||s_i||_2) in B^d (radii differ, so the Poincare distance is not a monotone function of any Euclidean chord).
 Poincare distance: d(x,y) = arcosh( 1 + 2||x-y||_2^2 / ((1-||x||_2^2)(1-||y||_2^2)) ).
 Mobius addition: x (+) y = ((1 + 2<x,y> + ||y||^2) x + (1 - ||x||^2) y) / (1 + 2<x,y> + ||x||^2 ||y||^2).
 exp_x(v) = x (+) tanh(||v||_2/2) v/||v||_2 ;  log_x(y) = 2 artanh(||(-x)(+)y||_2) ((-x)(+)y)/||(-x)(+)y||_2.
 T = 1/sqrt(c_curv) = 1 (curvature length scale, fixed).
 Codes: c(i) in {1..K} = the level-1 column of the SID table; K = number of distinct level-1 codes present (K <= 256); n_k = #{i in I : c(i)=k}; N = |I| = 24587.
 Cell centres: m_k = Frechet (Karcher) barycentre of {p_j : c(j)=k}, i.e. the point with sum_{j: c(j)=k} log_{m_k}(p_j) = 0; computed by 20 fixed Karcher iterations m <- exp_m( (1/n_k) sum_j log_m(p_j) ), started from the Euclidean cell mean projected into B (20 is fixed, not tuned).
 History query: for every training interaction (u,t) with t >= 2, let H = the items at positions < t in user u's sequence and i = the item at position t; b = Frechet barycentre of {p_j : j in H}, computed by the running recursion b <- exp_b( (1/|H|) log_b(p_j) ) over H in sequence order.
 Leave-one-out positive centre: with k* = c(i), if n_{k*} >= 2 set m*_{k*} = exp_{m_{k*}}( -log_{m_{k*}}(p_i) / (n_{k*} - 1) ); if n_{k*} = 1 the interaction contributes exactly 0.
 Logits: l_k = -d(b, m_k)/T for k != k* ;  l_{k*} = -d(b, m*_{k*})/T.
 p_{k*} = exp(l_{k*}) / sum_{k=1..K} exp(l_k), with max subtraction.
 Per-interaction score: g = log p_{k*} - log(n_{k*}/N).
 Aggregate: M = number of training interactions with t >= 2; PMI = (1/M) sum_m g_m.
 Entropy: H1 = - sum_k (n_k/N) log(n_k/N).
 METRIC VALUE: S = PMI / H1 if H1 > 1e-9, else S = 0. One scalar, higher is better.
INPUTS:
 (1) the exported Stage-2 SID table, level-1 code column only (levels 2-4 unused); (2) the frozen Issue #126 reference SOURCE representations s_i in R^d for the 24587 items, trained on training pairs only; (3) the training split (user->item sequences), used only to define the histories H. Nothing else: no validation interaction, no test interaction, no recall, no Stage-3 artefact, no fitted quantity.
GEOMETRY:
 The score lives entirely in the Poincare ball of fixed curvature c_curv = 1 (sectional curvature -1). Curvature enters (a) through the Poincare distance d, which is not Euclidean: the conformal factor 2/(1-||x||^2) inside arcosh makes the same Euclidean gap far more costly near the boundary than near the origin, and items with larger reference norms sit nearer the boundary and get a steeper metric; (b) through exp/log and Mobius addition, which define every barycentre (the history query b and the K cell centres m_k) and the leave-one-out centre exp_m(-log_m(p_i)/(n-1)), a first-order Riemannian gradient step on the Frechet functional; (c) through the temperature T = 1/sqrt(c_curv), so the softmax is the heat kernel of the curved metric and ||log_b(m)||_b = d(b,m) is exactly the compared quantity. Points are NOT placed on a common sphere, so the ordering is not a re-expression of a Euclidean or cosine ranking.
WHY IT SHOULD TRACK RECALL:
 Stage-3 Recall@10 asks whether a generator conditioned on the history emits the true next item's code within ten tries. That is governed by two things the table controls: is the level-1 code conditionally predictable from the history, and is the prefix fine enough to separate the true next item. S = PMI/H1 is the fraction of the level-1 code's entropy that the frozen reference geometry of the history can explain, so it estimates the first factor directly and divides out the second. What it adds over Q_H (+0.634) and HBAA (+0.701): (i) it replaces the mean over ten negatives with the full negative distribution -- the log softmax normaliser over all K <= 256 cells -- so a table that puts the true cell first with a flat posterior is separated from one that is confidently first; (ii) the explicit size-matched marginal log(n_k/N) makes the score a calibrated gain over a size-only baseline rather than a raw likelihood, so a coarse table is capped at log 2 and is never paid for branching less, which is exactly the defect that drove the path likelihood to -0.488 with the 2/3/12-code tables at the top; (iii) the leave-one-out positive centre removes the item's own representation from its cell mean, so a table cannot buy score by shrinking cells towards singletons, i.e. by turning the level-1 prefix into an item identifier -- the mechanism that killed Q_H at levels 2 and 3; (iv) the query is the Frechet barycentre of the whole history, so the quantity is conditional predictability, not a marginal score. HBAA measures a signed margin along one direction from the mean of negatives; this measures a normalised log-evidence ratio against the whole negative mass, on a size-matched scale, with the item's own point removed.
COMPUTE:
 N = 24587 items, K <= 256 cells, reference dimension d (order 64-256), M training interactions. Item map O(N d). The K cell Frechet means are 20 passes over N points, about 5e8 multiply-adds. History barycentres are one exp/log step per interaction, O(M d). The logits need d(b, m_k) for all K cells, computed as batched pairwise Poincare distances with precomputed squared norms: about M x K x d multiply-adds, roughly 2e9 at M = 1e5, d = 64, which BLAS does in a few seconds with chunking to bound memory at M x K floats (about 100 MB at M = 1e5). The leave-one-out centre is closed form, O(d) per interaction. Total well under a minute, one pass, no optimisation, no training.
RISKS:
 (a) Low variance: if the reference source geometry is close to isotropic with respect to the level-1 partition, every table sits near PMI = 0 and the Spearman is noise -- the same failure that produced -0.081 and +0.156; the first diagnostic is the spread of S across the 97 tables. (b) Softmax saturation: if source norms are large, all p_i crowd the boundary, distances blow up and the softmax degenerates to argmax, making S coarse; the fixed T = 1 in ball units should be checked against realised distances being O(1). (c) A single dominant cell acts as a gravity well and makes PMI negative for items outside it -- intended, since that table is genuinely bad, but it can produce a bimodal distribution. (d) M = 0 if all training sequences have length 1, in which case S = 0. (e) For 2-3 code tables H1 is small and the ratio is noisy, which is the reason for the H1 > 1e-9 guard. (f) The metric inherits whatever the reference's source space gets wrong; a collapsed reference flattens S.
FAILURE MODE:
 It must be worst, and is exactly 0, on the table that gives every item its own level-1 code (all n_k = 1, every contribution is 0 by the leave-one-out rule) and on the one-code table (K = 1, log(n/N) = 0 and the only logit is a constant, so S = 0). Among non-degenerate tables it is worst on a size-matched random relabelling of a good partition: preserving the cell sizes but destroying the geometry gives p_{k*} = n_{k*}/N, hence g = 0 for every interaction and S = 0, with any residual being negative finite-sample noise. Those are the three tables on which the construction cannot be gamed.
