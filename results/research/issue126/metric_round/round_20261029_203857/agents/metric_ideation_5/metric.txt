METRIC: HYP_ADJ_R2_L1
TITLE: Dual-tower hyperbolic adjusted dispersion R^2 of the level-1 prefix partition.
FORMULA: Notation: I is the item set of the exported SID table, N=|I|; g(i) is item i's level-1 integer code, K is the number of distinct non-empty level-1 codes; T is the TRAINING item subset; tau in {S,T} indexes the two reference towers (S=source/query side, T=target/item side); z_i^tau in R^{d_tau} is the frozen Issue #126 representation. Standardise on training items only: mu_tau = (1/|T|) sum_{i in T} z_i^tau; sigma_tau = sqrt((1/|T|) sum_{i in T} ||z_i^tau - mu_tau||^2); v_i^tau = (z_i^tau - mu_tau)/sigma_tau; x_i^tau = tanh(||v_i^tau||) v_i^tau/||v_i^tau|| (x=0 if v=0), which is exp_0(v_i^tau) in the Poincare ball of curvature c=1. Distance: d(x,y)=arcosh(1 + 2||x-y||^2 / ((1-||x||^2)(1-||y||^2))). Hyperbolic barycentre beta(B) of a finite set B (Klein/Einstein centre of mass): kappa_j = 2 x_j/(1+||x_j||^2); gamma_j = 1/sqrt(1-||kappa_j||^2); kbar = (sum_j gamma_j kappa_j)/(sum_j gamma_j); beta(B) = kbar/(1+sqrt(1-||kbar||^2)). Per tower: m_tau = beta({x_i^tau : i in I}), m_{g,tau} = beta({x_i^tau : g(i)=g}); W_tau = sum_{i in I} d(x_i^tau, m_{g(i),tau})^2; T_tau = sum_{i in I} d(x_i^tau, m_tau)^2; HDR_tau = 1 - (W_tau/(N-K))/(T_tau/(N-1)) if K<N, else HDR_tau=0; HDR_tau = clip(HDR_tau, -1, +1). METRIC = (HDR_S + HDR_T)/2. One scalar; higher is better; 0 means the partition does no better than a size-matched random partition; 1 means perfectly tight codes; negative means anti-coherent.
INPUTS: (1) the exported SID table, an N x L integer code array, of which only the level-1 column is read; (2) the frozen Issue #126 reference, the source vectors z_i^S and target vectors z_i^T per item (learned on training pairs only); (3) the TRAINING split item ids, used only for mu_tau and sigma_tau. Nothing else: no recall value, no Stage-3 output, no validation/test interaction.
GEOMETRY: Fixed negative curvature c=1, Poincare ball of radius 1; c is a definition, not a tuned constant. Curvature enters in three explicit places: the exponential map exp_0(v)=tanh(||v||)v/||v|| that places finite reference vectors inside the ball; the Poincare distance whose denominators (1-||x||^2)(1-||y||^2) make distance diverge near the boundary; and the Klein/Einstein barycentre, where gamma_j = 1/sqrt(1-||kappa_j||^2) up-weights boundary (semantically specific) points relative to central ones. Replacing tanh by the identity, or the Poincare distance by a Euclidean one, gives a different number.
WHY IT SHOULD TRACK RECALL: Stage-3 recall@10 requires the level-1 prefix to be a genuine behavioural partition: a query whose true items share a level-1 code must be able to emit that coarse code and still find its top-10 inside a small, coherent candidate set. HDR measures the fraction of the reference's curved dispersion that the level-1 partition removes beyond a size-matched random partition, in both the query-side (source) and item-side (target) geometry. That is precisely the property that lets a query encoder commit to a coarse code without losing its positives. It adds over Q_H because: Q_H is a rank/order statistic on prefix agreement, whereas HDR uses continuous squared hyperbolic distances and is sensitive to how tight each bucket actually is, not merely to how often a prefix wins a ranking comparison; HDR is dual-tower, so it penalises a table whose codes are coherent for items but not for queries; the (N-K)/(N-1) baseline makes HDR invariant to bucket occupancy, so it is neither bucket count nor the 0/1 same-bucket ratio in disguise; and hyperbolic boundary weighting makes HDR dominated by the specific, fine-grained items that decide top-10, which a linear prefix count under-weights. It is deliberately level-1-only: any R^2-style score rises mechanically to 1 as buckets become singletons, which is exactly the level>=2 identifier collapse already visible in Q_H (+0.634 -> +0.287 -> +0.393).
COMPUTE: One pass for mu_tau, sigma_tau, v_i, x_i: O(N*d_tau). One pass to accumulate the K+1 Klein barycentres: O(N*d_tau). Two distance passes (own code, global): O(N*d_tau) each. Total O(N*d_tau); with N=24587, K<=256, d<=~512 this is a few 10^7 flops, under 1 s in numpy and far under the 1-minute budget; memory O(N*d_tau).
RISKS: (a) If the frozen reference geometry is unrelated to the space in which the SID was built, HDR measures the wrong manifold and becomes noise; this is the main external risk. (b) tanh saturation: a few very large-norm items hug the boundary and can dominate the barycentres, flattening differences between otherwise good tables; training-RMS standardisation limits but does not remove this. (c) The (N-K)/(N-1) baseline is exact under the Euclidean variance decomposition and only approximate in hyperbolic space, so a truly random partition may score slightly off zero; sign and ordering are still preserved. (d) K very close to N makes HDR_tau large-negative; the clip to [-1,+1] bounds it, and K=N returns 0. (e) If the 97 tables were exported against different references, the scale is not comparable; the contract implies one frozen reference.
FAILURE MODE: The table on which it must be worst is a SID whose level-1 partition is geometrically excellent (level-1 buckets tight and well separated, so HDR is high) but whose level-2/3 codes are assigned independently of behaviour, e.g. randomly or by id order inside each level-1 bucket. There the query encoder can hit the right level-1 code, but the deeper prefix it must emit is arbitrary, so top-10 within a ~N/K candidate bucket is near-random and recall@10 stays low while HYP_ADJ_R2_L1 reads high. The reason is structural: the metric is deliberately blind to levels >=2 to avoid the identifier collapse, so it cannot see that the deep codes are unusable. The opposite degeneracy, a hash/modulo level-1 assignment, is correctly scored strongly negative and is therefore a success, not a failure.
END METRIC
