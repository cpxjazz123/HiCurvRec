METRIC: HSMRE
TITLE: Hyperbolic Size-Matched Radius Enrichment of an exported SID code tree
FORMULA:
Symbols. N = 24587 items; L = number of code columns in the table; C = 256 codes per column; c(i,l) in {0..C-1} the integer code of item i at level l; t_i in R^d the frozen reference's target representation of item i; tau its scalar temperature.
1. Scale (derived, never fitted): alpha = 1/tau; if no temperature is exported, alpha = 1 / median_i ||t_i||.
2. Lift with the Poincare exponential map at the origin, curvature -1: x_i = tanh(alpha*||t_i||) * t_i/||t_i|| in the open unit ball B^d; x_i = 0 if ||t_i|| = 0.
3. Geodesic distance (curvature -1): d_H(u,v) = arcosh(1 + 2||u-v||^2 / ((1-||u||^2)(1-||v||^2))).
4. Geodesic (Frechet) barycentre of a finite set S: mu(S) = argmin_{p in B} sum_{j in S} d_H(x_j,p)^2, evaluated by the Karcher flow  p <- exp_p( mean_{j in S} log_p(x_j) ),  I = 20 iterations, started at p0 = Euclidean mean of S rescaled to norm <= 0.9, with
   log_p(y) = (2/(1-||p||^2)) * artanh(||(-p)(+)y||) * ((-p)(+)y)/||(-p)(+)y||,
   exp_p(v) = p (+) ( tanh(||v||) * v/||v|| ),
   u(+)v = ((1+2<u,v>+||v||^2)u + (1-||u||^2)v) / (1+2<u,v>+||u||^2||v||^2).
   I = 20 is a convergence setting, not a fitted parameter (radii move < 1e-4 after 15).
5. Bucket and its size: B_l(i) = { j : c(j,k) = c(i,k) for every k <= l },  n_il = |B_l(i)|.
6. Code radius: r_il = d_H( x_i , mu(B_l(i)) ).
7. Size-matched geodesic null: M_il = {i} union { the n_il - 1 items nearest to x_i in d_H, ties broken by ascending item index };  r*_il = d_H( x_i , mu(M_il) ).
8. Ratio and agreement: rho_il = r_il / r*_il ;  phi(rho) = 2*rho/(1+rho^2) = sech(ln rho).
9. Informativeness mask: I_il = 1 if 2 <= n_il <= N/2, else 0 (a singleton or a bucket holding more than half the corpus makes no discriminative claim).
10. Level score: Phi_l = [ sum_i I_il*(n_il-1)*phi(rho_il) ] / [ sum_i I_il*(n_il-1) ] , and Phi_l := 0 when that denominator is 0.
11. HSMRE = (1/L) * sum_{l=1..L} Phi_l .  Range [0,1], higher is better.
INPUTS: the exported SID table, read as an N x L integer code array (one code per item per level); the frozen Issue #126 reference's per-item target representation array (N x d) and, if exported, its scalar temperature tau (otherwise the median row norm of that same array). Nothing else: no validation or test pair, no recall value, no Stage-3 output, and no training-split interaction is read. The training split is not needed.
GEOMETRY: everything is computed in the Poincare ball of fixed curvature c = 1 (K = -1). The curvature is load-bearing in four places, not cosmetic. (a) The exp_0 lift is the tanh radial map, so an item at twice the median reference norm sits at geodesic radius 2*artanh(tanh 2) = 2.6, not at radius 2; radii grow exponentially in norm. (b) mu is the geodesic Frechet barycentre, the minimiser of squared geodesic distance, which in negative curvature is displaced outward toward the boundary relative to the Euclidean mean; hence r_il is not a monotone function of any Euclidean spread, and a Euclidean re-implementation produces a different number, not a relabelled one. (c) The null r*_il is the radius of the geodesic nearest-neighbour ball; at curvature -1 the radius needed to enclose n points grows like ln n (ball volume ~ sinh^2) rather than n^(1/d), which is why rho stays discriminative at n ~ 10^2 instead of saturating at 1 as a Euclidean same-size null would. (d) phi = sech(ln rho) is the hyperbolic secant of the log ratio of two geodesic lengths measured from the same point, i.e. the ball's radial volume-density factor evaluated at the length mismatch; it is symmetric, parameter-free, equals 1 at exact congruence and tends to 0 at both extremes.
WHY IT SHOULD TRACK RECALL: HSMRE asks, at each level, whether the code bucket is as geodesically tight as the tightest set of its own cardinality. That is exactly the property prefix-matching retrieval needs, measured on a size-free axis. Three things it adds over Q_H. (1) It sees depth. At n = 2 the construction reduces exactly to rho = d_H(x_i, code partner)/d_H(x_i, NN(i)) and phi peaks at 1 when the co-coded partner IS the true nearest neighbour, so Phi_3 is a direct geodesic test of "does the finest code merge true neighbours". Q_H has no way to say this: when level 2 or 3 becomes an item identifier, Q_H simply loses its competitors and its score drifts, whereas HSMRE marks a fully singleton level as Phi_l = 0. (2) It is not an order statistic. Q_H ranks items inside a prefix, and any rank statistic is invariant to a monotone stretch of the local geometry; HSMRE divides by a size-matched geodesic null and is therefore not invariant, so a table with very large but internally well-ordered prefixes scores high on Q_H and low here. (3) It cannot be a re-expression of bucket count or of the same-bucket ratio: both are functions of the multiset of bucket sizes alone, while HSMRE depends on which items are co-coded, since Step 7 renormalises the size away; conditional on an identical size profile, HSMRE still varies across tables. Mechanistically, Recall@10 needs a level whose buckets are of neighbourhood scale and semantically pure; HSMRE is maximised at that operating point and penalises both a random 256-way split (rho >> 1, phi -> 0) and the collapsed item-identifier level (masked, Phi_l = 0).
COMPUTE: one pass to build X (N x d, float32). Blocked squared-distance Gram in 12 chunks of 2048 rows: about 2*N^2*d = 7.7e10 flops, roughly 5-10 s on BLAS. Convert each chunk to d_H (6.0e8 arcosh evaluations, ~3 s) and immediately argpartition each row at n_i1 - 1 (sizes are nested, so the level-1 size is the maximum), keeping only about 2.4e6 neighbour indices, so the full N x N matrix is never resident (peak under 0.5 GB). Barycentres: one per bucket per level, cost 20*d*N*L = 9e7 flops, negligible; one null barycentre per (item, level), cost about 20*d*sum_{i,l} n_il = 3e9 flops, ~20 s batched by size class. Deterministic tie-breaking, no randomness, no sampling. Total roughly 30-50 s at N = 24587, L = 3, C = 256, d = 64 on a single node.
RISKS: (1) Scale sensitivity. The score is not invariant to alpha, because the ball is not a cone: if the reference norms are heavy-tailed, many items land at radius > 0.999, d_H saturates near ln(2/(1-r)), and every phi goes to 1, flattening the metric. Guard: clip radii at 1 - 1e-6 and, if more than 5% of items would be clipped, fall back to alpha = 1/q_95 (still derived, stated). (2) If the reference representations are exactly unit-norm and isotropic, all radii coincide and d_H becomes a monotone function of the Euclidean angle, so the curvature contribution shrinks toward the angular term only; the metric then behaves like a cosine-purity measure. (3) Very coarse tables (mean level-1 bucket above N/2) are fully masked at level 1, and if their deeper levels are singleton the score saturates at 0 for a whole family of tables, which compresses Spearman. (4) Karcher convergence is slow for nearly antipodal sets near the boundary; with I = 20 the radii error is about 1e-4 relative and effectively constant across tables, so it adds noise, not bias. (5) Level scores are averaged uniformly, so a table with one excellent level and two useless ones cannot exceed 1/3; this is intended but may under-credit two-level tables if the exporter pads with a constant column.
FAILURE MODE: worst is the index-hash table: assign level-1 codes by (i mod 256), level-2 by (floor(i/256) mod 256), level-3 by the rest. Every bucket then has a perfectly ordinary size, so bucket count (Spearman -0.065) and same-bucket ratio are fooled, but each bucket is a random spread of items unrelated to the reference geometry, so r_il is close to the radius of a random set of that size while r*_il is the tight nearest-neighbour radius; rho is large, phi is small, and HSMRE sits near its floor. Equally worst is the fully degenerate table: one code for all items at every level (masked, Phi_l = 0) or a unique code per item at every level (all singletons, Phi_l = 0); both give HSMRE = 0, which is correct because prefix retrieval on either carries no information. A subtler failure: a table with a perfect level-3 clustering but scrambled coarse levels scores about (Phi_1 + Phi_2 + 1)/3, i.e. partial credit, matching the partial recall such a hierarchy actually delivers.
END METRIC
