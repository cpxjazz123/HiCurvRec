METRIC: hyp_bucket_reach_lift_l1
TITLE: Level-1 SID bucket reach lift under the reference Poincare metric.
FORMULA: N items; b(i)=level-1 code; n_b=|{j:b(j)=b(i)}|; z_i=frozen reference target representation, isometrically rescaled to the unit Poincare ball (curvature -1), ||z||^2 clipped to 1-1e-6. d_H(i,j)=arcosh(1+2||z_i-z_j||^2/((1-||z_i||^2)(1-||z_j||^2))). D_i=min_{j!=i,b(j)=b(i)} d_H(i,j). r_i=1+#{j!=i:(d_H(i,j),j)<(D_i,j_i*)}, j_i* the smallest index attaining D_i (tie-break by index); r_i is the 1-based rank of the nearest same-bucket item, r_i=1 when a bucket mate is the geodesic nearest neighbour. If n_b=1, r_i=N. Null rank e_i=N/n_b (expected rank of the first of n_b-1 mates placed uniformly among N-1 others). Per item: lambda_i=0 if n_b=1 or n_b=N; lambda_i=(e_i-r_i)/(e_i-1) if r_i<=e_i; lambda_i=(e_i-r_i)/(N-e_i) if r_i>e_i. M=(1/N)sum_i lambda_i, in [-1,1]. M=1 perfect geometric alignment, 0 chance, <0 anti-aligned.
INPUTS: exported Stage-2 SID table (level-1 integer code per item) and frozen Issue #126 reference target representation per item (training-pairs only; Poincare coords, or Euclidean mapped by exp_0 at the reference's fixed curvature). Nothing else.
GEOMETRY: Poincare ball, curvature -1 after the isometry x->sqrt(c_ref)x (order-preserving, untuned). The curved metric enters in every r_i: the nearest same-bucket item is found by expanding a hyperbolic ball, and hyperbolic NN != Euclidean NN, so the rank order exists only through d_H. The null e_i is rank-based, so only the observed rank carries geometry.
WHY IT SHOULD TRACK RECALL: Stage 3 reranks the level-1 bucket Stage 2 selects, so Recall@10 needs the bucket of target i to be a coherent curved neighbourhood of i: a query near i then lands in a bucket of i's geodesic neighbours and i survives reranking. HBRL measures this locally and contrasts it with the exact size-matched random partition, so bucket size and collapse cannot drive it. Over Q_H (+0.634, code-statistics prefix ranking) it adds the orthogonal test of whether the partition follows the reference's curved geometry. Unlike the path likelihood (-0.49, confounded with bucket count at -0.78, top values on 12/2/3-code collapsed tables) the analytic null makes collapse and random both 0, and only alignment positive. It is not bucket count or same-bucket ratio: those are global pair statistics high for collapse and for fine random tables alike, while HBRL is a per-item first-moment statistic that is 0 in both cases.
COMPUTE: N=24587, 256 codes. Build the N x N arcosh argument in row chunks (512 rows, ~50 MB float32); rank by the monotone argument without arcosh; per row take the same-bucket min and count closer items. O(N^2 d + N^2), ~6e8 entries, seconds to well under a minute on CPU for d<=256. No iteration, no optimisation.
RISKS: noisy frozen reference -> all M near 0 and no Spearman; reference built from the same clustering -> M saturates and loses variance; boundary points need the clip; duplicate representations need the index tie-break; singleton-dominated tables contribute 0; if Recall@10 is driven by Stage-2 token generation rather than Stage-3 candidate geometry the signal is weak.
FAILURE MODE: worst on the anti-aligned table that orders items along a hyperbolic diameter and interleaves the two ends into level-1 buckets, so each bucket holds geometrically opposite items: r_i>>e_i, lambda_i -> -1, M -> -1. Random-hash codes and the one-bucket collapse both give M=0 (neutral, never rewarded), so the anti-aligned partition is the true worst case.
END METRIC
