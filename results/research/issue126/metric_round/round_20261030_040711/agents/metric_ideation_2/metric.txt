METRIC: horo_cell_rank
TITLE: Busemann (horospherical) height of each level-1 cell under the item's full training predecessor history, converted to a full-negative-population soft expected rank
FORMULA:
Notation. B^d is the Poincare ball of radius 1, curvature K = -1 (so c = 1); exp_x and log_x are its exponential and logarithm maps. N = 24587 items. code1(i) in {0..255} is the level-1 integer of item i in the exported SID table. s_i, t_i in B^d are the frozen Issue #126 reference's source and target representations of item i (learned on training pairs only). sigma(u) = 1/(1+e^{-u}). D_train is the training split of (history, target) pairs.
1. Predecessor history of an item (whole training history, not one pair):
   Pred(i) = the multiset union of the items j appearing in the histories of ALL training pairs whose target is i.
2. Query point: b_i = the Karcher (Frechet) barycentre of {s_j : j in Pred(i)} in B^d, computed by x_0 = 0, x_{k+1} = exp_{x_k}( (1/|Pred(i)|) * sum_j log_{x_k}(s_j) ) for k = 0..49. The query direction is the ideal boundary point xi_i = b_i / ||b_i|| in S^{d-1}. Item i is skipped if Pred(i) is empty or ||b_i|| < 10^-3; the skip set I is whatever remains.
3. Cell representatives (target side, because the decoder emits SID tokens of the target): for each level-1 code a, M_a = {j in training items : code1(j) = a}, n_a = |M_a|, m_a = Karcher barycentre of {t_j : j in M_a} in B^d (same 50-step iteration).
4. Horospherical height (the curved operation): for x in B^d and xi in S^{d-1},
   B(x; xi) = log( (1 - ||x||^2) / ||x - xi||^2 ).
   This is the Busemann function of the geodesic ray from the origin to the ideal point xi; it is constant on the horospheres orthogonal to that ray and grows without bound along it. The curvature enters through the conformal factor (1 - ||x||^2): as K -> 0 the expression degenerates into the affine projection xi . x, so the term is only score-bearing because the ball is curved.
   H_i(a) = B(m_a ; xi_i), the horospherical height of cell a as seen from item i's history direction.
5. Fixed scale (derived, never tuned): let H = { H_i(a) : i in I, a = 0..255 } be the pooled heights;
   tau = 1.4826 * median_{h in H} |h - median(H)|.
6. Soft expected rank of each item's own cell against the FULL negative population (all 256 cells, weighted by their true sizes):
   r_i = 1/2 + sum_{a=0}^{255} n_a * sigma( ( H_i(a) - H_i(code1(i)) ) / tau ),
   r_i_tilde = ( r_i - 1/2 ) / (N - 1).
7. The metric: HORO_CELL_RANK = 1 - 2 * (1/|I|) * sum_{i in I} r_i_tilde. One scalar, in [-1, +1], higher is better.
INPUTS:
(a) the exported Stage-2 SID table: the level-1 integer code for every item (levels >= 2 are not read); (b) the frozen Issue #126 behaviour reference: per-item source vector s_i and target vector t_i in the shared Poincare ball, both produced from training pairs only; (c) the TRAINING split of (history, target) pairs, used solely to form Pred(i). Nothing else: no validation pair, no test pair, no recall, no Stage-3 artefact.
GEOMETRY:
Curvature K = -1, Poincare ball of radius 1, c = 1 fixed by construction, not fitted. Three curved operations, all explicit: (i) Frechet/Karcher barycentres of the predecessor history and of each cell's target members, computed with exp/log maps on the ball (a mean in the interior of a negatively curved space, not a Euclidean average); (ii) the ideal-boundary direction xi_i = b_i/||b_i||, which exists because a negatively curved space has a sphere at infinity - the query is a direction, not a vector; (iii) the Busemann function B(x; xi) = log((1-||x||^2)/||x - xi||^2), a horocycle height. Where curvature bites: the factor (1 - ||x||^2) is the conformal factor of the ball, so two cells with the SAME Euclidean offset from the origin but different radii get different heights, and a cell sitting at the origin scores 0 no matter how well it points. At curvature 1e-3 the same expression collapses toward a linear projection and the metric must lose most of its correlation: that is the built-in curvature control.
WHY IT SHOULD TRACK RECALL:
Recall@10 is decided at level 1: the correct target must be in the winning (or near-winning) level-1 cell, because from level 2 the prefix is nearly an item identifier, so cell identity approximately equals item identity. The evidence in the collection is that the recall signal lives in the contrast between the query direction and a cell's centroid direction - that is what Q_H (+0.634) and HBAA (+0.701) exploit. This metric keeps that contrast but changes three things at once. (1) It replaces the pair-level query with the item's whole predecessor history: b_i is the barycentre of every training item that ever preceded i, so the query point averages away the noise of any single history and is a property of the item, not of one pair. (2) It replaces the alignment/distance score with a horospherical height, which is the correct way to compare points at very different radii in a ball. A centroid of small norm is weakly committed - its direction is unreliable - and a raw inner product or geodesic distance can be inflated by such a centroid merely pointing roughly the right way. The Busemann height discounts radius through the conformal factor, so a cell only scores if it is BOTH directional and radially committed, which is precisely the condition for a trie cluster to be confidently decodable. (3) It replaces the mean over ten sampled negatives with the entire negative population, through a sigma-smoothed expected rank over all 256 cells weighted by their true sizes, so a table whose true cell is high but whose whole competitor cloud sits in the same direction (the signature of a collapsed or geometry-blind partition) is penalised, and, crucially, the expected-rank form makes collapse score exactly zero with no size-matching hack: a one-code table gives every item r_i_tilde = 1/2 and HORO_CELL_RANK = 0, and a randomly relabelled table does the same because every cell centroid then sits near the global mean. That is the failure that killed the plain path likelihood (-0.49, correlated -0.78 with bucket count); here collapse is neutral by construction rather than penalised by a correction term.
COMPUTE:
50 Karcher iterations on |I| predecessor sets (total predecessor mass <= |D_train|, typically <= 2e5 items) plus 256 cell barycentres: O((|D_train| + N) * d * 50). Then |I| * 256 Busemann evaluations, each O(d): 24587 * 256 * 64 ~ 4e8 flops, fully vectorisable as one (24587, 256, d) broadcast in numpy, ~10-25 s and < 2 GB at float32. The expected-rank sum is over the 256 cell values only, not over pairs, so the rank stage is O(N * 256) sigmoid evaluations. Total well under one minute on 24587 items and 256 codes.
RISKS:
(a) If the frozen reference over-shrinks its target vectors toward the origin, all m_a sit near 0, all heights collapse, and the metric degenerates to ~0 with no signal - the same regime that makes any radius-sensitive score uninformative. (b) Mixing sides: xi_i comes from source representations while m_a comes from target representations; this assumes the reference's two sides share one ball's geometry, which is stated in the reference's contract but is an assumption. (c) Items with empty or near-zero-norm predecessor barycentres are dropped; if that set is large for a table (rare in practice, since it depends on the split and not on the table), the remaining set may not represent the table. (d) The Karcher iteration is only approximately convergent at 50 steps; it is deterministic and identical for every table, so it cannot bias the ranking across tables, but it can attenuate small-norm centroids further. (e) If a table places all its distinguishing power at levels >= 2 while level 1 is nearly constant, this metric - like Q_H - cannot see the levels 2+ structure and will under-rate it; that is a deliberate scope choice, not a bug, because the measured evidence says level 2+ prefixes are item identifiers.
FAILURE MODE:
Worst on a RADIALLY STRATIFIED table: one that assigns level-1 codes by the norm of the target representation (shell 1 gets codes 0-15, shell 2 codes 16-31, ...) so that all 256 cells are perfectly size-balanced and each cell's target barycentre has the same direction spectrum as the whole population. Every m_a then differs from the others only in radius, the horospherical heights B(m_a; xi_i) are near-identical for all a, every r_i_tilde is 1/2, and the metric returns 0 - while the bucket count is maximal, the same-bucket ratio is unremarkable and Q_H would also be near zero, yet the table is not obviously broken by any prefix-count statistic. Second worst is the one-code table, also 0. That is the intended behaviour: this metric measures only whether the level-1 partition is directionally aligned with the training predecessor geometry, and a partition that carries no directional information scores nothing.
