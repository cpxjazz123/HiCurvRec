METRIC: hyp_bmid_erank
TITLE: Hyperbolic behaviour-midpoint common-ancestor expected-rank alignment of level-1 SID cells
FORMULA: Work in the unit Poincare ball B^d={x in R^d:||x||<1}, curvature -1, with Mobius addition (+), d_H(x,y)=2*artanh(||(-x)(+)y||), log_x(y)=2*artanh(||(-x)(+)y||)*((-x)(+)y)/||(-x)(+)y||, exp_x(v)=x(+)(tanh(||v||/2)*v/||v||). If the frozen reference uses curvature -k, first map every point x -> sqrt(k)*x and divide every distance by sqrt(k); M is invariant because Gamma and tau scale together, while the curvature still sets the geodesics and barycentres, so the construction stays non-Euclidean. For each training item j let s_j, t_j be its source and target ball points. Define the behaviour midpoint m_j = exp_{s_j}(0.5*log_{s_j}(t_j)). Let F(S) be the Frechet barycentre argmin_{x in B^d} sum_{p in S} d_H(x,p)^2, computed deterministically by 200 Riemannian gradient steps x_{k+1}=exp_{x_k}(-(1/(1+k))*grad f(x_k)) from the Lorentzian centroid (lift to the hyperboloid, sum, renormalise), to 1e-8. For a level-1 code c let a_c = F({m_j : j in TRAIN, c_1(j)=c}). For training pair r (history H_r, positive p_r, negative set N_r) let u_r = F({s_j : j in H_r}). Define the metric Gromov product Gamma_r(c) = 0.5*( d_H(u_r,0) + d_H(a_c,0) - d_H(u_r,a_c) ) (distance from the origin to the common ancestor of the query and the cell in a CAT(-1) space). Let sigma(z)=1/(1+exp(-z)). With tau = tau_ref * Rbar, where tau_ref is the frozen reference temperature and Rbar = (1/C)*sum_c d_H(0,a_c) over the C anchored level-1 cells, define rho_r = (1/|N_r|) * sum_{n in N_r} sigma( (Gamma_r(c_1(n)) - Gamma_r(c_1(p_r))) / tau ), and M = 1 - (2/R) * sum_{r=1}^{R} rho_r. M in [-1,1], higher is better; all-equal alignments give rho=0.5 and M=0 exactly.
INPUTS: the exported Stage-2 SID table (integer level-1 code c_1(i) per item, 24587 rows, <=256 codes); the frozen Issue #126 reference's TRAIN-split source s_j, target t_j per item, TRAIN training pairs (H_r, p_r, N_r, |N_r|=10), curvature and temperature tau_ref; the TRAIN split. Nothing else: no validation or test interaction, no recall, no Stage-3 output.
GEOMETRY: explicit negative curvature -1. The curvature enters three times: (i) m_j is the geodesic midpoint of [s_j,t_j] (a Euclidean midpoint is a different point whenever the segment is off-origin); (ii) a_c and u_r are Frechet barycentres minimising a sum of squared hyperbolic distances; (iii) Gamma is the metric Gromov product, i.e. the depth of the common ancestor, computed with d_H, the hyperbolic analogue of a tree-prefix depth. The logistic is applied in these Gromov units, so the number is not a Euclidean distance in disguise: it is a monotone function of a hyperbolic common-ancestor depth, with geodesic-midpoint anchors.
WHY IT SHOULD TRACK RECALL: a Stage-3 run retrieves by matching the query to a prefix cell; recall@10 is high when the cell holding the true next item shares a deep semantic ancestor with the user history and when the cell points toward where the item's behaviour should go. HBAA measures the first half on source-only anchors with a mean margin over ten negatives. This metric (a) puts the item side on the geodesic midpoint between source and target, so a table whose cells are coherent in the reference's behaviour-update direction scores above one that merely clusters static sources; (b) replaces the mean of ten negative margins with the full temperatured expected rank, so a table is penalised when even a few negatives sit at or above the positive cell, which is what costs top-10 recall; (c) is zero for any table that does not order cells, so collapse cannot buy score. Over Q_H it adds the frozen reference's continuous curved geometry and its target side at all, rather than a learned prefix ranking score.
COMPUTE: O(N*d) midpoints plus O(200*N*d) for the C<=256 Frechet barycentres (batched), plus O(sum_r |H_r|*d) for the queries and O(R*10) sigmoids. On 24587 items and 256 codes this is a few vectorised numpy passes over 24587 x d and 256 x d arrays; well under one minute, no training.
RISKS: the target representation may be noisier or in a slightly different space than the source, so m_j could be worse than s_j (it degrades gracefully to the source anchor as t_j -> s_j); tau_ref may be stored as a unit-normalised logit temperature, in which case the Rbar rescaling is what makes it dimensionally meaningful, and a mis-scaled tau only saturates or flattens rho without changing the sign; cells containing no TRAIN item have no anchor and are dropped from N_r (positives always have one); a very small R or |N_r| makes M noisy; the Frechet solver must be seeded identically across tables or it adds jitter.
FAILURE MODE: the all-one-code table, where every item has the same level-1 code, is worst: all Gamma_r(c) are identical, every sigmoid is exactly 0.5, rho_r = 0.5 and M = 0. A uniformly random relabelling of the 256 codes onto the same item set also gives M ~ 0 because the anchors carry no history alignment. Any table that is a refinement with cells whose midpoint anchors are exchangeable with respect to the history is scored at the random baseline, never above it.
END METRIC
