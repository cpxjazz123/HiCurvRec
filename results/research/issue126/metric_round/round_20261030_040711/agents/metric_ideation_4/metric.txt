METRIC: hyp_hist_pmi_l1
TITLE: Curvature-corrected hyperbolic history-to-cell pointwise mutual information of level-1 SIDs
FORMULA: Work at curvature c = 1 (if the frozen reference stores c_ref, replace 1 by c_ref everywhere below; the formula is stated at c = 1 WLOG). For a nonzero vector v in R^d set E(v) = tanh(||v||/2) v/||v|| and E(0) = 0 (the exponential map at the origin of the unit Poincare ball); for x in the open unit ball set L(x) = 2 artanh(||x||) x/||x|| and L(0) = 0 (the inverse, log map). For a finite set X of ball points set B(X) = E( (1/|X|) * sum_{x in X} L(x) ) (the one-step tangent/Karcher barycentre; a curved barycentre). For p,q in the ball set p (+) q = ((1 + 2<p,q> + ||q||^2) p + (1 - ||p||^2) q) / (1 + 2<p,q> + ||p||^2 ||q||^2) and d(p,q) = 2 artanh(||(-p) (+) q||). Let T be the set of training items, N = |T|, and let s = sqrt( (1/(2N)) * sum_{i in T} ( ||eS_i||^2 + ||eT_i||^2 ) ), where eS_i and eT_i are the frozen reference source and target vectors of item i. Put xS_i = E(eS_i / s) and xT_i = E(eT_i / s). Let code1(i) in {1,...,K} be the integer level-1 code of item i and n_k = #{i in T : code1(i) = k}. For every k with n_k > 0 set C_k = B({xT_i : i in T, code1(i) = k}). Let U be the set of training (query, positive-target) pairs u = (H_u, i_u^+) with nonempty query history H_u; set q_u = B({xS_j : j in H_u}) and k_u^+ = code1(i_u^+). Let tau = 1/beta_ref, where beta_ref is the frozen inverse temperature (logit scale) stored with the reference; if the reference stores a temperature T_ref instead, tau = T_ref. Then p_u(k) = exp(-d(q_u,C_k)/tau) / sum_{j : n_j>0} exp(-d(q_u,C_j)/tau), and the metric is M = (1/|U|) * sum_{u in U} [ ln p_u(k_u^+) - ln(n_{k_u^+} / N) ]. Higher M is better. Queries with empty history are skipped; codes with n_k = 0 are omitted from the softmax denominator.
INPUTS: (i) the exported SID table: one integer level-1 code code1(i) per training item; (ii) the frozen Issue #126 behaviour reference: per-item source and target vectors eS_i, eT_i for training items and its frozen beta_ref (or T_ref), learned on training pairs only; (iii) the TRAINING split: the training item set T and the training (query-history, positive-target) pairs U. Nothing else: no validation item, no test item, no validation/test interaction, no recall, no Stage-3 output.
GEOMETRY: The unit Poincare ball with constant negative curvature -1. E and L are the exp/log maps at the origin, d is the geodesic distance, (-p)(+)q is Moebius addition, and B is a geodesic barycentre computed as exp_0 of the tangent-space mean of log_0. Curvature enters in three places: the map E(e/s) that puts the Euclidean reference vectors on the ball, the log/exp pair used to form every cell and history barycentre, and the geodesic distance d inside the softmax. At c -> 0 all three reduce to Euclidean means and Euclidean distances, so the construction is explicitly a curved one, not a Euclidean distance renamed.
WHY IT SHOULD TRACK RECALL: Stage 3 retrieves the target's level-1 cell from a source query, so a table is good when the target's cell is the one the query's whole history points to, against the whole field of competing cells. HBAA scores only a mean positive-minus-negative margin with a single tangent direction; it is blind to how the positive cell competes against the full set of cells and can be carried by one far negative. M instead uses (a) the full training history as the query point (a hyperbolic barycentre of its source items, more stable than a single anchor), (b) the full negative distribution through a log score over all K cells, which is a proper scoring rule: it rewards putting softmax mass on the true cell and penalises near-ties, and (c) the size-matched null ln(n_k/N), which removes the free mass that large or collapsed cells obtain and makes a random relabelling score 0. A table with fewer, purer cells wins only if the softmax mass on the positive cell exceeds what its size alone predicts; a table that shreds the reference neighbourhoods into cells that lose the softmax is penalised. This is more information than Q_H (a single prefix rank) and more than HBAA (a single mean margin), and it is not a count, collision or same-bucket statistic.
COMPUTE: One pass over T to compute s, the per-item maps xS_i, xT_i, the counts n_k, and the K barycentres C_k (K <= 256); one pass over U' to compute q_u; then a single |U'| x K geodesic-distance matrix and a softmax per row. Cost is O((N+|U'|) d + |U'| K d), with N = 24587 and K <= 256. All operations are closed-form and vectorisable in NumPy; no iteration beyond one tangent-mean step, no training, no pairwise item-item matrix. On 24587 items and 256 codes this is well under a minute per table, and the same xS_i, xT_i and C_k can be cached across the 97 tables because only code1 changes.
RISKS: (1) If the reference's source and target towers do not live in a comparable space, the cross distance d(q_u,C_k) is meaningless; the construction assumes the usual shared contrastive retrieval space. (2) If beta_ref is very large the softmax is one-hot and M is dominated by a few confident queries; if very small it is near-uniform and all tables score near 0. beta_ref is frozen, never fitted on the 97 recalls. (3) Very rare cells (n_k = 1) receive a large log(N) gain when hit, so a table that isolates a few highly predictable items can be rewarded; at K <= 256 and N = 24587 this affects a bounded minority of cells. (4) The history barycentre is undefined for cold-start queries with empty history; those queries are skipped, so a table could in principle look good on the warm subset only. (5) If the SID level-1 partition is already almost perfectly aligned, M saturates as p -> 1 and differences between near-perfect tables shrink (ceiling effect).
FAILURE MODE: M is worst on an anti-aligned table: a table with the same K and the same cell-size multiset n_k as a good table, but whose level-1 assignment is a permutation that sends each item to a cell whose target barycentre is far from that item's reference neighbourhood (for example, codes assigned by a hash of the antipodal target direction). Then p_u(k_u^+) is near 0 while n_{k_u^+}/N is still of order 1/K, so every term is strongly negative and M is strongly negative. It is exactly 0 on the one-code table (p = 1, n/N = 1) and approximately 0 on any size-matched random relabelling (p_u(k) ~ n_k/N), so collapse and count-balance cannot be rewarded.
END METRIC
