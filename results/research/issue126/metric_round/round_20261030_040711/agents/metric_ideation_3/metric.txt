METRIC: hfsc_rank_l1
TITLE: Hyperbolic free-energy cell rank — the chance-corrected soft rank of the true level-1 cell under a leave-one-out Karcher barycentre of the full training history, scored against the whole per-cell negative distribution.
FORMULA: Work in the open ball B^d = {x in R^d : ||x|| < 1} at constant curvature c = -1, with the Poincare Riemannian distance

  d(x,y) = arcosh( 1 + 2·||x-y||^2 / ( (1-||x||^2)(1-||y||^2) ) ).

KarcherMean(S): the point m in B minimising sum_{y in S} d(m,y)^2, obtained by Riemannian gradient descent with step 1, initialised at the Euclidean mean of S projected by x -> x·(1-1e-6)/max(1,||x||), stopped at ||grad|| < 1e-8 or 30 iterations, whichever comes first (step 1 and the cap 30 are fixed a priori, not fitted).
beta = 1/tau_ref, where tau_ref is the contrastive temperature stored in the frozen Issue #126 reference (or its stored learned inverse-temperature scale, if that is the form it exposes).
For a TRAIN pair (q,p): let H_q = { j : (q,j) in TRAIN }, and H_q^- = H_q \ {p}; set m_q = KarcherMean({u_j : j in H_q^-}) when H_q^- is non-empty, else m_q = u_q, where u_j is the reference's SOURCE representation of item j.
For every item i != q, delta_i = d(m_q, v_i), with v_i the reference's TARGET representation of item i.
For every level-1 cell c with member set C_c = { i : code1(i) = c }, write C_c^- = C_c \ {q} (drop cells with C_c^- empty) and

  F_c = -(1/beta) · log( (1/|C_c^-|) · sum_{i in C_c^-} exp(-beta · delta_i) ).

This is the per-item free energy of the cell: a log-mean-exp soft minimum, size-neutral because the 1/|C_c^-| cancels the |C_c^-| draws. Let K_eff be the number of cells with C_c^- non-empty, let c_p = code1(p), and let sigma(z) = 1/(1+exp(-z)). Then

  pi_q = 1 + sum_{c != c_p} sigma( beta · (F_{c_p} - F_c) )
  r_q  = 1 / pi_q
  M    = (1/|TRAIN|) · sum_{(q,p) in TRAIN} r_q  -  2/(K_eff + 1).

Higher means better. The subtracted constant is the exact chance level, not an estimate: it is precisely 1/pi_q in the all-cells-tied configuration, so an uninformative table scores 0 and a one-code table (K_eff = 1) scores exactly 0.
INPUTS: (1) the exported SID table, level-1 integer code per item only (levels 2..L are read but never used); (2) the frozen Issue #126 behaviour reference — per-item source representation u_i, per-item target representation v_i, and its stored contrastive temperature tau_ref; (3) the TRAINING split, used only as the pair list and for building H_q. Nothing else: no validation pair, no test pair, no recall, no Stage-3 artefact, no fitted quantity.
GEOMETRY: curvature enters in three places. In d, which is the Poincare-ball Riemannian distance at c = -1 and not a Euclidean distance in disguise: it diverges as either argument nears the boundary, so a cell whose members sit close to the sphere is penalised far more than its Euclidean offset suggests. In m_q, the Riemannian (Karcher) barycentre of the history's source points — the arithmetic mean of the same points is a different point of the ball, so the query location is itself curvature-dependent. And in F_c, which is a log-partition function of the per-item distance distribution, i.e. a soft minimum over the whole negative population. Curvature is fixed at exactly c = -1, nothing is tuned; beta = 1/tau_ref is inherited from the frozen reference rather than fitted.
WHY IT SHOULD TRACK RECALL: Stage 3 walks the code tree and can only re-rank the ten items its beam reaches, so Recall@10 is capped by whether the true item's level-1 cell is reachable for the query. This metric measures that reachability directly, with the frozen reference as arbiter: for each training query it asks where the cell containing the reference-nearest item to the query's whole training history sits in a soft ordering. It adds three things over HBAA and Q_H. First, it keeps HBAA's full-history barycentre but replaces the mean over ten negative barycentres with the free energy of the entire per-cell negative population, so a cell hiding one negative almost exactly on the query is penalised instead of having it averaged away — and the Stage-3 re-rank is exactly a competition against the single best negative, not against an average. Second, it is an order statistic over the item distribution and therefore sensitive to the left tail of the negatives, the one information source the brief identifies as still unused; a mean cannot see that tail. Third, its collapse behaviour is analytic rather than empirical: the K_eff chance offset plus the 1/|C_c^-| normalisation forces one-code, few-code and relabelled tables to 0, which is precisely what sank plain path likelihood (-0.488) and its collapse reward, and it does so without any size-matched shuffling null (whose bad construction already showed up as +0.061 in hbaa_size_matched_kept).
COMPUTE: one Karcher mean per training pair over |H_q|-1 history points (|H|·30·d flops, negligible), plus one distance vector over N = 24587 items (24587·d flops) and one segmented log-mean-exp over 256 cells. The distance vectors dominate and are formed as a chunked GEMM (chunk x d) @ (d x 24587) against precomputed ||v_i||^2, followed by arcosh: 1e4 pairs at d = 64 is about 1.6e10 flops, roughly 10-20 s on BLAS; 5e4 pairs is about 50-60 s. Memory is one 24587-vector per query plus the 24587 x 64 representation matrix (~6 MB), all dense float arrays. Because only level 1 is used, K_eff <= 256 and the cell reduction is O(N) per query, so the whole thing finishes inside a minute on 24587 items.
RISKS: (i) if the reference's candidate set is narrower than the full catalogue, the free energy is taken over a different population than Stage 3 ranks, which flattens the signal; (ii) if the reference exposes only a learned inverse temperature and not a temperature, beta falls back to beta = 1 in curvature-normalised units — this changes the sharpness of the soft minimum but not the ranking argument, and the chance offset is unaffected because it contains no beta; (iii) the segmentation assumes code1 is the exported level-1 column and that padding/duplicate sentinel codes are excluded, otherwise empty sentinel cells enter K_eff and inflate the subtraction; (iv) a singleton history falls back to m_q = u_q, reintroducing a direct source-target comparison for that one pair (bounded, but noisier); (v) with very skewed reference norms, d saturates, many cells tie in F_c and M is driven to the chance level 0 rather than to a false positive; (vi) it shares HBAA's dependence on the reference's source/target alignment, so a weak reference weakens it too.
FAILURE MODE: worst on a HUB-AND-SPOKE level-1 table, where each of the K cells holds one geodesically central medoid item plus uniformly random remaining items. The medoid pins every cell's free energy to nearly the same value, so F_{c_p} - F_c is near 0 on every pair, the sigmoids sit at 1/2, pi_q tends to (K_eff+1)/2 and M tends to 0 (slightly negative where the true cell's medoid happens to be the furthest). Second worst on extreme size skew — one very large cell plus 255 singletons — because the large cell wins the soft minimum for every query, true singleton cells accumulate exceedance, and M goes below 0. In both cases the table has thrown away the information that would let a prefix-restricted beam reach the right items, and the metric correctly reports no value instead of rewarding the collapse.
END METRIC
