METRIC: hgca_l1
TITLE: Hyperbolic Gromov-ancestry AUC of the level-1 cell (two-tree agreement between the trie's branch and the reference's common-ancestor depth)
FORMULA: Items i=1..N (N=24587), integer codes k_i=(k_i1,...,k_iL). Reference points x_s(i), x_t(i) in the Poincare ball B_c={p in R^d : c||p||^2<1} of curvature -c, with c=c_R (the curvature stored with the frozen reference artifact; no new constant).
  d(u,v) = (1/sqrt(c)) * arcosh( 1 + 2c||u-v||^2 / ((1-c||u||^2)(1-c||v||^2)) ).
  For every training interaction (u,i) used as a query: target i+=i, history H(u,i) = the training items of u strictly before i, truncated to the most recent 200 (compute cap, not tuned).
  Query point q = Einstein midpoint of {x_s(j) : j in H}: k_j = 2x_s(j)/(1+c||x_s(j)||^2) (Klein), g_j = 1/sqrt(1-c||k_j||^2), s = sum_j (1/|H|) g_j k_j, k_q = s/||s||, q = k_q/(1+sqrt(1-c||k_q||^2)).
  r_q = d(q,o), r_j = d(x_t(j),o) with o=0 (ball centre).
  G_j = 0.5*( r_q + r_j - d(q, x_t(j)) )  ==  the Gromov product (q|x_t(j))_o in (B_c,d).
  S+ = { j != i+ : k_j1 == k_{i+}1 },  S- = { j != i+ : k_j1 != k_{i+}1 }, n+=|S+|, n-=|S-|.
  AUC_u = [ sum_{j in S+} rank_{S+ U S-}(G_j) - n+(n++1)/2 ] / (n+ * n-), ranks with mid-ranks for ties.
  HGCA = (1/|Q|) * sum_{u in Q} ( 2*AUC_u - 1 ).  A query with n+=0 or n-=0 contributes exactly 0. Range [-1,+1], higher better. Q = all training interactions; if |Q|>4096, take every ceil(|Q|/4096)-th in fixed order (compute cap).
INPUTS: the exported SID table (one integer code per item per level); the frozen Issue #126 behaviour reference (x_s(i), x_t(i) per item, its curvature c_R, training-pairs-only); the TRAINING split (user, item, order) to form histories. Nothing else.
GEOMETRY: curvature is -c_R and enters twice, inseparably. (1) q is a Frechet/Einstein barycentre in the ball; (2) the score is the Gromov product (q|x_j)_o, the depth of the common ancestor of the query and item j in the ball's tree-like structure, with Poincare geodesic lengths. At c->0 the Gromov product degenerates to the flat inner product <q,x_j>, loses all ancestor meaning, and the metric stops comparing two trees. No log map, no tangent vector, no extra curvature constant; the only scale is the reference's own c_R, and AUC is invariant to any monotone rescaling of G.
WHY IT SHOULD TRACK RECALL: a Stage-3 Recall@10 miss happens when the target's level-1 branch is not the branch the decoder scores highly for the query, or when that branch drags in too many co-scored competitors. The reference embedding is tree-like: (q|x_j)_o is literally how deep the query's ancestry is shared with item j, and the trie's level-1 code is the code's own claim about that ancestor. HGCA asks, per query, whether the positive's cell holds the items that sit deeper in the query's ancestry than the corpus at large (AUC over all 24587 items), averaged over queries. That is the quantity the prefix beam is trying to rank. Over Q_H it adds: (a) the whole negative distribution through a rank statistic instead of one anchor's prefix rank; (b) like-for-like comparison (ancestor depth vs prefix, not prefix vs raw proximity); (c) the whole training history as the query point (barycentre), not a single anchor; (d) an exact zero under code/geometry independence, so collapse and relabelling are never rewarded and bucket count does not enter the number.
COMPUTE: precompute r_j and c-norms once (O(N d)). Per query: one N x d matrix-vector product for <q,x_t(j)>, the closed-form Poincare distance (O(N d)), then one argsort of N doubles for mid-ranks and a prefix-count pass over the 256 level-1 codes (O(N log N)). 4096 queries x 24587 items is about 10^8 flops and ~4096 sorts, roughly 10-20 s single core, O(N) memory. Fits the one-minute budget.
RISKS: G_j is bounded by min(r_q,r_j), so for co-radial items it is largely a radius/frequency term and the metric may partly be a popularity detector, over-crediting tables that reproduce frequency. Long histories collapse q toward the origin (small r_q), degrading G to 0.5*r_j and amplifying that confound. Level-1 only: two tables with the same level-1 partition but different deeper levels score identically (deliberate, since level >=2 is item-ID-like). Tables with extreme bucket counts give few contributing queries and a noisier average. If the stored reference points are in a differently normalised ball than c_R implies, G is distorted.
FAILURE MODE: worst on a level-1 code anti-aligned with the reference's ancestry, e.g. codes assigned by the angular sector opposite to each item's reference position, so the positive's cell holds exactly the items sharing least ancestry with the query: every AUC_u < 0.5 and HGCA goes to -1. It is exactly 0 on the tables that should be neutral: a one-code table (S- empty, every query contributes 0) and a randomly relabelled or round-robin-over-id table (codes independent of geometry, AUC=0.5).
END METRIC
