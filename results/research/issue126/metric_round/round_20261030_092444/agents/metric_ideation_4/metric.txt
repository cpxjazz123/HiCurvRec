METRIC: hyp_cell_mass_lift_l1
TITLE: Size-matched, decoder-temperatured hyperbolic predictive-mass lift of each item's level-1 SID cell, queried by its full training-history Frechet barycentre.
FORMULA: Let B = {x in R^d : c||x||^2 < 1} be the Poincare ball of curvature -c, c > 0, with c the frozen Issue #126 reference's curvature (if it is not exported, c = 1). Mobius addition: x (+) y = ((1 + 2c<x,y> + c||y||^2)x + (1 - c||x||^2)y) / (1 + 2c<x,y> + c^2||x||^2||y||^2). exp_x(v) = x (+) (tanh(sqrt(c)||v||/2) v / (sqrt(c)||v||)); log_x(y) = (2/sqrt(c)) artanh(sqrt(c)||(-x)(+)y||) ((-x)(+)y) / ||(-x)(+)y||; d_B(x,y) = (2/sqrt(c)) arcosh(1 + 2c||x-y||^2 / ((1-c||x||^2)(1-c||y||^2))). For a finite set S in B, mu(S) = argmin_{x in B} sum_{s in S} d_B(x,s)^2, computed from x_0 = the radius-clipped Euclidean mean by 20 iterations of x <- exp_x( (1/|S|) sum_{s in S} log_x(s) ) (a Frechet/Karcher barycentre). For item i: a_i is its frozen reference SOURCE representation, b_i its frozen reference TARGET representation, both projected into B by scaling to radius at most (1/sqrt(c))(1 - 1e-5). H_i = the items of i's user that occur strictly before i in the training split's fixed order, excluding i. u_i = mu({a_k : k in H_i}). tau = the frozen reference's own softmax temperature (its logit scale); if not exported, tau = 1/sqrt(c). p_i(k) = exp(-d_B(u_i,b_k)/tau) / sum_{m=1..N} exp(-d_B(u_i,b_m)/tau), evaluated by log-sum-exp. L1(i) = the level-1 integer code of item i; cell(i) = {k : L1(k) = L1(i)}; s_i = |cell(i)|; N = the number of items in the table. P_i = sum_{k in cell(i)} p_i(k). Q is the deterministic set of M = 2*256 = 512 query items: keep training items with |H_i| >= 1, sort them by integer item id, and for t = 0..M-1 take the item at index floor(t*(n-1)/(M-1)) (or all n if n < M); Q depends only on the training split and the codebook size 256, never on the SID table or on any recall. METRIC = (N/M) * sum_{i in Q} P_i/s_i - 1. One scalar, higher is better. No constant is fitted to the 97 recalls: c and tau come from the reference, M = 2*256 from the codebook size, 20 and 1e-5 are convergence and float-projection constants, N from the table.
INPUTS: the exported SID table (integer code per item and level; level 1 is used); the frozen Issue #126 behaviour reference's per-item source array a and target array b, plus its curvature c and temperature tau; the TRAINING split (user-item interactions in their fixed order) to build H_i. Nothing else: no validation interaction, no test interaction, no recall, no Stage-3 output.
GEOMETRY: the query point is a Karcher/Frechet barycentre in the curvature -c ball, built with the Poincare exp and log maps and Mobius addition, so it is not a Euclidean mean; the score is the Poincare geodesic distance d_B; the normaliser is a softmax over geodesic distances at the reference's own temperature. Curvature enters in d_B's denominator (1-c||x||^2)(1-c||y||^2), in every exp/log of the barycentre iteration, and in the temperature fallback 1/sqrt(c). The c -> 0 limit is a Euclidean mean and a Euclidean softmax and a numerically different number, so this is not a Euclidean distance in disguise.
WHY IT SHOULD TRACK RECALL: Stage 3 visits a level-1 cell only if the reference's own decoder assigns that cell enough probability mass for the query, so the quantity governing Recall@10 is exactly P_i, the temperatured predictive mass the decoder places on the item's cell. Dividing by the closed-form null s_i/N, the expected mass of a uniformly random size-matched cell (each item lies in the cell with probability s_i/N and the softmax sums to 1), makes the number a lift over chance: the factor by which the table's cell beats a random cell of the same size. It adds three things over HBAA, which estimates the same log-likelihood ratio from one positive and the mean of ten sampled negatives: (i) the full negative distribution with the decoder's exponential weights, hence no ten-negative sampling variance; (ii) a closed-form size-matched null, so a 1-code table scores exactly 0 and a random relabel scores ~0, and neither large nor collapsed cells are rewarded; (iii) the whole training history as the query point (the barycentre of its items' source representations) rather than a single anchor. It is not an expected rank either: it keeps the magnitude of the probability gap, which is what the beam consumes, not only the order. It is not a coverage, margin, tightness, adjacency-R2 or path-likelihood statistic, all of which were measured and failed.
COMPUTE: M = 512 queries times N = 24587 targets = 1.26e7 Poincare distances of dimension d (about 8e8 flops at d = 64), evaluated in query chunks so memory stays bounded; plus 512 Karcher means over histories of average length about 10 at 20 iterations each, and two log-sum-exp passes per query. Vectorised NumPy: a few seconds, comfortably under one minute on 24587 items and 256 codes.
RISKS: (a) tau matters: if the reference temperature is very small the softmax collapses to a 1-nearest-neighbour indicator and the metric becomes a noisy cell hit-rate; if it is very large P_i -> s_i/N and the metric flattens to 0 for every table. tau is used verbatim because Stage 3 uses the same value, so the risk is inherited rather than introduced. (b) Global popularity is not controlled: a table that groups globally popular items can raise P_i without personalisation, since the null controls cell size but not item frequency. (c) Level-1 only: at most 256 cells, so two tables with the same level-1 partition but different deeper branches get identical scores; if Stage-3 recall is driven by deeper branching the metric is blind to it. (d) If the reference representations are nearly Euclidean the curvature term contributes little and the value approaches its c -> 0 limit. (e) Items with empty or one-item histories are excluded from Q, and the 512-query sample adds sampling noise. (f) If the training split's temporal order is not fixed and reproducible, H_i is ill-defined.
FAILURE MODE: the table on which it must be worst is the anti-coherent derangement: a valid 256-code level-1 partition whose cells are built so that each item shares its cell with the items the reference finds LEAST probable given that item's history (for example, assign codes in reverse order of the items' frequency-sorted predictive rank, so every cell is a set of mutually unpredictable items). There P_i << s_i/N for almost every query and the metric is strongly negative, because it is a lift with no floor at 0. The one-code table gives exactly 0 (P_i = 1, s_i = N) and a uniformly random relabelling of any table gives 0 in expectation (E[P_i] = s_i/N), so the ordering is anti-coherent < collapse = random < coherent. A subtler failure is a table that is optimal at level 1 but random below it: it scores as high as the good table, which is a sensitivity failure rather than a low score.
END METRIC
