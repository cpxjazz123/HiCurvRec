METRIC: hyp_xview_gromov_auc
TITLE: Cross-view Gromov common-ancestor AUC of the level-1 SID cells against the full training history, lifted to zero by size-weighted negatives.
FORMULA: Let V be the N=24587 items. Fix curvature K=-1 and the Poincare ball B^d of radius 1 implied by the reference. For x,y in B^d:
  d(x,y) = arcosh( 1 + 2*||x-y||^2 / ((1-||x||^2)(1-||y||^2)) )
  (x|y)_o = 0.5*( d(o,x) + d(o,y) - d(x,y) )   [Gromov product at the origin o]
Lorentz lift of x: X = ( (1+||x||^2)/(1-||x||^2), 2x/(1-||x||^2) ) in R^{d+1}, with <U,V>_L = -U_0V_0 + sum_i U_iV_i and <X,X>_L = -1. The hyperbolic (Frechet) barycentre of a finite set {x_j} is its Lorentz centroid c = Xbar / sqrt(-<Xbar,Xbar>), Xbar = sum_j X_j, renormalised to <c,c>_L=-1 and projected back by x = c_{1:d}/(c_0+1). No fitted parameter.
Definitions:
  s_v, t_v = source and target reference representations of item v, both in the same B^d_{-1};
  P = training pairs (a,b), TRAIN split only; H(i) = { s_a : (a,i) in P } (the full training history of i);
  q_i = Lorentz centroid of H(i)  (one query point per target item);
  h(v) in {1..K1} = FIRST code of v's SID (level 1); C_h = { v : h(v)=h }; n_h = |C_h|;
  c_h = Lorentz centroid of { t_v : v in C_h }  (target-side codebook point of cell h);
  A_i(h) = ( q_i | c_h )_o.
For each i in I = { i : |H(i)| >= 1 }:
  E_i = (1/(N-1)) * [ (n_{h(i)}-1)/2 + sum_{h != h(i)} n_h * 1{ A_i(h) < A_i(h(i)) } ].
The metric is
  HG = (1/|I|) * sum_{i in I} ( E_i - 1/2 ).
HG is in [-1/2, +1/2], higher is better. E_i is the AUC-style probability (same-cell pairs credited 1/2) that a uniformly random OTHER item's level-1 cell is less Gromov-aligned with i's full-history query than i's own cell is. The only constants are 1/2 (AUC tie convention), N-1 (item count) and K=-1 (the reference's curvature). No temperature, no tuned weight.
INPUTS: the exported SID table (integer code per item at level 1); the frozen Issue #126 behaviour reference source/target representation arrays s_v and t_v; the TRAINING split pairs P. Nothing else.
GEOMETRY: Curvature K=-1 enters three times and is not removable. (1) d is the Poincare metric of a ball of fixed negative curvature, so (x|y)_o is a Gromov product; by construction it is the depth of the lowest common ancestor in the reference's tree-like semantic hierarchy, i.e. "the cell lies in the same semantic subtree as the query". (2) q_i and c_h are geodesic (Lorentz/Frechet) barycentres, minimisers of summed squared geodesic distance on the hyperboloid, not Euclidean means. (3) the comparison of A_i(h) with A_i(h(i)) is a tangent-space/common-ancestor comparison that is only defined because both points were lifted through the exponential map into the same negatively curved ball; a Euclidean distance on raw codes or raw features has neither the common-ancestor reading nor the exponential volume growth.
WHY IT SHOULD TRACK RECALL: Stage 3 recalls i iff the generator, conditioned on the query, emits i's SID in the top 10. That requires (a) i's first code to be the code the query's semantics predict, and (b) that code to outrank the competing codes. HG measures (a) and (b): q_i aggregates the WHOLE training history of i (all co-occurring source items), not one anchor and not a mean of ten negatives; c_h is built on the TARGET head, the side the generator must hit; and the statistic is taken against the ENTIRE size-weighted negative code distribution, so a cell is rewarded only if it beats most competing cells rather than the mean of ten convenient negatives. Adds over Q_H: Q_H scores the prefix ordering of items by their own reference geometry and never asks whether the code is the one the query predicts, so it cannot separate a semantically coherent code from a merely tidy one. Adds over HBAA: HBAA is a single signed margin (u_h|mu_+) - (u_h|mu_-) against one positive barycentre and one mean-over-ten-negative barycentre, on the source head; HG replaces that mean by the full negative distribution as a rank/AUC, making it invariant to the scale and offset of the Gromov products and ungameable by a few easy negatives, and it uses the target head for the codebook, i.e. the actual retrieval direction. The AUC form gives the right degeneracy: a one-code table has E_i=1/2 for every i (HG=0) and a random relabelling is exchangeable so E[1{A_i(h)<A_i(h(i))}]=1/2 (HG~0), so collapse is never rewarded.
COMPUTE: Lorentz lifts plus |I| history barycentres and K1 cell barycentres are closed form: O(N*d) time and O(N*d) memory (d<=256, N=24587, K1<=256). The alignment stage is |I|*K1 Gromov products, each three Poincare distances of O(d), i.e. at most 24587*256 ~ 6.3e6 products (~1.6e9 multiply-adds), fully vectorisable in numpy, a few seconds. Whole metric well under one minute.
RISKS: (i) the Gromov product carries a radial depth term, so cells whose centroid sits near the boundary can look aligned with every query; size weighting and the 1/2 same-cell credit reduce but do not remove this. (ii) if the source and target heads are not in a common ball/curvature the cross-view product is ill-defined; it must be the shared B^d_{-1} exported by Issue #126, else the statistic degenerates to noise. (iii) sparse training pairs make |H(i)| and |I| small, so the estimate is noisy. (iv) points near ||x||=1 make arcosh overflow; clamp ||x|| <= 1-1e-6 in double precision. (v) tiny K1 makes the AUC coarse and can leave it near 0 for every table.
FAILURE MODE: the worst table is the adversarial anti-alignment that assigns every item i the level-1 code whose Gromov alignment with q_i is SMALLEST (the exact reverse of the metric's preference), driving HG to about -(1/2)*(N-K1)/(N-1), the minimum. The degenerate one-code table (K1=1) is the worst structured case: there is no h != h(i), so E_i=1/2 for all i and HG=0 exactly by construction, and a uniformly random relabelling also gives HG~0, so neither collapse nor noise is rewarded. The metric is also near 0 when the target head is uninformative relative to the source head, because then all A_i(h) are nearly equal.
END METRIC
