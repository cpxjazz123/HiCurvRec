METRIC: hyp_recall10_emission_sim
TITLE: Curvature-ranked, occupancy-weighted top-10 emission hit rate of the level-1 cell partition, measured over chance.
FORMULA: N = 24587 items, K = 256 codes, L levels. c1(i) in {1..K} is the level-1 code of item i. G_c = {i : c1(i) = c}, n_c = |G_c|, m = #{c : n_c > 0}. kappa < 0 is the frozen reference's curvature (kappa = -1 if the reference does not state one); beta = sqrt(|kappa|). p_i = exp_0^kappa(s_i) = tanh(beta |s_i| / 2) * s_i / (beta |s_i|), with s_i the frozen reference source representation of item i and exp_0^kappa(0) = 0. d_kappa(x,y) = (1/beta) * arcosh(1 + 2|kappa| |x-y|^2 / ((1-|kappa||x|^2)(1-|kappa||y|^2))). bar(S) is the Klein-Einstein hyperbolic midpoint of the set S: k_i = 2 p_i / (1 + |kappa||p_i|^2), gamma_i = 1/sqrt(1 - |kappa||k_i|^2), kbar = sum_i gamma_i k_i / sum_i gamma_i, bar(S) = kbar / (1 + sqrt(1 - |kappa||kbar|^2)). b_c = bar(G_c), computed once per occupied cell. For each training example e = (H_e, t_e) with H_e the history item ids and t_e the target item id: q_e = bar({p_i : i in H_e}); rank the m occupied cells by d_kappa(q_e, b_c) ascending, ties broken by ascending code index c; let S_e = sum of n_{c'} over all cells c' ranked strictly ahead of c1(t_e); hit_e = min(1, max(0, (10 - S_e) / n_{c1(t_e)})). RESULT = (mean_e hit_e - 10/N) / (1 - 10/N). One scalar; higher is better.
INPUTS: the exported SID table (integer code per item for levels 1..L, N rows and the item-id order); the frozen Issue #126 reference source-representation matrix s_i (N x d, learned on training pairs only) together with its curvature kappa; and the TRAINING split as (history item ids, target item id) pairs. Nothing else: no recall values, no Stage-3 output, no validation or test interaction.
GEOMETRY: the construction is a Poincare-ball computation of fixed negative curvature. Curvature enters in three places: the exponential map at the origin that places each reference vector in B_kappa; the conformal factor (1 - |kappa||x|^2) inside the geodesic distance, which inflates distance near the ball boundary, so a cell whose centre sits at radius 0.9 is ranked as the hyperbolic distance demands and not as its chord suggests; and the Lorentz factors gamma_i that weight the Klein-Einstein barycentre of a cell and of a history. The cell ranking that produces hit_e is a geodesic ranking around a geodesic barycentre; kappa is taken from the reference and never fitted, and no other constant appears.
WHY IT SHOULD TRACK RECALL: it is an estimator of Recall@10 itself, not a proxy for tightness. Model Stage 3 as ordering items by the hyperbolic proximity of their level-1 cell centre to the history barycentre, and as being uniform inside a cell because the level-1 code is all it knows. Under that model hit_e is exactly the probability that the target is among the 10 emitted items, and 10/N is the exact chance level for any table under a target-independent ranking. Consequences: a one-code table has S_e = 0, hit_e = 10/N and RESULT exactly 0; a randomly relabelled table gives 10/N in expectation and RESULT ~0.0000x, with no sampling needed; a perfectly ranked but oversized cell is penalised by exactly the number of slots it consumes, which is exactly the recall it costs. Over Q_H and HBAA it adds the whole ranked negative list instead of a mean over ten negatives, plus cell occupancy, plus the hard 10-slot budget that is the actual evaluation boundary; over expected rank it adds truncation and slot arithmetic, so being ranked third inside a 500-item cell no longer looks good. It is not a margin, tightness, likelihood or coverage functional, and it does not live on the single-anchor contrast.
COMPUTE: one O(N) pass to build the cell index and the counts n_c; m <= 256 cell barycentres costing O(N) in total; then per training example one barycentre over |H_e| points and one distance vector of length m <= 256. At ~1e5 examples and 256 cells this is 2.6e7 distance evaluations, vectorised over examples in blocks of 4096, i.e. a few seconds in numpy and well under 15 s end to end; memory O(N*d). If the training split exceeds 1e5 examples, take every ceil(n_e / 1e5)-th example (a fixed compute cap, not a fitted parameter).
RISKS: the uniform-within-cell assumption is the main exposure: if Stage 3 orders items inside a cell better than uniform the number under-rates coarse tables, and if worse it over-rates them. The query is the reference history barycentre, so a table that suits a different Stage-3 query encoder is mispredicted. The [0,1] clamp and the 10/N subtraction compress the upper range, which can cost Spearman resolution if many of the 97 tables sit near the ceiling. A strongly unbalanced level-1 partition makes the average dominated by the few small cells, so part of the signal could be balance rather than geometry; the chance subtraction removes only the target-independent part. Curvature may turn out to matter little, as hbaa_euclid (+0.693 at curvature 1e-3) suggests, in which case the number is carried by the ranking and occupancy, though the construction remains hyperbolic. Levels 2..L are deliberately unused, so a table that is good only below level 1 is scored as flat.
FAILURE MODE: it must be worst on the one-code table, all 24587 items in a single level-1 cell: every target sits behind zero cells, hit_e = 10/N for every example, and RESULT is exactly 0. Second worst on the lumped table that spends all 255 remaining codes on singletons and puts the other 24332 items in the last cell: the target is almost always in the lump, hit_e = 10/24332, RESULT ~1e-4, even though the 255 singleton cells rank perfectly. It is also near 0 on any table whose level-1 code is a bijective relabelling of the item id for the first 256 items with the tail lumped, because nothing at cell granularity is rankable.
END METRIC
