METRIC: hyp_massrank_l1
TITLE: Hyperbolic leave-one-out mass-rank percentile of the true level-1 SID cell.
FORMULA: Let N be the number of items that have both a level-1 integer code and a target representation, K the number of distinct level-1 codes, c_i in {1,...,K} the code of item i, n_p = #{i : c_i = p}, and P_train the set of training interaction pairs. Work in the unit Poincare ball B^d = {x in R^d : ||x|| < 1} with constant curvature -1 and d_H(x,y) = arcosh(1 + 2||x-y||^2 / ((1-||x||^2)(1-||y||^2))). For a finite set Z = {z_1,...,z_m} in B^d, let Bary(Z) be the Frechet/Karcher barycentre argmin_{z in B^d} sum_i d_H(z,z_i)^2, computed in the Lorentz model by 20 iterations of z <- exp_z(mean_i log_z(z_i)), initialised at the normalised Lorentzian sum, stopping when the step norm is below 1e-6; Bary(empty) = 0 (the ball origin). For each training pair (u,j) in P_train let H_u = {k : (u,k) in P_train} and define the query point q_{u,j} = Bary({s_u} union {t_k : k in H_u, k != j}), where s_u is the frozen source representation of u and t_k the frozen target representation of k. For each code p let b_p = Bary({t_i : c_i = p}) for p != c_j, and b_{c_j}^{-j} = Bary({t_i : c_i = c_j, i != j}); put d_p = d_H(q_{u,j}, b_p), with b_{c_j} replaced by b_{c_j}^{-j}, and d_true = d_{c_j}. Then P_{u,j} = (1/N) [ sum_{p : d_p < d_true} n_p + 0.5 n_{c_j} + 0.5 sum_{p != c_j : d_p = d_true} n_p ]. Finally M = 0.5 - (1/|U|) sum_{u in U} (1/|H_u|) sum_{j in H_u} P_{u,j}, where U is the set of queries with at least one training pair. Higher M is better.
INPUTS: the exported SID table's level-1 integer code per item (all levels may be present, but only level 1 is read); the frozen Issue #126 behaviour reference arrays s_i and t_i for every item, learned on training pairs only; and the training split P_train. Nothing else: no validation interaction, no test interaction, no recall, no Stage-3 artifact.
GEOMETRY: the unit Poincare ball of curvature -1. Every distance is d_H, every cell summary and every query-history summary is a Frechet/Karcher barycentre in that ball, the leave-one-out true-cell barycentre and the empty-set origin are hyperbolic conventions, and the curvature enters both in the denominator (1-||x||^2)(1-||y||^2) of d_H and in the exp/log maps of the barycentre iteration. A Euclidean replacement of either the distance or the barycentre is a different metric and is not this one. If the frozen reference stores coordinates in a ball of curvature -c_ref, first rescale every coordinate by sqrt(c_ref) to the unit ball; this is an isometry and does not change the curvature sign.
WHY IT SHOULD TRACK RECALL: Stage-3 Recall@10 is high when the level-1 prefix of a target is the prefix selected by the query's reference geometry and that prefix is fine enough to resolve the target. P_{u,j} is the fraction of item mass that the table ranks ahead of the true cell, with the true cell's own mass counted at half; it is small only when the true cell is near the query-history barycentre and its own mass is small. A fine aligned table therefore gives P near 0 and M near +0.5; a random table gives P near 0.5 and M near 0; a collapsed table gives P near 0.5 and M near 0 because the true cell's own mass dominates its percentile; an anti-aligned table gives P near 1 and M near -0.5. This adds over Q_H in three ways: the query point is the Frechet barycentre of the whole leave-one-out training history plus the source point, not a single source anchor; the contrast is the full mass distribution over all K level-1 cells, not a mean over ten negatives; and the 0.5 symmetry baseline is exact for a percentile, so the metric cannot reward a table merely for collapsing into one large cell. It is a mass percentile, not a likelihood, margin, tightness or coverage.
COMPUTE: cell barycentres cost O(20 d N); query barycentres cost O(20 d sum_u |H_u|^2); the distance and rank step costs O(|P_train| K d). At N = 24587, K <= 256, d <= 64 and 250k training pairs with mean history 10, this is roughly 7 GFLOP; float32 vectorised Lorentz Karcher and NumPy distance blocks finish in well under a minute. There is no Stage-2 run, no Stage-3 run, no fitting, no permutation null and no free parameter.
RISKS: (1) if s_i and t_i are not in a common unit ball, the barycentres are not meaningful; the reference must document a shared ball or an exp map into it. (2) Very long histories make the leave-one-out query barycentre cost quadratic in |H_u|; a 1M-pair split with 50 interactions per query can approach the minute, although typical splits do not. (3) If target representations cluster near the origin, many distances tie, P tends to 0.5 and M tends to 0, so the metric loses discrimination. (4) The 0.5 centring assumes exchangeability of codes with respect to the reference geometry; if the table was itself built from the reference, the baseline is conservative rather than invalid. (5) Poincare distances overflow near the boundary; use Lorentz coordinates and clamp ||x|| <= 1 - 1e-7. (6) Only level 1 is read; if a particular Stage-3 run is driven by level-2/3 prefixes, this metric will miss that component.
FAILURE MODE: the table on which it must be worst is the level-1 assignment anti-aligned with the reference: a fixed permutation that sends, for every training query, the reference-nearest items into the cell farthest from the query-history barycentre, with small cells. Then the true cell is last, P_{u,j} tends to 1 and M tends to -0.5. A random balanced table gives M near 0. A single-code table (K = 1) has all distances tied and M = 0 by convention, so collapse is neutral rather than rewarded; a giant-cell-plus-singletons table also gives M near 0 because the true cell's own mass dominates its percentile.
END METRIC
