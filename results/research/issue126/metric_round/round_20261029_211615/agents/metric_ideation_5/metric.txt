METRIC: hyp_loo_sid_logprob
TITLE: Hyperbolic leave-one-out conditional SID code log-probability (per token).
FORMULA:
Notation. N items; L SID levels; C = 256 codes per level. For item i the integer code at level l is c_l(i) in {0..255}; the level-l prefix is pi_l(i) = (c_1(i),...,c_l(i)); the parent prefix is par_l(i) = pi_{l-1}(i) for l>=2. The frozen reference gives, per item, a source vector u_i and a target vector v_i in the open ball B_R^d = {x in R^d : ||x|| < R}. Curvature magnitude c = 1/R^2 (sectional curvature K = -c); R is the reference's stored ball radius (R=1 if absent). Everything is deterministic.

(1) Poincare distance (curvature -c):
    d_c(x,y) = (2/sqrt(c)) * arcosh( 1 + 2c*||x-y||^2 / ((1-c*||x||^2)(1-c*||y||^2)) ).

(2) Moebius sum and the Riemannian log/exp maps used by (4):
    x (+) y = ((1+2c<x,y>+c||y||^2)x + (1-c||x||^2)y) / (1+2c<x,y>+c^2||x||^2||y||^2).
    exp_x(v) = x (+) ( tanh(sqrt(c)*||v||/2) * v/(sqrt(c)*||v||) ),  exp_x(0)=x.
    log_x(y) = (2/sqrt(c))*artanh( sqrt(c)*||(-x)(+)y|| ) * ((-x)(+)y)/||(-x)(+)y||,  log_x(x)=0.

(3) Prototype of each prefix. For every level l and every prefix pi present in the table, G_pi = { i : pi_l(i) = pi }, n_pi = |G_pi|, and B_pi is the hyperbolic Frechet (Karcher) barycentre B_pi = argmin_x sum_{i in G_pi} d_c(x, v_i)^2, computed by the fixed-point iteration x <- exp_x( (1/n_pi) * sum_{i in G_pi} log_x(v_i) ), initialised at x0 = the member of G_pi with smallest d_c(0, v_i), stopped when ||(1/n_pi) sum log_x(v_i)|| < 1e-7 or at 100 iterations. B_empty = Karcher barycentre of all v_i.

(4) Leave-one-out own prototype. For the pair (i,l) with pi = pi_l(i):
    if n_pi >= 2:  q_{i,l} = exp_{B_pi}( - log_{B_pi}(v_i) / (n_pi - 1) )   (exact first-order Riemannian LOO mean, since sum_{j in G_pi} log_{B_pi}(v_j) = 0 at the Karcher fixed point);
    if n_pi = 1 and l >= 2:  q_{i,l} = B_{par_l(i)}  (the parent's prototype);
    if n_pi = 1 and l = 1:   q_{i,l} = B_empty.

(5) Sibling class set at (i,l). For l = 1: S_{i,1} = { every level-1 code present in the table } (|S| = k_1 <= 256). For l >= 2: S_{i,l} = { (par_l(i), k) : k is a level-l code that actually occurs under parent par_l(i) } (children of i's own parent; |S| <= 256, never the global 256, which is why deeper levels cannot degenerate into an item-identifier test). Denominator prototypes are the FULL barycentres B_pi' for pi' in S_{i,l}, pi' != pi_l(i); the own class uses q_{i,l}.

(6) Per-term source-conditioned log-probability, with reference scale sigma:
    sigma = median over all items i of d_c(u_i, v_i)   (one scalar from the frozen reference only; identical for all 97 tables, so it cannot be tuned per table).
    z_own = -d_c(u_i, q_{i,l})^2 / (2*sigma^2);
    z_pi' = -d_c(u_i, B_pi')^2 / (2*sigma^2) for pi' in S_{i,l}, pi' != pi_l(i);
    log p_{i,l} = z_own - logsumexp( {z_own} U {z_pi'} ).

(7) Informative support. T = { (i,1) : k_1 >= 2 } U { (i,l) : l >= 2 and |S_{i,l}| >= 2 }. A level that does not discriminate (parent with a single child) contributes no term, so an unused or duplicated level earns no free credit.

(8) THE METRIC (one scalar, higher is better):
    hyp_loo_sid_logprob = ( 1/|T| ) * sum_{(i,l) in T} log p_{i,l}      (nats per token, <= 0).
If T is empty the metric is defined as -log(C) = -log 256.
INPUTS: (a) the exported SID table: one integer code per (item, level), N = 24587, C = 256, L levels; (b) the frozen Issue #126 behaviour reference: per-item source vector u_i, per-item target vector v_i, ball radius R (hence c), and nothing else. No training split needed, no pairs, no labels, no recall, no Stage 2 or Stage 3 run.
GEOMETRY: The construction lives on the Poincare ball of constant curvature K = -1/R^2, c = 1/R^2: (i) d_c is the geodesic distance, not a Euclidean norm; (ii) every class prototype B_pi is a hyperbolic Frechet/Karcher barycentre obtained by Riemannian gradient flow, not an arithmetic mean; (iii) the leave-one-out prototype uses the Riemannian exp and log maps at B_pi (the correction log_{B_pi}(v_i)/(n_pi-1) is a tangent vector that the exp map wraps back onto the manifold). Curvature enters three times and is not removable: replacing d_c by Euclidean distance and exp/log by the identity changes all three steps (barycentres become centroids, the LOO correction becomes a linear shift, the Gaussian kernel changes shape). In the flat limit c -> 0 the metric collapses to a Euclidean centroid-classifier log-likelihood and its value changes.
WHY IT SHOULD TRACK RECALL: Stage 3 decodes the target SID token by token from the SOURCE item with a beam of 10; Recall@10 is high exactly when the true code at each step is among the highest-probability codes given the source. This metric is the average per-token log-probability of the true code under a curvature-faithful, source-conditioned prototype classifier whose own prototype has had the item itself removed. What it adds over Q_H: Q_H is a SYMMETRIC target-side level-1 neighbourhood purity and collapses at levels 2-3 because the prefix becomes an item identifier that is trivially pure. This one is ASYMMETRIC (source u_i -> target-derived code prototypes B_pi), SEQUENTIAL (one term per decoding step, conditioned on the actual parent), CHANCE-NORMALISED by the softmax over the actually competing sibling set (so it keeps discriminating at levels 2 and 3 instead of saturating), and LEAVE-ONE-OUT (a table cannot score well by giving each item its own cell, because the item is deleted from its own prototype before the likelihood is taken). The LOO step is exactly the distinction between "the code memorises the item" and "the code is predictable from the source" - i.e. between a table that names items and one that geometrically organises them; only the latter generalises to unseen test pairs, which is what Recall@10 measures. A table whose source->code map is sharp and whose cells are curvature-round raises every z_own; a table whose cells cut across the reference's geodesic neighbourhoods lowers it.
COMPUTE: Barycentres: 256 level-1 groups plus at most 24587 prefixes per deeper level, each with <= 100 Karcher iterations over its own members, total <= 100 * 3 * 24587 ~ 7.4M log/exp evaluations. Scoring: for each item and level at most |S| <= 256 Poincare distances, so <= 3 * 24587 * 256 ~ 1.9e7 distance evaluations, plus 24587 exp/log calls for the LOO correction. All operations vectorise over items within a level (numpy/torch): a few seconds, well under 60 s, with at most 3 * 24587 * d floats of prototype storage (~6 MB at d = 64).
RISKS: (a) Scale mismatch: sigma = median_i d_c(u_i,v_i) is the reference's own source-target geodesic scale; if the towers are globally offset, sigma is too small and every softmax saturates at p ~ 1 (all tables near 0), or if too large all p ~ 1/|S| (no variance). Because sigma is pre-registered from the reference, this appears as compression of the 97 scores, not as overfitting. (b) If the reference keeps source and target vectors in different balls or applies a per-modality offset, d_c(u_i, B_pi) is not meaningful; a per-item constant offset cancels inside each softmax, a code-dependent offset does not. (c) Very skewed parent sizes: one giant parent dominates the deeper-level terms. (d) Karcher means in sparse or crescent-shaped cells may hit the iteration cap; the last iterate is used, so it stays deterministic but slightly biased. (e) The LOO prototype is only first-order exact; for n_pi = 2 or 3 the correction moves far and may exit a badly conditioned cell. (f) One bad deep level only lowers the average, so an otherwise excellent table can be under-ranked.
FAILURE MODE: Worst on a SID table whose level-1 codes are assigned at random with respect to the reference geometry (codes hashed from the item id, or level-1 codes permuted across cells): every B_pi becomes a mixture of geodesically unrelated targets, u_i is roughly equidistant from its own and all competing barycentres, all z are near equal, and every log p_{i,l} sits at its chance value -log|S_{i,l}| (about -log 256 at level 1), driving the mean to the floor. Also worst on a maximally fine, geometry-blind enumeration: 256 arbitrary level-1 buckets each split into near-singleton level-2/level-3 codes, so after LOO deletion the own prototype reverts to the parent mixture while competing sibling prototypes sit on individual target vectors, making the true code no more likely than its siblings. It does NOT collapse on a table that gives every item a unique level-3 code with a geometrically coherent level 1 and 2 - exactly where Q_H's level-3 term saturates and stops discriminating.
END METRIC
