METRIC: hyp_history_fullneg_rank_excess
TITLE: Cross-fitted full-negative expected-rank of the level-1 bucket, queried by the geodesic barycentre of the user's whole training history.
FORMULA:
Work in the frozen reference's ball rescaled to unit curvature (c=1) by x -> sqrt(c_ref)*x; this is a fixed isometry, not a parameter. Let d(.,.) be that Poincare geodesic distance, and let Bary(S) be the Karcher/Frechet barycentre of a finite set S in the ball (the point minimising the sum of squared d). Let b(i) be the level-1 SID code of item i, and let the frozen reference give a source point s_i and a target point t_i per item (same ball).
Split the TRAINING users deterministically by hash(u) mod 2 into folds A and B. For direction A->B let T_A be all training items of fold-A users and let C_A = number of distinct level-1 codes present in T_A. Define, for every code b, mu_b = Bary({ t_i : i in T_A, b(i)=b }) (origin if empty). For each fold-B user u with non-empty training history H_u, using only items before u's final training item i+_u, set q_u = Bary({ s_j : j in H_u }) and p = b(i+_u). Define
  R_u = sum_{b != p, b in T_A} sigma( (d(q_u,mu_p)^2 - d(q_u,mu_b)^2) / (2*tau^2) ),
with sigma(z)=1/(1+e^-z) and tau = tau_ref, the frozen reference's contrastive temperature (rescaled with the ball; no grid, no tuning). Set e_u = R_u/(C_A-1).
Size-matched null: let n_b = |{i in T_A : b(i)=b}|. Sort T_A by the stable key CRC32(str(item_id)) ascending and hand out the codes in descending-n_b order in contiguous blocks of the observed sizes n_b; call this assignment btilde(i). Define mu_b^null = Bary({ t_i : i in T_A, btilde(i)=b }) and R_u^null, e_u^null exactly as above with mu^null. Then
  M = (1/|P|) * sum_{u in P} ( e_u^null - e_u ),
pooling the B->A direction (symmetric, centroids from fold B, users from fold A); |P| = number of evaluated training users. C_A=1 gives M=0. Higher M is better (range about [-1,+1]; perfect partition -> e_obs ~ 0, e_null ~ 0.5, so M -> +0.5; no-information or collapsed table -> e_obs = e_null -> 0; anti-aligned table -> M < 0).
INPUTS: the exported SID table (integer level-1 code per item; deeper levels unused); the frozen Issue #126 behaviour reference (per-item source s_i and target t_i, its curvature c_ref and temperature tau_ref, all fitted on training pairs only); the TRAINING interaction split with timestamps (to form H_u and i+_u). Nothing else.
GEOMETRY: the number is built entirely from the Poincare geodesic distance d (arcosh form) in a ball of fixed negative curvature, from Karcher/Frechet barycentres (whose defining iteration uses exp/log maps and parallel transport along geodesics, so it is not a Euclidean mean), and from squared-geodesic margins. Curvature enters in d and in every barycentre, and c_ref fixes the unit rescaling; the whole construction is meaningless in a flat space because the Karcher mean, the log/exp maps and the geodesic margin all change.
WHY IT SHOULD TRACK RECALL: with ~24587 items and ~256 level-1 codes a bucket holds ~96 items, so Recall@10 is high essentially only when the positive's bucket is ranked at or near the top of the competing buckets; the soft expected rank R_u is exactly that rank, averaged over the full set of 256 alternative buckets rather than a ten-negative mean. The query is the geodesic barycentre of the user's whole history, so the score asks where the user's trajectory points in the reference's source->target geometry. Against Q_H it adds the learned cross-space behaviour geometry (Q_H only counts prefix agreement and is blind to where the history points); against HBAA it replaces the mean of ten negatives by the full negative-bucket distribution with a logistic margin, so one hard competing bucket that would displace the positive from the top-10 is visible instead of being averaged away; the cross-fitting removes self-inclusion and the deterministic size-matched null removes the code-count/collapse advantage that destroyed the path-likelihood metric.
COMPUTE: 2 folds x (256 Karcher means over ~50-100 points, ~10 iterations) + one history barycentre per evaluated user (~a few thousand) + |P| x 256 vectorised geodesic evaluations x 2 (observed and null), about 10-30 million flops; seconds to well under a minute on 24587 items and 256 codes.
RISKS: if the reference's source and target live in separate non-comparable spaces the score is undefined (require shared ball); a near-chance reference makes q_u and mu_b uninformative and M noise around 0; tables with very few non-empty level-1 codes give high-variance M (the null centres it at 0 but does not shrink the variance); very short histories send q_u to the origin and reduce the metric to a global prior; item_id hashes must be used for the null order so raw id/popularity order cannot leak structure.
FAILURE MODE: worst on a table whose level-1 codes are assigned by a criterion orthogonal or anti-aligned to the frozen source->target geometry while keeping the same code count and bucket sizes (e.g. level-1 = popularity decile or a hash of item id), where e_obs ~ e_null ~ 0.5 and M ~ 0, and most negative when buckets deliberately group behaviourally distant items and split behaviourally close ones (e_obs > e_null); the one-code table gives exactly 0 by construction.
END METRIC
