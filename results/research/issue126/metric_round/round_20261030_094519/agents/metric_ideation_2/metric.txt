METRIC: hyp_gromov_offcell_expected_rank_l1
TITLE: Curvature-normalised Gromov common-ancestor expected rank of the target over the items its own level-1 cell fails to absorb.
FORMULA: Let N be the item count, K the number of distinct level-1 codes in the exported table, c = c_ref > 0 the frozen reference curvature, tau = tau_ref > 0 its frozen temperature, o = 0 the ball origin. For every item h let s_h be the reference source vector and t_h its target vector; map to the Poincare ball B_c = {x : c||x||^2 < 1} by x_h = exp_0^c(s_h), y_h = exp_0^c(t_h) (identity if the reference already emits ball points). Poincare distance: d_c(x,y) = c^{-1/2} arcosh( 1 + 2c||x-y||^2 / ((1-c||x||^2)(1-c||y||^2)) ). Gromov product (common-ancestor similarity) about o: G_c(x,y) = (x|y)_o = 1/2 [ d_c(o,x) + d_c(o,y) - d_c(x,y) ]. For item i let H_i be the set of items occurring before i in the TRAINING split (its history, i excluded), and q_i = Frechet barycentre of {x_h : h in H_i} in B_c, q_i = argmin_{q in B_c} sum_{h in H_i} d_c(q,x_h)^2, computed by the standard Riemannian iteration: initialise q = x_{last history item}; repeat 20 times { u = |H_i|^{-1} sum_{h in H_i} log^c_q(x_h); q <- exp^c_q(u); stop if ||u|| < 1e-6 } with the Poincare exp/log. Let code1(j) be the level-1 integer code of j, C_i = {j : code1(j) = code1(i)}, M_i = N - |C_i|. Define positive logit a_i = exp( G_c(q_i, y_i) / tau ) and negative mass D_i = sum_{j not in C_i} exp( G_c(q_i, y_j) / tau ). Then p_i = a_i / (a_i + D_i) and lift_i = ln( (M_i + 1) p_i ). METRIC = (1/|Q|) sum_{i in Q} lift_i, with Q = { i : H_i nonempty and M_i >= 1 }; if K = 1 or Q empty the metric is exactly 0. Higher is better. c and tau are the reference's own frozen constants; M_i and K come from the table; the iteration counts are fixed algorithm settings, not fitted to any recall.
INPUTS: the exported SID table (level-1 integer code per item); the frozen Issue #126 behaviour reference (source vector s_h, target vector t_h per item, plus c_ref and tau_ref); and the TRAINING split (only to build H_i). Nothing else.
GEOMETRY: the score is built from the Gromov product, a genuinely hyperbolic similarity: (x|y)_o equals the distance from o to the geodesic joining x and y, i.e. the depth of their common ancestor in the reference's tree. It is defined only through the negative-curvature metric and has no Euclidean counterpart (a flat space has no common-ancestor invariant). The query is a Frechet barycentre, a curved mean defined only through the exp/log maps; curvature -c enters the distance, the barycentre and G. The comparison is meaningful precisely because the space is negatively curved.
WHY IT SHOULD TRACK RECALL: Stage 3 recalls the target by following the code tree from a query built from the user history. A good level-1 cell is exactly the set of items geometrically confusable with the target (the deep common-ancestor neighbours of the history). Removing that cell from the candidate pool must leave the target as the dominant Gromov match, so lift_i is large when the cell absorbed the hard negatives and drops toward 0 when those hard negatives remain outside. Averaged over Q this is a retrieval-quality proxy that varies with the table's partition. Over Q_H it adds: Q_H ranks the target prefix from one fixed query and ignores the geometry of the confusables; here the full history is a curved query point, the positive is scored against the entire off-cell distribution (not a mean of ten), and the Gromov product measures subtree overlap rather than raw proximity. Over HBAA it adds: HBAA averages the negative side into one barycentre and uses a single distance contrast; here the negative side is the whole table-defined off-cell distribution under a temperatured softmax (a true expected rank), so hard negatives are not averaged away, the partition itself defines the pool, and the uniform size-matched null (M_i + 1) keeps collapse neutral instead of rewarding it.
COMPUTE: per query the metric needs d_c to every off-cell item, so O(|Q| N) distances. With |Q| <= N = 24587 and N = 24587 this is at most 6.0e8 Poincare distances; chunked over 512 queries in float32, with c||y_j||^2 and d_c(o,y_j) precomputed, that is about 25-45 s on one CPU core. The Frechet barycentres add O(|Q| mean|H| 20) ~ 1.5e7 operations. If a slower machine is used, queries are stride-subsampled to at most 8K = 2048 items (a constant derived from the codebook size K = 256, never from a recall), cutting the distance count to 5e7 (<10 s) with a mean shift below 0.01. Nothing is trained and no matrix is persisted.
RISKS: (i) the metric depends on the frozen reference's geometry, so it is a property of table-plus-reference, not of the integer codes alone; here the reference is frozen, which is intended. (ii) Near-singleton cells give M_i ~ N for all i, so every lift is near 0 and the ordering is carried by small residuals; variance across tables shrinks. (iii) A norm prior is present because G_c contains d_c(o,y_j); if the reference pushes all items onto the boundary, that term dominates and the metric degenerates toward a norm ranking. (iv) arcosh arguments must be clamped to >= 1 or x = y produces NaNs. (v) The metric is invariant to relabelling of codes (only the partition matters), which is intentional, but it means two tables with the same partition but different code order score identically.
FAILURE MODE: it must be worst on a table whose level-1 partition is anti-aligned with the reference geometry - e.g. codes assigned by an item-id hash, by a random frequency bucket, or by deliberately grouping far items and isolating each item from its Gromov neighbours. Then for every i the target's deep-ancestor confusables lie outside C_i, D_i is dominated by them, p_i ~ 1/(M_i + 1), and lift_i ~ 0 (or strongly negative if the cell is anti-correlated), so METRIC ~ 0 regardless of K. The one-code table is exactly 0 by construction, and a random relabelling of a fine partition leaves the metric unchanged, also ~0 because the cell no longer absorbs the confusables.
END METRIC
