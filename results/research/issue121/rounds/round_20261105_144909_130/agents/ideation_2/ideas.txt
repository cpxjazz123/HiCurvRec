IDEA: DEMARGIN-L1-CURV
TITLE: Level-1 RQ-VAE assignment by a single fixed-curvature Poincare distance minus a measured behaviour-demand margin
MOTIVATION: RQ-VAE Semantic IDs spend level-1 codebook capacity on latent density, not on what users actually do next. Two items that look alike but are consumed in very different behavioural contexts, or a latent region that is dense but never entered by a real transition, get the same level-1 code budget as a heavily entered one. The result is a coarse prefix that the generative recommender cannot use to place probability mass where next-item demand really is. This idea lets measured next-item demand enlarge or shrink individual level-1 Voronoi cells, and does it in a curved metric so that the enlargement is not a uniform Euclidean shift but depends on how far from the ball origin the item sits.
NOVELTY: The repository has already tried a per-codeword curvature field (OCCURV-FIELD-RQ), stratified curvature with a hyperbolic Sinkhorn transport (strataot-curv-rq) and branching-adaptive shallow curvature on radial coordinates (brancurv-l1-rq). This proposal has none of those: exactly one global curvature, no Sinkhorn and no transport (plain hard argmin), no per-code curvature, no capacity units, no cross-graph movement. The new element is a single additive behaviour margin inside the curved argmin, with its weight derived from the measured level-1 distance margin and its demand computed as an EMA of the curved soft assignments themselves, so the behaviour term is computed with the geometric term and the geometric term decides the behaviour term.
CHANGE: Level-1 assignment stops being argmin_k ||r - a_k||^2 and becomes argmin_k [ d_c(exp_0^c(r/s), exp_0^c(a_k/s)) - w*log(1 + demand_k) ], where demand_k is a frozen, detached EMA of the curved soft-assignment mass that training transitions deposit on code k. Levels 2 and 3, the residuals they see, the reconstruction loss, the commitment term and the straight-through estimator are byte-for-byte the baseline.
SPECIFICATION:
  Frozen measurement pass (once, before step 0, on the 24 556 training items only):
    s = sqrt( mean_i ||r_i||^2 )            # r_i = level-1 input residual of item i at init
    sqrt(c) = atanh(0.5)  =>  c = 0.30170, R_c = 1/sqrt(c) = 1.82048   # one RMS tangent vector -> ball norm 0.5
    v_i = r_i / s ,  b_k = a_k / s ,  u_i = exp_0^c(v_i) ,  q_k = exp_0^c(b_k)
    D_ik = d_c(u_i, q_k) for the first 4096 training items
    w = mean_i [ (max_k D_ik - min_k D_ik) / 2 ]      # mean half-margin, the offset scale
    T = w                                             # softmax temperature for demand, same measured unit
    beta = 1/24                                       # EMA horizon = one epoch at the frozen scale
    demand_k <- 1 for all k  (so off_k = 0 at step 0 and training starts identical to the baseline)
  Every training step, for a batch of items with level-1 residuals r:
    v = r/s ; u = exp_0^c(v) ; u <- u * min(1, (1-1e-5)/||u||)          # radial clip, no grad through clip mask
    q_k = exp_0^c(a_k/s)  (recomputed from the CURRENT baseline codebook; codebook update rule untouched)
    D_k = d_c(u, q_k) = (2/sqrt(c)) * atanh( sqrt(c) * ||(-u) (+) q_k|| ), argument clipped to 1-1e-7
    with stop_grad:  pi_k = softmax_k(-D_k / T) ;  demand_k <- (1-beta)*demand_k + beta*mean_batch(pi_k)
    demand_hat_k = demand_k / mean_j demand_j                 # m

ean-normalised, so a flat demand is a constant shift
    off_k = clamp( w * log(1 + demand_hat_k), 0, 3*w )
    k_1 = argmin_k (D_k - off_k), ties -> smallest index
    levels 2 and 3: identical to baseline (same residual recursion, same Euclidean distances, same argmin, same STE)
    loss = baseline reconstruction + baseline commitment, unchanged; the reassigned code position q_{k_1} is the one used for reconstruction, exactly as in the baseline
  Switches (exist and are correct, no arm is trained):
    BEHAVIOUR_OFF: demand_k forced to 1 for all k => off_k = 0, curved distance still used.
    GEOMETRY_OFF: c -> 0 => exp_0 = identity, d_c -> 2*||u - q||; behaviour offset still applied.
COST: One extra forward pass over the training split for the frozen measurement (<0.1 epoch). Per step at the frozen scale (batch ~1023 items, K1 = 256 level-1 codes, 24 steps/epoch): one exp map for the batch plus 1023x256 Moebius additions and atanhs, about 0.8 M transcendental scalar ops, i.e. a few milliseconds on four cards and under ~3% of step time; levels 2-3 are unchanged, so their cost is unchanged. Over 3000 epochs = 72 000 steps the added wall clock is minutes, not hours. No extra parameters, no extra memory beyond one K1-vector of demand.
HYPOTHESIS: If next-item demand identifies latent regions that deserve level-1 capacity, then the coupled assignment must (i) raise the correlation between level-1 code occupancy and demand, (ii) change the level-1 prefix partition in a radius-dependent way (cells near the ball boundary gain relatively more under the same offset than cells near the origin, because the metric is radial), and (iii) raise Stage3 test Recall@10 above the 0.0555 baseline and above the 0.0638 historical best, i.e. above 0.065 in the single formal run. Observed from the single run's training log (occupancy-demand correlation, code usage entropy, level-1 prefix transfer predictability) and from the Stage3 test_recall@10.
RISKS: The demand EMA can be dominated by a handful of codes early, and the offset then collapses level-1 usage (mitigated by clamping at 3w and by starting from demand = 1, but not impossible). The frozen s drifts away from the encoder's scale during training, so late-training residuals may sit near the ball boundary where atanh explodes (clip handles numerics but not the geometry shift). A pure re-parameterisation risk: the offset may only permute which items share a prefix without adding prefix information, giving no recall change. A soft behaviour bias in a hard argmin makes the straight-through gradient slightly mismatched to the forward assignment. Finally, a single run cannot separate the two contributions, so a null result will not say which term failed.
BEHAVIOR SIGNAL: Training-only next-item demand per level-1 codeword: how much of the observed directed transition mass of the training sequences lands on the items that a codeword owns.
BEHAVIOR COMPUTATION: From the training split only, for every consecutive pair (i_t -> i_{t+1}) in the training user sequences, take the level-1 residual r of the TARGET item i_{t+1} (encoder output for that item at the current step), compute its curved soft assignment pi_k = softmax_k(-D_k/T) and accumulate mean_batch(pi_k) into an EMA with beta = 1/24. The signal is thus "arrival mass", i.e. how often items in code k are actually consumed next, not how often they are departed from; it is mean-normalised and detached, and it enters the assignment only.
LEAKAGE BOUNDARY: de

mand is built exclusively from (a) training-split item latents and (b) transitions inside training-split user sequences; counts, EMA state and the measurement pass (s, w) touch no validation and no test item or interaction. Validation is used only to pick the checkpoint in the frozen protocol and never feeds the codebook, the offset, or the EMA. The EMA state is a running statistic of gradient steps taken on training batches, so any influence from a sequence can only come from the training split.
HYPERBOLIC OPERATOR: Poincare ball of fixed curvature kappa = -c with c = atanh(0.5)^2 = 0.30170, radius R_c = 1.82048, exponential map exp_0^c(v) = tanh(sqrt(c)||v||) v / (sqrt(c)||v||), and the geodesic distance d_c(x,y) = (2/sqrt(c)) artanh(sqrt(c)||(-x)(+)y||).
HYPERBOLIC LOCATION: Quantization, level 1 only, inside the assignment step of the RQ-VAE (forward pass, argmin of the first codebook); levels 2 and 3 stay Euclidean and unchanged.
COUPLING PATH: The same level-1 distance D_k both decides the code and defines the soft mass that builds the demand EMA, and that demand becomes an additive margin on the same D_k in the same argmin: k_1 = argmin_k (D_k - w log(1 + demand_hat_k)). Remove the behaviour (demand = 1) and the argmin is pure curved nearest neighbour, so boundaries move; remove the curvature (c = 0) and both the distance and the soft demand mass change, and because an additive offset in the ball metric is radius-dependent, the resulting cells are not a Euclidean nearest-neighbour partition with the same bias.
COUPLING EQUATION: k_1(x) = argmin_k [ d_c( exp_0^c(r/s) , exp_0^c(a_k/s) ) - w * log(1 + demand_hat_k) ], with demand_hat_k built from pi_k = softmax_k( -d_c(exp_0^c(r/s), exp_0^c(a_j/s)) / T ) accumulated over training transitions.
OBSERVABLES: Level-1 code usage entropy and per-code occupancy; correlation between code occupancy and demand_hat; the radius distribution of the items whose level-1 assignment flipped because of the offset; level-1 prefix transfer predictability on held-out training prefixes; and the judgement quantity, Stage3 test_recall@10 in the single formal run.
ABLATION BEHAVIOR OFF: demand_k pinned to 1 so off_k = 0 for every code; the curved level-1 argmin runs alone. Exists as a switch, correct, never trained in this round.
ABLATION GEOMETRY OFF: c -> 0 so exp_0 becomes the identity and d_c becomes 2||u - q||, with a_i, r kept unscaled; the behaviour margin w log(1 + demand_hat) still modifies the Euclidean argmin. Exists as a switch, correct, never trained in this round.
ABLATION BOTH ON: The full coupled level-1 assignment above, which is exactly what the single formal training run executes.
SPEC EQUATIONS: v = r/s; u = exp_0^c(v); b_k = a_k/s; q_k = exp_0^c(b_k); D_k = (2/sqrt(c)) artanh(clip(sqrt(c)||(-u)(+)q_k||, 0, 1-1e-7)); pi_k = softmax(-D_k/T) with stop_grad; demand_k <- (1 - 1/24) demand_k + (1/24) mean_batch(pi_k); demand_hat_k = demand_k / mean_j(demand_j); off_k = clamp(w log(1 + demand_hat_k), 0, 3w); k_1 = argmin_k (D_k - off_k); residual for level 2 = r - a_{k_1} (baseline rule, baseline STE); loss = baseline. Constants: s and w measured once on the training split before step 0, c = atanh(0.5)^2, T = w, beta = 1/24.
SPEC INPUTS OUTPUTS: Input: the level-1 residual batch r (B x d), the current baseline level-1 codebook a (K1 x d) with its baseline update rule untouched, the frozen scalars s, w, c, T, beta, and the running demand vector (K1,). Output: the level-1 code index batch k_1 (B

,) used for reconstruction and for the residual passed to level 2 (levels 2-3 then run unchanged), the updated frozen demand vector, and the unchanged baseline loss.
SAFEGUARDS: curve v and b_k norms floored at 1e-12 before the division in exp_0^c; ball norm clipped to 1-1e-5 pointwise with a detached mask so no gradient flows through the clip; the artanh argument clipped to 1-1e-7; demand initialised to 1 so off_k = 0 at step 0 and step 0 equals the baseline exactly; demand computed under stop_grad and never entering any loss term, so it cannot backpropagate; off_k clamped to [0, 3w] to bound the largest possible margin flip; deterministic tie-break to the smallest index in argmin; if any demand entry is non-finite the whole vector is reset to 1 (mean normalisation then makes the offset identically zero, i.e. a safe fallback to the curved-only assignment); the measurement pass and the EMA use only training-split items and transitions; all switches default to the coupled-on configuration so the single formal run needs no configuration change.
END IDEA
