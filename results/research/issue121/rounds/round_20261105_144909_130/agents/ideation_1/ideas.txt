IDEA: l1pdo-rq
TITLE: Level-1 Poincare demand offset: a curved level-1 distance biased by a curvature-measured codeword demand, leaving levels 2-3 and the loss exactly as baseline.
MOTIVATION: In an RQ-VAE Semantic ID the first token is the only token every item must share; the baseline assigns it by pure reconstruction geometry, so items that are co-consumed or strongly transition-targeted nevertheless scatter across unrelated first-level prefixes, and the generative recommender must relearn transition and popularity structure from the token alphabet. The mechanism lets training-only transition demand steer the first-level partition while a hyperbolic metric keeps the level-1 neighbourhood curved instead of a flat Euclidean hull.
NOVELTY: Unlike the rejected arms (per-occupant curvature field, stratified behaviour-marginal Sinkhorn, branching-adaptive radial level-1, cross-graph transport, capacity units, hierarchical curvature + Sinkhorn) there is no per-code curvature, no Sinkhorn, no radial coordinate and no second transport segment. The behavioural signal is one frozen scalar per codeword (mean-centred log demand) subtracted additively from the same curved level-1 distance that produced it, and that statistic is measured through the codeword's own curved softmax assignment: a closed geometry -> behaviour -> geometry loop inside a single argmin. Levels 2 and 3, the reconstruction loss, the commitment term and the straight-through estimator are identical to baseline.
CHANGE: The level-1 residual is scale-normalised and mapped into a Poincare ball (c = 1 after RMS normalisation), level-1 codes are the baseline codebook mapped by exp_0^c, and the level-1 index becomes argmin_k ( d_c(u, q_k) - w * centred_log1p(demand_k) ), where demand_k is an EMA of the transition in-degree of the items that the same curved softmax currently gives to code k. The chosen code is used exactly as in baseline (r_2 = r_1 - a_k1, same STE, same loss).
SPECIFICATION:
Conventions (contract): ball curvature kappa = -c, c > 0, radius R_c = 1/sqrt(c);
d_c(x,y) = (2/sqrt c) * artanh( sqrt c * || (-x) (+) y || );
exp_0^c(v) = tanh(sqrt c ||v||) * v / (sqrt c ||v||), exp_0^c(0) = 0;
Moebius addition x (+) y = ((1 + 2c<x,y> + c^2||y||^2) x + (1 - c||x||^2) y) / (1 + 2c<x,y> + c^2||x||^2||y||^2).
Frozen measured constants (no tuning):
 s = sqrt( mean_i ||r1_i||^2 ) over level-1 encoder latents, running mean over the first 50 optimiser steps, then frozen as a buffer;
 c = 1 in the frame v = r1 / s (documented default: ball radius = data RMS tangent radius, so bulk radius tanh(1) = 0.762 and saturation is bounded at 0.964 for a 2 sigma item);
 tau = running mean over the same 50 steps of mean_i min_k d_c(u_i, q_k), clamped to [0.01, 10], frozen (measured local distance scale, used only as softmax temperature);
 w = beta, the baseline commitment weight, documented default 0.25;
 rho = 1/48 (EMA horizon = two epochs = 48 steps).
Batched computation, every step, level 1 only:
 v_i = r1_i / s ; u_i = exp_0^c(v_i) ; q_k = exp_0^c(a^(1)_k)  (a^(1) = baseline level-1 codebook, parameter untouched)
 S_ik = softmax_k( -d_c(u_i, q_k) / tau )                      (detached, no grad)
 m_k = sum_i S_ik D_i , n_k = sum_i S_ik , raw_k = m_k / max(n_k, 1e-8)
 demand_k <- (1-rho) demand_k + rho * raw_k * K1 / max(sum_j raw_j, 1e-8)  (init 1; held at 1 for steps < 50)
 ell_k = log1p(demand_k) ; off_k = beta * clip(ell_k - mean_j ell_j, -ln 3, +ln 3)  (detached)
 k1(i) = argmin_k ( d_c(u_

i, q_k) - off_k ), ties -> smallest k
 r2_i = r1_i - a^(1)_{k1(i)} ; levels 2,3, reconstruction, commitment, STE, optimiser: baseline, unchanged.
D_i is precomputed once from the TRAINING split only: D_i = number of times item i occurs as the next item over all consecutive training pairs, divided by its mean over training items (mean_i D_i = 1), float32, requires_grad = False.
Gradient rules: forward uses the hard k1; no new differentiable term; off_k, S_ik, demand_k, s, tau, c, D_i are detached or frozen. The parameter update changes only because a different codeword is selected (different a^(1)_{k1} in r2 and in the level 2-3 reconstruction, hence different reconstruction and commitment gradients on level-1 codebook rows and on the encoder). Argmin is non-differentiable; STE unchanged.
Training integration: no extra epoch, no extra loss, no schedule change; only the level-1 forward assignment differs.
Switches (present in code, no arm trained): BEHAVIOUR_OFF=true sets D_i = 1 for all i => raw_k = 1 => demand_k = 1 => ell_k - mean = 0 => off_k = 0 (pure curved assignment). GEOMETRY_OFF=true sets c = 0, which in the same formulas gives exp_0 = identity and d_c = 2||x - y||, so k1 = argmin_k (2||v_i - a_k|| - off_k) (Euclidean; the factor 2 is argmin-invariant). Both switches are read at module init and logged in the run config.
COST: 72,000 optimiser steps in total (24 steps/epoch x 3000 epochs) at 24,556 training items, unchanged from baseline. Per step the additions, with batch B = 1024, K1 = 256 level-1 codes and latent dim 64, are one [1024,256,64] Moebius-add + norm + artanh block (~17M elements, ~10 flops each = ~0.17 GFLOP, a few elementwise kernels), one [1024,256] softmax and one [256] EMA update: well under 2% of a transformer step, so <= +3% wall clock over the whole 3000 epochs, with no extra memory beyond a [B,K1] matrix. One-off extra work: the 50 frozen statistics steps (already inside steps 1-50) and one CPU pass over the training transition list (O(#train interactions)) to build D_i. No extra backward pass, no ablation arm, no sweep, no extra seed.
HYPOTHESIS: If first-token partitioning is limited by missing behavioural structure rather than by reconstruction geometry, then biasing the level-1 curved assignment with a curvature-measured transition demand should lift Stage3 test recall@10 above the 0.0555 baseline toward or past 0.065 in one run, and it must show up as (a) a level-1 code-usage distribution whose per-code offset correlates with per-code assignment share and (b) an improved first-token hit rate for the held-out next item when predicted from the history's SID prefixes, without materially degrading the reconstruction loss.
RISKS:
- tanh saturation at c = 1 could compress level-1 margins so the offset dominates and many items collapse onto a few high-demand codes, destroying level-1 resolution for the tail.
- the demand EMA can be captured by a few very popular codewords, producing a self-reinforcing rich-get-richer loop (offset raises assignment share, which raises demand).
- at data RMS radius 0.762 the Poincare metric differs only mildly from Euclidean, so the geometry switch may be a near no-op and the effect would come from the offset alone.
- the change is discrete (argmin) and may barely alter the optimisation path, so a single run could be indistinguishable from baseline within seed noise.
- D_i from raw transition counts is popularity-heavy; centring and the ln 3 clip may be too weak to expose co-co

nsumption structure.
- first-level reassignment could push residual mass into levels 2-3 beyond what they were sized for, leaving more SID collisions or short effective prefixes.
BEHAVIOR SIGNAL: Training-only directed item-transition demand: the mean-normalised in-degree D_i of each training item (how often it is the next item in training sequences), aggregated into per-first-level-codeword demand through the model's own curved soft assignment and EMA-smoothed.
BEHAVIOR COMPUTATION: From the training split interaction sequences only: for every consecutive pair (u_t -> u_{t+1}) in each training sequence increment count[u_{t+1}]; then D_i = count[i] / mean_j count[j] over the 24,556 training items (items never appearing as a next item get D_i = 0). Per step, raw_k = sum_{i in batch} S_ik D_i / sum_{i in batch} S_ik with S_ik the detached curved softmax; demand_k is an EMA with rho = 1/48, initialised to 1, held at 1 for the first 50 steps, then mean-normalised to 1 across the K1 codes and frozen with respect to gradients.
LEAKAGE BOUNDARY: D_i uses only training-split transitions; no validation or test interaction, no test user, no test item and no Stage3 label enters D_i, s, tau, c or off_k. s and tau are measured from training latents only during the first 50 training steps, before any evaluation. off_k is one scalar per code and never stores per-item or per-user information, so no validation/test item identity can be memorised into the SID construction; the SID vocabulary comes from the same encoder and codebook for every split, with no split-dependent state. Diagnostics are logged after the fact and never fed back.
HYPERBOLIC OPERATOR: Fixed negative curvature c = 1 (ball radius R_c = 1): Poincare exponential map exp_0^c, Moebius addition (+), and Poincare distance d_c(x,y) = (2/sqrt c) artanh(sqrt c ||(-x)(+)y||); c = 0 is the exact Euclidean limit used by the geometry-off switch.
HYPERBOLIC LOCATION: In the level-1 quantisation step of the RQ-VAE, forward only: the level-1 residual is exponentiated into the ball and scored against exponentiated level-1 codes, and the same curved distances produce the softmax weights that define the demand statistic. Levels 2-3, the loss and the STE are untouched.
COUPLING PATH: One connected pathway: r1 -> /s -> exp_0^c -> {d_c(u,q_k)} -> {S_ik} -> demand_k (EMA) -> off_k -> argmin_k(d_c(u,q_k) - off_k) -> k1 -> r2 = r1 - a^(1)_{k1} -> levels 2-3 -> reconstruction/commitment gradient -> parameter update. Curved distances generate the behaviour weights and the behaviour weights shift the curved assignment; behaviour off sets off_k = 0 on this path, geometry off sets c = 0 inside both d_c and exp_0^c on this path, so neither can be removed without changing k1, r2 and the update.
COUPLING EQUATION: k1(i) = argmin_k [ d_c( exp_0^c(r1_i / s), exp_0^c(a^(1)_k) ) - beta * clip( log1p(demand_k) - mean_j log1p(demand_j), -ln 3, +ln 3 ) ] with demand_k = EMA_rho( sum_i S_ik D_i / sum_i S_ik ) and S_ik = softmax_k( -d_c(u_i, q_k) / tau ); the behaviour term D_i / demand_k and the curved term d_c(exp_0^c(.), exp_0^c(.)) meet inside the single argmin.
OBSERVABLES: (1) fraction of training items whose level-1 code differs from the c = 0, off = 0 assignment (forward-only diagnostic, logged, never used to select anything); (2) level-1 code usage entropy and the correlation between per-code off_k and per-code assignment share (positive correlation capped by the ln 3 clip); (3) first-token predictability: hit rate o

f the true next item's level-1 token given the history's SID prefix, recorded as a diagnostic; (4) reconstruction and commitment loss trajectories staying close to baseline; (5) the judgement: Stage3 test_recall@10 of the single trained candidate versus the 0.0555 baseline and the 0.0638 previous best.
ABLATION BEHAVIOR OFF: BEHAVIOUR_OFF=true sets every D_i = 1, hence raw_k = 1, demand_k = 1, log1p demand constant and off_k = 0 for all k, so level 1 is the pure curved assignment argmin_k d_c(u_i, q_k); levels 2-3, loss and STE unchanged. The code path exists and is unit-tested for exactly zero offsets; no such arm is trained this round.
ABLATION GEOMETRY OFF: GEOMETRY_OFF=true sets c = 0, so exp_0^0 = identity, d_c(x,y) = 2||x - y|| and S_ik = softmax_k(-2||v_i - a_k||/tau); level 1 becomes argmin_k(2||v_i - a_k|| - off_k), reducing to the baseline Euclidean assignment when off is zero as well. The code path exists and is unit-tested to agree with the baseline quantiser on a random batch; no such arm is trained this round.
ABLATION BOTH ON: the single trained candidate: c = 1 curved level-1 distance plus the detached demand offset off_k, levels 2-3, reconstruction, commitment and STE identical to baseline, trained once for 3000 Stage-2 epochs on four cards and evaluated by the frozen Stage3 protocol.
SPEC EQUATIONS:
# frozen once
s    = sqrt(mean_i ||r1_i||^2)            # running mean, first 50 steps, buffer
c    = 1 ; R_c = 1/sqrt(c) ; beta = cfg.commitment_weight (default 0.25)
tau  = clamp(mean over first 50 steps of mean_i min_k d_c(u_i,q_k), 0.01, 10)
D_i  = count_next(i, train split) / mean_j count_next(j)      # frozen, no grad
demand_k = 1 for all k                                        # buffer, no grad
# every step, level 1
v  = r1 / s
u  = exp0c(v)                      # tanh(sqrt(c)||v||) v / (sqrt(c)||v||), 0 -> 0
q  = exp0c(a1)                     # a1 = baseline level-1 codebook parameter
Dk = (2/sqrt(c)) * artanh( clamp( sqrt(c) * || moebius_neg(u) (+) q ||, 0, 1-1e-6 ) )
S  = softmax_k(-Dk / tau)          # detached
raw_k  = (S * D[None,:]).sum(0) / S.sum(0).clamp_min(1e-8)
demand = (1-rho)*demand + rho * raw_k * K1 / raw_k.sum().clamp_min(1e-8)   # rho = 1/48, no_grad
ell = log1p(demand.clamp_min(1e-8))
off = beta * (ell - ell.mean()).clamp(-ln3, +ln3)                          # detached
k1  = argmin_k (Dk - off)                                                  # ties -> smallest k
r2  = r1 - a1[k1]                                                          # same as baseline
# loss = baseline reconstruction + baseline commitment, STE unchanged
SPEC INPUTS OUTPUTS: Inputs: level-1 residual batch r1 (B x 64), baseline level-1 codebook a1 (K1 x 64), frozen buffers s, c, tau, D (24,556), demand (K1), and the two boolean switches. Outputs: hard level-1 index k1 (B, long) used for r2 and for the SID token, updated demand buffer (K1, no grad), and logged diagnostics (offset vector, assignment share, changed-assignment fraction). Nothing else returned to levels 2-3 changes apart from k1.
SAFEGUARDS: (i) artanh argument clamped to [0, 1 - 1e-6] and the Moebius sum norm recomputed in float32 to avoid values > 1 from rounding; (ii) exp_0^c guarded at ||v|| = 0 and ||v|| clamped to at most 12 standardised units so tanh never sees inf; (iii) demand floored at 1e-8, mean-normalisation denominator clamped, EMA held at 1 for the first 50 steps, everything under torch.no_grad and detached; (iv) off_k hard-clipped to +-beta*ln3 so the

behavioural term can break near ties but cannot override a clear geometric margin; (v) deterministic tie-break to the smallest index so k1 is reproducible across cards; (vi) s, tau, c computed on one rank and broadcast, with NaN/Inf checks before writing to the buffers; (vii) the geometry-off path is unit-tested to reproduce the baseline quantiser and the behaviour-off path to produce exactly zero offsets, and both are logged in the run config although no arm is trained; (viii) D_i built only from the training split, with an assertion that no validation or test sequence id is read.
END IDEA
