IDEA: curvdemand-codeword-rq
TITLE: Per-codeword demand curvature: one arcosh geodesic score drives both the RQ assignment and the same-chart Mobius residual
MOTIVATION: Transition demand is heavy-tailed after popularity adjustment: a few SID codewords must serve many distinct successor transitions while tail codewords serve almost none, yet a uniform-curvature quantizer gives every codeword the same geodesic resolution, so hot codewords overload and their prefixes become hard for the generative recommender to predict. The previous round also failed structurally because assignment and reconstruction optimised different codeword positions; this design keeps one codeword point and one geometric score for both.
NOVELTY: A bounded, mean-normalised negative curvature scalar per codeword per level, derived from a training-only demand table, is the same quantity that (a) ranks the codeword in the assignment, (b) measures the quantization error and (c) sets the curvature of the Mobius residual. One chart, one point, one metric. No parallel transport, no per-level feedback scalar, no radial ranking, no holonomy, no Sinkhorn, no geodesic budget, no volume/radius allocation, no entropy table.
CHANGE: Replace the single quantizer distance by a codeword-specific geodesic score G_kappa with kappa_{l,j} from a detached EMA demand table, and use the SAME kappa_{l,j*} to subtract the residual, so assignment and reconstruction optimise identical codeword positions in identical geometry.
SPECIFICATION: (1) Offline from the training split only: item demand d_i. (2) Each epoch: per-level codeword demand D_{l,j} = EMA of the mean d_i over items whose level-l argmin is j. (3) kappa_{l,j}=clip(mean_j D_{l,j}/D_{l,j},0.5,2). (4) Encoder item vector e -> ball point x via radial tanh with radius bound rho0=0.6. (5) j*_l=argmin_j G_{kappa_{l,j}}(x_l,c_{l,j}). (6) Decoder reads exactly c_{l,j*}; quantization loss G_{kappa_{l,j*}}(x_l,c_{l,j*})^2; residual x_{l+1}=Pi_rho0(x_l (+)_{kappa_{l,j*}} (-c_{l,j*})). (7) Switches BEHAV and GEOM exist; only both-on is trained.
COST: Negligible: the curvature path is O(L*K*B) with L=4 levels, K=256 codewords, B~1024 items/step => ~1.05e6 arcosh/div evaluations per step, versus the encoder's transformer cost; the demand table update is O(24556*4) once per epoch at 24 steps/epoch and 3000 epochs. Expected wall clock baseline +2..5%, memory +O(L*K) floats.
HYPOTHESIS: In the single 3000-epoch run, kappa must differentiate (std>0, fewer than 10% of codewords pinned at a clip bound), level-2 distinct prefixes must exceed 1, level-3 collision must fall below 1.0, refinement_gain_bits must be >0, and Stage-3 test_recall@10 must exceed 0.065. If prefix counts stay at 1 and collision stays 1.0, the demand->curvature pathway does not break the collapse and the idea is falsified.
RISKS: The factor-2 clip gives only a modest distance gain, too weak to escape the one-codeword-per-level attractor seen last round.; kappa saturates at the clip bounds for most codewords, so curvature degenerates into a two-state meter and the assignment behaves like the Euclidean one.; The demand table lags codeword motion; in early epochs kappa==1 and the collapse may lock in before curvature differentiates.; Popularity-adjusted in-transition mass may proxy plain popularity, so the mechanism reduces to frequency bucketing.; Per-codeword kappa makes the residual chain non-monotone, so deeper levels carry noise and refinement bits drop.; arcosh argument approaches 1 when kappa*||x||^2 nears 1, giving gradient blow-up.
BEHAVIOR SIGNAL: Popularity-adjusted directed in-transition mass of each training item, aggregated per codeword and per level (a behaviour-conditioned assignment weight built from directed transitions).
BEHAVIOR COMPUTATION: One offline pass over the Stage-2 training sequences only: a_i = sum over training transitions u->i inside window W of 1/sqrt(pop_u) with pop_u the training frequency of u; d_i = a_i/(a_i + median(a_train)) in [0,1). Then, per epoch, for each level l and codeword j: D_{l,j} <- 0.9*D_{l,j} + 0.1*mean{ d_i : argmin_k G_{kappa_{l,k}}(x_i,c_{l,k}) = j }, initialised to the global mean of d so epoch 0 has kappa==1 everywhere.
LEAKAGE BOUNDARY: d_i is a function of training-split sequences only; no validation or test interaction is read anywhere in the SID construction. The codeword table is updated solely from the model's own training-split assignments under stop-gradient, is frozen at the end of Stage 2, and Stage 3 consumes the frozen SIDs without touching the demand table.
HYPERBOLIC OPERATOR: Fixed ambient negative curvature -1 on the open unit ball, plus a per-codeword negative curvature -kappa_{l,j} with kappa in [0.5,2] and level-mean 1; the operations are the arcosh Poincare geodesic score, kappa-Mobius gyro-addition and radial projection.
HYPERBOLIC LOCATION: Inside the RQ quantizer at every level: the assignment score, the quantization/reconstruction term and the residual chain. It is not a side loss and no point leaves the chart.
COUPLING PATH: item training-transition demand -> codeword demand EMA -> kappa_{l,j} -> the arcosh score that selects j* -> j* fixes the residual computed at kappa_{l,j*} -> the next level's point -> the SID tokens and the reconstruction loss. Setting the behaviour off (kappa==1) changes every argmin; setting the geometry off (arcosh -> Euclidean, Mobius -> subtraction) changes every argmin as well.
COUPLING EQUATION: j*_l = argmin_j G_{kappa_{l,j}}(x_l, c_{l,j}), G_kappa(u,v) = arcosh(1 + 2*kappa*||u-v||^2/((1-kappa*||u||^2)(1-kappa*||v||^2))), kappa_{l,j} = clip( mean_k D_{l,k} / D_{l,j}, 0.5, 2 ), x_{l+1} = Pi_rho0( x_l (+)_{kappa_{l,j*}} (-c_{l,j*}) ).
OBSERVABLES: Distribution of kappa (std, min/max, fraction at clip); per-level codeword usage histogram and entropy; level-2 distinct prefixes; level-3 collision rate; refinement_gain_bits; the geodesic quantization term per level over training; Stage-3 test_recall@10.
ABLATION BEHAVIOR OFF: BEHAV=0: d_i set to a constant so D_{l,j}==1 and kappa_{l,j}==1 for every codeword; the arcosh score and the Mobius residual remain, everything is unit curvature. Code exists and is correct; this arm is never trained.
ABLATION GEOMETRY OFF: GEOM=0: G^E_kappa(u,v)=2*sqrt(kappa)*||u-v|| and the residual becomes plain subtraction x_l - c_{l,j*} with the same radial projection; the behaviour table and its per-codeword weights are untouched. Code exists; this arm is never trained.
ABLATION BOTH ON: BEHAV=1, GEOM=1: the single 3000-epoch Stage-2 run followed by the frozen Stage-3 protocol, one seed, no early stopping.
SPEC EQUATIONS: # offline a_i = sum_{u->i in train, gap<=W} 1/sqrt(pop_u) ; d_i = a_i/(a_i + median(a_train)) D[l][j] = mean(d) for all l,j   # init, gives kappa==1 each epoch: D[l][j] = 0.9*D[l][j] + 0.1*mean{d_i : level-l argmin(x_i)==j}   # detached kappa[l][j] = clip( mean_j(D[l,:]) / D[l][j], 0.5, 2.0 ) # forward per item x_1 = rho0 * tanh(||e||/sqrt(Dim)) * e/max(||e||,1e-8) for l in 1..L: G[l][j] = arcosh(clamp(1 + 2*kappa[l][j]*||x_l-c[l][j]||^2 / ((1-kappa[l][j]*||x_l||^2)*(1-kappa[l][j]*||c[l][j]||^2)), 1+1e-7, None)) j*[l] = argmin_j G[l][j] z[l] = c[l][j*[l]]                       # SAME point for decode and for residual x_{l+1} = Pi_rho0( x_l (+)_{kappa[l][j*[l]]} (-z[l]) ) L = ||Dec(z[1..L]) - e||^2 + sum_l G[l][j*[l]]^2 + 0.25*sum_l ||x_l - sg(z[l])||^2 Mobius: u (+) _k v = ((1+2k<u,v>+k||v||^2)u + (1-k||u||^2)v) / (1+2k<u,v>+k^2||u||^2||v||^2) Pi_rho0(z) = z * min(1, rho0/||z||), rho0 = 0.6 GEOM=0: replace arcosh term by 2*sqrt(kappa)*||x_l-c[l][j]|| and (+) by plain subtraction.
SPEC INPUTS OUTPUTS: Inputs: encoder item vector e (Dim), codeword table c[L][K][Dim] in the unit ball, detached demand vector d[24556] and table D[L][K]. Outputs: per-item per-level indices j*[1..L] (the SID tokens), the decoder input z[1..L], the residual chain x_2..x_{L+1}, and the scalar loss. No other state is produced.
SAFEGUARDS: rho0=0.6 so that kappa_max*rho0^2 = 0.72 < 1 keeps every arcosh argument finite; denominators clamped at 1e-3; arcosh argument clamped to >= 1+1e-7; kappa clipped to [0.5,2]; demand table detached and updated once per epoch with EMA 0.9 so it cannot chase batch noise; codewords reprojected to radius <= rho0 after every optimiser step; any non-finite entry in the table update is skipped and the previous table is kept; the table is frozen before Stage 3.
END IDEA
