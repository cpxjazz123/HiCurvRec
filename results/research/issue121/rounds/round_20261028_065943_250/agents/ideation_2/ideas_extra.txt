IDEA: interest_signature_hypball
TITLE: User-interest signature parents with hyperbolic coarse assignment
MOTIVATION: A first-level code should group items that serve the same training-user interest contexts, while subsequent residual digits remain free to preserve item identity; global item-to-item transition communities can miss this cross-user role.
NOVELTY: Instead of defining coarse parents by graph partition, continuation mass, or an appended behaviour token, construct a low-dimensional item signature from the users who transition into each item, then use that signature to restrict the coarse codebook and a curved distance to make the actual first-token choice.
CHANGE: From training-only immediate user transitions, build each item's normalized distribution over user-interest cohorts, assign the item to its maximum-mass cohort, and allocate each cohort a share of the first-level codewords. Within that cohort, choose the first code by Poincare distance to a behavior-shifted latent point; quantize levels 2–3 with the unchanged residual quantizer so third-level identity capacity is retained.
SPECIFICATION: Deterministically assign each training user to one of M cohorts by hashing their training-only ordered item history into M buckets (M is the existing first-level codebook size, not tuned). For each item i, let h_i[m] be the number of training transitions u: x_{u,t}->i for which user u hashes to m; smooth by one count per cohort and normalize a_i[m]=(h_i[m]+1)/(sum_q h_i[q]+M). Set parent g_i=argmax_m a_i[m] (lowest index breaks ties). Allocate K1 first-level codes across nonempty parents proportional to their item counts by largest remainder, at least one per parent. Let b_i be the Poincare-ball log-map of the normalized cohort-mass vector a_i, after embedding it in the latent dimension with a fixed seeded orthonormal projection P; set y_i=exp_0(log_0(z_i)+b_i). Select q_i=argmin_{k in C_{g_i}} d_{-1}(y_i,c_k)^2, use q_i's code vector in the ordinary straight-through reconstruction update, then perform baseline Euclidean residual quantization for levels 2–3. Fix P from the run seed; no learned behaviour encoder or extra loss weight.
COST: One pass over training transitions, O(T) cohort-count accumulation and O(NM) normalization/projection; per quantization step one projection/map per item and restricted Poincare comparisons. At 24,556 items, 24 steps/epoch and 3,000 epochs (72,000 steps), the extra per-step work is O(BD M) for the signature map plus no more first-level distance comparisons than baseline; cohort counts are precomputed and reused. No additional training run, epoch, or model.
HYPOTHESIS: User-cohort transition roles are more predictive of next-item token structure than global pairwise graph neighborhoods, and curved within-parent scoring can consolidate coarse first-level assignments without destroying third-level identity. Record first-token assignments, L1 hard error, third-level distinct triples and train-prefix next-token predictability; keep only if the single frozen Stage3 run has test Recall@10 > 0.065.
RISKS: Hash cohorts may be noisy or arbitrary; users with short histories provide weak cohort evidence; dominant-cohort assignment can separate items used by multiple interests; the additive tangent shift may saturate the ball or distort content geometry. First-level code allocation can leave a parent too few codes.
BEHAVIOR SIGNAL: Training-only user-conditioned immediate predecessor-to-target transition counts, summarized by hashed user-interest cohorts.
BEHAVIOR COMPUTATION: Read only the Stage2 training sequences. Hash each user ID deterministically into M cohorts, count h_i[m] for every observed consecutive transition ending at item i by the source user's cohort, then add-one smooth and normalize. Do not read valid/test events or interaction-derived user statistics from those splits.
LEAKAGE BOUNDARY: Cohort assignments and h_i are constructed once from Stage2 training transitions and frozen before RQ-VAE fitting/export; validation and test interactions, labels, and metrics are unavailable to the builder and do not affect projection, assignments, optimization, or checkpoint selection.
HYPERBOLIC OPERATOR: Fixed-curvature (-1) Poincare log map, exp map, and squared geodesic distance.
HYPERBOLIC LOCATION: The behavior-conditioned first-level item point and its restricted hard code assignment during Stage2 quantization; later residual levels remain baseline to protect item identity.
COUPLING PATH: Training-user cohort mass produces the item tangent displacement b_i and parent candidate set C_{g_i}; exp_0(log_0(z_i)+b_i) followed by Poincare distance chooses the first code and determines its straight-through update. Turning behaviour off removes both displacement and parent restriction; replacing hyperbolic operators by Euclidean ones changes the same assignment path.
COUPLING EQUATION: a_i[m]=(h_i[m]+1)/(sum_q h_i[q]+M); g_i=argmax_m a_i[m]; b_i=log_0(Pa_i); q_i=argmin_{k in C_{g_i}} d_{-1}(exp_0(log_0(z_i)+b_i),c_k)^2. Here h_i is the training-user behaviour term and exp/log plus d_{-1} are the curved terms in one assignment computation.
OBSERVABLES: With both switches on, the behavior-derived cohort parent and Poincare-shifted argmin should change first-level assignment and its straight-through parameter gradient; record first-level occupancy, L1 hard error, third-level distinct triples, prefix next-token predictability and Stage3 test Recall@10. Diagnostics are reported, not used as admission gates.
ABLATION BEHAVIOR OFF: Set a_i to the uniform cohort vector and b_i=0, remove parent restriction (all first-level codes eligible), and retain Poincare assignment; this is a defined switch only, not a separately trained arm.
ABLATION GEOMETRY OFF: Preserve h_i, g_i, code allocation and b_i, but replace log_0/exp_0 with identity mappings and d_{-1} with squared Euclidean distance on the resulting vectors; no separate run is trained.
ABLATION BOTH ON: Use the training-only cohort masses and parent restriction together with Poincare log/exp maps and squared curvature -1 distance exactly as specified; train this single candidate only.
SPEC EQUATIONS: For training transitions (u,i)->(u,j), hash c(u)=hash(u) mod M. Set h_j[m]=sum_{(u,i,j) in train}1[c(u)=m]; a_j[m]=(h_j[m]+1)/(sum_q h_j[q]+M); g_j=argmax_m a_j[m]. For fixed seeded orthonormal P, b_j=log_0(Pa_j), y_j=exp_0(log_0(z_j)+b_j); q_j=argmin_{k in C_{g_j}}d_{-1}(y_j,c_k)^2. Feed selected first code to the existing straight-through RQ-VAE loss; levels 2 and 3 use the unchanged baseline residual quantizer. Allocate K1 codes by largest-remainder proportional allocation over nonempty parent item counts.
SPEC INPUTS OUTPUTS: Inputs are Stage2 training user/item sequences, item latents z_i, first-level codebook size K1 and vectors, and run seed. Outputs are frozen user cohort labels, item cohort masses and parent labels, first-level assignments, and complete three-level SIDs with baseline later-level assignments.
SAFEGUARDS: Hash deterministically with a documented stable hash, use add-one smoothing so no row is empty, resolve all ties by integer ID, and ensure every nonempty parent receives at least one code (merge smallest parents by nearest cohort-mass vector if necessary). Construct P once as a seeded orthonormal projection and normalize Pa_i before mapping; project all ball points to norm <=1-1e-5, clamp acosh inputs to >=1+1e-7, calculate maps/distances in float32 or higher, and use finite checks with safe zero-vector limits. No coupling constant is tuned; the only count smoothing is the documented Dirichlet-one default. Diagnostics never gate admission.
END IDEA
