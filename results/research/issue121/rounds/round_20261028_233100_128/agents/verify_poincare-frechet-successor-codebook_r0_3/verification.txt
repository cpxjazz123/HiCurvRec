FINDING LOCATION: model/layers.py:198-201 (with model/frechet_poincare.py:88-98, 143-151)
FINDING DETAIL: The level-2/level-3 codebook initialisation applies the Poincare distance to a point that is not in the ball. `VQLayer.init_codebook` receives `x` = the residual handed in from the previous level, which at level 1 is the raw encoder output in R^d and at levels 2-3 is a tangent residual `x - log_0(code)`. It then does `embed_ind = torch.argmin(self.frechet.distances(x, self.get_code_embs()), dim=-1)` where `distances` (curvature on) evaluates `poincare_distance(x.unsqueeze(1), codebook.unsqueeze(0))`, i.e. it treats that unbounded tangent vector as a point of B^d. For `||x|| > 1` the `mobius_add(-x, y)` denominator and the `(1 - c*||x||^2) * y` numerator make the Möbius difference exceed unit norm for essentially every code; `log_at`/`poincare_distance` then clamp the `atanh` argument at `1 - ARTANH_EPS = 1 - 1e-7` (model/frechet_poincare.py:97-98) and return the same saturated value 2*atanh(1-1e-7) = 16.118 for every slot. All 256 distances tie, `torch.argmin` returns 0, so every item is assigned to code 0 at initialisation. The residual handed to the next level is then `x - log_0(c_0)`, a single constant shift for the whole item set, and the next level's KMeans is fitted to that shifted set; `_copy_init_embed` maps the large-norm centres through `exp_0` (model/layers.py:93), whose norm is `tanh(||v||/2)`, so levels 2 and 3 start with all 256 codes squeezed onto the boundary shell at radius ≈ 0.9999 instead of being spread over the ball. The docstring directly above the call ("Same cost and same residual as the training step: a Euclidean assignment here would start levels 2 and 3 in another geometry than the one the mechanism moves in") is false: the training step maps the latent first, `point = clamp_ball(exp_0(latent))` at model/layers.py:153, and the initialisation does not. This is the curved operation not reaching the computation it claims, at exactly the point where the shared codebook state is created, and it is why the author's own `tests/test_mechanism.py:141-157` ("the start uses the curved cost") passes: it only asserts the returned residual is finite and below 25, which a saturated assignment trivially satisfies.
FINDING REPRODUCTION: By hand, with c = 1 and a collinear worst case: x = 5e, y = r*e, r = 0.5 gives numerator = -(1 + 10r + r^2)*5*e - (1 - 25)*r*e = -43.25e and denominator = 1 + 10r + 25r^2 = 12.25, so `mobius_add(-x, y)` has norm 3.53 > 1 and the distance is the clamped 16.118; the same holds for r = 0.9 (norm 2.50), r = 0.1 (norm 1.58) and r = 0.001 (norm 5.02), and it already saturated at ||x|| = 1.1. Since the residual is `x - log_0(c_0)` with `||log_0(c_0)|| <= 2*atanh(1-1e-4) ~ 18.4`, the shift does not bring it back inside the ball.
