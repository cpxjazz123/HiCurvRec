IDEA: BFRQ-KARCHER-MASS
TITLE: Behaviour-mass weighted Karcher (Poincare) codebook estimation for the RQ-VAE semantic-ID quantizer.
MOTIVATION: Every existing curved-SID mechanism moves the *assignment* (curved cost, Sinkhorn, cones, shells) or the *residual* (transport), while leaving the estimator untouched: a code vector is still a Euclidean centroid of its assigned points. Consequence: a code is pulled by the raw item cloud, so behaviourally central items (the ones that actually determine what follows what) get exactly as much say in the code position as dead-tail items that merely happen to land in the same cell. Behaviourally coherent prefixes therefore stay diluted, and the generative recommender is asked to predict tokens whose geometry was never shaped by transitions.
NOVELTY: The curved operation is placed on the code-vector *estimator*, not on the cost. Each code is computed as a behaviour-weighted Frechet (Karcher) mean in the Poincare ball, so (i) the behaviour signal changes which assigned points dominate the code, and (ii) curvature changes how those dominant points pull (hyperbolic log maps grow like log((1+r)/(1-r)), and the Karcher mean contracts toward the ball centre relative to the Euclidean mean). No previous arm in this programme estimated codes geodesically; nothing here reuses a Sinkhorn cost, a tangent-space fork transport, a radial shell/volume scalar, a margin/cone, or a per-node curvature field.
CHANGE: Replace the quantizer's Euclidean code-vector update (EMA centroid or gradient step) by a single Riemannian Karcher step in the Poincare ball, with each assigned residual point reweighted by a popularity-adjusted transition centrality of its item. Assignment code path, encoder, decoder, loss and Stage 3 are untouched.
SPECIFICATION: Chart the latent: p = z/(||z||+tau), tau = median ||z|| measured once over the frozen 24,556 Stage-2 items; curvature c = 1 (unit negative curvature, ball radius 1). For each level l and each code k with assigned points p_i and item weights w_i: g_k = sum_i w_i * log_{m_k}(p_i) / sum_i w_i ; m_k <- exp_{m_k}( eta_k * g_k ) ; eta_k = 1/(1+N_k) with N_k the raw (unweighted) assignment count. Behaviour enters only through w_i; geometry enters only through log/exp and the metric factor lambda. w_i = 1 + log1p( mu_tilde(x_i) ) where mu_tilde is the transition-centrality normalized to mean 1 and clipped at its data 99th percentile.
COST: Stage 2 is 3000 epochs x 24 steps = 72,000 steps at 24,556 items (~1023 items/step). Per step the update touches 3 levels x ~1023 points x d=64: about 2e5 elementwise ops (two Mobius additions, one artanh, one tanh per point-level), fully vectorised, well under 1 ms on one GPU against a typical 50-150 ms encoder step, i.e. an estimated +1 to +3 percent Stage-2 wall clock, roughly +2 to +5 minutes over the whole 72,000 steps. One-off preprocessing: counting training transitions (a few million pairs) plus one forward pass over 24,556 items to measure tau: about 1 to 2 minutes. Stage 3 cost is exactly zero (it consumes integer SIDs). No extra epochs, no extra forward or backward passes, no extra parameters.
HYPOTHESIS: If within-cell transition mass is strongly heterogeneous (heavy-tailed popularity gives mu_tilde coefficients of variation well above 1 inside most cells) and the hyperbolic Karcher mean materially relocates codes, then hub-adjacent items get finer effective resolution and SID prefixes become more behaviourally predictable, lifting Stage 3 test Recall@10 above 0.065 in the single coupled run. It is worth keeping if that run exceeds 0.065 AND the logged diagnostics confirm the mechanism actually fired (weight dispersion and code displacement are non-trivial); it is not worth keeping if recall does not move even though the diagnostics show the coupling was active, or if recall moves while the diagnostics show the weights were nearly uniform.
RISKS: The 99th-percentile clip could still let a handful of hub items dominate a cell, collapsing several codes toward the same region and creating prefix collisions. The hyperbolic mean contracts codes toward the ball centre, which may crowd many codes into the inner region and destroy the radial spread the frozen quantizer relied on. Long-tail data may make mu_tilde nearly uniform for the bulk of items so the mechanism barely fires. If the frozen quantizer already assigns under a hyperbolic metric, the interaction with a curved estimator may be redundant or unstable. A single run cannot separate a real gain from seed noise, so a marginal improvement (e.g. 0.0655) is not evidence.
BEHAVIOR SIGNAL: Popularity-adjusted directed-transition centrality of each item (a parameter-free, normalized successor/predecessor flow), used as the per-item weight inside the code estimation.
BEHAVIOR COMPUTATION: From the frozen split files, take only the Stage-3 TRAINING interaction sequences (the same prefix used to train the generative recommender), after the frozen dedup/filtering. For each consecutive pair (x_t, x_{t+1}) in a training sequence increment n(x -> y). Normalize with no free exponent: n_hat(x->y) = n(x->y) / sqrt(d_out(x) * d_in(y)), with d_out(x) = sum_y n(x->y) and d_in(y) = sum_x n(x->y). Item mass mu(x) = sum_y n_hat(x->y) + sum_z n_hat(z->x). Then mu_tilde(x) = mu(x) / mean over training items, clipped at the empirical 99th percentile, and w(x) = 1 + log1p(mu_tilde(x)); items with no training transition get mu = 0 hence w = 1. The table is computed once, before Stage-2 training starts, and is a read-only lookup during training.
LEAKAGE BOUNDARY: The transition table is built exclusively from the Stage-3 training sequences; validation and test interactions are removed from the file before any counting, so no validation/test co-occurrence, popularity or ordering can influence a weight. Items that appear only in validation/test are absent from the table and receive w = 1; they are never dropped and their SIDs come from the frozen Stage-2 item features alone. SID construction is therefore a deterministic function of (frozen Stage-2 item features, Stage-3 training transitions) only; the same frozen SID table is used for all three splits; and since there is no early stopping and no arm selection, no validation quantity ever feeds back into the SID.
HYPERBOLIC OPERATOR: Unit negative curvature (c = 1) Poincare ball with Mobius addition, metric factor lambda_u = 2/(1 - c||u||^2), exponential and logarithmic maps exp_u / log_u, and geodesic distance d_c(u,v) = (2/sqrt(c)) artanh(sqrt(c) ||(-u) (+) v||); the estimator is the Riemannian (Karcher) mean, i.e. repeated geodesic steps along the tangent-space average of log maps.
HYPERBOLIC LOCATION: Inside the quantizer's code-vector estimation, at every Stage-2 step, for every level of the residual chain; it acts on how m_k is produced from the points assigned to k. The assignment step, the encoder, the decoder, the reconstruction and commitment terms, and all of Stage 3 are unchanged.
COUPLING PATH: mu(x) [training transitions] -> w(x) -> weighted tangent mean g_k = sum_i w_i log_{m_k}(p_i)/sum_i w_i -> geodesic step m_k <- exp_{m_k}(eta_k g_k) -> codebook positions -> nearest-code assignment -> SID tokens -> Stage-3 prefix statistics. Removing the behaviour term makes g_k an unweighted Karcher mean; removing curvature (Euclidean log/exp, lambda = 1) makes it an ordinary weighted arithmetic centroid. Either removal changes the codebook, hence the SIDs.
COUPLING EQUATION: m_k <- exp^{c}_{m_k} ( eta_k * [ sum_{i in A_k} w(x_i) * log^{c}_{m_k}( p_i ) ] / [ sum_{i in A_k} w(x_i) ] ), with w(x_i) = 1 + log1p( mu_tilde(x_i) ), p_i = z_i/(||z_i|| + tau), and exp^c / log^c the curvature-c Poincare maps; the behaviour term is w(x_i), the curved term is (log^c, exp^c, lambda^c), and they multiply inside one gradient.
OBSERVABLES: (1) the fraction of the 24,556 items whose level-0 (and level-1) code differs from the code the Euclidean uniform estimator would have produced on the same assignments; (2) dispersion of w inside each cell (per-code coefficient of variation of mu_tilde) and per-code weighted mass versus item count, i.e. whether hub-heavy cells absorb more items; (3) mean geodesic Karcher step size ||eta_k g_k|| per level over epochs, and the radial distribution of codes (checking that codes do not all collapse toward the origin); (4) prefix behaviour predictability: on training-only sequences, the conditional entropy / top-1 accuracy of the next item's level-k code given the previous codes, compared against the frozen baseline SID table; (5) Stage-3 test Recall@10, the judgement.
ABLATION BEHAVIOR OFF: A switch `use_behaviour_weights = False` that sets w(x) := 1 for all items, so g_k becomes the unweighted Karcher mean and the codebook is purely geometry-driven while every other line, including the curved estimator, is identical. Present and unit-checked in code; never trained.
ABLATION GEOMETRY OFF: A switch `curvature_off = True` that replaces the Poincare log/exp with Euclidean subtraction/addition and sets lambda = 1, so the estimator becomes the ordinary weighted arithmetic centroid (w still applied) while the behaviour table and the assignment code path are identical. Present and unit-checked in code; never trained.
ABLATION BOTH ON: The full coupled run, `use_behaviour_weights = True` and `curvature_off = False`: behaviour-weighted Karcher estimation in the Poincare ball. This single run is the candidate; no arm is trained with either switch off.
SPEC EQUATIONS: 
Precompute once (CPU, before training):
  tau := median_{x in Stage2train} ||z_x||                      # one forward pass, 24,556 items
  chart: p(z) := z / (||z|| + tau)                               # p in ball, ||p|| < 1
  transitions n(x->y) from Stage-3 TRAIN sequences only
  n_hat(x->y) := n(x->y) / sqrt(d_out(x) d_in(y)), d_out(x)=sum_y n(x->y), d_in(y)=sum_x n(x->y)
  mu(x) := sum_y n_hat(x->y) + sum_z n_hat(z->x)
  mu_tilde(x) := mu(x) / mean(mu), then clip at quantile_0.99(mu)
  w(x) := 1 + log1p(mu_tilde(x))                                # w == 1 iff behaviour switched off
Poincare primitives, c = 1:
  mobius(u,v) := ((1 + 2c<u,v> + c||v||^2) u + (1 - c||u||^2) v) / (1 + 2c<u,v> + c^2||u||^2||v||^2)
  lam(u)      := 2 / (1 - c||u||^2)
  log_u(v)    := (2/(sqrt(c) lam(u))) * artanh(sqrt(c)||mobius(-u,v)||) * mobius(-u,v)/max(||mobius(-u,v)||, eps)
  exp_u(t)    := mobius(u, tanh(sqrt(c) lam(u)||t||/2) * t / max(sqrt(c)||t||, eps))
Per Stage-2 step, for each level l (codes m_k already in the ball), after the frozen forward pass gives assignments A_k and residual points z_i:
  p_i := p(z_i)
  for k with A_k non-empty:
      g_k := sum_{i in A_k} w(x_i) * log_{m_k}(p_i) / sum_{i in A_k} w(x_i)
      eta_k := 1 / (1 + N_k)                       # N_k = raw count of assignments to k, accumulated
      m_k := exp_{m_k}( eta_k * g_k )              # stays in the ball for any finite g_k
  N_k := N_k + |A_k|
  write m_k back as the codebook entry, then continue with the frozen loss and backward pass.
Geometry-off variant: log_u(v) := v - u, exp_u(t) := u + t, lam := 1, chart p(z) := z.
Behaviour-off variant: w := 1.
SPEC INPUTS OUTPUTS: Inputs: the frozen Stage-2 item latent z_i produced by the encoder for the current batch (reset points per level), the current codebook matrices {m_k} in chart coordinates, the per-item weight table w (24,556 floats), the accumulated assignment counts N_k, and the two switches. Outputs: updated codebook matrices {m_k} in the ball, updated N_k, and per-step scalars for the diagnostics (mean ||eta_k g_k||, per-code weight dispersion, fraction of cells touched). The operator returns nothing else; it does not alter logits, assignments, or gradients.
SAFEGUARDS: Compute all norms with an epsilon of 1e-8 in denominators; verify after each update that max_k ||m_k|| <= 1 - 1e-5 and clamp radially if floating point ever violates it (the exp map is contractive so this is a numerical guard, not a mechanism); clip the tangent vector norm ||g_k|| at 1e3 before the exp map to avoid an artanh/tanh overflow on degenerate batches; skip cells with |A_k| = 0; skip a whole update and log a warning if any non-finite value appears in m_k (never write NaN into the codebook); compute the chart with tau floored at 1e-6; initialise codes at the chart images of the frozen Euclidean init so the geometry-off and both-on runs start from identical code vectors; keep the update in float32 and run the Mobius/log/exp arithmetic in a fixed order (no reordering that changes summation) so the run is reproducible; assert at start-up that w == 1 exactly when the behaviour switch is off and that log/exp round-trip (exp_u(log_u(v)) ~= v within 1e-4) when curvature is on.
END IDEA
