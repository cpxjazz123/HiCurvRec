IDEA: SUCC-GEO-CBTAB
TITLE: Behaviour-weighted geodesic triplet margin that moves the shared RQ codebook table so successor items' hierarchical code prefixes are Poincare-close
MOTIVATION: RQ-VAE semantic IDs are built for reconstruction, not for transitions. Two items a user actually moves between often land on unrelated prefixes, so the generative recommender must memorise the transition instead of reading it off the code tree. The fix cannot be "add a graph loss", because a flat Euclidean graph loss just pulls code vectors together and collapses the codebook; the natural geometry for a tree-shaped prefix code with an exponentially growing frontier is negative curvature.
NOVELTY: Prior rounds put curvature on the assignment (Sinkhorn / voronoi / curvature cells), on transported tangent frames (fork angle, shell, cone), or on anchored charts. This one leaves the assignment, the encoder and the Sinkhorn machinery completely untouched and puts the curved operation on the CODEBOOK UPDATE: a curvature-measured geodesic triplet margin over prefix-truncated code sums, with the margin violation weighted by a row-normalised transition strength. It is a code-table geometry, not an assignment geometry, not a transport, not a chart, and not an auxiliary hyperbolic head on the encoder.
CHANGE: After each epoch we snapshot every training item's L code indices (free: they come from the forward passes already run). Each step we sample training-only transitions, form prefix code sums at levels 1, 2 and L, map them by exp_0^kappa into a Poincare ball of fixed measured curvature -kappa, and apply a softplus triplet margin in which the positive/negative geodesic gap is multiplied by the transition weight; gradient flows into the codebooks only.
SPECIFICATION: see SPEC EQUATIONS.
COST: No extra forward passes and no extra encoder compute. Per step at the frozen scale: 1024 sampled transitions x 3 prefix depths x 2 distances (positive and negative) = 6144 Poincare distance evaluations at dimension d (64-128), about 0.5 MFLOP, plus 3 gather-sums over 3 tables per endpoint, i.e. under 0.5 percent of one optimizer step. Cache refresh is O(24556 x 3) integer writes once per epoch (72000 steps over 3000 epochs; 24 steps per epoch). Memory: 24556 x 3 int32 = 295 KB. Expected wall-clock delta on four cards: under 1 percent.
HYPOTHESIS: If the successor table carries usable structure at the granularity of code prefixes, then a behaviour-weighted geodesic margin on the codebook should raise the fraction of transitions whose successor shares the anchor's level-1 and level-2 code above the reconstruction-only baseline, and that gain should carry into Stage 3 test Recall@10 above 0.065 without any change to the Stage 3 protocol. Observed through: successor-prefix hit rate per level, codebook usage entropy, mean geodesic distance of true successor pairs versus random pairs, and finally Stage 3 test_recall@10 on the single run.
RISKS: (a) Codebook-only gradient may be too slow to relocate codes within 3000 epochs, leaving SIDs close to baseline. (b) Negative sampling noise can pull unrelated items together when the table is sparse (cold items with one transition). (c) The margin can be satisfied by driving two items to identical codes, which would help the objective but destroy SID uniqueness and hurt generation; a duplicate-count diagnostic covers this. (d) If code sums sit very near the origin the derived curvature is too flat and Poincare distance degenerates toward Euclidean, so the coupling becomes numerically inert.
BEHAVIOR SIGNAL: Directed item transitions with row-normalised strength, taken from consecutive co-consumption inside a training session, used as a per-edge weight and as a negative-sampling constraint.
BEHAVIOR COMPUTATION: From the Stage 2 training split only. For every training session (ordered item list) and every adjacent pair (i_t, i_{t+1}) with both items in the 24556-item training vocabulary, increment T[i_t, i_{t+1}]. Then for each anchor i set w[i,j] = T[i,j] / max_{j'} T[i,j'], so w lies in (0,1] and the strongest successor of every anchor gets 1.0. N(i) = {j : T[i,j] > 0}. Anchors with out-degree 0 are excluded. The table is built once before training and is never rebuilt from model state.
LEAKAGE BOUNDARY: The transition table is built exclusively from training-split sessions; validation and test interactions are never read by the table builder, never enter the cache of code indices (filled only from training-item forward passes), and never appear as anchors, positives or negatives. Validation/test items absent from the training vocabulary are not in the cache, so they cannot enter the margin. The mechanism touches only Stage 2 (the RQ-VAE); the Stage 3 protocol and its split stay frozen, and the SID construction sees only the training graph, so no validation or test interaction can influence a code assignment.
HYPERBOLIC OPERATOR: Fixed negative curvature -kappa with kappa = 1/s^2 and s^2 = mean_i ||zhat_i||^2 measured at the end of epoch 0 and frozen. Operations: exp_0^kappa(v) = tanh(sqrt(kappa)||v||) * v / (sqrt(kappa)||v||) into the open unit ball, Moebius addition, and the Poincare distance d_kappa(u,v) = (2/sqrt(kappa)) * artanh(sqrt(kappa) * ||(-u) (+) v||).
HYPERBOLIC LOCATION: Entirely in the quantization stage, as a gradient on the shared codebook parameters C_1..C_L of the RQ-VAE. The encoder, the nearest-code assignment rule, the decoder, the commitment loss and the reconstruction loss are all unchanged.
COUPLING PATH: w[i,j] (behaviour) multiplies the softplus of a geodesic gap (geometry) computed on prefix code sums drawn from the codebook table; the resulting gradient is the only thing that moves the codebook away from its reconstruction optimum, so it is the single path by which both signals reach the SID. Setting w to zero removes every gradient of the term (behaviour-off is exactly the baseline trajectory); replacing d_kappa with the Euclidean norm changes the direction and scale of every codebook update while keeping the identical term structure (geometry-off). Neither substitution leaves the other intact, because w and d_kappa appear multiplied inside the same softplus argument.
COUPLING EQUATION: L_succ = mean over sampled (i,j) of softplus( w[i,j] * [ D_ij - D_ijminus + m0^2 ] ), with D_ij = (1/3) * sum_{h in {1,2,L}} d_kappa^2( p_i^(h), p_j^(h) ), p_i^(h) = exp_0^kappa( sum_{l<=h} C_l[k_l(i)] ), and m0^2 the measured mean geodesic distance between random code pairs.
OBSERVABLES: (a) successor-prefix hit rate at levels 1 and 2 versus baseline; (b) mean d_kappa for true successor pairs relative to random pairs (separation ratio); (c) codebook usage entropy and the number of exact L-code duplicates; (d) Stage 3 test_recall@10. All diagnostics are recorded, none is an admission gate; the single run's test_recall@10 decides.
ABLATION BEHAVIOR OFF: w[i,j] is set to 0 for all edges (the sampler returns a constant-zero weight). L_succ then has value mean(log 2) and exactly zero gradient, so the run reproduces the baseline RQ-VAE trajectory up to non-determinism. The switch exists in code and is correct; it is not run this round.
ABLATION GEOMETRY OFF: kappa is disabled and d_kappa^2(u,v) is replaced in the same equation by ||zhat_i^(<=h) - zhat_j^(<=h)||^2 (Euclidean, with m0^2 recomputed as the Euclidean counterpart at epoch 0). Same sampler, same weights, same softplus, same prefix depths. Exists in code, not run.
ABLATION BOTH ON: The full term with row-normalised w[i,j] and Poincare d_kappa at the measured curvature -1/s^2, added to the unchanged RQ-VAE loss with weight 1 (dimensionless, because numerator and m0^2 share units). This is the only arm trained in this round.
SPEC EQUATIONS:
```
# --- once, before training ---
T = zeros(N, N)
for each train session s:
    for t: if s[t] in vocab and s[t+1] in vocab: T[s[t], s[t+1]] += 1
N(i) = {j : T[i,j] > 0};  out_i = sum_j T[i,j];  T[i,i] = 0
w[i,j] = T[i,j] / max_{j'} T[i,j']            # in (0,1]

# --- end of epoch 0, frozen for the rest of training ---
zhat_i = sum_{l=1..L} C_l[k_l(i)]              # cached training code indices
s2     = mean_i ||zhat_i||^2
kappa  = 1.0 / s2
m0_sq  = mean over 10000 random training pairs (i,j) of d_kappa^2(p_i^(L), p_j^(L))

# --- every step ---
S = sample 1024 (i,j) pairs with T[i,j] > 0
loss = 0; kept = 0
for (i,j) in S:
    jm = uniform item with T[i,jm] == 0 and jm not in {i,j}
         resample <= 5 times; if it fails, drop the pair
    D_pos = 0; D_neg = 0
    for h in (1,2,L):
        u   = exp0(sum_{l<=h} C_l[k_l(i)])
        D_pos += (1/3) * d_kappa^2(u, exp0(sum_{l<=h} C_l[k_l(j)]))
        D_neg += (1/3) * d_kappa^2(u, exp0(sum_{l<=h} C_l[k_l(jm)]))
    loss += softplus( w[i,j] * (D_pos - D_neg + m0_sq) );  kept += 1
L_total = L_RQVAE + loss / max(1, kept)
backward(); step()

# --- end of epoch ---
overwrite cache k_1..k_L for all 24556 training items with the argmin
indices produced by that epoch's forward passes (no extra forward pass)
# kappa and m0_sq are NEVER recomputed after epoch 0
```
SPEC INPUTS OUTPUTS: Inputs: the precomputed sparse transition table T and row-normalised weights w (training split only), the epoch cache of code indices k_l(i) for the 24556 training items, the shared codebook parameters C_1..C_L, and the two frozen scalars kappa and m0_sq measured at epoch 0. Output: the scalar L_succ and its gradient with respect to C_1..C_L only (the cached indices are integer constants, so no encoder gradient is taken through this path). It returns nothing else and does not modify assignment, decoding or the SID export.
SAFEGUARDS: (1) Clamp ||v|| before exp0 so the mapped radius stays below 1 - 1e-5 (tanh saturates to exactly 1 in float32). (2) Clamp the artanh argument to 1 - 1e-7 and compute d_kappa in float64. (3) If s2 <= 1e-12, fall back to kappa = 1 and log a warning instead of dividing by zero. (4) Guard s2, kappa and m0_sq so they are finite and positive; otherwise disable the term for the run and record the flag (no retuning). (5) Skip pairs with out_i = 0, with w = 0, or with an endpoint not yet in the cache; never let an unseen item contribute. (6) The negative must not be in N(i) and must differ from i and j; if all 5 resamples fail, drop the pair rather than use a false negative. (7) Record the L-code duplicate count each epoch so the collapse failure mode is visible (no extra repulsion term is added; that would be a different mechanism). (8) Force w[i,i] = 0. (9) Divide L_succ by the number of kept pairs so gradient magnitude does not drift with table density. (10) Freeze kappa after epoch 0 so curvature cannot drift toward zero and silently Euclideanise the term.
END IDEA
