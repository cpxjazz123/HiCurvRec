IDEA: bgcd-fine-v1
TITLE: Behaviour-directed geodesic code drift on the fine residual levels: displacing each code along the item's directed-transition direction inside the Poincare ball, inside the baseline Sinkhorn cost, for levels 2 and 3 only.
MOTIVATION: The previous round proved that behaviour+curvature coupling CAN re-partition the coarse level (L1 Hard ER 16.39 -> 6.36, all 256 level-1 codes used) but that re-partitioning the coarse level spends the fine levels' spatial freedom: only 955 distinct L2 prefixes survived against 7414 in the frozen baseline and 16145 in the reference arm, and the item-weighted 3-level collision rose to 0.771 (reference 0.065), so that arm was refused at the Stage3 gate and Stage3 test Recall@10 was never measured. The real recommender problem here is not coarse semantics, it is that many distinct items are forced to share the same fine prefix, so the generative model cannot emit the right item even when it emits the right coarse token. This idea attacks exactly that: keep the coarse partition as the baseline builds it, and use behaviour+curvature to protect the resolution of the fine levels.
NOVELTY: Not a cohesion bias on level 1, not a scalar behaviour offset added to a distance, not a second hyperbolic loss. The behaviour signal moves the CODE POINT itself along a hyperbolic geodesic (a Mobius translation of the code inside the Poincare ball) before the distance is taken, so the behaviour term is a geometric displacement of the codebook, not an additive score. It is repulsive by construction (a code already crowded by the item's successors is pushed geodesically away from that item), it acts only on levels 2 and 3, and the curvature is what makes the displacement non-uniform: the same behavioural arc length buys a much larger separation near the ball boundary, where fine residual codes live, than near the origin. No existing mechanism in this repository displaces a code point; existing code either biases a cost additively or runs an independent hyperbolic loss.
CHANGE: For each item i and each fine-level code k, the code's ball point u_k is translated by Mobius addition along the item's unit behavioural direction n_i by a hyperbolic arc length m_i, and the Sinkhorn cost entry becomes the exact Poincare distance from v_i to that displaced code; the balanced plan itself is the baseline's, only the cost matrix changes.
SPECIFICATION: Per level l in {2,3} (level 1 is deliberately untouched). Let c = 1.0 (fixed negative curvature, K = -1), lambda(x) = 2/(1 - c*||x||^2), Mobius addition x (+) y, and geodesic distance d_P(x,y) = (1/sqrt(c)) * artanh(sqrt(c) * ||(-x) (+) y||). Residual r_i = z_i - sum_{j<l} e_{k_j(i)} (unchanged baseline residual). Bounded ball lift with a frozen per-level scale q_l measured on the training split at epoch 0 (95th percentile of ||r||): v_i = (1/sqrt(c)) * tanh(sqrt(c)*||r_i||/q_l) * r_i/||r_i||, and u_k = same lift of codebook row e_k. Behaviour: for item i let S_i be its directed successor multiset in the training sequences with counts w_is, and let v_s be the ball points of those successors at level l taken from the per-epoch no-grad snapshot. Tangent behaviour vector at the item t_i = sum_s (w_is/W_i) * Log_{v_i}(v_s); unit direction n_i = t_i/||t_i||; raw magnitude M_i = ||t_

i||. Displaced code q_{i,k} = u_k (+) ( tanh(sqrt(c)*m_i/2)/(sqrt(c)) * n_i ), where m_i = min(M_i, 0.5 * min_k d_P(v_i, u_k)). Cost C[i,k] = d_P(v_i, q_{i,k}). Feed C to the baseline's Sinkhorn (same epsilon, same uniform item marginal, same balanced code marginal, same plan extraction) and take the baseline's assignment; no argmin replaces the plan. t_i and n_i are detached per-epoch constants; gradients flow only through v_i and u_k.
COST: Frozen scale 24556 training items, 24 steps per epoch (about 1023 items per step), 3000 epochs. Per step: extra 2 levels * 1023 items * 256 codes = 524k Mobius-add + artanh + norm evaluations at d = 32, about 0.07 GFLOP, under 1% of the encoder forward+backward. Per epoch: one extra forward-only pass over all 24556 items (24 forward batches, no backward) to refresh the successor snapshot, about one third of an epoch's forward cost, so roughly +5% to +7% wall clock per epoch and about the same over the whole run. No extra epochs, no extra seeds, no extra arms.
HYPOTHESIS: If the fine-level prefix collapse of the previous round was caused by fine codes being free to crowd behaviourally similar items together, then a repulsive, curvature-amplified code displacement derived from train-only directed transitions must raise the number of distinct L2 prefixes well above 955, push the item-weighted 3-level collision under the 35% gate, leave level-1 ER near the baseline (about 16.4), and give Stage3 test Recall@10 above 0.065 in the single frozen run. It is worth keeping if the collision rate drops without level-1 ER degrading and recall clears the target; it is refuted if collisions stay above 0.5 or if level-1 ER degrades while recall does not move.
RISKS: Successor directions may be dominated by a few hub items, injecting noise into n_i; the per-epoch detached snapshot lags the encoder and could misdirect the displacement early in training; the repulsion may fight the Sinkhorn balance enough to degrade the level-2 Euclidean reconstruction or level-1 ER; the tanh lift could saturate near the boundary and freeze the fine codebook; the curvature amplification near the boundary could make the cost matrix ill-conditioned for Sinkhorn (needs the artanh clamp and the half-nearest-code cap); the effect may be too weak relative to the encoder gradient to show in one run, in which case the collision metric is the observable that decides.
BEHAVIOR SIGNAL: Directed item transitions in the training split: for each item i, the multiset of items s that occur immediately after i in a training user sequence, with their counts w_is (sequential co-consumption of a directed, successor form). Nothing else; no user ids, no timestamps, no popularity signal.
BEHAVIOR COMPUTATION: One pass over the training split sequences only (the same split the encoder is trained on). For every adjacent pair (i, s) inside a training sequence increment w_is; store S_i as a sparse row of (s, w_is). W_i = sum_s w_is. No pruning threshold and no top-K: all successors are kept with their counts, so no tuned constant enters. Successor ball points v_s are read from the per-epoch snapshot table indexed by item, so the field refreshes once per epoch and is detached.
LEAKAGE BOUNDARY: S_i is built exclusively from adjacency pairs inside training-split sequences, computed once before training and frozen for the whole run; validation and test sequences are never read, never encoded into the snapshot, and never used to set q_l, m_i or the clip. The peer-c

lip uses min_k d_P(v_i, u_k) from the current training step only, so nothing about held-out interaction can influence the SID construction, the codebook, or the assigned identifiers. q_l is a percentile of training residuals at epoch 0, also training-only.
HYPERBOLIC OPERATOR: Fixed negative curvature c = 1.0 (K = -1), with the Poincare ball metric lambda(x) = 2/(1 - c||x||^2); operations: bounded exponential-style lift (1/sqrt(c)) tanh(sqrt(c)||r||/q_l) * r-hat, Mobius addition (+), geodesic distance d_P(x,y) = (1/sqrt(c)) artanh(sqrt(c)||(-x)(+)y||), and tangent logarithm Log_x(y) used to build the behaviour direction. A trainable log-curvature per level (eta_l initialised at 0, c_l = exp(eta_l)) is available in code but left at its documented default, not swept.
HYPERBOLIC LOCATION: In the quantisation step of the RQ-VAE, inside the Sinkhorn cost matrix of levels 2 and 3, before the balanced plan is solved; it changes both which code each fine level assigns (through the plan) and the gradient that reaches the residual encoder and the fine codebooks (through d_P and through the displacement).
COUPLING PATH: single connected pathway: train-only successor statistics -> behaviour tangent vector t_i at the item's ball point -> unit direction n_i and arc length m_i -> Mobius translation of the fine code u_k to q_{i,k} -> exact Poincare distance C[i,k] = d_P(v_i, q_{i,k}) -> baseline Sinkhorn balanced plan -> assignment and codebook/encoder gradients. Removing behaviour sets n_i and m_i identically to zero, q_{i,k} = u_k, and the pathway collapses to plain Poincare distance; removing curvature replaces d_P and Mobius addition by their Euclidean limits and the displacement becomes a flat shift.
COUPLING EQUATION: C[i,k] = d_P^c( v_i , u_k (+) ( tanh(sqrt(c) m_i / 2)/sqrt(c) ) * n_i ), with m_i n_i = clip_{0.5 * min_j d_P(v_i,u_j)}( sum_s (w_is/W_i) Log_{v_i}(v_s) ).
OBSERVABLES: distinct L2 prefix count (from 955 upward, baseline reference 7414), item-weighted 3-level collision rate (from 0.771 toward and below the 0.35 gate), level-1 Hard ER (should stay near the baseline 16.4 instead of moving), per-item entropy of level-2 and level-3 code usage, fraction of fine codes never used, prefix behaviour predictability during Stage 3, and the deciding number: Stage3 test Recall@10 above 0.065.
ABLATION BEHAVIOR OFF: BEHAV=off sets t_i = 0 for every item, so n_i = 0 and m_i = 0, q_{i,k} = u_k, and the fine-level Sinkhorn cost is the pure Poincare distance d_P(v_i, u_k). Everything else, including the balanced plan and the curvature, is unchanged. The switch exists and is unit-checked; this arm is not trained.
ABLATION GEOMETRY OFF: GEOM=euclid sets c -> 0, so the lift becomes a bounded Euclidean radial map, Mobius addition becomes vector addition and d_P becomes ||v_i - q_{i,k}||_2, giving C[i,k] = || (v_i - u_k) - m_i n_i ||_2 with the same behaviour field. The switch exists and is unit-checked; this arm is not trained.
ABLATION BOTH ON: BEHAV=on and GEOM=poincare, i.e. exactly the mechanism above: successor-derived geodesic code displacement with exact Poincare distance inside the baseline balanced plan. This is the only arm that is trained, once, for 3000 Stage 2 epochs on four cards followed by the frozen Stage 3 protocol.
SPEC EQUATIONS: input residual batch r, codebook E (256 rows), level l, successor sparse rows S_i, snapshot table V (item -> ball point), curvature c, scale q_l. l1: v_i = tanh_lift(r_i; q_l, c); u_k = tanh_lift(E_k; q_l, c)

. l2: for each i, t_i = sum_s (w_is/W_i) * Log_{v_i}(V[s]); if BEHAV=off then m_i = 0, n_i = 0 else n_i = t_i/max(||t_i||, 1e-12), d_nn_i = min_k d_P(v_i, u_k), m_i = min(||t_i||, 0.5*d_nn_i). l3: for each (i,k): q_{i,k} = mobius_add(u_k, (tanh(sqrt(c)*m_i/2)/sqrt(c)) * n_i); C[i,k] = d_P(v_i, q_{i,k}) (Euclidean branch if GEOM=euclid). l4: P = baseline_sinkhorn(C, epsilon, uniform_item_marginal, balanced_code_marginal); assignment = baseline_plan_to_index(P). l5: loss = baseline RQ-VAE loss on the assigned codes; gradients flow through v_i and u_k only (t_i detached). Helper: artanh_arg = min(sqrt(c)*||(-x)(+)y||, 1 - 1e-5).
SPEC INPUTS OUTPUTS: takes the current batch of fine-level residuals r_i (B x d), the level-l codebook rows E_k (256 x d), the frozen training successor rows S_i with counts, the per-epoch detached successor ball-point snapshot V, the curvature c and the frozen scale q_l; returns the B x 256 cost matrix C (Poincare distance to the behaviour-displaced codes), the balanced Sinkhorn plan P from the baseline rule, and the resulting level-l code indices for the batch, plus the quantities C is built from so the three switches can be toggled.
SAFEGUARDS: artanh argument clamped to 1 - 1e-5; tanh lift bounds every ball point to radius < 1/sqrt(c) so lambda never diverges; m_i capped at half the distance to the nearest code (scale-relative, no tuned constant, measured per step on training items); the behaviour vector is detached so no cross-item second-order graph and no gradient explosion through successors; zero-norm guards on ||t_i||, ||r_i||, ||(-x)(+)y||; cold items with no successors get m_i = 0 (fall back to pure Poincare cost); level 1 is excluded so the coarse partition and level-1 ER are not disturbed; the percentile scale q_l is frozen at epoch 0 so the ball geometry cannot drift with training; the Sinkhorn epsilon, the marginals and the plan extraction are the baseline's untouched code path, so the mechanism can only change the cost matrix, never replace the balanced assignment with an argmin; runtime assertions check that every level still uses the plan and that code-usage entropy stays within the baseline's tolerance.
END IDEA
