## 是否需要训练(§4 判定)

**需要。** 依据:

- §5 判据:"主指标为最终导出的真实三层 SID……三种 Δ 和满足率均超过同协议原始基线,fork Δ>0,
  三种 Δ 均优于真正打乱对照" —— 这些 Δ 由导出的硬 SID 计算,只能由一次 3000-epoch 训练产生。
- §4:"正式实验至少包括:原始 RQ-VAE(256×3) / 新硬 SID Loss / 同机制同预算的真正角色打乱对照"。
- §1:"仅 Stage2,固定 seed 42,正式训练 3000 epochs;不启动 Stage3,不做多种子实验"。

结论:Stage2 训练**必须**;Stage3 **不跑**。

## 与 #230 的关系(必须先记清,否则会重犯)

#231 正文点名 #230 的四个问题,本 issue 的每次实现都要显式避开:

| #230 的做法 | #231 的要求 |
|---|---|
| 用 `autograd.grad` 取梯度后加到**距离矩阵** | `L_total = L_RQVAE + λL_graphlet`,结构项**必须真正参与 optimizer 的 backward** |
| 打乱对照 = 整实例置换(三对集合不变) | 在**训练三元组内部改变中心/中间角色**,使 near/far 实际改变,并断言标签集合确有差异 |
| 基线用 1024 码本 | 公平基线是 **256×3**;1024 仅作历史参考 |
| 训练期调分配、导出用 argmin,差异未记录 | "普通训练与推理/导出的分配机制保持一致",差异须明确记录 |
