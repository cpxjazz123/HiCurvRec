### 崩塌定位:在 L2

| 层级 | 本臂 | TIGER | 比值 |
|---|---:|---:|---:|
| L1 distinct | 256 | 249 | 1.028 |
| **L2 distinguished** | **3,091** | **7,374** | **0.419** |
| L2 最大桶 | **4,862** | 85 | **57.2** |
| L2 条件熵 bits | **3.524** | **4.979** | **0.708** |
| L3 distinct | 7,859 | 20,425 | 0.385 |
| L3 条件熵 bits | 2.923 | 2.203 | 1.326 |

**关键观察**:
- L1 熵反而**略高**(8.000 vs 7.960)——一级码全用上了,但**分布极度不均**(最大桶 10,700)
- **L2 把 4,862 个商品塞进同一个(一级+二级)前缀**,而 TIGER 最大桶只有 85
- L3 的条件熵**高于**基线(2.923 vs 2.203),说明 L3 本身还在努力区分,是 L2 先塌掉

**结论**:崩塌不是"码本用完了",而是 **L2 的桶被 L1 的粗分组挤爆**。L1 把大量商品推到一起后,
L2 的 256 个码无法再区分这 4,862 个商品,只能继续堆叠。
