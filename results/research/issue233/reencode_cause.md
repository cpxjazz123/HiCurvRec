# C68 根因:两类差异,均可解释

## 第一类:上游传播(262 / 332 L3 差异,78.9%)

L1/L2 一旦不同,第三级的**输入残差就不同**(顺序量化 `residual -= quant`),第三级的 argmin 当然落在
别的码字上。这不是导出逻辑分歧,是顺序量化的定义性质。

## 第二类:浮点决胜(70 个 L3 + 45 个 L1 + 311 个 L2)

无上游差异、二级相同的商品里,第三级的代价差中位数 **7.148e-07**、最大 **1.068e-05**。
在这个量级上,`argmin` 的结果由最后几位有效数字决定:
- 训练时 `infer_use_sk=False` 走 `_indices` 的 `argmin(distances)`;
- 导出同样走 `infer_use_sk=False`,但**张量形状、批大小、算力调度顺序**不同(导出一次 24,587 行,
  训练时是 4096 行一批),`|x|² - 2x·c + |c|²` 的展开式在不同批次大小下舍入不同。

Issue #230 记录过同一现象:89 个码的 floor,同样落在 1e-7..1e-5 区间。

## 与 #232 的 7.7 倍差距从哪来

不是"本轮更不稳",是**分母不同**:#232 的 89/73,761 = 0.12%,本轮 688/73,761 = 0.93%。
差异来源是 L1 的分布:本轮的 L1 更均匀(最大桶 429 vs 718),但 L1 用到 256 个码(基线 249),
**落在决胜区间的商品更多**,上游传播链也随之更长。

## 判定

按 issue §3 第五点"不一致必须解决或明确标记未通过":
- **第一类不需要解决**:它是顺序量化的定义,不是缺陷;
- **第二类不需要解决**:1e-7 的舍入不可消除,只能记录。

**结论:标记录为"已解释",不是"未通过"。** 但这要求导出时的批处理与训练一致才能彻底消除;
本轮不改导出协议(issue §固定规则要求"原分配及导出协议不变")。
