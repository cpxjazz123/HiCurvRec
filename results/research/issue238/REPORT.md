## 4. 结论:两条路径都失败,但失败方式不同

### 4.1 G1:checkpoint 不可复现地坍缩

训练器内存里导出的是 **24,498 个互不相同的三码**(collision 0.0036);
而 `stage3_start` 按 CLAUDE.md §67 的 export_gate 从 checkpoint 重导,得到
**849 个三码、最大桶 13,810 个商品**、collision **0.9655**。

`export_manifest.json` 记着 `original_differing_items: 24587` —— **全部商品都变了**。

即:**#237 的纯结构表示可以让 RQ-VAE 在训练时看起来完美区分(0.0036),但保存下来的
checkpoint 前向会把 56% 的商品塞进同一个码字。** 这不是抽样噪声,是分配在该表示下
不可复现。基线在同样协议下只差 122–291 项(0.3–1.2%)。

### 4.2 G2:同样大幅漂移,但侥幸低于门槛

训练器 0.0092 → checkpoint 0.1738(24,575/24,587 项不同),刚好低于 0.4 硬门槛,
因此 G2 得以进入 Stage3。**它与基线 0.1693 已经几乎同一量级**,说明 G2 的 SID 在
重导之后回到了基线那种「大量共享码字」的形态。

### 4.3 机制层面的教训

1. **「训练时 collision 低」不能作为 SID 质量的证据**:两个臂的训练器值(0.0036/0.0092)
   与 checkpoint 值(0.9655/0.1738)相差两个数量级。CLAUDE.md §67 的 export_gate 正是
   为此存在,这次它拦下了 G1。
2. **#237 的表示不适合直接作为 RQ-VAE 输入**:它的 latent 分布让码字分配对
   checkpoint/内存差异极度敏感。若要接入,需要先解决量化稳定性(例如在 Stage2 目标里
   加码本利用率约束,或改用 #237 的切空间输出做 PCA 后再量化)。
3. 这条结论**不是**「混合曲率无效」:G1/G2 只是把 #237 的表示喂给标准 RQ-VAE,
   没有改动几何或分配规则。

## 8. 第三条机制:测地代价进 Sinkhorn(H,`TIGER_kappa_cost_rq`)

### 为什么是这里

§19h 规定机制创新必须进 Sinkhorn 的代价矩阵,分配规则仍是基线的均衡分配;`distances/__init__.py`
自己的约定是「换度量 = 换实验,选择写在源码里」。所以 H 的改动只有三处:

| 文件 | 改动 |
|---|---|
| `distances/curved.py` | 新增:κ=−1 球面平方测地距离 |
| `distances/__init__.py` | 注册 `"curved"` |
| `train_rqvae.py` | `build_distance(CONFIG, name="curved")` |

输入嵌入、损失、训练超参全部未动,所以量化稳定性应当接近 TIGER 基线(与 G1 的 0.9655 崩塌对比)。

### 定义

```
u = 0.9 · tanh(r/τ) · x/r ,  r=|x| ,  τ = mean‖c‖(当前 step)
d(u,v)² = ( arcosh(1 + 2‖u−v‖² / ((1−‖u‖²)(1−‖v‖²))) )²        (κ = −1)
```

- κ 取 #236 实测 −1.0188 的整数点 −1,**不是搜索变量**(§19g 不做调参)。
- τ 取当前码本平均范数,使映射尺度等变,**没有自由超参**。
- 半径上界 0.9 是数值条件数要求,不是拟合参数:不加时 `(1−‖u‖²)` 极小,展开式
  `‖u−v‖²` 的浮点误差被放大,自距离实测 **14 而非 0**。这是本轮真实踩到的坑,已写进模块注释。

### 数学验证(`results/research/issue238/tests/test_curved_cost.py`,7/7 通过)

| 性质 | 结果 |
|---|---|
| 映射后半径 < 1 | 通过(50× 放大输入仍封在球内) |
| 自距离 = 0 | 通过(≤1e-5) |
| 非负、有限、形状 (B,K) | 通过 |
| 沿穿过码字的射线单峰(近侧单调降、远侧单调升) | 通过 |
| 两个点集间对称 | 通过 |
| 与欧氏代价不同(机制未退化为基线) | 通过 |
| 梯度流向 latent 与 codebook | 通过 |

**为什么可能有收益**:负曲率球上靠近边界的点距离增长更快,把紧簇拆到不同码字的代价高于欧氏;
Sinkhorn 仍保证均衡(§19h 的分配规则不变)。

## 9. 第四条机制:分层混合曲率(`TIGER_kappa_sk_only_rq`)

### 定义

与 H 是同一份测地代价,**只给 Sinkhorn 层**(最后一层,`sk_epsilon>=0`);下两层保持欧氏 argmin。

| 臂 | L1 分配 | L2 分配 | L3 分配(Sinkhorn 均衡) |
|---|---|---|---|
| TIGER 基线 | 欧氏 | 欧氏 | 欧氏 |
| H 一致曲率 | 测地 | 测地 | **测地** |
| J 混合曲率 | 欧氏 | 欧氏 | **测地** |

三臂只在「哪一层用什么度量」上不同,输入、损失、超参完全相同,所以 H vs J vs 基线构成
「统一曲率 / 混合曲率 / 无曲率」的直接对照。

### 为什么必须让 Sinkhorn 层而非低层用测地

§19h:创新必须进入**均衡分配**的代价矩阵。实测本栈 `sk_epsilon` 逐层为 `[-1, -1, 0.003]`,
即只有最后一层跑 Sinkhorn;若把曲率放在低层,那些层仍是 argmin,机制就落空了。
`test_per_level_metric.py` 把这一条写成机器断言。

### 实现与验证

改动只在 `model/layers.py` 的层构造循环(3 处 `distance=level_metric`)与 `ARM_NAME`;
`_indices`/`_distances` 的调用点逐字未变,所以 anti-collapse floor 的锚点仍全部命中
(实测 `changed=True`、6 处未保护赋值全部保护)。

| 断言 | 结果 |
|---|---|
| 入口选中的是 curved | 通过 |
| `sk_epsilon>=0` 的层恰好是最后一层 | 通过 |
| 最后一层 distance 是 curved 对象 | 通过 |
| 下两层 distance 是 euclidean 对象 | 通过 |
| 下两层数值等于基线欧氏代价 | 通过 |
| 最后一层数值不等于欧氏代价 | 通过 |

## 11. 量化诊断:低有效秩是必要条件,不是充分条件

`tools/research/stage2/sid_quality.py` 对三个臂的 checkpoint + 嵌入复算(§89 口径):

| 臂 | 三码碰撞率 | 量化误差(带 0.035–0.100) | 有效秩(限 8.0) |
|---|---:|---:|---:|
| TIGER 基线 | 0.1693 | **0.251 越界** | **11.48 越界** |
| G1 纯结构 | **0.9655** | 0.118 越界 | 7.41 |
| G2 语义保留 | 0.1738 | **0.075 带内** | **6.74 合格** |

### 读法

1. **G1 的失败不是「编码抖动」,而是「码本被撑爆之前先被压平」**。它的有效秩 7.41 比基线(11.48)
   低得多,量化误差也更小(0.118 vs 0.251)——按旧口径它「更好」。但碰撞率 0.9655:纯结构目标把
   24,587 个商品压进一个低秩、低方差的子空间,三级 8-bit 码本在这个子空间里无法再区分它们,
   绝大多数商品落到同一批三元组上。**低秩只保证「码本能覆盖」,不保证「码本能区分」。**
2. **G2 是三者中 SID 结构质量最好的**:量化误差 0.075 落在设计带内、有效秩 6.74 合格,而碰撞率
   0.1738 与基线 0.1693 基本持平——即粒度可比,可以直接进 Stage3 对照。
3. **基线自身两项诊断都越界**(0.251 / 11.48),说明 #237 的语义保留残差不只是「没变差」,它在保持
   碰撞率的同时把「挤压」和「未组织」两个毛病都修掉了。这是本轮不依赖 Stage3 就能定的结论。

### 对「结构信号接进 RQ-VAE」的意义

结构信号有两种接法,本轮的四个臂把它们都测了:

| 接法 | 代表臂 | 结果 |
|---|---|---|
| 换输入(纯结构) | G1 | 码本失去区分力,碰撞率 0.9655,被闸门拒绝 |
| 换输入(结构作残差,语义主导) | G2 | 诊断全合格,碰撞率与基线持平,Stage3 待定 |
| 换分配代价(曲率) | H / J | Stage2 待跑 |

**结论**:「结构信息直接当输入」这条路需要先解决码本区分力;「结构作残差不替换」是目前唯一
通过全部诊断的接法;而「曲率进分配代价」是本轮尚未取数的第三条独立路径。

## 12. 码本使用:纯结构输入退化成「一个码字」

同一批 24,587 个商品,只读 `item_sids.json` 复算各级码字的使用分布:

| 臂 | L1 使用码字 | L1 熵 / 上限 8 bit | 最大 L1 桶占比 | L2 熵 | 三码组合数 | 碰撞率 |
|---|---:|---:|---:|---:|---:|---:|
| TIGER 基线 | 249 / 256 | 6.959 | 2.92% | 11.938 | 20,425 | 0.1693 |
| G2 语义保留 | 256 / 256 | 6.898 | 3.21% | **12.132** | 20,314 | 0.1738 |
| G1 纯结构 | 256 / 256 | **0.232** | **98.34%** | 1.571 | **849** | 0.9655 |

### 这解释了 §11 里「有效秩合格却崩塌」的矛盾

G1 的**一级**几乎完全退化:**98.34% 的商品落在同一个一级码字**上,L1 熵只有 0.232 bit(上限 8)。
它的有效秩 7.41 量的是编码器输出张量,测不到「这些向量全被分到同一个桶里」;只有碰撞率能测到。
这就是 §89 最终只保留碰撞率作硬门槛、把量化误差与有效秩降为诊断值的实证依据——本轮给出了一个
反例型证据,不是理论论证。

### G2 与基线在码本使用上等价

256 个一级码字全部用上,熵 6.898 vs 6.959,最大桶 3.21% vs 2.92%,二级熵反而略高(12.132 vs 11.938)。
即 G2 在**保持 SID 粒度不变**的前提下修好了量化误差与有效秩(§11),这让它的 Stage3 数字与基线可比:
差异只能来自「结构残差是否带来了更好的语义分组」,而不是「SID 变粗或变细」。

### 对机制设计的推论

纯结构目标的问题不是噪声,而是**表示里几乎没有跨商品的可区分方差**:#237 的 32 维 graphlet 统计
在逐商品归一化后,主要变异方向被编码器压成了一个全局尺度,三级码本只能切出 849 个桶。
要让它可用,必须先做两件事之一:去掉逐商品归一化造成的尺度主导,或在量化前做白化/PCA 提升方向多样性。

## 13. 更正 §12:问题不在结构嵌入,在量化训练本身

§12 推测「逐商品归一化造成尺度主导,量化前应白化/PCA」。直接测量推翻了这条推测。

### 13.1 主成分结构(`issue237/enhanced_768.npy`,24,587×768)

| 嵌入 | PC1 | PC2 | PC3 | 前 10 主成分 | 行范数变异系数 |
|---|---:|---:|---:|---:|---:|
| #237 结构 | **0.520** | 0.184 | 0.147 | **0.997** | 0.53 |
| #237 结构(行归一化) | 0.381 | 0.240 | 0.173 | 0.995 | 0.11 |
| stage1 T5 | 0.149 | 0.070 | 0.035 | 0.388 | 0.64 |

结构嵌入确实强各向异性(前 10 个方向占 99.7%),但行归一化后仍有 99.5%,说明各向异性来自
表示本身而非尺度。

### 13.2 它能否被 256 个码字区分?能

对同一份嵌入做 PCA-32(解释 99.97% 方差)后跑 256 中心 k-means:

| 输入 | 用到的码字 | L1 熵 / 上限 8 bit | 最大桶占比 |
|---|---:|---:|---:|
| PCA-32 原始 | 256 / 256 | **7.869** | 0.93% |
| PCA-32 白化 | 256 / 256 | 7.759 | 1.16% |

**白化没有帮助**(7.76 < 7.87),而普通 k-means 就能把 L1 熵做到 7.87 bit——与训练后的
**0.232 bit** 相差 34 倍。

### 13.3 结论

- **结构嵌入本身具备充足的跨商品区分力**,§12 的「数据缺乏方差」判断**错误,予以更正**。
- 崩溃发生在**量化训练**里:同一份输入,无监督 k-means 得到 7.87 bit,训练后的编码器只给 0.232 bit。
  即 RQ-VAE 的训练把输入的方向多样性压成了「一个全局码字 + 残余」。
- 因此正确的下一轮方向不是「预处理嵌入」,而是**量化目标本身**:纯结构输入下,重构目标几乎可以靠
  一个码字加残差满足,编码器没有任何压力去使用其余 255 个一级码字。
- 这也解释了为什么 G2(语义保留残差)不崩:它的残差目标带着 T5 语义,重构误差无法靠单一码字消除。

### 13.4 不可省略的教训

`results/research/issue238/whiten_probe.py` 是可复跑的证据(参数写在文件常量里)。
本节的更正保留了 §12 的错误判断,因为「先提出尺度主导假设、再用 k-means 证伪」这个过程本身
比结论更有用:**在没有测过码本区分力之前,不要用有效秩推断结构信号可用性。**

## 18. H 的结果:曲率代价让码本崩塌,但不是因为饱和

### 18.1 结果

| 项 | 值 |
|---|---|
| 训练 | 3000 epoch 完成,单卡,全局 batch 4096,`0.19 s/epoch` |
| 最终三码碰撞率 | **0.825111**(4,300 个三码 / 24,587) |
| 轨迹 | 1750: 0.8068 → 1900: 0.8327 → 2950: 0.8249 → 3000: **0.8251** |
| 闸门判定 | `allow=false`,`three-level collision 0.825111 is not below 0.40` |

与基线 0.1693 相比,曲率代价把码本的区分力打掉了近 5 倍,与 G1 的纯结构输入(0.9655)
同属「码本失效」一类,但程度轻一些。

### 18.2 假设与证伪

**假设**:κ=−1 的径向映射 `0.9·tanh(r/τ)` 在 `r≫τ` 时饱和,所有点被压到球面同一处。

**测量**(`saturation_probe.py`,读 checkpoint + 全部 24,587 个嵌入):

| 量 | 值 |
|---|---|
| τ(一级码本平均范数) | 0.6454 |
| latent 半径 均值 / p05 / p95 | 0.180 / 0.113 / 0.371 |
| `r/τ` 均值 / p95 | 0.28 / 0.58 |
| `tanh(r/τ)` 均值 / p95 | 0.236 / 0.467 |
| 映射占用球半径 `(p95−p05)/0.9` | **0.3464** |

`tanh` 在 x≈0.28 处仍接近线性,**映射只用到球半径的 35%**,没有饱和。

**结论:饱和假设被证伪。**

### 18.3 剩下什么解释(未验证,不得当作结论)

崩塌的具体机制还没定。可测的候选:

1. **度量对半径的依赖**。`d² ∝ arcosh(1 + 2‖u−v‖²/((1−‖u‖²)(1−‖v‖²)))`,分母随半径变化,
   使「同样方向差、不同半径」的两点距离被放大,基线里本来靠欧氏距离区分的东西被重排。
2. **梯度几何**。`arcosh` 及其平方对 `‖u−v‖²` 的导数在近处很大,等价于给量化目标加了一个
   与基线不同的权重剖面;§19g 禁止为同一候选重训,所以这条只能留给下一个候选去测。

### 18.4 这一条的净结论

- 在本构造下(κ=−1、τ=码本平均范数、半径上界 0.9),**把测地距离直接当分配代价会毁掉码本**。
- 但**不能**把它归因于径向饱和 —— 实测只用了 35% 的球半径。
- 也不能据此说「曲率不适合」:J(只在 Sinkhorn 层用曲率)是另一个候选,它的结果决定
  「是不是所有层都该用同一个度量」这个问题。

### 18.5 第二个框架缺口

H 训练结束后 `export_manifest.json` **没有生成**(worker 已退出),即 §67 的 checkpoint 重导闸门
这一次没跑。§89 的 `stage3_start` 仍然用 `sid_quality` 从表 + checkpoint 复算并正确拒绝,
所以 H 的判定不受影响;但「训练结束 → 自动重导」这条链在本次运行里没有发生,记为待查缺口。

## 25. 更正:按 §19h,H 与 J **超出机制范围**

### 25.1 规则原文(§19h,摘要)

> 新机制必须是**训练只行为信号**与**显式曲线运算**在同一条连通计算通路上的耦合……**仅把欧氏距离换成
> 双曲距离**……判 OUT_OF_SCOPE。

### 25.2 我的判定

| 臂 | 有曲线运算 | 有行为信号 | 是否在范围内 |
|---|---|---|---|
| H(三层测地) | 是 | **否** | **OUT_OF_SCOPE** |
| J(仅 Sinkhorn 层测地) | 是 | **否** | **OUT_OF_SCOPE** |
| G1/G2(#237 结构嵌入) | 否 | 是(结构统计) | 单侧,同样不构成 §19h 的耦合 |

**所以本轮四个臂没有一个满足 §19h 的双侧耦合要求。** 这不是数据问题,是提案形态问题。

### 25.3 这改变了什么、不改变什么

**不改变**已记录的事实:四个臂的 Stage2 与 Stage3 数字都是实测,§89 闸门的两次拒绝是正确行为,
「几何必须分层施加」这个结构性发现(0.8251 vs 0.1530)是真实的因果对照,
「SID 质量不预测 recall」的 31 臂分析也不依赖任何机制是否在范围内。

**改变**的是它们能主张什么:

- H/J **不能**作为「曲率机制」的提案或消融;
- 它们应被读作**范围内机制的前置可行性测量**:在这个量化器里,几何能不能被单独注入而不毁码本、能不能
  换来排序收益。答案是「能注入(分层时)、换不来收益」;
- 若将来要提一个 §19h 合规的曲率机制,这两条测量是有用的负结果,但不是它的证据链。

### 25.4 合规的下一个机制长什么样(设计,未实现)

必须在同一条通路上同时含行为信号与曲线运算,且信号只能来自训练划分可见的交互(§16)。
我评估后**没有**在本轮实现它的原因写在下面,不省略:

```
机制草案:行为-曲率耦合的分配代价
  信号:  AF3 曲率 κ_ij = 4 − d_i − d_j + 3·T_ij,只在 train 交互上计算(§89b 规范图)
  运算:  d̃(i, c) = d_κ(i, c) + λ · mean_{k ∈ N(i)} d_κ(k, c)
  耦合:  行为图邻居通过同一个曲率度量进入 Sinkhorn 的代价矩阵(§19h 指定的位置)
  λ:     取 1(等权),可推导,不调参(§19g)
```

**阻塞点**:`distances(latent, codebook)` 只收到 latent 张量,**拿不到 item id**,因此拿不到邻居索引。
要让行为信号进入代价矩阵,必须把 batch 的 item id 穿进 `RQVAE.forward` → `RQLayer.forward` →
`_distances`,而这会改动 anti-collapse floor 依赖的锚点(`_indices(self._distances(latent), ...)`)。
正确做法是先在 `patch_tree.py` 增加一个「带 id 的 `_distances`」锚点与回归测试,再改候选树 ——
否则会重现本轮修过的第一个缺陷(floor 找不到锚点,任何臂都无法启动)。

这不是「做不到」,是「不在本轮做」:它需要先改框架,再改候选,再跑 40 分钟训练 + 35 分钟 Stage3,
而且 §19g 只允许每个候选跑一次,没有试错空间。

## 26. §19h 合规臂:`TIGER_af3_graphgeo_rq`

### 26.1 机制(双侧耦合)

```
w_i    = 归一化秩( mean_{j∈N(i)} |AF3_ij| )       行为信号,只读规范图的 train 交互(§89b)
cost_i = (1−w_i)·‖z_i − c‖² + w_i·d²_{κ=−1}(z_i, c)   曲线运算,在 Sinkhorn 代价矩阵内(§19h)
```

每个商品的几何由一个**混合权重**决定,权重来自它自己在行为图里邻域的 AF3 曲率:
链条型邻域(高 |AF3|)推向双曲球,紧密三角邻域(低 |AF3|)保持欧氏。
把信号置为常数、或把曲线侧置为 0,都会改变分配 —— 满足 §19h 的「去掉任一侧即改变」。

**如何把 item id 送进度量**:`distances(latent, codebook)` 只收到张量。做法是数据集产出
`(行, item_id)`,`RQVAE.forward`/`get_indices` 与残差栈转发 `item_ids`,
`RQLayer.forward` 在调用前把 id 安装到度量模块上。**`_distances`/`_indices` 的调用点逐字未变**,
实测 floor 仍然 `changed=True`、6 处锚点全部命中。

**权重表不入库**(`stage2_RQ-VAE/**/*.npy` 被 gitignore,§46):入口发现缺表时从
`behavior_graph/{edges.parquet,graph.npz}` **重建**,实测重建结果与手工计算的表逐位一致。

## 28. 为什么所有机制都只动 ±0.001:命中集中在 20% 的商品上

本轮五个臂的 recall 全在基线的 ±0.003 内。这不是巧合,是**指标结构**决定的。

用 AF3 臂的逐商品预测(57,439 行,它是本轮唯一留下 per-item 输出的 Stage3)对照规范行为图的
节点度数(`role_recall.py`,零 GPU 复跑):

| 度分位 | 商品数 | 平均度 | 命中数 | 占总命中 | hit@10 |
|---|---:|---:|---:|---:|---:|
| q1 | 11,233 | 6.9 | 5 | 0.2% | 0.00045 |
| q2 | 11,669 | 18.6 | 46 | 1.5% | 0.00394 |
| q3 | 11,393 | 42.7 | 98 | 3.1% | 0.00860 |
| q4 | 11,653 | 109.2 | 553 | 17.6% | 0.04746 |
| **q5** | **11,491** | **527.9** | **2,433** | **77.6%** | **0.21173** |

**最高的 20% 商品贡献了 77.6% 的全部命中;最低的 60% 合计只有 4.8%。**
按聚类系数分组则呈倒 U:峰值在第二分位(0.105),最高分位跌到 0.010。

### 28.1 这解释了什么

1. **为什么五个臂都只动 ±0.001。** `test_R@10` 的分母是全部 57,439 个样本,但命中几乎全部来自
   11,491 个高度数商品。任何**均匀施加**的机制(SID 几何、分配代价、逐商品曲率)最多只能改变
   那 20% 里的一小部分,其余 80% 的样本无论 SID 怎么变都命中不了(它们的 hit@10 已经是 0.0004–0.0086,
   接近地板)。要在 0.0555 上做出 0.005 的提升,等于要在 q5 里多命中约 290 个商品 —— 而 q5 已经命中 2,433 个。
2. **为什么「按 graphlet 类型分配几何」在这个指标上很难有作为。** 商品的**难度**由度数主导,
   而不是由它属于哪种 graphlet 主导。聚类系数的倒 U 说明「三角形多」既不是更难也不是更易,
   而是一个与度数纠缠的中间变量。
3. **为什么 §23 的跨臂相关性是 +0.239 而不是负数。** 若机制的效应全部落在 80% 的近零样本上,
   它对总 recall 的贡献就是噪声,剩下能形成相关性的只是「哪些臂恰好改善了 q5」。

### 28.2 下一轮该测什么(基于这条证据,而不是猜测)

如果目标是 `test_R@10`,那么**必须直接针对高度数商品**做机制,例如:
按商品度数分层加权的对比/采样,或对 q5 单独评估一个分层指标,让机制的效果不被 80% 的地板稀释。
继续在「SID 是否更干净」「量化器里用什么几何」上加机制,按本轮证据不会移动这个数字。

### 28.3 局限

- 逐商品命中只在 AF3 臂上有(基线那次 Stage3 只写 `per_user` 聚合),所以这里的对照是**臂内**的
  难度结构,不是「机制 vs 基线」的分层差异。要做后者需要给基线补一次带 per-item 输出的 Stage3。
- 度数来自 `results/research/behavior_graph/`,与 Stage3 的测试划分不独立(度数用训练交互算,
  这与 §16 一致),因此这里的「高度数商品更容易命中」是流行度偏置的直接体现,不是泄漏。

### 29.3 对 §10 判定规则的更正

以 1e-4 为噪声底,§10 的 ±0.005 带**过宽**,它把「4 倍噪声」和「9 倍噪声」的负向变化都当成「无净收益」。
按新标定,更准确的说法是:

- G2 −2.66e-3 = 26× 噪声 → **明确变差**;
- AF3 −8.7e-4 = 9× 噪声 → **小幅变差**;
- J −4.0e-4 = 4× 噪声 → **小幅变差**。

**没有任何一个臂是「中性」的:三个都是负向**,只是幅度小。§10 的预注册表本身没有错(它按当时的认知设带),
错在我把「落在带内」读成「没有影响」;按定标后的噪声底,它们是小而真实的退化。

**SID 确实能移动 0.015** —— 比本轮所有机制强一个数量级以上。而两个碰撞率几乎相同的表
(0.2653 / 0.2745)对应了 0.0555 / 0.0402 这样天差地别的结果。

所以:**「SID 怎么分配」极其重要,但碰撞率、量化误差、有效秩、几何度量、结构信号这五个量都没有抓住它。**
本轮五臂之所以全负,不是因为 SID 无关紧要,而是因为我改的都不是那个真正起作用的东西。

这是下一轮唯一值得投的方向:找出 0.0402 与 0.0554 那两个表**在结构上到底差在哪**
(目前只知道它们不是同一张表),而不是继续在已知不相关的五个量上做机制。

## 30. 更正 §29:那个 0.015 的缺口**不能**归因于 SID 变更

§29 写「SID 变更曾让这个臂移动 0.015」。继续核查后这条**站不住**,在此撤回。

### 30.1 核查发现

`53273cb6…`(§29 记为「旧表」的那张)与以下臂的表**逐字节相同**:

```
results/stage2_RQ-VAE/TIGER_RQ-VAE__canonical/item_sids.json
results/stage2_RQ-VAE/TIGER_BEHAVIOR_SAMPLE_RQ-VAE/{resample_l2only,resample_l3only,bw0}/item_sids.json
```

而 `TIGER_RQ-VAE__canonical`(2026-11-14)的 Stage3 结果是 **0.054719** —— 用**同一张表**。

同时 `TIGER_RQ-VAE` 目录下的三次 Stage3 是 0.040199 / 0.055450 / 0.055537。

### 30.2 为什么无法归因

**Stage3 日志不记录它所读的 SID 表的哈希**(`_stage3_run.log` 只写路径 `item_sids.json`)。因此:

- 无法证明 2026-11-01 那次(0.0402)用的是哪张表;
- 也无法证明 2026-10-26 与 2026-11-12 那两次(相差 8.7e-5)用的是同一张表。

**能确定的只有一件事**:历史上这个臂出现过 0.0402 这个离群值,而同一张表在另一个臂上给出 0.0547 ——
所以 0.015 的缺口**至少部分**来自 Stage3 的运行层面(代码版本、数据顺序、并行归约),而不是 SID。

### 30.3 修正后的标定

| 量 | 值 | 可靠度 |
|---|---:|---|
| 两次 0.0555 运行之间的差 | 8.7e-5 | 高(同臂、邻近期) |
| 0.0402 与 0.0554 之间的差 | 1.5e-2 | **原因未定**(SID 或 Stage3 运行层面) |
| 本轮的机制效应(G2/AF3/J) | 2.7e-3 / 8.7e-4 / 4.0e-4 | 高(同协议、同代码) |

因此 §29.3 的结论(「三个臂都是小而真实的负向」)仍然成立 —— 它只依赖「同一协议下噪声约 1e-4」这一条,
而不依赖 0.015 的归因。撤回的只是 §29.4 中「SID 能移动 0.015、比我的机制强 10 倍」这句话。

### 30.4 这条更正本身给出的工程建议

**Stage3 必须在运行产物里记录它实际读取的 `item_sids.json` 的 sha256。** 一次写入、三个字段,
就能让「这张表给出多少 recall」成为可复算的关联(§64b 已经要求按 `sid_sha256` 关联,但 Stage3 侧没有落盘)。
在这一点补上之前,库里所有「同一臂多次运行」的对比都只能当区间看,不能当配对看。

## 31. 第六臂:按度数分配温度(`TIGER_degree_temp_rq`)

### 31.1 为什么做这一臂

§28 的分析显示命中集中在最高的 20% 度数商品上。在 §19h 的规则空间内,唯一还能作用于**分配锐度**的
手段是**逐商品温度**:

- Sinkhorn 先做**全局**仿射(`center_distance`:减全局中点、除全局幅度),再逐行归一化;
- 逐行**加性**偏移会被行归一化抵消(等于没做);
- 逐行**缩放**不会:exp(−d/τ) 的行形状随 τ 变,argmax 会受影响。

`test_degree_temperature.py` 把这两半都钉住:同一个 latent 的代价随 τ 精确成反比(tau=0.5 → 代价 ×2),
而该行的 argmin **不变**(正缩放不改变行内排序)——也就是说温度只在 Sinkhorn 那一层起作用。

```
τ_i = 1 / (1 + 秩归一化度数_i)        无自由参数
cost_i = [(1−w_i)·欧氏 + w_i·测地]/τ_i   w_i = AF3 曲率权重(§26)
```

### 31.2 Stage2 结果

| 项 | 值 |
|---|---|
| 训练 | 3000 epoch,smoke `SMOKE_PASS` |
| 训练器碰撞率 | **0.199252**(19,688 / 24,587) |
| 闸门复算(重导后) | collision **0.172734**,quant_error **0.0578**(带内),effective_rank 16.01(告警) |
| 训练时 vs checkpoint 重导差异 | **12,150 项(49.4%)** |

重导漂移 12,150 项是本轮最大 —— 温度让分配对「用哪个前向算」更敏感。

### 31.3 一个必须记录的副产物:三码表的「容量不变量」

`AF3` 与 `degree_temp` 两个臂的三码表**逐行完全不同**(24,587 个三元组全不同,文件哈希不同),
但闸门给出的 collision **逐位相同**(0.1727335583845121),不同三元组数**都恰好是 20,340**。

解释:L1/L2 在这两个臂里都是欧氏 argmin,因此**前缀结构相同**;L3 的 Sinkhorn 列容量也相同。
于是「有多少个不同三元组」由前缀与容量决定,与 L3 用什么度量无关 —— L3 的改动只改变**哪些商品共享**
同一个三元组,不改变**有多少个**三元组。

| 臂 | 不同三元组 | collision | 最大桶 |
|---|---:|---:|---:|
| TIGER 基线 | 20,425 | 0.169276 | 24 |
| J(仅 L3 曲率) | 20,826 | 0.152967 | 21 |
| AF3 | 20,340 | 0.172734 | 35 |
| degree_temp | 20,340 | 0.172734 | **47** |

**含义**:在最末层做文章时,碰撞率这个指标几乎不动(它是容量的函数),而**共享结构**在变
(最大桶 35 → 47)。这进一步说明 §23 的「碰撞率不预测 recall」:它是容量的度量,不是分配的度量。

4. 机制越依赖逐商品行为信号,分配越不是模型的不动点(重导漂移 2,788 → 11,761 → 12,150 → 24,587)。

1. 结构嵌入尺度主导、应白化(§13);
2. H 的崩塌源于 tanh 饱和(§18);
3. 针对高度数商品做温度能提升 recall(§32)。

**范围内未被测到的**:
按 graphlet **类型**(三角形/星形/链)分别给不同曲率。按 §32.2 的证据,它的预期收益同样是负的,
因为改变的是**共享结构**而不是**可用容量**。

## 33. 库里两个「优于基线」的臂没有共同的结构签名

本轮之后,库里 recall 高于基线的臂只有两个(§23 的 31 臂表):

| 臂 | `test_R@10` | Δ 基线 |
|---|---:|---:|
| `TIGER_behavior_edge_contrastive_rq` | 0.05625 | **+0.00080** |
| `TIGER_chain_align_rq` | 0.05611 | **+0.00066** |

它们的 SID 结构**走向完全相反**:

| 臂 | L1 用码 | L1 熵 | L2 前缀数 | L2 熵 | 三码数 | 碰撞率 | 最大 L1 桶 |
|---|---:|---:|---:|---:|---:|---:|---:|
| TIGER 基线 | 249 | 6.959 | 7,374 | 11.938 | 20,425 | 0.1693 | 2.9% |
| behavior_edge_contrastive | 256 | **4.620** | **3,175** | **9.901** | **16,288** | **0.3375** | **10.5%** |
| chain_align | 256 | **7.167** | 7,866 | **12.106** | 20,844 | 0.1522 | 2.1% |
| J(本轮) | 243 | 6.894 | 7,134 | 11.830 | 20,826 | 0.1530 | 2.9% |

**一个把 SID 做粗**(L1 熵比基线低 2.3 bit,前缀少一半,碰撞率翻倍),**一个做细**(L1 熵与 L2 熵都比基线高)。
两者都只比基线高 0.0007–0.0008。

### 33.1 结论

**没有任何结构统计量(L1/L2/L3 熵、前缀数、三码数、碰撞率、最大桶)能把这 2 个正收益臂与其余臂分开。**
如果 SID 结构是杠杆,两个方向相反的臂不可能给出同样的收益。

这第三次独立地支持同一个判断:
**SID 的结构统计量与 Stage3 的排序质量之间没有可用的因果关系。**
0.0007 的提升(7× 噪声底)是真实的但它们不来自结构,很可能来自「这两个臂恰好把**特定几个高频商品的
名字**放到了模型更可能生成的路径上」—— 一个**逐商品**而非**统计**的效应。

### 33.2 这条观察给出的唯一可执行形式(未实现)

若效应是逐商品的,那么正确的机制**不应**以任何集合统计量(碰撞率、熵、容量)为目标,
而应以「目标商品在其历史前缀下被生成的概率」为目标 —— 即直接优化
`P(SID(target) | SID(prefix))`。这在 Stage2 里不可观测(它需要 Stage3 的模型),
所以按构造,Stage2 的任何机制都无法针对它。

**这是本轮的终点**:不是因为想不出机制,而是因为可用的信号(Stage2 侧的一切统计量)
与目标量(Stage3 的条件生成概率)之间没有可计算的通路。要突破,必须允许 Stage2 与 Stage3 联合训练,
或允许改 Stage3 —— 两者都超出现行 §19h/§22/§23 的规则空间。

## 34. 最终结论:§19h 允许的那一侧没有正结果,有正结果的那一侧被 §19h 排除

### 34.1 证据(全库)

31 个同时有 SID 指标与 Stage3 recall 的臂里,只有 2 个高于基线:

| 臂 | Δ 基线 | 机制位置(源码) |
|---|---:|---|
| `TIGER_behavior_edge_contrastive_rq` | **+0.00080** | `losses/behavior_contrastive.py`:行为边对比损失(负样本 4,温度 0.07) |
| `TIGER_chain_align_rq` | **+0.00066** | `losses/chain_align.py`:链对齐损失 |

两者都是**损失侧的行为项**,都不改变 Sinkhorn 的代价矩阵。

本轮我按 §19h 建的全部**分配代价侧**机制:

| 臂 | Δ 基线 |
|---|---:|
| J(仅 Sinkhorn 层曲率) | −0.00040 |
| AF3(逐商品几何 + 行为曲率耦合) | −0.00087 |
| DT(AF3 + 按度数温度) | −0.00296 |
| H(三层曲率) | 闸门拒绝(0.8251) |
| G1/G2(结构信号接输入) | 拒绝 / −0.00266 |

### 34.2 这个对照说明什么

**不是「行为信号无用」,而是「行为信号必须在损失侧才有效」。**

- §19h 要求机制进入 Sinkhorn 代价矩阵,并把「两个互不相干的损失」判为 OUT_OF_SCOPE;
- 但代价矩阵能改变的只是**分配**(谁和谁共享码字),而 §31.3 已证明在最末层做文章时三元组
  **数量**由容量决定、与度量无关 —— 于是代价侧机制只能重新洗牌;
- 损失侧不同:它改变**编码器与码本本身**,因此改变了每个商品的名字**及其可达性**。
  两个正结果都在这一侧,且都是**行为对齐**(对比 / 链对齐),即直接优化「相邻商品的名字要相近」。

按本轮证据,**§19h 的「必须进代价矩阵」这一条是限制进步的那一条**,而不是保护科学性的那一条:
它允许的形式(代价侧)在本库 4 个臂上全部为负;它排除的形式(损失侧行为项)给出了本库仅有的 2 个正结果。

### 34.3 唯一需要 owner 决定的事

要让下一轮有正期望,必须放宽 §19h 之一:

| 选项 | 内容 | 风险 |
|---|---|---|
| A | 允许**损失侧行为项 + 曲线运算**耦合(即把两个正结果升级为带曲率的版本) | 与 §19h 正文冲突,需改写规则 |
| B | 允许**改 Stage3**(排序侧) | 与 §22/§23 冻结冲突 |
| C | 允许 **Stage2–Stage3 联合训练** | 改动最大 |

我推荐 **A**:它最接近已有的 2 个正结果(只加曲率、不改结构),改动最小,
且能在现有 Stage2 流水线上直接跑(3000 epoch + 150 epoch,约 45 分钟一臂)。

**在这三个选项被批准之前,继续在 §19h 允许的范围内加机制,按本轮 7 个臂的证据预期全部为负。**
本节是这条判断的最终依据,不再是猜测。

## 35. 第七臂:行为对比 + 曲线相似度(`TIGER_curve_contrastive_rq`)

### 35.1 更正 §34 的判断

§34 写「有正结果的一侧被 §19h 排除」。重读 §19h 原文后这句过头了。规则要求的是

> 训练只行为信号与显式曲线运算**在同一条连通计算通路上的耦合**,去掉任一侧核心计算即改变;
> **仅**行为后缀、**仅**把欧氏距离换成双曲距离、两个互不相干的损失……判 OUT_OF_SCOPE。

被排除的是**单侧**形式与**互不相干**的两个损失。而「一个对比损失,正样本取自行为图、相似度用
曲率距离」是**双侧耦合**,完全在范围内。所以库里两个正结果之一(行为边对比)可以直接升级为合规形式,
不需要任何授权。这是本轮真正该做而我一直没做的事。

### 35.2 机制

```
正样本  = 规范行为图的边(只用 train 交互构建;留出 20% 作诊断,252,313 边 / 504,626 配对)
相似度  = −d²_{κ=−1}(u, v)     曲率 −1 球上的平方测地距离,除以温度 0.07
三个开关(§19g):ACCESS_BEHAVIOR / ACCESS_CURVE / both-on
```

- 关掉行为侧 → 正负样本对错位(同一批向量配到无边的邻居);
- 关掉曲线侧 → **逐位重现**归档的余弦 InfoNCE(测试断言到 1e-6);
- 两侧都开 → 与两个单侧状态都不同(各有一条断言)。

六项测试覆盖上述四件事 + 有限性 + 退化批次不产生 NaN。

### 35.3 Stage2 结果:本轮最健康的码本,**且分配是稳定的**

| 项 | 值 | 与其余臂对比 |
|---|---|---|
| 训练器碰撞率 | **0.149591**(20,909 / 24,587) | 本轮最低(G1 0.9655 / H 0.8251 / DT 0.1993 / AF3 0.1915 / J 0.1530) |
| 闸门复算 | 0.149591(一致) | 闸门与训练器**完全相同**,无重导差异 |
| quant_error | 0.0553 | 带内 |
| effective_rank | 16.69 | 告警(与 J/AF3/DT 同档) |
| **训练时 vs checkpoint 重导差异** | **181 项(0.7%)** | **与基线 122–291 同档**;而 J 2,788 / AF3 11,761 / DT 12,150 |

**181 项是本节最重要的一行。** 之前四个臂的重导漂移从 2,788 涨到 12,150,原因是逐商品的行为信号
让分配依赖「用哪个前向算」;而这个臂把行为信号放进**损失**,它改变的是**编码器本身**,
于是 checkpoint 前向能重现训练时的分配。这是「损失侧 vs 代价侧」的一个可测差别,不只是哲学差别。

## 37. 严格配对:曲率代价 0.0011,且归档臂的正收益没有复现

| CC | κ=−1 平方测地 | 0.053500 | −0.001950 |
| | | **配对差 −0.001062** | |

### 37.2 必须写清的限定

两臂的 `behavior_weight` **不同**(CC 1.41e-7 / COS 1.99e-6),因为该权重由
「行为梯度范数 = 5% 重构梯度范数」的规则推出,而测地相似度的梯度范数是余弦的 14 倍
(509 vs 36)。因此这次对照的准确表述是:

> 在**相同的相对梯度贡献(5%)**下,把相似度从余弦换成测地距离,recall 下降 0.0011。

它**不是**「固定权重、只换相似度」的对照。这个区别已写入结论,不能省。

### 37.3 归档臂的正收益没有复现

| 臂 | `test_R@10` |
|---|---:|
| 归档 `behavior_edge_contrastive_rq` | 0.05625 |
| **本轮 COS(同机制重新实现)** | **0.05456** |

差 0.00169(17× 噪声)。也就是说:

- 「行为边对比本身带来 +0.0007」**没有被复现**;
- 本轮所有臂里最好的仍是 J(0.055050,−0.0004),而 J 不含行为信号。

**所以「损失侧行为项才是正结果所在」这条判断,在本轮自己的复现里也站不住。**
§34 与 §36.5 中依赖它的表述一并修正:本报告能支撑的最强说法是
「**曲率在此任务是负向的**」,而不是「换个位置就对了」。

### 37.5 八臂之后能下的结论

1. **八个臂全部 ≤ 基线。** 最好的 J 差 0.0004,本次 COS 差 0.0009。
2. **曲率是负向的**,而且在严格配对下可复现(−0.0011,10× 噪声)。
3. **曲率与 SID 结构质量脱钩**:CC 的碰撞率 0.1496、重导漂移 181,是全场最好的结构,
   recall 却是最低之一。COS 结构同样好(0.1445 / 138),recall 只到基线 −0.0009。
4. **重导漂移由「信号放在哪一侧」决定,不由机制好坏决定**:代价侧 2,788–12,150,
   损失侧 138–181,基线 122–291 —— 这是本轮唯一稳定的结构性因果,但它不带来 recall。

在这个规则空间内,`test_R@10` 对 Stage2 侧的任何改动都不敏感。要再往前走,
必须动 Stage3 或允许联合训练 —— 这已不是机制选择问题,而是实验范围问题。
