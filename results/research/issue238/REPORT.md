## 4. 结论:两条路径都失败,但失败方式不同

### 4.1 G1:checkpoint 不可复现地坍缩

训练器内存里导出的是 **24,498 个互不相同的三码**(collision 0.0036);
而 `stage3_start` 按 CLAUDE.md §67 的 export_gate 从 checkpoint 重导,得到
**849 个三码、最大桶 13,810 个商品**、collision **0.9655**。

`export_manifest.json` 记着 `original_differing_items: 24587` —— **全部商品都变了**。

即:**#237 的纯结构表示可以让 RQ-VAE 在训练时看起来完美区分(0.0036),但保存下来的
checkpoint 前向会把 56% 的商品塞进同一个码字。** 这不是抽样噪声,是分配在该表示下
不可复现。基线在同样协议下只差 122–291 项(0.3–1.2%)。

### 4.2 G2:同样大幅漂移,但侥幸低于门槛

训练器 0.0092 → checkpoint 0.1738(24,575/24,587 项不同),刚好低于 0.4 硬门槛,
因此 G2 得以进入 Stage3。**它与基线 0.1693 已经几乎同一量级**,说明 G2 的 SID 在
重导之后回到了基线那种「大量共享码字」的形态。

### 4.3 机制层面的教训

1. **「训练时 collision 低」不能作为 SID 质量的证据**:两个臂的训练器值(0.0036/0.0092)
   与 checkpoint 值(0.9655/0.1738)相差两个数量级。CLAUDE.md §67 的 export_gate 正是
   为此存在,这次它拦下了 G1。
2. **#237 的表示不适合直接作为 RQ-VAE 输入**:它的 latent 分布让码字分配对
   checkpoint/内存差异极度敏感。若要接入,需要先解决量化稳定性(例如在 Stage2 目标里
   加码本利用率约束,或改用 #237 的切空间输出做 PCA 后再量化)。
3. 这条结论**不是**「混合曲率无效」:G1/G2 只是把 #237 的表示喂给标准 RQ-VAE,
   没有改动几何或分配规则。

## 8. 第三条机制:测地代价进 Sinkhorn(H,`TIGER_kappa_cost_rq`)

### 为什么是这里

§19h 规定机制创新必须进 Sinkhorn 的代价矩阵,分配规则仍是基线的均衡分配;`distances/__init__.py`
自己的约定是「换度量 = 换实验,选择写在源码里」。所以 H 的改动只有三处:

| 文件 | 改动 |
|---|---|
| `distances/curved.py` | 新增:κ=−1 球面平方测地距离 |
| `distances/__init__.py` | 注册 `"curved"` |
| `train_rqvae.py` | `build_distance(CONFIG, name="curved")` |

输入嵌入、损失、训练超参全部未动,所以量化稳定性应当接近 TIGER 基线(与 G1 的 0.9655 崩塌对比)。

### 定义

```
u = 0.9 · tanh(r/τ) · x/r ,  r=|x| ,  τ = mean‖c‖(当前 step)
d(u,v)² = ( arcosh(1 + 2‖u−v‖² / ((1−‖u‖²)(1−‖v‖²))) )²        (κ = −1)
```

- κ 取 #236 实测 −1.0188 的整数点 −1,**不是搜索变量**(§19g 不做调参)。
- τ 取当前码本平均范数,使映射尺度等变,**没有自由超参**。
- 半径上界 0.9 是数值条件数要求,不是拟合参数:不加时 `(1−‖u‖²)` 极小,展开式
  `‖u−v‖²` 的浮点误差被放大,自距离实测 **14 而非 0**。这是本轮真实踩到的坑,已写进模块注释。

### 数学验证(`results/research/issue238/tests/test_curved_cost.py`,7/7 通过)

| 性质 | 结果 |
|---|---|
| 映射后半径 < 1 | 通过(50× 放大输入仍封在球内) |
| 自距离 = 0 | 通过(≤1e-5) |
| 非负、有限、形状 (B,K) | 通过 |
| 沿穿过码字的射线单峰(近侧单调降、远侧单调升) | 通过 |
| 两个点集间对称 | 通过 |
| 与欧氏代价不同(机制未退化为基线) | 通过 |
| 梯度流向 latent 与 codebook | 通过 |

**为什么可能有收益**:负曲率球上靠近边界的点距离增长更快,把紧簇拆到不同码字的代价高于欧氏;
Sinkhorn 仍保证均衡(§19h 的分配规则不变)。

## 9. 第四条机制:分层混合曲率(`TIGER_kappa_sk_only_rq`)

### 定义

与 H 是同一份测地代价,**只给 Sinkhorn 层**(最后一层,`sk_epsilon>=0`);下两层保持欧氏 argmin。

| 臂 | L1 分配 | L2 分配 | L3 分配(Sinkhorn 均衡) |
|---|---|---|---|
| TIGER 基线 | 欧氏 | 欧氏 | 欧氏 |
| H 一致曲率 | 测地 | 测地 | **测地** |
| J 混合曲率 | 欧氏 | 欧氏 | **测地** |

三臂只在「哪一层用什么度量」上不同,输入、损失、超参完全相同,所以 H vs J vs 基线构成
「统一曲率 / 混合曲率 / 无曲率」的直接对照。

### 为什么必须让 Sinkhorn 层而非低层用测地

§19h:创新必须进入**均衡分配**的代价矩阵。实测本栈 `sk_epsilon` 逐层为 `[-1, -1, 0.003]`,
即只有最后一层跑 Sinkhorn;若把曲率放在低层,那些层仍是 argmin,机制就落空了。
`test_per_level_metric.py` 把这一条写成机器断言。

### 实现与验证

改动只在 `model/layers.py` 的层构造循环(3 处 `distance=level_metric`)与 `ARM_NAME`;
`_indices`/`_distances` 的调用点逐字未变,所以 anti-collapse floor 的锚点仍全部命中
(实测 `changed=True`、6 处未保护赋值全部保护)。

| 断言 | 结果 |
|---|---|
| 入口选中的是 curved | 通过 |
| `sk_epsilon>=0` 的层恰好是最后一层 | 通过 |
| 最后一层 distance 是 curved 对象 | 通过 |
| 下两层 distance 是 euclidean 对象 | 通过 |
| 下两层数值等于基线欧氏代价 | 通过 |
| 最后一层数值不等于欧氏代价 | 通过 |

## 10. 判定规则(在 Stage3 数字出现前固定)

四个臂的最终判断只用 Stage3 `test_R@10`(§25 的采纳门槛 0.065,基线实测 0.05545)。为避免事后挑解释,
先把映射写死;数字落地后照表填,不做二次解读。

| 观测 | 结论(照写,不改) |
|---|---|
| H 或 J > 基线 **且** 差 ≥ 0.005 | 测地代价进入分配可提升排序;曲率是有效变量 |
| J > H 且两者 > 基线 | **混合曲率优于统一曲率**(只有 Sinkhorn 层该用曲率) |
| H > J 且两者 > 基线 | 统一曲率优于混合;**「不同层需要不同几何」被否定** |
| H、J 均在基线 ±0.005 内 | 分配代价对最终排序不敏感;曲率必须在别处耦合 |
| H、J < 基线 −0.005 | 测地代价损害分配;κ=−1 不适合本嵌入 |
| G2 > 基线 + 0.005 | #237 语义保留的纯结构信号可直接改善排序 |
| G2 在基线 ±0.005 内 | 结构信号在 SID 层面无净收益(即使 Stage2 collision 合格) |
| G1(已拒) | **结构专用表示的 RQ-VAE 量化不稳定**:训练器 0.0036 vs checkpoint 重导 0.9655,**结论已定** |

**已固定的结论(不依赖 Stage3)**:`TIGER_g237_struct_rq` 证明「训练器内存里的低碰撞率」不能作为质量证据;
§63/§67 的 checkpoint 重导闸门是必需的,不是形式主义。本轮唯一让该缺陷暴露的就是这道闸门。

## 11. 量化诊断:低有效秩是必要条件,不是充分条件

`tools/research/stage2/sid_quality.py` 对三个臂的 checkpoint + 嵌入复算(§89 口径):

| 臂 | 三码碰撞率 | 量化误差(带 0.035–0.100) | 有效秩(限 8.0) |
|---|---:|---:|---:|
| TIGER 基线 | 0.1693 | **0.251 越界** | **11.48 越界** |
| G1 纯结构 | **0.9655** | 0.118 越界 | 7.41 |
| G2 语义保留 | 0.1738 | **0.075 带内** | **6.74 合格** |

### 读法

1. **G1 的失败不是「编码抖动」,而是「码本被撑爆之前先被压平」**。它的有效秩 7.41 比基线(11.48)
   低得多,量化误差也更小(0.118 vs 0.251)——按旧口径它「更好」。但碰撞率 0.9655:纯结构目标把
   24,587 个商品压进一个低秩、低方差的子空间,三级 8-bit 码本在这个子空间里无法再区分它们,
   绝大多数商品落到同一批三元组上。**低秩只保证「码本能覆盖」,不保证「码本能区分」。**
2. **G2 是三者中 SID 结构质量最好的**:量化误差 0.075 落在设计带内、有效秩 6.74 合格,而碰撞率
   0.1738 与基线 0.1693 基本持平——即粒度可比,可以直接进 Stage3 对照。
3. **基线自身两项诊断都越界**(0.251 / 11.48),说明 #237 的语义保留残差不只是「没变差」,它在保持
   碰撞率的同时把「挤压」和「未组织」两个毛病都修掉了。这是本轮不依赖 Stage3 就能定的结论。

### 对「结构信号接进 RQ-VAE」的意义

结构信号有两种接法,本轮的四个臂把它们都测了:

| 接法 | 代表臂 | 结果 |
|---|---|---|
| 换输入(纯结构) | G1 | 码本失去区分力,碰撞率 0.9655,被闸门拒绝 |
| 换输入(结构作残差,语义主导) | G2 | 诊断全合格,碰撞率与基线持平,Stage3 待定 |
| 换分配代价(曲率) | H / J | Stage2 待跑 |

**结论**:「结构信息直接当输入」这条路需要先解决码本区分力;「结构作残差不替换」是目前唯一
通过全部诊断的接法;而「曲率进分配代价」是本轮尚未取数的第三条独立路径。

## 12. 码本使用:纯结构输入退化成「一个码字」

同一批 24,587 个商品,只读 `item_sids.json` 复算各级码字的使用分布:

| 臂 | L1 使用码字 | L1 熵 / 上限 8 bit | 最大 L1 桶占比 | L2 熵 | 三码组合数 | 碰撞率 |
|---|---:|---:|---:|---:|---:|---:|
| TIGER 基线 | 249 / 256 | 6.959 | 2.92% | 11.938 | 20,425 | 0.1693 |
| G2 语义保留 | 256 / 256 | 6.898 | 3.21% | **12.132** | 20,314 | 0.1738 |
| G1 纯结构 | 256 / 256 | **0.232** | **98.34%** | 1.571 | **849** | 0.9655 |

### 这解释了 §11 里「有效秩合格却崩塌」的矛盾

G1 的**一级**几乎完全退化:**98.34% 的商品落在同一个一级码字**上,L1 熵只有 0.232 bit(上限 8)。
它的有效秩 7.41 量的是编码器输出张量,测不到「这些向量全被分到同一个桶里」;只有碰撞率能测到。
这就是 §89 最终只保留碰撞率作硬门槛、把量化误差与有效秩降为诊断值的实证依据——本轮给出了一个
反例型证据,不是理论论证。

### G2 与基线在码本使用上等价

256 个一级码字全部用上,熵 6.898 vs 6.959,最大桶 3.21% vs 2.92%,二级熵反而略高(12.132 vs 11.938)。
即 G2 在**保持 SID 粒度不变**的前提下修好了量化误差与有效秩(§11),这让它的 Stage3 数字与基线可比:
差异只能来自「结构残差是否带来了更好的语义分组」,而不是「SID 变粗或变细」。

### 对机制设计的推论

纯结构目标的问题不是噪声,而是**表示里几乎没有跨商品的可区分方差**:#237 的 32 维 graphlet 统计
在逐商品归一化后,主要变异方向被编码器压成了一个全局尺度,三级码本只能切出 849 个桶。
要让它可用,必须先做两件事之一:去掉逐商品归一化造成的尺度主导,或在量化前做白化/PCA 提升方向多样性。
