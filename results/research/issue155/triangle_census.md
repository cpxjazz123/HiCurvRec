# #155 闭合三角形项的可用量（修正后）

`structure_prior.npz` 的 `item_ids` 不是「节点 → 商品」映射：节点 id 就是商品 id，`item_ids` 只是**有结构信息的商品集合**（24556 / 24587，缺 31 个）。把两者当成不同空间会得到错误计数——我第一版快速脚本正是这么错的（报 10 个），独立复算与建表脚本一致为 **258**。

正确口径（`u ≥ 1` 即 AF3 ≥ q95 的高边，三角形按商品 id 判定）：

| 量 | 数值 |
|---|---|
| 高边（`u = 1`） | 16919 |
| 低边（`u = 0`） | 15788 |
| 三边全高的三角形 | **258**（全图 546438 个三角形中） |
| 8 个 1024 行 batch 见到的全高三角形 | **0** |
| 8 个 2048 行 batch 见到的 | **0** |
| 8 个 4096 行 batch 见到的 | **7**（每 batch 0.88） |

含义：`L_tri` 在冻结的 per-rank batch（1024 行）上几乎恒为空、在全局 batch（4096 行）上平均不足 1 个三角形；即使把四个 rank 合起来看，`L_tri` 每步能作用到的对象也只有个位数。它与 #154 的同类项一样，是「实现正确但几乎无事可做」的项，必须在报告里与 `L_struct` 分开陈述。
