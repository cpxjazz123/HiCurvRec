# Quantizer rotating-history lifetime repair

The full-FP32 production batch-invariance regression passes, but that generation exposed an existing two-identical-instances hard-output test failure. The old coverage map is keyed by `id(layer)` and never releases dead-layer entries. This permits recycled object ids to inherit unrelated coverage history. The failed process did not persist its counter map, so that particular failure is not retrospectively asserted to have this cause.

A separate deterministic regression copies the actual frozen baseline into an isolated repository test workspace, installs the real framework floor, and invokes actual VQLayer._indices. It verifies first cheap assignment[0,1], same-owner next rotating assignment[2,3], and another live owner's independent first assignment[0,1]. After deleting both quantizers, the old implementation fails exactly `destroyed quantizer must release its rotating-coverage history` (FLOOR_LIFETIME_RED.log,1failed,4.09s); this is a demonstrated engineering defect, not a crash or a fabricated identity collision.

The framework floor now uses WeakKeyDictionary keyed by the actual layer object. Both installed quantizer families and existing live installations migrate every active call to counts_key=self; no integer-key runtime compatibility cache remains. The actual current candidate floor and layer source are updated atomically. Historical baseline/archive/run trees remain unchanged. Live coverage choices, cost order, Sinkhorn, greedy repair and count increments are unchanged; destroying an owner releases only its own state. Formal1024/256-item training populations and the full24587-item export are in the feasible regime and never read this rotating-history map at all.

The regression and the existing baseline-install/idempotence test join complete launcher-owned controller/framework execution and exact source inventory. Current candidate tests, raw real-loss/DDP, epoch51, inclusive performance and machine entry/graph must all be regenerated. Stage2/genrec MCP children were reloaded, with actual read-only/fail-closed tool calls recorded in MCP_RELOAD.json; no formal training was launched.
