# 完整守卫 + 完整预算:3000 epoch 实测

上一个完整预算运行(round16)早于**相对间距检查**,所以"3000 epoch 带着完整守卫跑完"当时并不成立。这一轮补上,并回答一个具体风险:参考值取自第 1 epoch,若健康码本在长训练中合法收紧到初始值的十分之一以下,判据就会误杀。

## 结果:跑完,零拒绝

```
epoch=3000 loss=0.00033496 recon=0.00006737 raw_unique=20740/24587 collision=0.156465
产物审计: PASS  levels 256/256/256  collision 0.156465  gate allowed
```

- **`CodebookCollapse` 0 次**(3000 个 epoch 全程)。
- 每级 256 个码字全在用;三级码碰撞 **0.1565**,与 round16(0.1557,无间距检查)基本一致。
- 稳态每 epoch **0.2089 s**(中位 0.2360),与 round16 的 0.2130 s 无显著差异 —— 新检查不带来可测开销。

## 安全余量(实测)

末态 checkpoint 上,`min_pair / 分辨率` 逐级:

| 级 | 终值 | 判据触发点(0.1 × 初始) | 余量 |
|---|---|---|---|
| L1 | **2.168** | ≈0.044 | ×49 |
| L2 | **1.370** | ≈0.033 | ×42 |
| L3 | **1.603** | ≈0.030 | ×53 |

比值随训练**上升**(初始 ≈0.30–0.44 → 终值 ≈1.37–2.17),所以判据的触发点落在健康运行终值的 40–50 倍以下。这不是"刚好没触发",而是数量级的余量。

## 结论

"完整守卫 + 冻结预算"这条证据链现在闭合:

| 项 | 值 |
|---|---|
| epoch | 3000 / 3000 |
| 拒绝次数 | **0** |
| L1 死码 | **0** |
| 碰撞率 | 0.1565(未保护基线 0.1693) |
| 每 epoch | 0.2089 s |
| 间距判据余量 | ×42 – ×53 |
