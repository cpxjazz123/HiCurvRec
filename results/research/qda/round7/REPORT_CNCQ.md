# CNCQ:认证式非坍缩量化(第一阶段:模块 + 验收 + 对抗验证)

目标不是"再试一个防坍缩 Loss",而是让**任何**后续机制都不可能把坍缩模型当作合格结果交出去。三层保护各自给出不同种类的保证:

| 层 | 机制 | 保证类型 | 本轮状态 |
|---|---|---|---|
| 容量 | 全目录硬约束分配,`n_k ≥ m` | **构造性**(不可行即抛错) | 已实现 + 测试 |
| 几何 | 固定原型 + 有界偏移,`‖Δ_k‖ ≤ ρ`,`2ρ < δ` | **结构性**(梯度再大也改不破) | 已实现 + 对抗测试(双曲半只能实测) |
| 表示 | 有效秩 + 行为结构保真 vs 认证参考 | **裁决性**(不能构造,只能拒绝) | 已实现 + 20 个臂的实际裁决 |

**先写边界**:量化器无法凭空恢复编码器从未产生的语义。若某个机制把所有商品编码成同一向量,第一、二层仍可被满足(容量层总能搬商品凑数),因此**必须以第三层拒绝它**。下面第 3 节就是这个对抗例的实测。

## 1. 容量层(构造性)

`cncq/capacity.py::hard_capacity_assignment(cost, m)`:

1. 每个商品先取最便宜的码字;
2. 只要还有码字不足 `m`,就从"仍有盈余"的码字里挑**后悔值最小**的商品搬过去;
3. 每次搬运把总缺口减少 1 ⇒ 必然终止;`N ≥ K·m` 是可行性的充分必要条件,**不满足时抛 `InfeasibleCapacity`**,绝不返回"部分满足"的分配。

`m` 的取值:平衡份额 `N/K` 的 **25 %**(N=24587、K=256 时 = 24 个商品/码)。这是"最弱但仍禁止少数码字承担全部商品"的档位,记录在 `Policy.minimum_share`,不是调出来的。

测试(`test_cncq.py`):随机代价矩阵下 `min count ≥ m` 恒成立;同一代价矩阵两次调用结果逐位相同;20 个商品要 10 个码各 3 个(需 30)时**抛错**。

## 2. 几何层(结构性)

`bounded_codes(a, Δ, ρ) = a + Δ·min(1, ρ/‖Δ‖)`,即把偏移**投影**进半径 `ρ` 的球。若原型最小间距为 `δ` 且 `2ρ < δ`,则对任意一对码字

$$\lVert c_j-c_k\rVert \ge \lVert a_j-a_k\rVert-\lVert \Delta_j\rVert-\lVert \Delta_k\rVert \ge \delta-2\rho > 0 .$$

- 测试把偏移放大到 `1e3 ×` 原型间距,`bounded_codes` 之后最小两两距离仍 `≥ δ − 2ρ`;`ρ = 0.8 > δ/2 = 0.707` 时认证器判 `ok = False`。
- **双曲半没有免费三角不等式**:球面/双曲测地距离不满足这种"减法"界,所以模块对混合度量只**实测**码字间最小代价(`mixed_min_distance`),为零即拒绝,并明确标注这不是解析保证。

## 3. 第三层为什么必须存在:退化编码器的对抗例

构造"所有商品编码成同一向量"的极端输入:

- 代价矩阵全 0 ⇒ 容量层**仍然满足**(它把 1000 个商品硬塞进 8 个码,每个 125 个,`min_count ≥ 50` ✓);
- 原型间距 `δ = √2`、`ρ = 0.1` ⇒ 几何层**仍然满足**;
- 但量化表示的有效秩 = 1、行为保真 = 0.5(随机)⇒ **验收拒绝**:`failed = [representation, fidelity]`,而 `capacity` 不在失败列表里。

这正是"三层缺一不可"的实测证据:前两层能保证"码字都被用、彼此不重合",但它们对"编码器什么都没输出"无能为力。

## 4. 在现有 20 个臂上的实际裁决

参考 = `B0_replay@300`(F0 原始配方,L3 行为 AUC **0.6592**);判据:容量 `m=24`、有效秩 ≥ 8、L3 AUC ≥ 参考 − 0.0005、五个结构类各自 ≥ 参考 − 0.001。

| 臂 | 活跃码 | 最小占用 | 有效秩 | L3 AUC | 裁决 |
|---|---:|---:|---:|---:|---|
| **B3_l1_balanced_s43** | 256 | **26** | 10.6 | **0.6615** | **CERTIFIED** |
| B3_l1_balanced | 256 | 21 | 11.7 | 0.6590 | capacity, stratum:dense, stratum:intra |
| B3_l1_balanced_s44 | 256 | 33 | 12.9 | 0.6577 | fidelity + 三个结构类 |
| B4_revival | 256 | 1 | 11.9 | 0.6535 | capacity, fidelity, 四类 |
| B2_code_freeze | 103 | 0 | 12.6 | 0.6577 | capacity, fidelity |
| D1 / D2 / D3 / E1 / F1 / F2 | 54–198 | 0 | 8.4–15.5 | 0.6305–0.6580 | capacity(+ 多数 fidelity) |
| B0(参考自身) | 26 | 0 | 6.4 | 0.6592 | capacity, representation |
| A_fine / B3_long | 35 / 256 | 0 / 32 | 8.9 / 14.2 | 0.6613 / 0.6618 | **预算不匹配(3000 vs 300),不可比** |

三条必须写进来的观察:

1. **20 个臂里只有 1 个通过**,而且它和它的同机制另一颗种子(s44)结论相反 —— 认证判的是**模型**,不是机制。这正是这套闸门该有的粒度。
2. **参考必须同预算**:本轮实测,若不做预算匹配,`B3_long`(3000 epoch,在 300 epoch 处 L3 = 0.6618)会被误判为通过;它的 3000-epoch 参考是 `A_fine`(0.6679),那样它其实不通过。脚本现在按 `train_start.epochs` 强制匹配。
3. **参考自身也没通过**:F0 的 L1 只有 26 个活跃码、最小占用 0、有效秩 6.4 —— 它作为行为参考合格,作为认证模型不合格。

### 追加闸门(可选,本轮默认关闭)

把 round 4 量到的**导出一致性**作为第四道闸:训练分配与 `argmin` 导出在 L1 上必须 100 % 一致,缺失即 `NOT_RUN`(**失败关闭**,不是通过)。开启后:

- `B3_l1_balanced_s43` 因为快照里没有 `train_code_1` 字段 → `export_l1:NOT_RUN` → 拒绝;
- **结论:开启该闸后认证数为 0**。

这也是本阶段的诚实起点:**我们还没有一个同时满足全部要求的已认证模型。**

## 5. 未实现的部分(不能宣称)

1. **第三层的"受保护子空间"没有实现。** 用户提出的 `[q_protected, q_learnable]` 需要一份"经过验证的结构表示"作为输入;若它来自行为图,就改变了本仓库"只用行为监督、不直接输入行为结构"的设置,这是需要 owner 决策的取舍,不能由我默认。本轮的第三层只是**验收**(有效秩 + 行为保真),不是构造保护。
2. **容量层与几何层还没有接进 trainer。** 本轮交付的是模块、测试与认证协议;把它们接进训练需要改分配(每步硬约束会与 STE 的批内 argmin 冲突,需要按 epoch 而非按 batch 施加并在导出时复用同一规则)和码本参数化(原型 + 偏移),这是下一阶段的工程,不在本轮。
3. **双曲半只有实测分离度**,没有解析保证。
4. **认证依赖同预算参考**,而当前唯一"通过"的模型没有导出测量,因此严格口径下认证数为 0。
