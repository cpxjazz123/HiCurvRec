# 撤回与重算记录（2026-11-21 复审后）

复审指出四处实现错误与两处结论过强。全部已修，旧数字作废，下面是逐条与新的实现。

## 撤回的结论

| 原结论 | 状态 |
|---|---|
| GNN 输入 0.664→0.663，量化几乎无损 | **撤回**。原探测传入未归一化向量（内积而非余弦），留出商品的真实向量被均值替换，且 `q` 实际读的是 Decoder 输出。 |
| 瓶颈在输入、不在量化 | **撤回**。需要在正确归一化、真实留出输入、四个分离状态（input / z / hard q / Decoder）上重算。 |
| PCA 结果说明 128 维信息已饱和 | **撤回**。128→128 白化只改变尺度与度量，不是降维；该臂是度量控制，不是容量证据。 |
| Orbit 标签因混入删除实例而损坏 | **撤回**。`role_headroom()` 用常数先验当“oracle”并混用了 log 底数。直接检查后：12266 行**全部**行和为 1（±5e-8）、无负值、无非有限值；中位归一化熵 0 bit、46.1% 行有效角色 ≥2。标签**不是**损坏的行和，只是大量单角色稀疏行。 |
| 小差异可解释为浮点误差 | **未证明**。现在按臂分别报告 token 一致率与完整 SID 一致率。 |
| `TIGER_RQ-VAE` 必为错配 | 保留为**待查**：token 0.3% / 完整 SID 0%，但脚本对本臂沿用基线 config（`PCA_DIM=0`）重建模型，不能排除该臂自身配置不同。 |

## 修复后的实现

1. **余弦**：`behaviour_probe()` 先做 L2 归一化（零行直接报错），`normalised: True` 写进结果；旧的内积分数不可与 relation 审计的 0.739 并列。
2. **留出输入**：所有商品保留真实向量，划分只决定优化器迭代哪些商品；探测分别在“全部覆盖”“仅留出覆盖”“仅训练覆盖”三个掩码上报告。
3. **状态分离**：`quantise()` 返回 `latent`(32)、`q`(**硬量化，32**)、`decoder`(输入宽度)、`tokens`；`widths` 字段把各自维度写死进结果；`probe_q` 与 `probe_recon` 不再读同一个数组。
4. **推理路径**：`infer_use_sk=False`，与 trainer 导出 `item_sids.json` 的路径一致；`sweep.json` 里 `infer_use_sk` 随每个 epoch 记录。
5. **角色测试的对照**：打乱标签组复用同一初始权重、同一梯度裁剪（1.0），并记录训练/评估子图的平均度（4.3 / 4.3，随机控制 8.3 / 8.2）——子图规模差异现在可查。
6. **配对判定**：token 一致率与完整 SID 一致率分开报告，MATCH 要求完整 SID 100%；每臂附 `arm_space`（导出 manifest、checkpoint 的 `selection` 字段），说明本脚本只重建了基线结构。

## 重新计算的结果

### 角色预测（`representation/role_probe.json`，修正对照后）

| 状态 | 交叉熵 | 常数先验 | 打乱标签 | 相对先验 |
|---|---|---|---|---|
| 随机 32 维 | 3.6220 | 3.4794 | 3.6080 | −0.1426 |
| 语义 768 | 3.4691 | 3.4794 | 3.5417 | +0.0103 |
| GNN 冻结 128 | 3.4776 | 3.4794 | 3.5138 | +0.0018 |

修正对照后数字几乎不变（打乱组 3.5417/3.5138 对 3.5327/3.5150）。仍只有约 0.01 nats 的正增益，`gnn` 与打乱组的差距只有 0.036 nats——**这条测试目前既证明不了帮助，也证明不了无帮助**；需要更灵敏的对照（例如只保留有 ≥2 有效角色的行、或换成可预测的聚合角色）才能定论。
