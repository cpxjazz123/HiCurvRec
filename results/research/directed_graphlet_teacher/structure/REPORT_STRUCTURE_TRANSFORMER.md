# Graph Transformer 读取候选子图：量化前后的结构保真

**问题**：用一个能读整个候选子图的 Graph Transformer 重新验证——量化前的 `z` 与量化后的 `q`，
在真实行为图提供的结构答案上分别能预测到什么程度？当前优先任务是训练**可靠的结构识别模型**，
因此本报告先看模型是否真的在读结构，再看 z/q 的差异。

## 0. 输入与答案的边界

| 项 | 内容 |
|---|---|
| 样本 | `directed_graphlet_role/instances.npz` 的真实实例：P3/K3（宽度 3）、C4/P4/K1_3（宽度 4），每族最多 12000 条训练、12000 条留出（确定性抽样） |
| 划分 | 实例池自带的 `split==0` 训练、`split==1` 留出，**按实例隔离** |
| 模型输入 | 成员向量（`z`/`q`/`semantics`/`decoder`）+ **由这些向量自己构造的互惠 kNN 注意力掩码**（k=2）+ 成员槽位掩码（宽度 3/4 的 padding 信息） |
| 从不提供 | 真实邻接矩阵 |
| 答案 | Graphlet 家族（来自该实例属于哪一族）、有向 subtype、每个成员**在当前子图内**的 Orbit（真实训练图给出） |
| 模型 | 2 层 4 头 Graph Transformer，HIDDEN=128，三头（family/subtype/orbit），120 epoch，**单种子** |
| 对照 | 去掉 kNN 掩码（全连接注意力）；常数多数类基线 |

同一 checkpoint（`TIGER_drq_D1`，重算 SID 与存储表 100% 相同，碰撞率 0.0253），四种表示各一次运行。

## 1. 结果

| 表示 | 掩码 | family 准确率（多数类 0.200） | subtype 准确率 | Orbit 准确率（多数类 0.375） | Orbit Macro-F1 |
|---|---|---|---|---|---|
| q | kNN | **0.696** | 0.391 | 0.376 | **0.226** |
| q | 无 | 0.642 | 0.368 | 0.379 | 0.188 |
| z | kNN | **0.702** | 0.390 | 0.376 | **0.231** |
| z | 无 | 0.634 | 0.374 | 0.379 | 0.194 |
| semantics | kNN | 0.432 | 0.347 | 0.372 | 0.180 |
| semantics | 无 | 0.392 | 0.339 | 0.365 | 0.204 |
| decoder | kNN | 0.454 | 0.348 | 0.375 | 0.167 |
| decoder | 无 | 0.416 | 0.351 | 0.377 | 0.160 |

## 2. 读法

1. **模型确实在读结构**：`z`/`q` 的 family 准确率 0.696–0.702，是多数类基线 0.200 的 3.5 倍；
   Orbit Macro-F1 0.226–0.231，高于多数类控制能给出的水平。这条任务不再是"全猜多数"。
2. **kNN 掩码有实质贡献**：同一表示去掉掩码后 family 掉 0.054（q）与 0.068（z），Macro-F1 掉 0.038。
   即"候选子图的 KNN 关系"确实提供了额外信息，而不是可有可无。
3. **z 与 q 的差异在噪声量级**：family 0.702 vs 0.696、subtype 0.390 vs 0.391、Macro-F1 0.231 vs 0.226。
   单次运行下这是**持平**；按实验政策不做种子重复，因此不估计种子方差，也不声称哪一方更好。
4. **语义输入显著弱**：0.432/0.392 对 0.70，说明结构信息主要在 GNN 表示里，768 维语义里几乎没有。
   `decoder`（0.454/0.416）也接近语义而非 z/q，说明信息在量化编码器里被重新组织，而不是简单复制。
5. **Orbit 与多数类持平**（0.372–0.379 对 0.375）：**具体成员角色仍未学到**。Macro-F1 0.16–0.23 高于
   随机，但准确率没有超过多数类，说明模型把成员角色都压到最常见的那个 label 上。这是当前模型
   （单样本监督、120 epoch、每族 12000 条）的能力上限，而不是量化造成的——z 与 q 一样。

## 3. 结论与下一步

- 结构识别模型**对 family 与 subtype 已经可用**（相对多数类 0.20 的 0.70），且 KNN 子图信息有贡献；
- 量化前后在 family/subtype 上**持平**，即这一步没有测到量化损失结构信息；
- **Orbit 头还不可用**，任何"结构被保留/丢失"的结论都只能针对 family 与 subtype；
- 下一步要提升的是 Orbit 头（每子图内的相对角色、类别不平衡处理、更长的训练预算），
  而不是继续改 RQ-VAE——与"当前优先任务是训练可靠的结构识别模型"一致。
