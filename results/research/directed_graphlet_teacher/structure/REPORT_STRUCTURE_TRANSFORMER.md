# Graph Transformer 读取候选子图：量化前后的结构保真（v2，含一次全面撤回）

## 撤回声明

v1 报告的 family 0.700 / subtype 0.39 / Orbit Macro-F1 0.23 **全部作废**：

| v1 的缺陷 | 后果 |
|---|---|
| 各家族的本地 subtype 编号直接合并 | 不同结构被当成同一类（全局 subtype 实际有 47 类） |
| 各家族的本地 Orbit 编号直接合并 | 有向 Orbit 被压成 4 类，Orbit 成绩无意义（全局 376 类） |
| family 基线只报 0.200 | 模型知道子图有 3 还是 4 个节点，**只看宽度的基线是 0.526**；"3.5 倍多数类"的说明不成立 |
| 声称互惠 KNN，实为对称并集 | 宽度 3、k=2 时全连通，掩码没有区分度 |
| 文档写了打乱标签对照，实际没跑 | 结论缺少必要的负对照 |
| 只做实例隔离，未做商品隔离 | 同一商品可能同时在训练与测试里 |

v1 报告里"结构信息主要在 GNN 表示中"的推断也不成立：本次四种表示全部来自
`TIGER_drq_D1`，它的编码器输入是 **768 维语义**，并不是此前冻结的 128 维 GNN 表。
正确的说法是：**经过行为图训练的 RQ-VAE 编码器空间**优于其原始语义输入与其解码输出。

## v2 的修正

- 用 `directed_role.instance_targets()` 把每个家族的本地编号映射到**全局** subtype（47 类）与
  **全局** orbit（376 类）；
- KNN 掩码改为**互惠**（两侧互为一方的近邻才连边）；
- 三项对照：**只用宽度的基线（0.526）**、subtype/orbit 的**多数类基线**、**打乱标签**；
- 商品隔离：先按实例池划分，再丢弃任何成员在训练集中出现过的留出行。
  **实测 243525 条留出行因此被丢弃，剩余不足 1000 条**，脚本按记录在案的规则回退为实例隔离，
  `labels.heldout_isolation = "instance_only"` 与丢弃数都写进 JSON——商品隔离在本目录规模下不可行，
  这一点不能用"实例隔离"含糊带过。

## 读数

1. **family 仍有信号**：0.759–0.779 对宽度基线 0.526、多数类 0.200，说明模型确实在用表示，
   不只是数节点个数。z 与 q 差异 0.004（0.779 vs 0.777，去掉掩码时），在这一量级上持平。
2. **subtype 与 Orbit 均未超过多数类**（0.354–0.364 对 0.455；Macro-F1 0.013–0.025）：
   全局 47 类 / 376 类下，模型没有学到具体的连接模式与成员角色。
3. **打乱标签与真实标签几乎相同**：family 0.759 vs 0.759（q/knn）、0.779 vs 0.778（z/none）。
   这说明 family 头主要依赖**宽度这一输入结构**（被 padding 掩码暴露），打乱标签不会破坏它；
   因此 family 的 0.76 不能读成"从表示里读出结构类型"，只能读成"比只数宽度好一点（+0.23）"。
4. **KNN 掩码没有帮助，反而略降**：同一表示加掩码后 family 掉 0.016–0.018、Orbit 也下降。
   v1 说"KNN 有实质贡献"**撤回**。

## 结论

- 结构识别模型**只对 family 有超出宽度基线的判别力**，且该判别力对标签打乱不敏感；
- **subtype 与 Orbit 目前没有学到**，任何"量化后结构被保留/丢失"的结论都还**不能**给出；
- z 与 q 在所有指标上持平（差异 ≤0.004 与 ≤0.006 F1），即**没有测到量化损失**，
  但在任务本身未达标之前，这不能作为"量化保留结构"的证据；
- 下一步仍是把结构识别模型做实（宽度不再作为免费信息、Orbit 类不平衡、更长预算），
  而不是继续改 RQ-VAE。
