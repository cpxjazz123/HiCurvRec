# 修正版三层设计：L1 进入 Sinkhorn、L2 恢复 margin、L3 针对真实碰撞

## 1. 按审查意见改了什么

| 层 | 上一版 | 本版 |
|---|---|---|
| L1 | 独立"提高共享概率"损失（无下界，坍缩） | 链式对齐代价 `a_k(i) = −log(mean_{j∈R(i)} p_j(k))` **加进 L1 代价矩阵**，用 **Sinkhorn 均衡分配**出软分配，容量由分配规则承担 |
| L2 | AB、BC 两个独立 log 损失 + AC 反项（与前缀传递性冲突） | 恢复为**平均共享的 margin**：`max(0, m + S(A,C) − (S(A,B)+S(B,C))/2)`，`m=0.5` |
| L3 | 随机商品对的完整 SID 一致度（梯度 1e-5，形同虚设） | 只取**实际发生三码碰撞的商品组**，把它们在 L3 上推开 |
| 对照 | 无 | 新增 **相同训练预算、相同 batch、无结构项** 的 recon-only 对照 |

## 2. 结果

### 2.1 修正版无法完成训练

`--arm three` 在约 50–100 步内被该臂**自身的反坍缩守卫**拒绝，两次独立复现：

- `assignment_floor.InfeasibleFloor: no droppable item for the empty codewords`
- `ValueError: Cannot center a constant distance matrix`（编码器把整个 batch 压成同一点）

为区分"是机制造成还是守卫太严"，原型里把 `ASSIGNMENT_FLOOR` 临时设为 0 后重跑，仍然在
10 秒内以第二条错误终止。**结论：L1 的对齐压力即便经由 Sinkhorn 代价进入，仍会把编码器推向
"整批同点"的退化状态**；这不是一个可以只靠均衡分配约束解决的问题。

### 2.2 预算匹配的无结构对照（这是上一轮缺失的对照）

| 指标 | 训练前 | recon-only 400 步（对照） |
|---|---:|---:|
| L1 平均共享 | 0.0078 | 0.0256 |
| L1 使用熵 | 4.931 | 4.173 |
| L2 对齐差值 | −0.0001 | 0.0000 |
| 链 Δ（全层平均） | −0.0008 | +0.0028 |
| **三码碰撞率** | **0.0253** | **0.0920** |
| 语义 R² | 0.280 | 0.299 |

**这个对照改变了上一轮的解读**：400 步 recon-only 微调本身就把碰撞率推到 0.092、把语义 R²
提到 0.299。因此：

- 上一轮"单链 margin 把碰撞率从 0.025 抬到 0.083"——**碰撞上升不是机制的代价**，而是微调
  本身的属性（对照 0.092，机制臂 0.083，反而更低）；
- 但该机制的**效果仍然成立**：链 Δ 从对照的 +0.0028 提到 **+0.0258**（≈ 9 倍），
  而对照的 L2 差值为 0.0000。

## 3. 结论

1. **L1 的"整体对齐"无论以损失还是以 Sinkhorn 代价的形式给出，都会退化**：前者坍缩到少数
   码字（碰撞 0.63），后者把编码器推向整批同点，被臂自身的守卫拒绝。要保留"L1 保留整体
   结构"，必须换一种有下界的形式（例如只要求"链内共享 > 链间共享"，并显式约束使用分布熵），
   或干脆把它交给分配规则本身的均衡性。
2. **L2 的平均共享 margin 是唯一在预算匹配对照之上有量级差异的项**（+0.0258 vs +0.0028），
   这与用户的原始设计一致。
3. **L3 需要真实碰撞组**才有梯度；但在 L1 失效的情况下，L3 没有可施加的对象。
4. 后续比较必须一律使用 **recon-only 同预算对照**，不能再用训练前基线——否则会把微调收益
   误记为机制收益（本轮已实际踩到）。

## 4. 下一步（按此结论）

先只做"L2 margin + L1 均衡分配（不加上对齐代价）"这一最小组合：L1 不施加任何共享压力，
只保留 Sinkhorn 的均衡性；L2 用已验证的 margin；L3 只监控碰撞。若该组合能同时保持
碰撞率 ≈ 对照水平、且链 Δ 显著高于对照，再考虑是否加入有条件约束的 L1。
