# L1 按商品 ID 取邻居码字 + 温度标定的 L2：结构监督确实生效，但代价是 L1 容量

## 1. 两处修复

| 审查项 | 上一版 | 本版 |
|---|---|---|
| L1 邻居对应关系 | 用**上一个 batch 的位置切片**，两个 batch 商品不同 → 结构项指向无关商品 | 维护**全局 item→code 表**（按商品 ID 写入本步 tokens），每个商品的邻居从链库**按 ID** 查出其当前码字；未见过的邻居不提供证据（先验保持均匀） |
| L2 软共享概率 | `std` 归一化 softmax，概率过平，hinge 全程停在 0.5 | 恢复臂自己的 **`measure_temperature` + `level_softmax`**（温度标定） |
| 守卫 | 已开启 | 保持开启（臂的 `Sinkhorn(SK_EPSILON=0.003, SK_ITERS=50)` + `ASSIGNMENT_FLOOR` 全部生效） |
| 评估 | 已统一 | 同一函数：L1+L2+L3 累积共享、同预算对照 |

## 2. 结果（400 步，同一 batch 序列，守卫全开）

| 指标 | 初始 | 对照组 | 结构接入组（修复后） |
|---|---:|---:|---:|
| 链 Δ（L1+L2+L3） | −0.0008 | +0.0018 | **+0.0686** |
| 置换零模型 95% 区间 | [−0.003, +0.003] | [−0.003, +0.003] | [−0.009, +0.012] |
| L1 相邻 / 两端 | 0.0076 / 0.0083 | 0.0114 / 0.0098 | **0.1989 / 0.1962** |
| L2 相邻 / 两端 | 0.0004 / 0.0004 | 0.0004 / 0.0003 | **0.0214 / 0.0139** |
| 三码碰撞率 | 0.0253 | 0.0729 | **0.5369** |
| 语义 R² | 0.280 | 0.277 | 0.255 |

训练日志：L2 损失从 0.500 降到 **0.46**（有真实信号，不再是平的），温度 `[1e-6, 0.0099]`
（第 1 层温度打到下限，说明最近码字距离≈0），梯度缩放 4e-4~1e-3。

## 3. 读数（重要区分）

1. **修复后 L1 真的起作用了**：链 Δ +0.0686 远超零模型，与此前 +0.0022 的"惰性"状态完全不同。
   这证明"L1 邻居对应关系错误"确实是上一轮无效的原因。
2. **但它起的作用是"整体集中"，不是"链式对齐"**：L1 相邻 0.1989 与两端 0.1962 只差 **+0.0027**
   —— 三者一起被推到 0.199（约 5 个有效码字）。真正的链式信号来自 **L2**（0.0214 对 0.0139，
   +0.0075）。
3. **代价超过收益**：碰撞率 0.073 → **0.537**，语义 R² 0.277 → 0.255。SID 已不可用于 Stage3。
4. **臂的均衡分配拦不住它**：`SK_EPSILON=0.003 / SK_ITERS=50` 与 `ASSIGNMENT_FLOOR` 都在运行，
   但 Sinkhorn 平衡的是软分配 `q`，最终仍是逐行 `argmax`，使用分布可在 `argmax` 后集中；
   而附加在距离上的 offset 又能把 `q` 进一步拉偏。

## 4. 结论

- **不能再说 L1 无效**：按 ID 修复邻居后，L1 结构代价明确改变了离散码字。
- **但当前形式不可用**：它把"共享更多"误当成"结构对齐"，付出 7 倍的碰撞率，而链式专有的
  L1 差异只有 +0.0027。
- **缺的是一条真正会约束容量的通路**，而不是更强的对齐压力。

## 5. 下一步（可执行的单一改动）

把 L1 的 offset 限制成**近邻并列时的决胜项**：只在"与最近码字距离相差 ≤ ε"的候选集合内
改变选择，ε 取该 batch 最近距离与次近距离之差的中位数（相对尺度，不试值）。这样：

- 使用分布由距离本身决定，offset 无法把商品推离其近邻码字 → 容量不会被牺牲；
- 链式对齐只能在注解歧义处生效，正是"前缀共享只在可行处发生"的工程对应；
- 仍走 `_distances` 内部、守卫全开、与同预算对照比较。

若该形式能在碰撞率不高于对照（0.0729）的前提下把链 Δ 显著推高（当前对照 +0.0018），
才说明 L1 结构监督可作为机制保留；否则应退回到"只保留 L2"的最小机制。
