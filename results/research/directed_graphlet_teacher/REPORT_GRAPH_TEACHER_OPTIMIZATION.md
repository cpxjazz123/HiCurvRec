## 0. 结论:先回答问题

> Teacher 之前是优化不足、模型表达受限、任务监督有问题,还是给定图与商品向量条件下未发现可泛化的新关系信号?

| 假设 | 判定 | 直接证据 |
|---|---|---|
| 优化不足 | **成立,主因** | 同一 B 架构、同一数据、同一 head:40 次真实更新 test AUC **0.5039**;600–725 次更新 **0.6780 / 0.6699** |
| 模型表达受限 | 不成立 | 固定 1,024 对过拟合 gate,B **1.000**、C **0.993**;C 在 held-out 上 **0.7473 / 0.7475** |
| 监督有问题 | **部分成立(方向任务)** | #227 的对称 pair head 无法表达 `score(i→j) != score(j→i)`,且方向损失与边损失同批相加;本轮的 edge-only 与 edge+direction 分开后,B 在联合损失下跌到 0.51,C 不受影响 |
| 无泛化信号 | 不成立(边存在性) | C−A = **+0.0395** [0.0372, 0.0418],C−D = **+0.0343** [0.0322, 0.0363](seed 平均,簇 bootstrap) |
| 方向可学 | **未成立** | 全部变体 balanced accuracy 0.4969–0.5111,真实多数类 0.5016 |

## 1. 步数语义(问题根源)

#227 的 `train_variant` 在 24 个子批次累积 Loss 后调用一次 `optimizer.step()`,外层循环 40 次
⇒ **40 次参数更新**,而不是 40×24=960。本轮定义为:

```
one step = zero_grad -> (forward, backward) x accum -> clip_grad -> optimizer.step()
```

计数分开记录:`epochs` / `microbatches` / `steps`;`accum=3`,`micro=4096` 对/子批次。
本轮每个臂的真实步数见下表(steps 列),没有一列是“epoch 数 × 24”。

## 8. 失败与停止记录

1. 首版 `graph_teacher3.py` 在 `degree_preserving_rewire`、稀疏张量宽度、特征方向三处有实现错误,
   均先写回归测试再修(见 `tests/test_teacher_optimization.py` 13 项)。
2. 主进程在 orbit profile 阶段被杀死:把 numpy 数组当 membership 集合用,`in` 是 O(N)。
   已修为 set;恢复脚本从 checkpoint 重算尾部,并断言重算 AUC 与原记录一致(20 个 checkpoint 全部通过)。
3. 高阶级特征(CN/AA/游走)在本划分上无区分度,未继续加深模型。
4. 方向任务未成立;没有因此调整数据或增加预算来“救”它。
