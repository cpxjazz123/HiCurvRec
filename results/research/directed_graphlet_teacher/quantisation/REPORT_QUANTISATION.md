# 冻结输入上的量化对照：行为信息经过 RQ-VAE 还能剩多少

**问题**：不改 RQ-VAE 的算法，只换输入——把 GNN 冻结表示直接喂给 RQ-VAE，与 768 语义主线比，
量化后还剩多少行为判别力？**没有任何额外结构损失**，所以差异只能来自输入。

**产物**：`run_quantisation_check.py`、`sweep.json`。

## 设置

| 项 | 值 |
|---|---|
| 引擎 | 冻结基线 `stage2_RQ-VAE/baseline/TIGER_RQ-VAE` 的 `RQVAE` + `build_distance` + `build_loss` |
| 冻结超参 | `HIDDEN_SIZES=[512,256,128]`、三级码本各 256、`CODEBOOK_DIM=32`、`BETA=0.25`、AdamW、seed 42，全取自 `config/train_config.json` 的 sha |
| 唯一扫描项 | `EPOCHS ∈ {50,150,400}`（冻结预算是 3000；这里看曲线形状，不是最终 SID） |
| 训练/验证划分 | 24587 商品按 seed 42 打乱，80% 训练引擎，20% 留出并且**完全不参与** |
| 探测 | 与 relation 审计同一批 45869 组三元组：`cos(q_a, q_b)` vs `cos(q_a, q_d)` 的 AUC；`q = decoder(tokens)` |
| 输入 | `semantics`=768 语义；`gnn`=冻结 GNN 表(128)；`gnn_pca128`=GNN 表白化 PCA 到 128；`semantics_pca128`=语义白化 PCA 到 128 |
| 无证据商品 | 133 个无行为证据商品的行替换为覆盖行均值，数量记在 `masked_rows` |

## 结果（修正后，2026-11-21 复审）

> 本报告上一版的三条结论全部撤回，原因与修复见 `../representation/RETRACTIONS.md`：
> 探测传入了未归一化向量（内积而非余弦）、留出商品的真实输入被均值替换、`q` 实际读的是
> Decoder 输出。下面是四项修正后重算的数字。

探测口径：`cos`（行先 L2 归一化），同一批 45869 组三元组；四个状态各自打分：
`input`=输入表、`z`=32 维编码器输出、`q`=**硬量化 32 维**、`decoder`=Decoder 输出（输入宽度）。

### 四臂（epoch 400，全部覆盖 / 仅留出）

| 臂 | 输入维 | R² | 三级碰撞 | 一级用码 | input | z (32) | q (硬量化 32) | decoder | 留出 input | 留出 q |
|---|---|---|---|---|---|---|---|---|---|---|
| semantics | 768 | 0.606 | 0.189 | 203/256 | 0.610 | 0.685 | 0.684 | 0.629 | 0.580 | 0.630 |
| gnn | 128 | 0.925 | 0.038 | 121/256 | 0.739 | 0.730 | 0.729 | 0.737 | 0.720 | 0.709 |
| gnn_pca128（度量控制） | 128 | 0.314 | 0.047 | 256/256 | 0.629 | 0.684 | 0.685 | 0.651 | 0.580 | 0.642 |
| semantics_pca128（宽度控制） | 128 | 0.500 | 0.174 | 252/256 | 0.608 | 0.648 | 0.649 | 0.628 | 0.580 | 0.614 |

三个 epoch 的完整曲线见 `sweep.json`；排序在 50/150/400 之间稳定。

## 现在能说什么

1. **量化对两种输入的作用方向相反**：`semantics` 由 input 0.610 升到 q 0.684（+0.074），
   `gnn` 由 0.739 降到 0.729（−0.010）。RQ-VAE 的 32 维编码器对 768 语义做了有益重加权，
   对已压缩的 GNN 表几乎没有可再压缩的空间。**上一版"量化几乎无损"因此撤回**：它把
   Decoder 输出当成了 q、又用了未归一化内积，两个效应同时被掩盖。
2. **GNN 输入仍优于语义主线**（全量 q 0.729 vs 0.684；留出 q 0.709 vs 0.630），但优势从
   上一版声称的 0.10 缩小到 0.045（全量）/ 0.079（留出）。
3. **`gnn_pca128` 是度量控制，不是容量证据**：128→128 白化只改尺度与度量，它的 input 0.629
   与留出 input 0.580 都和语义同水平，说明 GNN 表的优势来自其原始坐标的度量，白化后大部分丢失；
   因此不能由此断言"128 维信息已饱和"（上一版的说法已撤回）。
4. **`semantics_pca128` 才是宽度控制**：语义降到 128 后 q 0.649，低于全宽语义的 0.684，
   说明宽度确实损失了一部分可用信息，但与 GNN 的 0.729 仍有 0.08 差距。
5. **仍不能当更好 SID 的证据**：`gnn` 臂 R² 0.925、一级只用 121/256 个码，是低失真但码本利用不足；
   400 epoch 只是曲线，正式结论需要跑冻结的 3000 epoch。
6. **代价**：SID 从此依赖 GNN 表示，新商品/行为图更新如何产生同一条 128 维输出仍未回答。
