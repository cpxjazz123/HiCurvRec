# 方向来自序列时间，不来自商品对

## 问题

所有商品级模型（融合 / 不融合、有向 GNN / 无向 / 随机方向、困难负样本）都学不到方向。
是模型不够好，还是方向本身不在这条信息通道里？

## 检验

用训练序列（`train.parquet` 的 `history → target`）构造**相邻购买对** `(u_t, u_{t+1})`，
检查行为图里这条边的方向：

| 量 | 数值 |
|---|---|
| 相邻购买对总数 | 2,698,387 |
| 图中方向 **与时间同向** | **2,507,694** |
| 图中方向 **与时间反向** | **0** |
| 双向边 | 190,693 |
| 图中不存在 | 0 |
| 有向对中"顺时间"占比 | **1.0000** |

## 读数

1. **行为图的方向完全由购买时间决定**：2.5M 个相邻对里，**没有一个**是与时间相反的边。
   双向边对应"同一对商品在不同用户里出现于两种顺序"。
2. 因此"方向"是**序列的属性**，不是**商品对的属性**。任何只看两个商品静态向量
   （无论是 768 语义、32 维 z、还是任何图增强）的模型，在原理上都拿不到它——
   这解释了此前所有失败，包括原版 DiGAE 的 0.471。
3. 也解释了为什么"增强越强、AUC 越高、方向越差"：增强把商品级关联做得更清楚，
   而关联本来就不含方向。

## 结论

- **不要再试图从商品级 Embedding 预测方向**；这条通道里没有这个信息。
- 若确实要让 SID 保留方向，需要**序列级信息**：例如时间感知的 item 表示
  （购买时间分布、位置分布），或者把方向作为序列建模目标（下一跳预测）而不是
  商品对分类。
- 这是本轮唯一一个**机制性结论**：它不是"某个模型没调好"，而是信息源与目标的错配。
