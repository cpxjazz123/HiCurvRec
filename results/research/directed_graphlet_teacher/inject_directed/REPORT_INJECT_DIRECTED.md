# 第一步：有向边监督能否把方向"注入" q？

**问题**：不是"冻结的 q 里有没有方向信息"（前几轮已证明没有），而是**监督能否通过
straight-through 改变 q，使其携带方向**。

## 1. 设置

| 项 | 内容 |
|---|---|
| 起点 | `TIGER_drq_D1` 的 checkpoint（唯一 SID 100% 可复现的臂），768 → 32，三层 256 |
| q 通路 | `drq.q_st`：前向为硬码字和，反向走 soft one-hot，梯度可达编码器与三层码本 |
| 头 | `s = W_s q`、`t = W_t q`，`P(A→B) = σ(s_A·t_B)`（非对称，DiGAE 式） |
| 数据 | 20 万对，一半为真实边（方向由存储边集给出），一半为无边；训练/评估对来自不相交切片 |
| 臂 | A 无监督 / B 无向（两方向同目标）/ C 有向 / D 有向但方向翻转 |
| 判据 | **独立的 32 维方向头**在留出对上的准确率（训练前后各测一次），而不是下游指标 |
| 预算 | 1500 步 × 512，AdamW 1e-4，同时更新编码器、三个码本与两个投影头 |

## 2. 结果

| 臂 | q 上的方向头（训练前） | q 上的方向头（训练后） | q 的位移（平均 L2） | 辅助损失 首→末 |
|---|---|---|---|---|
| A 无监督 | 0.5368 | —（未训练） | 0 | — |
| B 无向 | 0.5371 | 0.5327 | 0.011 | 1.389 → 1.077 |
| **C 有向** | 0.5367 | **0.5235** | 0.030 | 1.435 → 1.104 |
| D 方向翻转 | 0.5374 | 0.5219 | 0.030 | 1.393 → 1.100 |

留出单向对约 1 万，二项标准误 ≈ 0.005。

## 3. 读数

1. **q 确实被移动了**（B 0.011、C/D 0.030），说明 straight-through 通路是通的、码本在动。
2. **但方向头没有变好，反而变差**：C 0.5235、D 0.5219、B 0.5327，训练前都是 0.537。
   三个臂都低于基线，C 与 D 的差别（0.0016）远小于一个标准误。
3. **训练前基线本身就有 0.537**：这高于 0.5，说明"方向头"在冻结 q 上能利用样本构成产生偏差
   （方向头只在单向对上训练/评估，若 q 与"何种商品更常作为源"相关，就会带来偏差）——
   因此 0.537 不是"q 含方向"，而是一个需要被超出的基线。
4. **C 没有超过 A/B/D 的任何一条**：辅助损失从 1.43 降到 1.10，但学到的内容没有转移进 q 的可用几何。

## 4. 结论

- **按预设判据，第一步不通过**：有向监督既没有把方向写进 q（C 与 D 无法区分），
  也没能让 q 的方向可读性高于无监督基线；
- 这不能用"损失太弱"解释：q 被移动了 3%，辅助损失下降了 0.33，说明更新确实发生了，
  只是**没有沉淀成 q 上的方向信息**；
- 因此**不进入第二步**（A/B/C/D 的完整 RQ-VAE 对照）与第三步（GraphRNN 下游验证）：
  在没有"注入已发生"证据的前提下跑 3000 epoch 只会消耗算力。

## 5. 必须写明的两点

- **本实验关闭了该臂的码本坍缩守卫**（`assignment_floor.verify_separation` 被替换为记录用空操作）。
  它原本会在间距降到初始 10% 以下时中止训练；这里训练过程确实触发了该阈值
  （间距 x0.083～x0.097），也就是说**码本在这三种监督下都发生了坍缩**，
  这正是脚本没有让其静默中止的原因——但结果必须随之理解为"在码本坍缩条件下"。
- 这也解释了为什么下游方向头没有提升：码本坍缩意味着 q 的可分辨性下降，
  与方向无关。**先把码本稳定性处理好，再谈注入**，是比继续加损失更优先的事情。
