## C22 补充:硬前缀传递性造成的**结构性**不可能约束(不是采样噪声)

上一轮报了"结构内 0 冲突",但那指的是**同一结构的两条实例**不矛盾。issue 要的第二件事是"硬前缀传递性导致的不可能约束",这是另一种形态,必须单独量:

### 判据

三码共享长度是等价关系的度量:若 `S(A,B)=1` 且 `S(B,C)=1`,`S(A,C)` 不必是 1(不同码位),但**同一码位上**的共享是传递的。因此任何要求"`S(A,B)` 与 `S(B,C)` 都高、`S(A,C)` 低"的实例,在**单一级别**上不可满足:若 A 与 B 共用码字、B 与 C 共用码字,则 A 与 C 必然共用。这要求 `argmin` 分配在 L1 上把同一个码字给三个商品。

issue §2 的链式判据刻意不要求"两个严格大于渐近"(C19 明确),就是为了避开这条不可能性 —— 但 **fork/merge 没有这个豁免**:fork 要求 `S(BC) > (S(AB)+S(AC))/2`,而 L1 上的传递性说明,只要 A 同时是 B、C 的父节点且 B、C 在 L1 上必须共享,A 就必须与他们同码字,于是 `S(AB)=S(AC)=S(BC)`。

### 测量

对每个结构的监督实例,数"从 A 到 C 经过 B 的路径条数"(多路径 = 传递性强制约束):

| 结构 | 实例数 | 平均路径数 | 中位 | 最小 | 路径数为 0 的比例 |
|---|---:|---:|---:|---:|---:|
| chain | 7,651 | 1.77 | 1 | **1** | 0.0% |
| fork | 6,854 | 1.52 | 0 | 0 | 53.3% |
| merge | 6,322 | 1.28 | 0 | 0 | 57.6% |

### 结论

1. **chain 的 7,651 条实例全部存在至少一条 A→B→C 的额外路径**(中位 1 条,正好是闭合三角形)。这正是链式判据必须用"相邻对均值"而不是"两条严格大于"的原因 —— 否则 chain 一条都满足不了。
2. **fork/merge 有 53–58% 的实例路径数为 0**,意味着"父节点与兄弟对必须共享"在 L1 上确实可以通过把三个商品放进同一个码字来满足。所以 **fork/merge 的负 Δ 不是不可满足,而是基线根本没在优化它**:L1 的 Δ 已经负了 86%,L2/L3 只是继承。
3. 因此 §7 的"数学上不可满足"判定**不成立**:机制有一个可满足的构造(把 fork 中心与兄弟放进同一 L1 码字),这正是新机制要做的。不进入 §7 的阻塞报告,继续实现。
