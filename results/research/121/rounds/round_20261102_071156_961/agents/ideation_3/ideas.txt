IDEA: CURVCHART-EQUIMARGIN-RQ
TITLE: Per-code chart curvature on the training behaviour quotient graph, spent as a hard-marginal entropic transport assignment that cannot give up codebook resolution.
MOTIVATION: The previous round proved that the standardised behaviour-graph curvature profile carries real signal (Spearman -0.20 over 115 mechanism families on the level-1 minus level-3 deviation) but that spending it on the per-level code radius destroys the thing recall actually needs: resolution. That run exported 2/13/56 SIDs, collision 0.998, level-1 positive/negative hit rates 0.982/0.980 (the first token carried no information), and scored 0.041888. The underlying pathology is level collapse in the first RQ level: 2 of 256 codes alive. This idea gives the curvature a place to act where it cannot shrink anything, and separately removes the collapse by construction.
NOVELTY: Three things absent from CURVALLOC-LORENTZ-RQ, BRad-RQ, CURVCTRL-SID, behcone-prefix-rq, poincare-frechet-successor-codebook, succboost-geoshift, MIXCURV-FIBRE-RQ, LORENTZ-SUCCPROFILE-SMOOTH-RQ and BRANCHCURV-MOEB-RQ. (1) Curvature is a FIELD, one value per code per level, `kappa_{l,k} = kappa_0 * exp(alpha * kappa_hat_{l,k})`; all earlier mechanisms set one number per level and applied it to the whole level. (2) Curvature acts on the DISTANCE CHART of each code, never on the code vector, its norm, its count or the space's radius; the code table keeps the inherited parameterisation bit for bit. (3) The assignment is an entropic optimal transport problem with hard uniform column marginals, so code utilisation is fixed at B/K by the constraint, not by a loss weight; the resolution guarantee is a constraint, not a hyperparameter. Curvature reorders who goes where and is structurally forbidden from changing how many codes are used.
CHANGE: Each RQ level solves its assignment as a Sinkhorn transport problem whose per-code cost uses a Poincare distance in the code's own curvature chart `kappa_{l,k}`, with uniform column marginals; the per-code curvatures come from the standardised Ollivier curvature of the K-node code-transition quotient graph built from training transitions under the previous sync's memberships, so curvature can only permute items between codes, never remove codes.
SPECIFICATION:
  Notation: level l in {1,2,3}, K_l codes per level, batch B items (B = 1023 at the frozen scale).
  Code table: `c_{l,k} in R^d`, inherited parameterisation, inherited init, inherited K_l. Untouched by this mechanism.
  Residual: `x_i^(1) = E(u_i)`; `x_i^(l+1) = x_i^(l) - c_{l, a_i^(l)}`.
  Scale: `s_l = 0.99*s_l + 0.01*RMS(||x_i^(l)||)`. Curvature base `kappa_0 = 1/(s_l^2 + 1e-8)` (derived from the measured residual scale, no free constant).
  Ball embedding: `rho_k(z) = (tanh(sqrt(k)||z||/2) / (sqrt(k)||z||)) * z`, `rho_k(0)=0`.
  Poincare distance: `d_k(x,y) = (2/sqrt(k)) * artanh( sqrt(k) * || (-x)(+)y || )`, with `(-x)(+)y = ((1-k|x|^2)y - (1-k|y|^2)x) / (1 - 2k<x,y> + k^2|x|^2|y|^2)`.
  Local chart distance (the object the mechanism spends): `dhat_k(x,y) = d_k(x,y) / lambda_k(y)`, `lambda_k(y) = 2/(1 - k|y|^2)`. Note `dhat_k -> ||x-y||` as `k -> 0`.
  Assignment cost: `C_l[i,k] = dhat_{kappa_{l,k}}( rho_{kappa_{l,k}}(x_i^(l)), rho_{kappa_{l,k}}(c_{l,k}) )^2 / eps_l`, `eps_l = median(C_l)` detached.
  Transport: `P_l = Sinkhorn(C_l, r = 1/B, c = 1/K_l, iters = 8)` on kernel `exp(-C_l)`.
  Forward assignment `a_i^(l) = argmax_k P_l[i,k]`; straight-through: code term uses `sum_k P_l[i,k] c_{l,k}` with argmax as the forward value and the soft plan as the backward gradient.
  Curvature field (schedule, no gradient), synced every S = 20 epochs from last-synced detached memberships `A_l[i]`:
    `N_l[k,k'] = #{ (u,v) in T_train : A_l[u]=k, A_l[v]=k' }`, `W_l = N_l + N_l^T`.
    `P_l = N_l / max(rowsum, 1)`.
    For each edge `(k,k')` with `W_l[k,k']>0`: `kappa(k,k') = 1 - W1(P_l[k,·], P_l[k',·]) / d_Gamma(k,k')`, `d_Gamma` = hop distance on the quotient graph, W1 = entropic Wasserstein with the same Sinkhorn solver (20 iterations).
    `kappa_raw[l,k] = sum_{k'} W_l[k,k'] kappa(k,k') / sum_{k'} W_l[k,k']`.
    Null: shuffle item->code labels `A_l` uniformly (fixed torch seed), recompute `kappa_raw` 8 times (documented default) giving `mu[k], sigma[k]`.
    `kappa_hat[l,k] = clip( (kappa_raw[l,k] - mu[k]) / (sigma[k]+1e-6), -3, +3 )`.
    `kappa_{l,k} = kappa_0 * exp(alpha * kappa_hat[l,k])`, `alpha_0 = 1`.
  Safeguard schedule: after each sync, on a fixed 4096-item TRAINING probe compute `U_l` (codes used) and `D` (distinct SIDs); if `U_l < 0.9*K_l` then `alpha <- 0.5*alpha` (automatic decay, capped at 5 halvings). No searching.
  Switches (present in code, all correct, none trained as an arm): BEHAVIOUR off sets `kappa_hat := 0` so all codes share curvature `kappa_0`; GEOMETRY off sets `kappa_{l,k} := 0` so `dhat` is Euclidean and `kappa_hat` has no channel; BOTH ON is the full path above.
COST: Frozen scale: 24556 training items, 24 steps per epoch, B = 1023 items per step, K = 256, L = 3, 3000 epochs.
  Per step: 3 levels x 1023 x 256 = 785,664 cost entries, each needing tanh/artanh/exp/log/sqrt; 8 Sinkhorn sweeps on the same matrices = ~6.3M elementwise ops plus ~30 small kernel launches; extra activations 3 x (1023x256) float32 = 3.1 MB. Estimated +3% to +6% step time, zero extra trainable parameters (the field is 3x256 scalars set by schedule, not by gradient).
  Curvature sync: 3000/20 = 150 syncs x 3 levels on a 65536-entry quotient graph with typically ~5e3 nonzero edges, each edge a 20-iteration Sinkhorn W1 over 256 bins: ~150 x 3 x 5e3 x 20 x 256 = 1.2e10 elementwise ops over the whole run, tens of seconds of GPU time; the 8 shuffle nulls multiply that by nine, still under a few minutes total.
  Collective cost: one `all_reduce(SUM)` of a fixed-shape float32 tensor [3,256,256] (768 kB) per sync, 150 times. Fixed shape, identical order on all four ranks, no variable-length transport support, no rank-0-only broadcast, no CPU tensor collective.
HYPOTHESIS: The profile can be expressed as a per-code chart that only reorders items, while a hard equipartition supplies the resolution the previous round lost. Confirmed in the single run by: (i) used codes `U_l >= 0.9*K_l` after the first sync instead of 2/256; (ii) exported SID counts at least 247/7414/20223 and collision rate far below 0.998; (iii) the level-1 positive-minus-negative hit-rate gap growing past 0.02 (baseline gap 0.002), i.e. the first token starts carrying information; (iv) Stage3 test_recall@10 above 0.055537, reaching 0.065 if the resolution gain translates. If (i)-(iii) hold and (iv) does not, the diagnosis is that the coarse partition was forced too flat and the chart field is not the limiter.
RISKS: Hard uniform marginals may be too rigid for a genuinely hierarchical corpus, splitting natural coarse clusters and inflating prefix entropy; utilisation would be perfect while level-1 accuracy degrades. The one-epoch-lag feedback (curvature from last memberships, memberships from curvature) may oscillate or lock into a self-confirming partition; the 20-epoch sync and the alpha decay are the only damping. On a 65536-entry quotient graph many codes have few edges, so `kappa_raw` can be noise-dominated even after shuffle standardisation, and the +-3 sigma clip may then produce a nearly uniform field that degenerates to the geometry-only behaviour. Ollivier W1 on a sparse quotient graph is a crude proxy and may be uncorrelated with the item-level curvature measured in round 1. Forcing exactly 4 items per code per step means level 1 can no longer represent a dominant generic prefix, which may be right for the export and wrong for the training signal.
BEHAVIOR SIGNAL: Directed item transitions (u -> v, v the next interaction in the same training sequence), aggregated into a code-level transition graph; the quantity the mechanism consumes is the Ollivier curvature of that quotient graph, i.e. how much the successor distributions of two codes overlap.
BEHAVIOR COMPUTATION: Enumerated from TRAINING split interactions only, in order, giving a multiset `T_train` of directed pairs (u,v). For each level l each pair is mapped to `(A_l[u], A_l[v])` using the last-synced detached memberships, EMA-updated every 20 epochs from the current argmax assignment. Count, symmetrise (`W = N + N^T`), row-normalise, compute per-edge Ollivier curvature with an entropic W1 over the quotient graph, aggregate per node by W-weighted mean, standardise against a member-shuffle null (8 shuffles), clip to +-3 sigma. No gradient flows through any of it; it is a schedule producing 3 x 256 scalars every 20 epochs.
LEAKAGE BOUNDARY: The transition set is built exclusively from training-split sequences. Validation and test sequences are never enumerated, never mapped to codes, never enter the quotient graph or the null. The null shuffles only training memberships, so `sigma` is a property of the training split's own size and degree distribution. The 4096-item probe used by the alpha safeguard is drawn from training items only. The exported SID is a deterministic function of the training-only code table, training-only transition graph and training memberships, and since the protocol has no early stopping there is no validation signal that could select an epoch. Nothing in the assignment consumes a validation or test interaction.
HYPERBOLIC OPERATOR: Poincare ball distance with schedule-set per-code curvature `kappa_{l,k} = kappa_0 * exp(alpha * kappa_hat_{l,k})`, where `kappa_0 = 1/s_l^2` comes from the measured residual RMS and `kappa_hat` is the clipped standardised behaviour curvature. The distance is normalised by the conformal factor at the code, `dhat_k = d_k / lambda_k(c)`, so the chart reduces exactly to the Euclidean metric as `kappa -> 0`.
HYPERBOLIC LOCATION: Inside the RQ-VAE quantisation, in the assignment step of every level: it defines the cost matrix that the entropic transport plan minimises, hence which code each item inherits at each level. It does not touch the code parameters, their norms, the codebook sizes, the loss weights, the decoder or the generative recommender.
COUPLING PATH: Single path: training transitions -> code quotient graph -> standardised Ollivier curvature `kappa_hat[l,k]` -> per-code chart curvature `kappa_{l,k}` -> Poincare chart distance in the cost matrix `C_l` -> Sinkhorn plan `P_l` with uniform marginals -> forward SID token `a_i^(l)`. The behaviour term is multiplied into the curvature, the curvature is the only thing that changes the metric, and the metric is the only thing that changes the plan; drop behaviour (`kappa_hat = 0`) and every code shares one curvature so the plan becomes the curvature-uniform one; drop geometry (`kappa = 0`) and the metric is Euclidean so the behaviour field has no channel. Neither acts alone.
COUPLING EQUATION: `C_l[i,k] = dhat_{kappa_0 * exp(alpha * kappa_hat[l,k])}( rho_{...}(x_i^(l)), rho_{...}(c_{l,k}) )^2 / eps_l`, with `kappa_hat[l,k] = clip( (kappa_raw^{W_l}[l,k] - mu[k]) / (sigma[k]+1e-6), -3, 3 )` computed from the training transition counts `W_l`, and `P_l = argmin_{P in U(1/B, 1/K_l)} <P, C_l> - eps_l H(P)`.
OBSERVABLES: Used codes per level `U_l` (2/13/56 in the failed arm; 247/7414/20223 distinct SIDs in the frozen baseline); distinct SID count and collision rate; level-1 and level-2 positive-minus-negative hit-rate gap (baseline 0.982 vs 0.980); prefix-conditional entropy `H(next prefix | current prefix)` per level measured on the training split only; Spearman correlation between `kappa_hat` and the level's realised utilisation; variation of information between the current assignment and the previous sync's assignment (small but nonzero, showing the field is doing something stable); Stage3 test_recall@10.
ABLATION BEHAVIOR OFF: `kappa_hat[l,k] := 0` for all k, so `kappa_{l,k} = kappa_0` everywhere. The Poincare chart, the Sinkhorn plan, the uniform marginals and the code table are identical to the full run; only the per-code curvature differences disappear, so the plan becomes the curvature-uniform balanced transport plan. Isolates whether the behaviour field, rather than the balanced transport, carries the gain.
ABLATION GEOMETRY OFF: `kappa_{l,k} := 0` for all k, so `dhat_k` is the ordinary Euclidean distance and the assignment is a Euclidean balanced transport with the same uniform marginals. The curvature measurement still runs and still produces `kappa_hat`, but `kappa_hat` now multiplies nothing that survives the `kappa -> 0` limit, so the behaviour signal is provably inert. Isolates the curved chart and, by construction, the coupling itself.
ABLATION BOTH ON: The run that is actually trained: per-code chart curvature from the training quotient graph, hard uniform column marginals, straight-through assignment, inherited code table, 3000 Stage 2 epochs on four cards, then the frozen Stage 3 protocol with no early stopping. One run, one seed; the switches exist in the code and are asserted correct in a unit test at B=8, K=4 against hand-computed Poincare distances, but no arm is trained.
SPEC EQUATIONS:
```
# per step, per level l
s_l        = 0.99*s_l + 0.01*RMS(||x^(l)||);   kappa_0 = 1/(s_l^2 + 1e-8)
kappa[l,k] = kappa_0 * exp(alpha * kappa_hat[l,k])      # behaviour-off: kappa_hat:=0 ; geometry-off: kappa:=0
y_i        = rho_{kappa[l,k]}(x_i)                       # broadcast over k
ct_k       = rho_{kappa[l,k]}(c_{l,k})
D2[i,k]    = d_{kappa[l,k]}(y_i, ct_k)^2 / (lambda_{kappa[l,k]}(ct_k)^2 + 1e-8)
C[i,k]     = D2[i,k] / (median(D2) + 1e-8)
Kmat       = exp(-(C - rowmin(C)))
for t in 1..8:
    Kmat = Kmat / (rowsum(Kmat) * B)          # row marginal 1/B
    Kmat = Kmat / (colsum(Kmat) * K_l)        # col marginal 1/K_l
P      = Kmat / rowsum(Kmat)
a_i    = argmax_k P[i,k]
loss   = recon(x_i - sum_k P[i,k] c_{l,k}  [straight-through])
       + lambda_commit * || x_i - sg(sum_k P[i,k] c_{l,k}) ||^2      # inherited loss, unchanged

# every 20 epochs, all four ranks, no gradient
N[k,k']      = bincount(A[u]*K + A[v] for (u,v) in T_train).reshape(K,K);  W = N + N.T
Prow         = N / clamp(rowsum(N), 1)
kap(k,k')    = 1 - sinkhorn_W1(Prow[k], Prow[k'], d_Gamma, iters=20) / d_Gamma(k,k')
kappa_raw[k] = sum_k' W[k,k']*kap(k,k') / clamp(sum_k' W[k,k'], 1)
mu, sigma    = mean and std over 8 member-shuffles of kappa_raw
kappa_hat    = clamp((kappa_raw - mu)/(sigma + 1e-6), -3, 3)
if used_codes_on_train_probe(level l) < 0.9*K_l:  alpha *= 0.5
```
SPEC INPUTS OUTPUTS:
  Input (per step): `x_i^(l)` for i=1..B (encoder output or residual), the code table `c_{l,k}` for k=1..K_l, the current field `kappa_hat[l,·]` (a 256-vector refreshed on schedule), the measured scale `s_l`.
  Output (per step): a hard token `a_i^(l)` in {1..K_l} per item per level, the soft plan `P_l` used for the straight-through gradient, and the next residual `x_i^(l+1) = x_i^(l) - c_{l,a_i^(l)}`.
  Input (per sync): the training transition pair list, the last-synced memberships `A_l` over all training items, one fixed shuffle seed and shuffle count 8.
  Output (per sync): the `3 x 256` curvature field plus recorded diagnostics (`kappa_raw`, `mu`, `sigma`, utilisation, conditional prefix entropy, collision rate). The field is broadcast inside the same fixed-shape all_reduce, so every rank holds an identical copy with no separate communication.
SAFEGUARDS:
  Distances: clamp the Mobius sum norm to `1 - 1e-6` before artanh; clamp the ball radius to `0.9/sqrt(kappa)` when embedding; add `1e-8` inside every sqrt, log and division; clamp `||z|| >= 1e-8` before the `rho` division so `rho_k(0)=0` is exact.
  Curvature: clamp `kappa` to `[1e-3*kappa_0, 1e3*kappa_0]` so the chart can never invert or vanish; clamp `kappa_hat` to +-3 sigma so one noisy code cannot dominate; add `1e-6` to `sigma`.
  Transport: subtract the row-minimum of `C` before `exp`; if a row has all-equal `C` under float precision, fall back to the uniform plan for that row; if `B < K_l` so a uniform column marginal is unattainable, restrict that step to a fixed cycling subset of `K_l` codes of size B chosen by a fixed permutation, so all codes are covered across steps.
  Utilisation: the automatic alpha halving when a level's training-probe utilisation drops below `0.9*K_l`; it only ever shrinks the curvature spread, never the codebook, and is capped at 5 halvings.
  Determinism and deadlock: the code-transition counts live in a fixed `[L,K,K]` float32 buffer, zeroed first and filled by `index_add`, then `all_reduce(SUM)` with every rank participating in the same order and the same shape; no rank-0-only path, no CPU-side broadcast, no variable-length transport support. Export writes the SID CSV from rank 0 after a barrier and every other rank proceeds to the next epoch without waiting on a broadcast; the shuffle null uses a seed derived only from the level and the sync index, so all four ranks generate the same shuffle without communication.
  Feedback stability: the field is refreshed from a detached EMA of memberships (momentum 0.9), never from the current step, so the assignment and the field cannot chase each other within an epoch.
END IDEA
