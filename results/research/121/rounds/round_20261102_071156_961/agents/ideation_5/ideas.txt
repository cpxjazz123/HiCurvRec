IDEA: CURVEBEND-NORM-RESIDUAL
TITLE: Resolution-safe behaviour-curvature bending of the RQ residual direction
MOTIVATION: Round 20261102_031529_470 spent the null-standardised behaviour-graph curvature on the code radius rho_l inside the RQ-VAE assignment and collapsed the codebook (2 first-level codes, 13 prefixes, 56 SIDs, collision 0.998, L1 positive/negative hit rates 0.982/0.980, Stage3 test_recall@10 0.041888). The recommendation problem is still the one the correlation analysis identified: the coarse level should stay flat and the fine levels should be more curved, so that items inside one coarse prefix split into behaviourally meaningful sub-branches, which is what the generative model needs to predict fine SID tokens. This proposal obtains that profile without touching any code scale.
NOVELTY: In every earlier mechanism the curvature changes the codebook (radius, assignment metric, codebook update, or a code-level loss). Here the curvature changes only the DIRECTION of the inter-level residual, and the residual norm is preserved exactly, so the code vectors, their count, their radius and the commitment weight are unchanged in form from the frozen baseline. The curvature magnitude is expressed in units of the measured median residual norm of that level, so the bend is scale-free; the profile is the null-standardised Ollivier curvature of the level's own behaviour quotient graph, referenced to the coarse level (z_1 - z_l), which is exactly the quantity the earlier 115-family analysis found predictive (Spearman -0.20 for the level-1 minus level-3 deviation). No prior mechanism bends the residual direction.
CHANGE: Replace the Euclidean RQ residual r_{l+1} = r_l - c_l with a unit hyperbolic direction times the original Euclidean residual norm, r_{l+1} = ||r_l - c_l|| * unit( (-exp(c_l)) (+) exp(r_l) ) in a Poincare ball whose curvature kappa_l is a detached, null-standardised, coarse-referenced behaviour profile, applied to the residual entering levels 2 and 3 (level 1 stays Euclidean). Nothing else changes: same encoder, same codebook sizes, same code-radius rule, same losses, same Stage3 protocol.
SPECIFICATION: Notation: ball B_k = {x : k||x||^2 < 1}, Mobius addition x (+) y = ((1 + 2k<x,y> + k||y||^2)x + (1-k||x||^2)y) / (1 + 2k<x,y> + k^2||x||^2||y||^2), exp_0^k(v) = tanh(sqrt(k)||v||) v/(sqrt(k)||v||), log_0^k its inverse. Residual operator bend_k(r,c): v = r-c; if ||v|| < eps return 0; p = exp_0^k(r); q = exp_0^k(c); w = (-q) (+) p; if ||w|| < eps return ||v|| v/||v||; return ||v|| w/||w||. As k -> 0, exp_0 -> id and (+) -> +, so w -> v and the operator returns exactly v. Curvature schedule every 100 epochs, detached, training split only: build the item transition graph W; for l=1,2,3 map training items to their current level-(l-1) prefix (level 1 = item itself), sum W over prefix pairs to obtain quotient adjacency A_l, compute edge Ollivier-Ricci curvature with a lazy random walk and Wasserstein-1, take the transition-count-weighted mean kappa_raw,l, standardise against B=10 size-preserving nulls (level 1: degree-preserving stub rewiring of W; levels 2,3: shuffle item-to-prefix membership preserving prefix sizes), z_l = clip((kappa_raw,l - mu_null,l)/sigma_null,l, -3, +3). Then b_l = z_1 - z_l, k_ref,l = 1/m_l^2 with m_l the median training residual norm ||r_l - c_l|| at the previous recompute, and kappa_l = clip(k_ref,l * exp(b_l/2), 0.22*k_ref,l, 4.48*k_ref,l). For l=2,3 set r_l <- bend_{kappa_l}(r_{l-1}, c_{l-1}) before the level-l nearest-code search; level 1 uses r_1 = z unchanged. The three switches are constructor flags: BEHAVIOUR_OFF sets z_l = 0 for all l (flat profile, kappa_l = k_ref,l, geometry still active); GEOMETRY_OFF sets kappa_l = 0 exactly (exp_0 = id, (+) = +, residual = r_l - c_l, Euclidean RQ); both on uses the real z_l. No arm is trained in this round; the flags exist only so the coupling can be audited.
COST: At the frozen scale (24556 training items, 24 steps/epoch, 3000 epochs = 72000 steps, batch ~1023): the bend adds per item per bent level two exp_0 (d tanh), one Mobius add (~12d mul/add) and two norms, about 40d flops; with d=64 and two bent levels this is ~5 MFLOP per step, under 0.5 ms on one GPU, about 0.2-0.5 percent of step time, ~30-40 s over the whole run. The curvature schedule runs 30 times: one full encode of 24556 items (24 batches), prefix aggregation, edge curvature and 10 null shuffles, roughly 1-3 min on one CPU core per recompute (30-90 min total, 1-3 percent of a multi-hour four-rank run). No new trainable parameters, no extra forward pass in the training step, no collective.
HYPOTHESIS: If the coarse-to-fine curvature deviation is spent on the residual direction instead of the code radius, then fine-level code boundaries align with behaviour sub-communities while the codebook keeps the baseline resolution; the Stage3 model then sees finer tokens that are predictable from the coarse prefix, and test_recall@10 rises above the inherited 0.0446 and the frozen 0.055537 toward 0.065. It is worth keeping only if the counterfactual assignment sensitivity is non-trivial (a measurable fraction of items changes level-2/3 code when b_l is zeroed or kappa_l is set to 0) AND the exported table still has at least the inherited 247/7414/20223 distinct L1/L2/L3 counts with a collision rate near the baseline rather than 0.998.
RISKS: The direction bend could be too weak in high dimension (residuals are nearly orthogonal to codes) and act as noise; the level-2 and level-3 quotient curvatures are estimated on thousands of small prefixes and may be unstable despite null standardisation; the codebook/quotient feedback loop could oscillate (mitigated by the 100-epoch schedule, the z clip and the usage monitor); the generative Stage3 model consumes only tokens, so a geometrically nicer residual may not translate into prefix predictability; Mobius arithmetic near the ball boundary can lose precision in float32.
BEHAVIOR SIGNAL: Directed item-to-item transitions and user-interest branching extracted from training sequences, aggregated at each RQ level into a prefix-level quotient graph whose standardised Ollivier-Ricci curvature profile is the behaviour term.
BEHAVIOR COMPUTATION: From the training split only, over all training sequences, count directed pairs (u_t -> u_{t+1}) with immediate repeats suppressed, giving a sparse item transition matrix W (24556 x 24556). At recompute time, take the current DDP-synchronised encoder and codebooks, encode the 24556 training items once, assign prefixes 1..l-1, and sum W over prefix pairs to build the sparse quotient graph A_l (level 1 is the item graph itself). Compute Ollivier-Ricci curvature per edge (lazy random walk with standard 0.5 laziness, Wasserstein-1 via a sparse min-cost solve or Sinkhorn with a fixed small epsilon), and take the transition-count-weighted mean as kappa_raw,l. Null: B=10 replicates; for level 1 rewire W by degree-preserving stub matching; for levels 2,3 permute the item-to-prefix labels while preserving each prefix size, then recompute. z_l is the standardised deviation. Everything is computed with torch.no_grad and stored as a schedule tensor; it never enters the backward graph.
LEAKAGE BOUNDARY: W is built exclusively from training-split sequences; validation and test sequences are never read, and no validation or test item is added to the graph or to the prefix map used for curvature. The null shuffles permute only training items. The schedule uses only the training item universe and the current codebook, which itself is trained on the training split. The exported SID table is built from the training item universe only. No validation or test interaction, reward, or click can enter kappa_l or the residual operator, and the Stage3 protocol remains frozen and untouched.
HYPERBOLIC OPERATOR: Poincare ball of fixed negative curvature -kappa_l (kappa_l > 0), with Mobius addition, exponential map at the origin exp_0^k(v) = tanh(sqrt(k)||v||) v/(sqrt(k)||v||), logarithm log_0^k, and the geodesic direction of the residual taken at the chosen code, w = (-q) (+) p. kappa_l is fixed per level and per 100-epoch block (not backpropagated); it is bounded to [0.22, 4.48] * k_ref,l by the z clip.
HYPERBOLIC LOCATION: In the RQ quantization path between levels: the curved operator transforms the residual that enters levels 2 and 3, before the level's nearest-code search. It does not act on the code radius rho_l, the code count K_l, the assignment metric, the commitment weight, the encoder, or the decoder.
COUPLING PATH: Training behaviour graph -> quotient graph at each RQ level -> null-standardised Ollivier curvature z_l -> coarse-referenced bend b_l = z_1 - z_l -> level curvature kappa_l -> Mobius exp/add in bend_kappa -> direction of r_l entering level l -> level-l nearest-code assignment -> prefix and SID tokens -> Stage3. Removing behaviour (z_l = 0) flattens kappa_l to k_ref,l and changes the direction of r_2 and r_3. Removing geometry (kappa_l = 0) makes exp_0 the identity and (+) ordinary addition, so r_l = r_{l-1} - c_{l-1} and the path is Euclidean RQ. Either switch changes the same tensor path and therefore the assignment.
COUPLING EQUATION: r_l^{in} = ||r_{l-1} - c_{l-1}|| * ( (-exp_0^{kappa_l}(c_{l-1})) (+)_{kappa_l} exp_0^{kappa_l}(r_{l-1}) ) / || (-exp_0^{kappa_l}(c_{l-1})) (+)_{kappa_l} exp_0^{kappa_l}(r_{l-1}) ||, with kappa_l = clip( k_ref,l * exp( (z_1 - z_l)/2 ), 0.22*k_ref,l, 4.48*k_ref,l ), z_l = clip( (kappa_raw,l - mu_null,l)/sigma_null,l, -3, +3 ), and k_ref,l = 1/m_l^2 measured from the training residual scale. The behaviour term is (z_1 - z_l); the curved term is exp_0^{kappa_l} and (+)_{kappa_l}; the Euclidean limit is kappa_l = 0.
OBSERVABLES: (1) Exported table resolution: distinct L1 codes, L2 prefixes, L3 SIDs, and collision rate, compared with the frozen 247/7414/20223 and with the failed 2/13/56 and 0.998. (2) Per-level code-usage entropy, compared with its own epoch-0 value. (3) L1 positive and negative hit rates, which must not both sit at ~0.98. (4) Counterfactual assignment sensitivity measured forward-only inside the single run: the fraction of training items whose level-2 and level-3 code changes when b_l is set to 0 (behaviour-off counterfactual) and when kappa_l is set to 0 (Euclidean counterfactual); this proves the coupling acts without training a second arm. (5) The measured kappa_l and b_l profiles and the distribution of realised bend angles. (6) Stage3 test_recall@10, target above 0.065, with 0.055537 as the frozen reference.
ABLATION BEHAVIOR OFF: The flag sets z_l = 0 for l=1,2,3, hence b_l = 0 and kappa_l = k_ref,l for all levels; the Mobius geometry is still switched on and the code radius/count are unchanged. This run has the same code scale and the same operator but no behaviour profile, so any difference is attributable to the behaviour term.
ABLATION GEOMETRY OFF: The flag sets kappa_l = 0 exactly for all levels, so exp_0 is the identity and (+) is ordinary addition; bend returns r - c and the model is exactly the Euclidean RQ-VAE on the same codebooks. The behaviour profile is still computed and logged but has no effect. This run isolates the curved operation.
ABLATION BOTH ON: kappa_l is the real coarse-referenced, null-standardised profile and the Mobius residual operator is active at levels 2 and 3. This is the single trained candidate; the two switches above exist in the code but are not trained in this round.
SPEC EQUATIONS: Mobius: x (+) y = ((1 + 2k<x,y> + k||y||^2)x + (1 - k||x||^2)y) / (1 + 2k<x,y> + k^2||x||^2||y||^2). Exp: exp_0^k(v) = tanh(sqrt(k)||v||) * v/(sqrt(k)||v||), exp_0^k(0)=0. Bend pseudocode:
  v = r - c; nv = ||v||
  if nv < 1e-8: return zeros_like(r)
  p = exp_0^k(r); q = exp_0^k(c)
  w = mobius_add(-q, p, k); nw = ||w||
  if nw < 1e-8: u = v / nv
  else: u = w / nw
  return nv * u
Curvature pseudocode (no_grad, every 100 epochs):
  for l in 1..3: A_l = quotient(W, prefix_map[l-1])
  kappa_raw[l] = weighted_mean(ollivier_ricci(A_l), weights=transition_counts)
  for b in 1..10: A_l^null = null(A_l, mode=l); kappa_null[l,b] = same(A_l^null)
  mu[l] = mean_b kappa_null[l,b]; sigma[l] = std_b kappa_null[l,b]
  z[l] = clip((kappa_raw[l]-mu[l])/max(sigma[l],1e-6), -3, 3)
  m[l] = median over training items of ||r_l - c_l||
  k_ref[l] = 1/m[l]^2
  b[l] = z[1] - z[l]
  kappa[l] = clip(k_ref[l]*exp(b[l]/2), 0.22*k_ref[l], 4.48*k_ref[l])
SPEC INPUTS OUTPUTS: Inputs: r_l (batch x d) Euclidean residual entering level l, chosen code c_l (batch x d), scalar kappa_l, epsilon=1e-8. Output: r_{l+1} (batch x d) with ||r_{l+1}|| = ||r_l - c_l|| exactly, plus the unchanged integer codes and SID tokens. The curvature schedule takes the training transition matrix, the training item-to-prefix map and the current codebook, and returns the detached vector (kappa_1, kappa_2, kappa_3).
SAFEGUARDS: (1) Exact norm preservation: the output is nv * unit(w), so no level can shrink or grow the residual scale; this is the direct answer to the CURVALLOC failure. (2) The code radius rho_l, code count K_l, commitment weight and assignment metric are never functions of kappa_l; the codebook remains the baseline RQ-VAE codebook. (3) Ball safety: ||exp_0^k(v)|| < 1/sqrt(k) for every finite v; clamp ||p|| and ||q|| to 0.999/sqrt(k) and clamp the Mobius denominator to at least 1e-6. (4) Float32 bend with float64 graph curvature; if any r_{l+1} is NaN or Inf, fall back to the Euclidean v for that batch and level and increment a counter. (5) Curvature is clipped to z in [-3,3] and kappa to [0.22, 4.48] k_ref, both derived from the clip, not tuned. (6) Usage monitor at every recompute: if a level's usage entropy falls below 0.9 times its epoch-0 value, set b_l = 0 for the next block (documented default, measured reference). (7) No collective in the training loop: the transition matrix and the null permutations are built once before training and saved; every rank loads the same file and recomputes the quotient curvature locally from the DDP-synchronised codebook, so there is no rank-0 broadcast, no oversized transport and no rank-0 export deadlock. (8) The schedule runs at epoch boundaries in eval mode with torch.no_grad; it is a schedule/penalty-like quantity, never a backpropagated one.
