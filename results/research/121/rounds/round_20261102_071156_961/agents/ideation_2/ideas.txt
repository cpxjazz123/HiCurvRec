IDEA: CURVCAP-SUCCPLAN
TITLE: Capacity-frozen, successor-curvature-field Poincaré assignment for the RQ-VAE, with the code radius left untouched by construction
MOTIVATION: The prior round proved that the curvature signal tracks SID quality (Spearman -0.20) but spent that signal on the per-level code radius rho_l, collapsing the codebook: exported support 2/13/56, collision rate 0.998, L1 positive/negative hit rates 0.982/0.980, Stage3 test_recall@10 0.041888 against 0.055537. Curvature and resolution were competing for the same scalar. The fix is to change the currency: curvature may decide WHICH item occupies WHICH code, never how much of the ball a code occupies.
NOVELTY: Unlike CURVALLOC (curvature -> c_l and rho_l), BRad-RQ (rank/radial assignment by context entropy), CURVCTRL-SID (prefix score -> per-level temperature), poincare-frechet (curved codebook update), and unlike a behaviour-weighted Sinkhorn with an additive Euclidean cost, behaviour here is not a weight and not a suffix: it IS the local curvature of the distance, c_ik = c_l * exp(-a_ik). The transport column marginals are frozen to the Euclidean nearest-code counts, so curvature is structurally incapable of changing code usage; that is the property the previous mechanism lacked.
CHANGE: Replaces the per-level nearest-code step by a curvature-field, capacity-frozen optimal-transport assignment in which each item-code pair carries its own Poincaré sectional curvature, fixed by the fraction of the item's training successors already sitting in that code's community.
SPECIFICATION: Per level l, map the residual and the codes into a Poincaré ball with per-level curvature c_l (from the standardised behaviour-graph curvature profile), price each pair by C_ik = d_{c_ik}(psi(z_i), psi(v_k)) with c_ik = c_l*exp(-a_ik), solve a Sinkhorn plan whose row sums are 1 and whose column sums are exactly the Euclidean nearest-code counts u_k of the same batch, take the code as argmax_k P_ik with a straight-through gradient through the soft code, and recurse on the residual. Column capacities equal to the Euclidean counts is the resolution guarantee: the per-level usage multiset, and therefore the exported support, is exactly the Euclidean one.
COST: Added ~108M MAC per step at the frozen scale (B=1023, K=256, d=64, J=10: 3*B*K*d for the curved cost matrix, 3*B*K*d for the Euclidean capacity pass, 3*B*K*J for the ten Sinkhorn iterations), about 0.22 GFLOP per step, i.e. roughly 1.0-1.8x the ~120M MAC RQ-VAE step. Over 72,000 steps that is ~1.6e13 added FLOPs, about 10-40 min extra on four cards including launch overhead. The curvature schedule (60 recomputations x 3 levels x <=256-node exact ORC) costs under one minute. The 256-per-level codebooks are consistent with the frozen 247/7414/20223 support; if one level used 4096 codes its per-step cost would grow 16x.
HYPOTHESIS: If an item's level-l prefix should coincide with the level-l prefix its training successors already occupy, then letting curvature pull the assignment toward successor codes while capacity forbids any resolution loss should raise prefix sharing along transitions and lift Stage3 test_recall@10 above 0.065 (from 0.055537), with the exported SID support unchanged and with 5-40% of level-1 codes permuted relative to the geometry-off assignment. It is worth keeping only if both the permutation fraction is non-trivial and recall moves.
RISKS: The curvature carrier is only a 3-vector, so bandwidth is low; a_ik computed from Euclidean successor codes may be noisy early and behave like a random permutation; the Sinkhorn temperature derived from the measured cost gap can be unstable in early epochs; capacity matching limits codebook adaptation; cross-level SID collisions may rise even though per-level support is preserved; the curvature may act as a mild regulariser with less than 1% assignment change and no recall movement.
BEHAVIOR SIGNAL: Directed item-to-item transitions from the training split, aggregated as each item's top-M successor set, plus the level-l community curvature of the training transition quotient graph.
BEHAVIOR COMPUTATION: From the TRAIN split only. Scan each user's consecutive interactions, count item->item transitions, keep the top M=20 successors S(i) per item (ties by item id) in a cached sparse matrix. Per level, euc_l(j) = argmin_k ||z_j^l - v_k|| over all 24556 training items, recomputed identically at each epoch from the current codebook; a_ik = (1/|S(i)|) * sum_{j in S(i)} 1[euc_l(j)=k] in [0,1]. Curvature profile: nodes are the K_l codes used at level l, edge weight w_kk' = number of training transitions u->v with euc_l(u)=k and euc_l(v)=k'; Ollivier-Ricci curvature kappa(k,k') = 1 - W1(m_k, m_k')/d_G(k,k') with m_k = 0.5*delta_k + 0.5*sum_k' (w_kk'/deg k) delta_k' and exact OT on at most 256 nodes; kappa_l = transition-weighted edge mean; 200 member-shuffles that preserve community sizes give mu_l, sigma_l; kappa_hat_l = clip((kappa_l-mu_l)/max(sigma_l,1e-6), -2, 2); delta_l = kappa_hat_l - mean_l' kappa_hat_l'. Recomputed every 50 epochs under no_grad.
LEAKAGE BOUNDARY: Every transition, successor set, community size, curvature value, null sample, capacity count and code table is built from training interactions and the training item universe only. Validation and test interactions are never tokenised for SID construction, never counted in w_kk', and never used for a_ik or u_k. The curvature profile is computed offline before launch, written to a file, and read identically by every rank, so no validation pass can influence the SID; the export uses only train-fitted codebooks.
HYPERBOLIC OPERATOR: Poincaré ball distance with Möbius addition and a per-pair negative sectional curvature -c_ik, where c_ik = c_l*exp(-a_ik) and c_l = clamp(exp(-delta_l/2), 0.25, 4.0) with c_0 = 1 dimensionless: d_c(u,v) = (2/sqrt(c))*artanh(sqrt(c)*||(-u) (+) v||_c). The curvature is fixed/scheduled, never trained.
HYPERBOLIC LOCATION: Inside the residual quantizer's assignment step at all three levels, and in the gradient that flows through the straight-through soft plan to the encoder and the codebook. Not in the code radius, not in the decoder, not in the latent scale.
COUPLING PATH: a_ik (the codes of the item's training successors) sets the local curvature c_ik of the distance that prices item i against code k; that same distance forms the cost matrix of a transport whose marginals are frozen to the Euclidean counts, so the plan, the chosen code, the residual and the next level's assignment all depend jointly on the behaviour affinity and the curved metric. Removing behaviour makes c_ik uniform and removes the successor channel; removing geometry makes the cost Euclidean and the affinity has no channel at all, so the plan collapses to the Euclidean assignment.
COUPLING EQUATION: C_ik = d_{c_l * exp(-a_ik)}( psi(z_i^l), psi(v_k) ), with a_ik = (1/|S(i)|) * sum_{j in S(i)} 1[euc_l(j)=k] and c_l = exp(-delta_l/2).
OBSERVABLES: (1) fraction of items whose level-l code differs from the geometry-off assignment, target 5-40%, with less than 1% meaning the curvature is inert; (2) exact equality of the per-level usage multiset with the Euclidean counts, logged every step; (3) exported support, which must be at least the same-run Euclidean support and is expected to stay at or above 247 level-1 codes / 7414 prefixes / 20223 three-token SIDs; (4) collision rate and L1 positive/negative hit rates should stay near the frozen baseline rather than 0.998 / 0.982 / 0.980; (5) successor prefix hit rate, the fraction of training transitions with code_l(u)=code_l(v), should rise above the geometry-off run; (6) Stage3 test_recall@10 above 0.065 against the frozen 0.055537.
ABLATION BEHAVIOR OFF: config flag behaviour_off sets a_ik = 0 for all pairs and delta_l = 0, so c_ik = 1 at every level; the cost is a uniform-curvature Poincaré distance and the capacity-frozen Sinkhorn is otherwise unchanged.
ABLATION GEOMETRY OFF: config flag geometry_off sets C_ik = ||z_i^l - v_k||, the Euclidean limit; because the column capacities are exactly this assignment's own counts, the plan returns the Euclidean nearest-code assignment, a_ik has no channel, and the run is the plain RQ-VAE plus a no-op permutation.
ABLATION BOTH ON: the full C_ik = d_{c_l*exp(-a_ik)}(psi(z_i), psi(v_k)) with capacity-frozen Sinkhorn and straight-through gradient; this is the single trained arm, and no arm is trained with the switches off in this round.
SPEC EQUATIONS: for l in 1..3: s_l = max(quantile_0.9({||z_i^l||} U {||v_k||}), 1e-8); psi(x) = (0.95/sqrt(c_l)) * tanh(||x||/(2*s_l)) * x/max(||x||,1e-12); a_ik as above, detached; c_ik = c_l*exp(-a_ik), detached; C_ik = d_{c_ik}(psi(z_i), psi(v_k)); u_k = #{i : argmin_k' ||z_i^l - v_k'|| = k}; tau = clamp(mean_i (C_i,(2) - C_i,(1)), 1e-3, 10); log-domain Sinkhorn for j=1..10, f_i = -tau*logsumexp_k(-C_ik/tau + g_k), g_k = -tau*logsumexp_i(-C_ik/tau + f_i) + tau*log(u_k/B); P from the normalised potentials; repair the column sums to u_k/B by largest remainder; c_ihat = argmax_k P_ik with ties by cost then code id; vbar_i = sum_k P_ik v_k; z_q = z_i + (v_{c_ihat} - z_i).detach() + (vbar_i - vbar_i.detach()); r_i^{l+1} = z_i^l - v_{c_ihat}. The loss is unchanged from the RQ-VAE baseline (reconstruction plus commitment); no new loss term and no new parameter.
SPEC INPUTS OUTPUTS: inputs are the per-level residual batch z_i^l (B x d), the codebook V_l (K x d), the top-20 training successor lists S(i), the detached Euclidean code table euc_l(.) over all training items, and the detached scalars (c_l, s_l, tau). Outputs are a code c_ihat in 1..K per item, the quantized vector z_q, the next residual r_i^{l+1}, and the plan P used for the straight-through gradient.
SAFEGUARDS: psi maps into radius 0.95/sqrt(c_l) so sqrt(c_ik)*||.|| <= 0.95 < 1 always; the artanh argument is clamped to 1-1e-6; the Möbius denominator is clamped to 1e-12; Sinkhorn runs in the log domain for 10 iterations with largest-remainder repair of the column sums; tau is clamped; ties are broken deterministically; sigma_l is floored at 1e-6 and delta_l is set to 0 if the null is degenerate; c_l is clamped to [0.25, 4.0]; codes with u_k = 0 are excluded from the plan exactly as in the Euclidean pass; s_l falls back to the previous step's value if the batch is degenerate; the per-level usage-multiset equality is asserted and logged. Four-rank safety: the curvature profile is produced offline and read from a file by every rank; the Euclidean code table is recomputed identically on every rank from the replicated codebook after the DDP step; any gather is an equal-shape all_gather on all ranks; there is no rank-0-only broadcast or export inside the training loop.
END IDEA
