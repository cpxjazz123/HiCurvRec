IDEA: nullcurv-hinge-rq
TITLE: A size-preserving null-calibrated curvature hinge on the per-level code quotient learns the per-level curvature of a hyperbolic RQ-VAE quantizer
MOTIVATION: The curvature forensics over 182 SID tables say the informative object is not a level's raw quotient-graph curvature (Spearman +0.03, p=0.65, confounded by level size) but the size-preserving-null-standardised curvature profile and specifically its across-level slope: standardised level-3 curvature correlates +0.26 with recall (+0.34 on mechanism families, p=0.001), level-1 curvature correlates -0.16, and their difference is -0.20 (p=0.0095), so SIDs whose prefix quotient curvature rises with depth recall better. Today that number is only a post-hoc predictor of finished SIDs. This idea turns the slope into a training-time design target: the RQ-VAE must produce a code partition whose standardised quotient curvature is non-decreasing in depth, and the only free variables that can satisfy that target are the per-level curvature values of the hyperbolic metric the quantizer assigns in. Level 1 is therefore pushed toward the expander-like end and level 3 toward the clustered end, which is the direction the data wants and is the opposite of the Issue #127 failure, where the coarse level was aligned to a 17-cell behavioural partition, collapsed to 4 codes and fell to 0.0513.
NOVELTY: Three things are new relative to everything already tried here. (1) The curvature parameter of the space is not set by a formula from a behavioural score (the CURVCTRL-SID shape), not a per-item rank or radius (the BRad-RQ shape) and not a successor-weighted Frechet mean (the round-128 shape): each level's curvature is a trainable parameter whose gradient is supplied by a hinge on the standardised curvature of the partition the quantizer is actually producing, so curvature becomes an output of a matching problem, not an input knob. (2) The matching target is the null-standardised, group-size-controlled quantity, so the level-size confound that made the raw curvature useless is removed inside the loop; the null (10 membership shuffles with the code histogram held fixed) is re-estimated every 250 epochs from the current partition. (3) The target is a profile order (level 1 <= level 2 <= level 3), not a level-wise absolute value, so no level is pinned to a number and no constant has to be chosen; the hinge margin is 0, which is the sign boundary of the measured -0.20 effect, not a tuned value.
CHANGE: Replace the Euclidean nearest-code metric of the frozen RQ-VAE with a per-level Lorentz distance of trainable curvature c_l, and add one loss term that penalises any inversion of the standardised Ollivier-curvature profile of the soft code quotient; the gradient of that term flows into c_l only, and c_l is the same quantity that selects codes, so the partition and the metric are optimised against each other through a single path.
SPECIFICATION: Frozen protocol objects unchanged: encoder f_phi, L = 3 residual levels, codebook size K per level (K = 256 used for all arithmetic below), Euclidean reconstruction, straight-through assignment, 3000 Stage-2 epochs, 24 steps/epoch, batch floor(24556/24) = 1023 items. Behaviour graph from the training split only: W[i,j] = n(i->j) + n(j->i) over consecutive pairs of training sequences, degree-normalised W~[i,j] = W[i,j]/sqrt(d_i d_j), d_i = sum_j W[i,j], sparsified to the 20 largest entries per row. Per-level curvature eta_l in R trainable with eta_l(0) = 0, c_l = c_0 exp(eta_l), documented default c_0 = 1.0, eta_l clipped to [-2.3, +2.3]. Tangent codebook a_{l,k} in R^d, atom e_{l,k} = exp_0^{c_l}(a_{l,k}); encoder residual u_i^(l) = z_i - sum_{m<l} log_0^{c_m}(e_{m,k_m}); the point quantised is v_i^(l) = u_i^(l)/(1 + ||u_i^(l)||/r_max) with numeric guard r_max = 10. Selection k_l = argmin_k d_{L,c_l}(v_i^(l), e_{l,k}); the frozen Euclidean commitment is replaced one-for-one by d^2_{L,c_l}(v_i^(l), e_{l,k}) with no new coefficient; the decoder keeps consuming the tangent vectors sum_l a_{l,k_l}, so the generative Stage-3 interface is untouched. Behaviour-curvature target inside the step: p_l(i,k) = softmax_k(-d_{L,c_l}(v_i^(l), e_{l,k})/tau_l), tau_l = 1/sqrt(c_l); B_l = P_l^T W~_batch P_l symmetrised; lazy walk m_a = 0.5 e_a + 0.5 B_l[a,:]/sum(B_l[a,:]); kappa_l(a,b) = 1 - W1(m_a, m_b)/d_{L,c_l}(e_{l,a}, e_{l,b}) with W1 an entropic Sinkhorn (3 iterations, eps = 0.05 * mean_{a,b} d_{L,c_l}, a measured scale) on the 8x8 support; kappa-hat_l = mass-weighted mean over the top-128 edges of B_l by mass; standardise kappa-tilde_l = (kappa-hat_l - mu_l)/max(sigma_l, 0.05|mu_l| + 1e-6) where mu_l, sigma_l come from R = 10 shuffles of the item->code map preserving the code histogram, recomputed every 250 epochs from the current hard partition; L_curv = max(0, kappa-tilde_1 - kappa-tilde_2)^2 + max(0, kappa-tilde_2 - kappa-tilde_3)^2; L = L_RQ + lambda * L_curv with lambda = L_RQ(step 0)/max(L_curv(step 0), 1e-6) measured once at initialisation.
COST: Per step at the frozen scale (24556 items, 1023 per step, 24 steps/epoch, 3000 epochs = 72,000 steps): three K x K Lorentz distance matrices (3 x 65,536 pairs x d = 32, about 6.3M MAC), three P^T W~ P products (3 x 256 x 1023 x 256, about 200M MAC, i.e. 0.4 GFLOP, three small GEMMs), three Sinkhorn blocks of 128 edges x 8 x 8 x 3 iterations (about 74k flops), plus a 1023 x 256 softmax x 3 per level. Total about 0.4 GFLOP per step, roughly 1-3 ms on one modern GPU, i.e. +2 to +5 percent over the baseline step; over 72,000 steps about +2 to +4 minutes of wall clock. The null re-estimation runs 12 times at 12 x 10 shuffles x 3 levels x 0.4 GFLOP, about 25 GFLOP total, under a minute. Extra memory: 3 x 256 x 256 floats for the quotient and 3 x 256 x 256 for the code distance matrix, under 2 MB. No extra forward or backward pass through the encoder or decoder.
HYPOTHESIS: Worth keeping only if all three hold in the single run: (a) the learned curvatures move off their default, |eta_l| >= 0.05 for at least one level by epoch 3000, which proves the behaviour term reached the geometry rather than being absorbed elsewhere; (b) the produced SID's standardised profile becomes non-decreasing in the hard partition too (both hinge terms below 0.05 by the final null re-estimate) while the level-3 used-code count stays at or above 0.9x its epoch-0 count, which shows the target was met without the Issue #127 collapse; (c) Stage-3 test_recall@10 exceeds 0.065.
RISKS: (1) The differentiable curvature surrogate may be dominated by the temperature and the sampled edge set rather than by the partition, so eta_l drifts for reasons unrelated to behaviour and (a) passes while (c) fails. (2) The target is measured on the level-l code-marginal quotient (K nodes) rather than on the level-l prefix-tuple quotient used in the forensics (up to K^l nodes), because a per-step null over prefix tuples is outside the step budget; the marginal may have the opposite slope for some tables. (3) Hyperbolic arccosh gradients blow up when two codes coincide, which is exactly the collapse mode of #127; the radial squash, the tau floor and the usage guard are the only defences and they may not be enough. (4) At level 3 the partition is nearly pure, so the shuffle null can have a near-zero sigma and kappa-tilde explodes and hijacks the total loss; the sigma floor mitigates but also weakens the signal. (5) With one run and no ablation, a null result cannot distinguish "the slope target is wrong" from "the surrogate gradient is bad", and that ambiguity must be reported rather than resolved.
BEHAVIOR SIGNAL: The slope of the null-standardised Ollivier curvature of the training transition graph contracted into the level-l code quotient, i.e. the triple (kappa-tilde_1, kappa-tilde_2, kappa-tilde_3) and its inversions.
BEHAVIOR COMPUTATION: Directed transition counts n(i->j) over consecutive item pairs of training-split user sequences only; symmetrise W = n + n^T, degree-normalise, keep the 20 strongest neighbours per row. Contract with the current soft code posterior of a 1023-item training batch to get B_l; compute Ollivier curvature of the 0.5-lazy random walk on B_l with the eight largest-mass neighbours as support; average over the top 128 edges by mass. Standardise with mu_l, sigma_l from 10 shuffles of the item->code map that keep the exact code histogram, recomputed every 250 epochs from the hard partition. Nothing else is ever read.
LEAKAGE BOUNDARY: W, the code histogram used by the null shuffle, the edge sample and the initialisation-time usage count are all built from training-split sequences and the training item set only. Validation and test interactions are never counted, never used to choose eps, tau, r_max, c_0 or the null size, and the SID table is frozen before Stage 3 sees any test sequence. The curvature diagnostics and every check in HYPOTHESIS are recorded, never used to select among variants, because only one variant is trained. The one-time sign-consistency check between the marginal quotient and the forensic prefix-tuple quotient is computed on the training split and logged as a diagnostic only.
HYPERBOLIC OPERATOR: The Lorentz model of constant negative curvature -c_l with c_l = c_0 exp(eta_l) trainable per level: d_{L,c}(x,y) = (1/sqrt c) arccosh(-c <x,y>_L), the exponential map exp_0^c and its inverse log_0^c at the origin, and an entropic Wasserstein-1 distance whose ground cost is d_{L,c_l} between code atoms. The curvature is therefore both a trainable parameter of the metric and a quantity that enters the curvature estimator.
HYPERBOLIC LOCATION: In the quantizer's nearest-code metric and commitment term at every level, and in the ground metric of the Ollivier curvature estimator that produces the training signal for eta_l. The encoder, the decoder and the Stage-3 transformer stay Euclidean; the curved part is confined to the quantizer and to the curvature-matching head.
COUPLING PATH: W -> soft quotient B_l(c_l) -> 0.5-lazy walk -> entropic W1 with the Lorentz ground metric at curvature c_l -> kappa-hat_l -> null standardisation by the size-matched shuffle -> profile hinge -> dL_curv/deta_l -> c_l -> d_{L,c_l} in the nearest-code search -> codes -> SID. Removing W makes B_l constant across levels, the hinge terms vanish and c_l never leaves c_0. Replacing d_{L,c_l} by the Euclidean distance makes deta/dc identically zero, so the hinge cannot reach any parameter and the quantizer is the baseline. Only with both does the behaviour slope move a geometric parameter that then changes the assignment.
COUPLING EQUATION: L_curv = sum_{l=1}^{2} [ max(0, kappa-tilde_l(B_l(W~, P_l(c_l))) - kappa-tilde_{l+1}(B_{l+1}(W~, P_{l+1}(c_{l+1})))) ]^2, with kappa-tilde_l = ( mean_{E_l} [ 1 - W1_{d_{L,c_l}}(m_a, m_b)/d_{L,c_l}(e_{l,a}, e_{l,b}) ] - mu_l(W~, sizes) ) / sigma_l(W~, sizes) and c_l = c_0 exp(eta_l); the behaviour term is W~ through B_l and the null, the curved term is d_{L,c_l} inside both the W1 cost and the normaliser, and the two meet inside the same bracket.
OBSERVABLES: eta_1, eta_2, eta_3 and c_l over training; the standardised profile (kappa-tilde_1, kappa-tilde_2, kappa-tilde_3) of the hard SID at each null re-estimate; the two hinge terms; the number of codes actually used per level and the collision rate; the existing prefix behaviour-predictability and adjacency diagnostics; Stage-3 test_recall@10. Expected: the hinge terms fall, eta_1 becomes negative and/or eta_3 positive (a rising profile), level-1 usage rises or holds, level-3 usage holds, and test_recall@10 rises above the baseline.
ABLATION BEHAVIOR OFF: W~ replaced by a constant matrix of the same density (every retained edge weight set to 1), so B_l is the same object at every level up to the atom geometry, the two hinge arguments are equal by construction, L_curv is identically 0, eta_l stays at 0 and c_l = c_0 = 1. The curved quantizer is still fully active, so this arm isolates the behavioural target from the geometry.
ABLATION GEOMETRY OFF: d_{L,c_l} replaced by the Euclidean distance, exp_0/log_0 replaced by the identity, and W1 computed with the Euclidean ground cost, so dL_curv/deta_l = 0 and c_l is inert; the RQ-VAE reduces to the frozen Euclidean quantizer with the behaviour curvature computed but unable to act. This arm isolates the curvature from the behaviour.
ABLATION BOTH ON: W~ from the training transitions, the size-preserving shuffle null, the profile hinge, and the trainable per-level Lorentz curvature in the code selection, exactly as in SPECIFICATION. No arm is trained in this round; the switches exist in the code with c_0 = 1.0, tau_l = 1/sqrt(c_l), the 20-neighbour sparsification, the 3-iteration Sinkhorn, the top-128 edges, R = 10 shuffles, the 250-epoch null period and lambda from the step-0 loss balance, all derived or documented, none tuned.
SPEC EQUATIONS: pseudocode per step
inputs: batch X (1023 x d_x), W~_batch (1023 x 1023 sparse, 20 nnz/row), eta (3,), a (3 x 256 x d)
for l in 1..3:
    c[l] = 1.0 * exp(clip(eta[l], -2.3, 2.3))
    e[l] = expmap0(a[l], c[l])                      # 256 x (d+1)
    D[l] = lorentz_dist(e[l], e[l], c[l])           # 256 x 256, diag 0
residuals: u[1] = z; v[1] = squash(u[1]); k[1] = argmin_k D[1][v[1], k]
           u[l] = z - sum_{m<l} logmap0(e[m][k[m]], c[m]); v[l] = squash(u[l]); ...
P[l] = softmax_k( -dist(v[l], e[l], c[l]) / (1/sqrt(c[l])) )
B[l] = P[l]^T W~_batch P[l]; B[l] = 0.5 (B[l] + B[l]^T)
deg[l] = B[l] 1; m[a] = 0.5 onehot(a) + 0.5 B[l][a,:] / deg[l][a]
E[l] = top 128 edges of B[l] by mass
for (a,b) in E[l]:
    C = D[l][supp(a), supp(b)]                    # 8 x 8 ground cost
    pi = sinkhorn(m[a][supp(a)], m[b][supp(b)], C / (0.05 mean(D[l])), iters=3)
    W1 = sum(pi * C); kappa[a,b] = 1 - W1 / max(D[l][a,b], 1e-6)
khat[l] = sum_E B[l] * kappa / sum_E B[l]
ktilde[l] = (khat[l] - mu[l]) / max(sigma[l], 0.05 abs(mu[l]) + 1e-6)
Lcurv = max(0, ktilde[1] - ktilde[2])^2 + max(0, ktilde[2] - ktilde[3])^2
L = L_RQ + lambda * Lcurv
mu, sigma refreshed every 250 epochs: for r in 1..10 permute the item->code map preserving code sizes, recompute khat with the same e[l] and the same edge rule; mu[l] = mean_r, sigma[l] = std_r
usage guard: if usedcodes[l] < 0.9 * usedcodes[l](epoch 0) then zero the gradient of eta[l] for the next 100 epochs
SPEC INPUTS OUTPUTS: Inputs are the batch of encoder outputs z (1023 x d), the training-graph block W~_batch, the tangent codebooks a (3 x 256 x d), the trainable curvatures eta (3,), and the cached null statistics mu, sigma (3,). Outputs are the per-level curvatures c_l, the soft posteriors P_l (1023 x 256) that also define the hard SID, the scalar L_curv and its gradient dL_curv/deta_l (3,), the updated null statistics on the 250-epoch boundary, and the logged curvature profile and usage counts.
SAFEGUARDS: arccosh argument clamped to [1 + 1e-6, 1e6] and the Lorentz inner product clamped before the arccosh; c_l floored at 1e-3 and eta clipped to [-2.3, 2.3]; tau_l floored at 1e-3; the W1 normaliser d_{L,c}(e_a,e_b) floored at 1e-6 and edges with B_l mass below 1e-6 of the maximum dropped, so coincident codes cannot produce an infinite curvature; Sinkhorn in the log domain with a 1e-8 shift and 3 fixed iterations so its cost is bounded and its gradient finite; residuals passed through the smooth radial squash u/(1 + ||u||/10) so no point reaches the hyperboloid boundary; sigma_l floored at 0.05|mu_l| + 1e-6 so a near-pure level-3 partition cannot make kappa-tilde explode; deterministic top-128 edge selection so the loss is reproducible without a seed sweep; a non-finite L_curv sets that step's curvature gradient to zero and increments a counter that is reported; the usage guard freezes eta_l whenever the level's used-code count falls below 0.9x its epoch-0 value, which is the explicit defence against the Issue #127 collapse to 4 codes; K is never reduced and no code is ever merged.
END IDEA
