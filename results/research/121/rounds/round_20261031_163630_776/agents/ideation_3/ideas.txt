IDEA: DELTA-PERI-CURV-RQ
TITLE: Per-item Gromov-delta curvature that sets the behaviour-contrastive distance, temperature, weight and quantisation error in one pathway
MOTIVATION: The SID code space is currently organised by text reconstruction, so items that behave alike (co-transition, co-consumption) land far apart and a generative recommender cannot exploit behavioural regularity in the prefix. The probe says the same thing numerically: plain Euclidean RQ-VAE reaches only 0.0402 Spearman against the training behaviour distance and 0.0124 top-10 behaviour-neighbour overlap. The fix has to be a training-objective change that makes behavioural proximity a first-class geometric target, not a codebook post-processing.
NOVELTY: The curvature is not set by a schedule, not by prefix-transition scores and not fixed by hand: it is a measured per-item Gromov four-point delta of the behaviour metric, which says how tree-like each item's behavioural neighbourhood is. That single measured number c_i is then used four times at once (distance, temperature, pair weight, commitment error). No dead candidate uses the four-point condition, and none lets a behaviour-derived scalar set the softmax temperature. It is also not a Frechet/Karcher centroid rule, not a radial/cone assignment rule and not a metric swap on frozen code vectors: it changes the Stage-2 objective on the continuous latent that the codes are committed to.
CHANGE: The encoder latent is lifted into a Poincare ball whose curvature is per item, and a behaviour contrastive over training-transition neighbours is computed with that variable-curvature distance, with temperature 1/sqrt(c_ij) and weight c_i*exp(-D_ij/Dbar_i); the same c_i-curved metric replaces the Euclidean RQ commitment error so the code assignment inherits the curvature.
SPECIFICATION: See SPEC EQUATIONS. In one line: L = L_recon + beta*L_commit + lambda*L_geo, where L_geo is a softmax over batch negatives of the curved distance -d_P^{c_ij}(v_i,v_j)/tau_ij and every ingredient of it (positive set, weight, temperature, curvature) is a function of the training-transition behaviour metric and of its measured Gromov delta. lambda is measured once at initialisation as L_geo(0)/L_recon(0) and frozen; there is no coupling weight to tune.
COST: One-off precompute: transition counting over the training sequences, then O(24556 * m^3) quadruple evaluation with m = median positive out-degree (about 20), roughly 2e8 flops, 1-2 min on CPU, and a 24556 x m sparse table of ints/floats (~5 MB). Per step at the frozen scale (batch B = 1024, 24 steps/epoch, 3000 epochs = 72000 steps): one extra B x B = 1.05e6 variable-curvature distance evaluation plus its backward, about 2e7 forward flops and ~6e7 with backward, i.e. roughly +25-40% step time relative to reconstruction-only, and about +35-50 min wall clock on the whole Stage-2 run. Stage 3 is untouched (150 epochs, same protocol). No extra parameters, no extra optimiser state, no second model.
HYPOTHESIS: If behavioural proximity is a tree-like signal, then letting each item's measured tree-likeness set its curvature will align the code space with behaviour much more strongly than any assignment-side change, because the contrastive is computed in exactly the space the probe measures and its negatives are the batch. Observable: Spearman(d_code, d_beh) rises from 0.0402 to at least 0.15 and top-10 behaviour-neighbour overlap rises from 0.0124 to at least 0.08; if that holds, the SID prefixes become behaviourally predictable and Stage-3 test_recall@10 should exceed 0.065 (single run, +-0.013 noise).
RISKS: (1) The contrastive can overpower reconstruction, producing SIDs that cluster by behaviour but lose item identity, which the generative model then cannot discriminate; lambda balancing at initialisation only protects the start of training. (2) The transition graph is sparse and popularity-skewed, so many items have few or no observed neighbours and get a degenerate delta; the D_max clipping and the m floor are the mitigation but neighbourhood quality is not guaranteed. (3) Variable per-pair curvature is not a true metric (triangle inequality can fail), which is harmless for a softmax but makes "distance" a per-pair functional. (4) If the harness probe computes code-space distance on committed code vectors in plain Euclidean space, the gain depends on the curved commitment making codes track the latent; that link is real but weaker than the latent effect. (5) Extra ~35-50 min of Stage-2 compute may brush against the wall-clock budget.
BEHAVIOR SIGNAL: Directed item-to-item transitions aggregated over the training sequences (sequential co-consumption one step apart), popularity adjusted, symmetrised; plus the tree-likeness (Gromov delta) of that metric around each item.
BEHAVIOR COMPUTATION: From the training split only. For every consecutive pair (i -> j) inside a training user sequence, increment n_ij. pop_i = sum_j n_ij + sum_j n_ji. d_beh(i,j) = -log((n_ij + 1) / (sqrt(pop_i * pop_j) + 1)), exactly as in the tools-side probe. Symmetrise D_ij = (d_beh(i,j) + d_beh(j,i))/2. Set D_ij = D_max = max finite D for pairs with no observed transition in either direction, so absence is never rewarded. Neighbourhood size m = round(median_i |{j : n_ij > 0}|), clamped to [8, 50] as a documented default (not tuned). N_m(i) = the m smallest-D neighbours of i.
LEAKAGE BOUNDARY: The transition counts, the popularity vector, D, the neighbourhoods, the Gromov deltas and therefore the curvatures are all computed from training-split sequences only and frozen before Stage-2 step 1. Validation and test events are never read during SID construction; there is no test-time graph, no transductive propagation and no use of the Stage-3 labels. The probe itself is the training-split behaviour distance, so the coupling cannot be explained by test information entering the code.
HYPERBOLIC OPERATOR: Poincare-ball distance with variable negative curvature -c_ij, c_ij = sqrt(c_i c_j), computed on lifted points v = exp_0^{c}(u); the per-item curvature is derived from the measured Gromov delta, c_i = max(1 - 2*delta_i, eps)^2 with delta_i the normalised four-point delta of the item's behavioural neighbourhood, so c_i in (0, 1]: tree-like neighbourhoods (small delta) get unit negative curvature, Euclidean-like ones (delta near 1/2) get near-zero curvature. The same d_P is used in the RQ commitment error, so quantisation is curved too.
HYPERBOLIC LOCATION: Inside Stage-2 training, in two places that share the same c_i: (a) the latent-side behaviour contrastive that shapes the encoder output before quantisation, and (b) the residual-quantisation commitment term at every RQ level. Nothing is applied after training and nothing is applied to a frozen SID.
COUPLING PATH: training sequences -> n_ij -> D_ij -> per-item Gromov delta delta_i -> curvature c_i -> {pair weight w_ij = c_i exp(-D_ij/Dbar_i), temperature tau_ij = 1/sqrt(c_ij), distance d_P^{c_ij}, commitment metric} -> gradient into the encoder, the RQ codebooks and the decoder -> code vectors and SIDs -> code-space distance. Removing behaviour leaves no D, no delta, no w, so the term is identically zero; removing curvature flattens d_P to the Euclidean norm, sets tau to 1 and collapses c_i, so the term becomes a plain Euclidean contrastive. Both changes alter the same sum.
COUPLING EQUATION: L_geo = -(1/|P|) * sum_{(i,j) in P} w_ij * log[ exp(-d_P^{c_ij}(v_i, v_j)/tau_ij) / sum_{k in B} exp(-d_P^{c_ik}(v_i, v_k)/tau_ik) ], with w_ij = c_i * exp(-D_ij / Dbar_i), c_i = max(1 - 2*delta_i_norm, eps)^2, c_ij = sqrt(c_i c_j), tau_ij = 1/sqrt(c_ij), and d_P^{c}(a,b) = (1/sqrt(c)) * arcosh(1 + 2c||a-b||^2 / ((1 - c||a||^2)(1 - c||b||^2))). The behaviour term is (w_ij, P, tau) and the curved term is d_P^{c_ij}; they multiply inside one logarithm.
OBSERVABLES: (1) Probe Spearman between code-space distance and training behaviour distance, target >= 0.15 versus the 0.0402 baseline. (2) Top-10 behaviour-neighbour overlap, target >= 0.08 versus 0.0124. (3) Per-item curvature distribution: correlation between c_i and the local clustering coefficient of the behaviour graph, and the fraction of items near the c_floor. (4) Prefix behaviour predictability: for prefix lengths 1 and 2, the behaviour-weighted fraction of an item's top-10 behaviour neighbours that share its prefix, and the behaviour-weighted conditional entropy H(code_l | code_{<l}); both should drop versus baseline. (5) Codebook usage and reconstruction loss, to show the geometric term did not destroy content. (6) Stage-3 test_recall@10 with the explicit caveat that one run carries about 0.013 of noise.
ABLATION BEHAVIOR OFF: Set the behaviour switch to off, so D_ij is undefined, the positive set P is empty and w_ij = 0; L_geo contributes exactly zero and the run degenerates to the plain Euclidean RQ-VAE objective with the curved commitment still present but with c_i taken from the all-ones fallback (i.e. the geometry cannot express anything behavioural). Code path exists and is asserted to return a zero tensor.
ABLATION GEOMETRY OFF: Keep the behaviour switch on but replace the curved operator by its flat limit: d_P^{c}(a,b) -> ||a-b||, tau_ij -> 1, c_i -> 1 in the weights only (so w_ij = exp(-D_ij/Dbar_i)), and the commitment error becomes the ordinary Euclidean ||r_l - e_l||^2. This isolates how much of the gain comes from curvature rather than from the behaviour target.
ABLATION BOTH ON: The full mechanism as specified: behaviour positives, behaviour weights, c_i from the measured Gromov delta, variable-curvature Poincare distance in both the contrastive and the commitment error. This is the only arm that is trained in the round.
SPEC EQUATIONS:
  # ---- one-off, before Stage-2 (training split only) ----
  for each consecutive pair (i -> j) in training sequences: n_ij += 1
  pop_i = sum_j n_ij + sum_j n_ji
  d_beh(i,j) = -log((n_ij + 1) / (sqrt(pop_i*pop_j) + 1))
  D_ij = 0.5*(d_beh(i,j) + d_beh(j,i));  D_ij = D_max if both counts are 0
  m = clip(round(median_i |{j : n_ij > 0}|), 8, 50)
  S_i = {i} union N_m(i);  scale_i = mean_{j in S_i, j != i} D_ij
  for triples (j,k,l) in S_i:
      g1 = D_ij + D_kl; g2 = D_ik + D_jl; g3 = D_il + D_jk
      delta_raw = 0.5 * max(0, g1 - max(g2, g3))
  delta_i = max(delta_raw) / (scale_i + 1e-8)          # dimensionless, ~[0, 0.5]
  delta_i = clip(delta_i, 0, 0.49)
  c_i = clip(max(1 - 2*delta_i, 1e-3)^2, 1e-3, 1.0)
  Dbar_i = mean_{j in N_m(i)} D_ij
  # ---- every Stage-2 step, batch B of 1024 items ----
  u_i = Encoder(z_i)                                    # tangent space at the origin
  v_i = tanh(sqrt(c_i)*||u_i||) / (sqrt(c_i)*||u_i|| + 1e-8) * u_i   # exp_0^{c_i}
  d_ij = (1/sqrt(c_ij)) * arcosh(1 + 2*c_ij*||v_i - v_j||^2 /
                                  ((1 - c_ij*||v_i||^2)*(1 - c_ij*||v_j||^2)))
  c_ij = sqrt(c_i*c_j); tau_ij = 1/sqrt(c_ij); w_ij = c_i*exp(-D_ij/Dbar_i)
  L_geo = mean_{i in B} ( - sum_{j in N_m(i) ∩ B} w_ij * log_softmax_k( -d_ik/tau_ik ) )
  # curved commitment, same c_i, level by level
  r_0 = u_i ; for l in 1..L:
      a = exp_0(r_{l-1}) ; b = exp_0(e_l^{code})     # both lifted into the same c_i-ball
      L_commit += d_P^{c_i}(a, b)^2
      r_l = r_{l-1} - sg(e_l^{code})                 # straight-through, as in the baseline
  L = L_recon + beta*L_commit + lambda*L_geo
  lambda = L_geo.detach() / L_recon.detach()         # evaluated once at epoch 0, step 0; frozen
SPEC INPUTS OUTPUTS: Inputs: the frozen training-transition count matrix (sparse, top-m per item), the per-item tables D_ij, Dbar_i, delta_i, c_i built once, and per step the batch of item text embeddings z_i, the current encoder weights and RQ codebooks. Outputs: a scalar L_geo, a scalar curved L_commit, the straight-through quantised latent and the codes c_i^1..c_i^L per item (hence the SIDs), plus logged per-item curvature and probe diagnostics. The operator returns gradients with respect to the encoder, all L codebooks and the decoder; it returns no new parameters.
SAFEGUARDS: (1) c clipped to [1e-3, 1]; delta_i clipped to [0, 0.49] so 1-2*delta stays positive. (2) Latent norm constrained so c*||v||^2 <= 0.95^2 by construction of exp_0 (it is bounded by 1/sqrt(c)); assert max c*||v||^2 < 0.98 each step. (3) arcosh argument clamped to >= 1+1e-7; denominator clamped to >= 1e-8. (4) Pairs with no observed transition get D = D_max, never a small distance. (5) Items with fewer than 2 behaviour neighbours are excluded from P and keep the fallback c_i = 1; the count of such items is logged. (6) `if not behaviour_on: return zeros` and `if not geometry_on: use the Euclidean branch` are explicit early-exit switches, unit-tested by asserting zero output and by comparing against the flat formula. (7) Global gradient-norm clipping at 1.0 as in the baseline. (8) lambda is computed once and frozen; if L_geo(0) is non-finite the term is disabled for the run and the fact is logged (documented default, not a tuned value). (9) All probability-weighted sums over B use log_softmax with the max subtracted, so no exp overflow with tau as small as 1/sqrt(1) and distances up to ~20.
END IDEA
