IDEA: SHELL-CURV-RQ
TITLE: Margin-shell curved behaviour re-assignment: at most 5% of items may be re-tokenised, and only the Poincare distance to behaviour code-centroids decides among near-tied codes.
MOTIVATION: Rounds 1-3 showed that moving the SID partition toward behaviour costs recall monotonically, and that the loss grows with distance from the plain text geometry. But a codebook's Voronoi boundary is exactly where the text embedding is genuinely ambiguous; those items carry a SID that is arbitrary with respect to behaviour. Fixing only that thin shell keeps 95% of the text-geometry partition intact while making the remaining ties behaviour-consistent, which is the cheapest place to buy prefix predictability.
NOVELTY: Unlike behaviour-weighted Sinkhorn, curved residual chains, successor barycentre shifts and a fourth argmin level, this mechanism never moves the encoder, never updates the codebooks, never adds a level and never relocates a non-tied item. Behaviour acts only as a tie-break inside a hard 5% margin budget, and curvature acts as a bounded displacement budget through exp_0, so neither can drag the whole partition off the text geometry.
CHANGE: After the usual Euclidean RQ-VAE assignment pass, take the per-level margin shell containing the smallest 5% of nearest-vs-second-nearest gaps, recompute level-l behaviour centroids from train transitions, and let the Poincare distance from each shell item's behaviour point to those centroids choose the code among the shell candidates instead of the Euclidean argmin.
SPECIFICATION: See SPEC EQUATIONS. Inputs: text embeddings x_i for 24556 train items, L=3 codebooks of 256 codes each, train-only directed transition matrix. For each level, form the shell, compute q_k as a tangent-space Frechet mean, pick the code minimising d_c(b_i,q_k), keep straight-through gradients as in the base RQ-VAE. The budget B=0.05 is the round's stated guard, not a tuned value; delta_l is the B-quantile of the measured margin distribution.
COST: One extra bulk pass per epoch (24556x256 top-2 margins at all 3 levels, plus Poincare distances for about 1228 shell items per level), roughly 0.9M artanh evaluations per epoch, about 10-30 ms on one card, under 2% of the 0.145-0.16 s epoch; at 24 steps per epoch that is under 0.1 ms per step, so 3000 epochs add under 90 s wall clock. The PPMI behaviour points are built once before training.
HYPOTHESIS: If the margin-shell items are the ones whose SID is behaviourally arbitrary, replacing their code with the curved behaviour-consistent candidate raises prefix behaviour predictability in the recorded train diagnostics and Stage3 test_recall@10 holds at or above the 0.0679 baseline and above the 0.065 gate, while level-1 agreement with the baseline assignment stays >=0.95 and prefix counts stay within a few percent of 251/1769/2201. Observed through the per-level flip count and the recorded prefix counts.
RISKS: 5% may be too few flips to move recall beyond seed noise; the shell may be dominated by rare items with thin behaviour statistics, making flips noisy; the behaviour centroids may be unstable early in training (mitigated by origin fallback and the >=5-member rule); the curved ranking may coincide with the Euclidean ranking, which is a genuine possible negative that the geometry-off switch is designed to expose.
BEHAVIOR SIGNAL: Directed item-to-item transitions in the train split, aggregated into a PPMI successor profile per item, used as that item's behaviour point in the Poincare ball.
BEHAVIOR COMPUTATION: From the train split only, count consecutive pairs (a,b) within each user session; PPMI(a,b)=max(0, log( p(a,b)/(p(a)p(b)) )) with p(a,b)=#(a,b)/sum of all pairs and p(a)=#(a)/sum of marginals; keep the top-50 successors per item by PPMI, L2-normalise the row p_i, then b_i = exp_0(alpha * P p_i) with P a fixed seeded Gaussian projection to 16 dimensions and alpha = 0.5 / (max_i ||P p_i|| + 1e-12). Built once from train transitions, cached, never updated from validation or test interactions.
LEAKAGE BOUNDARY: The transition matrix, the PPMI rows, the projection and the behaviour points are computed only from Stage-2 train-split interactions before the SID run, and are frozen afterwards. Validation and test interactions are never read during SID construction, so no validation or test signal can influence which code an item receives.
HYPERBOLIC OPERATOR: Poincare ball distance at gauge-fixed negative curvature c=1, d_c(u,v)=(2/sqrt(c)) artanh(sqrt(c)||(-u) xor v||), together with the exp_0 and log_0 maps; c is fixed at 1 because curvature is a gauge, so it is not a free constant and no curvature sweep exists.
HYPERBOLIC LOCATION: Inside the per-level assignment step of the RQ-VAE quantizer during Stage-2 training, applied only to items inside the 5% margin shell; codebooks, encoder, decoder and the L=3 level count are untouched.
COUPLING PATH: train transitions -> b_i -> per-level code behaviour centroids q_k from currently assigned items -> Poincare distance d_c(b_i,q_k) -> argmin over the shell -> discrete code index -> straight-through gradient and SID token. Removing behaviour empties the shell (pure Euclidean argmin); replacing d_c by Euclidean changes which shell code wins; both change the same token.
COUPLING EQUATION: k*(i,l) = argmin_{k in S_i^l} d_c(b_i, q_k^l), with S_i^l = {k : ||z_i^l - c_k^l|| <= d_(1)(i,l) + delta_l} and delta_l = Quantile_{B=0.05}({m_i^l}).
OBSERVABLES: Flipped assignments per level; level-1 agreement with the baseline assignment (must be >=0.95); observed prefix counts at L1/L2/L3 against 251/1769/2201; the behaviour-contrast diagnostic; Stage-3 test_recall@10.
ABLATION BEHAVIOR OFF: behaviour_enabled=False sets S_i^l={argmin} and delta_l=0, so every token is the plain Euclidean argmin and the SID equals the baseline partition.
ABLATION GEOMETRY OFF: geometry='euclidean' keeps the same shell, the same b_i, the same q_k and the same budget but ranks by ||b_i-q_k||^2 instead of d_c, isolating whether curvature rather than behaviour is doing the work.
ABLATION BOTH ON: behaviour_enabled=True and geometry='poincare' with c=1 — the configuration actually trained in this round; the other two switches exist and are wired but are not trained.
SPEC EQUATIONS: B=0.05. For level l: d_ik=||z_i^l - c_k^l||; m_i^l = d_(2)(i) - d_(1)(i); delta_l = Quantile_B(m^l); shell S_i^l = {k: d_ik <= d_(1)(i)+delta_l}. At the start of each epoch, for every k with at least 5 assigned items, q_k^l = exp_0( mean_{i in A_k} log_0(b_i) ), else q_k^l = 0; q is detached. Choose k* = argmin_{k in S_i^l} d_c(b_i,q_k^l), ties broken by smaller Euclidean d_ik. Emit the code index with the base RQ-VAE straight-through estimator and continue with z_i^(l+1) = z_i^l - c_(k*)^l.
SPEC INPUTS OUTPUTS: Inputs: level residual matrix Z^l in R^(24556 x d), codebook C^l in R^(256 x d), frozen behaviour points b_i in the unit Poincare ball (d_b=16), budget B. Outputs: integer assignment a_i^l in {0..255}, its prefix, and the straight-through quantized vector.
SAFEGUARDS: Clamp ||b_i|| and ||q_k|| to 1-1e-6 before the Mobius addition; clamp the artanh argument to 1-1e-9; if delta_l <= 0 or the shell has fewer than 2 candidates, fall back to the Euclidean argmin; a code with fewer than 5 items keeps q_k at the origin so it cannot mirror unstable statistics; alpha rescales so all behaviour points stay inside radius 0.9; if a level loses more than 5% level-1 agreement or codebook usage drops below 200 of 256 codes, the shell is disabled for that level for the remaining training and the event is recorded; all arithmetic in float32 with log/exp maps computed through the tangent space at the origin.
END IDEA
