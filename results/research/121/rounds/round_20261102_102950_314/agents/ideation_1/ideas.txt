IDEA: QPEX-CURVBIAS
TITLE: Quota-preserving SID exchange under an additive, standardised-curvature Poincare proximity bias
MOTIVATION: The two measured failures are (i) a multiplicative behaviour weight on a Euclidean distance that moved margins but moved no arg-min, and (ii) a codebook whose radius was spent on curvature, collapsing support to 56 triples. What is missing is an assignment mechanism in which the behaviour-curvature signal is ADDITIVE on the cost (so it provably reorders the top-1), the per-level usage multiset is EXACT by construction (so the resolution cannot collapse), and the curvature is spent only as a signed re-ranking pressure, never as a radius.
NOVELTY: Earlier arms either (a) made curvature set a level/ball scale (CURVCTRL-SID, BRad-RQ, Poincare-Frechet codebook), (b) multiplied a distance by a behaviour weight (CURVCAP-SUCCPLAN), or (c) used a transport plan whose arg-max need not reproduce its marginals. This proposal uses a swap-exact assignment whose invariant is the Euclidean code histogram, and injects the training-split standardised curvature deviation as a zero-mean additive bias times a fixed-curvature Poincare distance held outside the gradient. Removing the behaviour zeroes the bias and the rule provably returns the Euclidean assignment (verified as Hamming 0); removing the curvature replaces d_P by a Euclidean tangent distance on the same ball. Nothing here rescales a code, a ball or a codebook radius.
CHANGE: Inside each RQ level, compute the normal Euclidean cost C_ik and the Euclidean assignment a0 with code histogram m_k; then add b_ik = lambda_l * delta_l * d_P(u_i, v_k) (centred over k) to the cost and run a fixed number of count-preserving item-code SWAPS starting from a0. The output digit vector has exactly the histogram m_k of the Euclidean argmin, and its digits differ from a0 for a measured set of items.
SPECIFICATION: (1) Pre-pass on the TRAINING split only: build the weighted quotient transition graph W^l_{jk} by counting training item transitions s_t -> s_{t+1} between the level-l codes j,k of the initial Euclidean codebooks; compute Ollivier-Ricci curvature kappa_e per edge with lazy random walk m_j = 0.5*delta_j + 0.5*W_j./deg_j and d = graph shortest path, kappa_e = 1 - W1(m_j,m_k)/d(j,k); take kappa_hat_l = mean_e kappa_e. (2) Null: R=20 size-preserving member shuffles (permute item->code membership inside each level keeping each code's item count), recompute kappa_hat_l each time; z_l = (kappa_hat_l - mean_null)/sd_null; delta_l = z_l - mean_{l'=1..3} z_{l'}; clip |delta_l| to 1.0. On the frozen baseline this reproduces delta = [-0.328, -0.071, +0.399]. (3) Save delta and a per-level lambda_l to the run config; every rank loads the same file. (4) Per training step (batch of n~1023 items), per level l=1..3 with residual r_i and code c_k: u_i = tanh(||r_i||/2) r_i/||r_i||; v_k = tanh(||c_k||/2) c_k/||c_k|| (both stop-gradient); d_P(u,v) = arcosh(1 + 2||u-v||^2 / ((1-||u||^2)(1-||v||^2) + 1e-9)); C_ik = ||r_i - c_k||^2; a0_i = argmin_k C_ik; m_k = count(a0 = k); lambda_l = median_i(C_{i,a1}-C_{i,a2}) / median_{i,k} d_P (measured once at epoch 0, frozen); b_ik = lambda_l * delta_l * (d_P(u_i,v_k) - mean_k d_P(u_i,v_k)). (5) T=1 sweep (documented default) in a seed-fixed item order: for item i at code j, for each non-empty bucket k != j, let i* = argmax_{i' in bucket k} (C_{i',k}+b_{i',k}); swap i and i* iff (C_ik+b_ik)+(C_{i*,j}+b_{i*,j}) < (C_ij+b_ij)+(C_{i*,k}+b_{i*,k}); update the two buckets. The bucket sizes are never changed, so the histogram is the invariant. (6) Commit digits, form residuals r_i <- r_i - c_{a_i}, keep the baseline reconstruction + commitment loss and the baseline EMA codebook update unchanged. (7) At SID construction time for any split (including Stage 3 items) the same frozen delta, lambda, codebooks and swap rule are applied; test items bring embeddings only, no behaviour.
COST: Offline: quotient graphs have <=256 nodes per level; 3 levels x 21 curvature evaluations (1 real + 20 nulls), Sinkhorn 50 iterations ~ 3.3e6 ops each, plus one pass over 24556 residuals x 256 x 3 for the margins: under 1-2 min on one GPU (or a few minutes CPU), executed before Stage 2, outside the training loop. Per step at the frozen scale (n~1023 items, K=256, L=3): 3 x 262k Poincare distances (~20 flops each) = ~16 MFLOP plus 3 x (262k cost entries + 2 x 262k exchange comparisons) ~ 2.4M scalar ops, i.e. roughly +5 to +15 percent step time over the baseline RQ forward/backward; ~+0.2 to +1 s per epoch, ~+10 to +50 min over the 3000-epoch run. No extra epochs, no extra forward passes.
HYPOTHESIS: If delta_l>0 means the level's behaviour quotient is more clustered than its size-preserving null, then a positive bias on d_P (penalising codes far from the item in the Poincare ball) reinforces the clusters the behaviour graph already shows, while delta_1<0 (fine level under-curved) pushes the fine digit away from hyperbolic proximity, i.e. separates items that the null says are not neighbours. If the coarse digit becomes more behaviourally predictable from its prefix, the frozen Stage 3 beam should find the right level-3 group more often, and test_recall@10 should exceed the baseline 0.055537 and approach 0.065, while the per-level histograms, the 247/7414/20223 supports and the 0.177 collision are unchanged by construction.
RISKS: The sign of the curvature deviation may be the wrong direction for recall and, with no tuning allowed, a single run loses; the bias is calibrated to the median top-2 margin so it only touches the ambiguous half of the assignment and the effect may be under one point of recall; tanh projection saturates for large residual norms, making d_P nearly constant and the coupling weak; one sweep of swaps may stop in a poor local optimum; the offline curvature is computed on the epoch-0 codebooks and goes stale as the codebook moves; exact quota preservation can still raise triple collisions if the swaps concentrate items, so the collision rate must be watched.
BEHAVIOR SIGNAL: Standardised, mean-zero behaviour-graph curvature deviation delta_l of the training item-transition quotient graph at each RQ level, measured against a size-preserving member-shuffle null.
BEHAVIOR COMPUTATION: From the Stage-2 training split only: count directed item transitions (s_t, s_{t+1}) over all training sequences; map each item to its current level-l Euclidean code; aggregate into the weighted directed quotient graph W^l on the K codes; compute Ollivier-Ricci curvature per edge with lazy random walk (alpha=0.5) and shortest-path ground distance; average over edges to kappa_hat_l; standardise against R=20 nulls obtained by permuting item-to-code membership within the level while preserving each code's item count; delta_l = z_l - mean_l z_l.
LEAKAGE BOUNDARY: The graph, its curvature, the null and the lambda margin calibration are built only from Stage-2 training sequences and Stage-2 training item embeddings, in a pre-pass that finishes before the training loop. No validation or test sequence, no validation or test co-occurrence and no validation or test code histogram enters delta, lambda, the codebook or the swap rule. Stage-3 items receive their SIDs from the frozen encoder plus the frozen rule; their own interactions are never read. Because delta is a 3-vector saved to config, there is no rank-dependent quantity and no in-loop all-reduce.
HYPERBOLIC OPERATOR: Poincare distance in the unit ball of fixed negative curvature -1 (curvature is fixed, never fit and never used to set a radius): d_P(u,v) = arcosh(1 + 2||u-v||^2 / ((1-||u||^2)(1-||v||^2))), applied to tanh-projected residuals and code vectors, with stop-gradient on both arguments.
HYPERBOLIC LOCATION: Exclusively in the discrete SID assignment step of each RQ level (the choice of which code digit each training item gets), as an additive term in the assignment cost; it never touches the codebook vectors, the EMA update, the encoder gradient or the loss.
COUPLING PATH: training transitions -> quotient graph -> standardised curvature profile delta_l -> additive assignment bias b_ik = lambda_l * delta_l * centred d_P(u_i, v_k) -> quota-preserving swap -> digit a_i -> codebook update and Stage-2 sequence of SIDs. delta_l enters only through b, and d_P enters only through b, so setting delta=0 or replacing d_P by a Euclidean distance changes the digits.
COUPLING EQUATION: b_ik = lambda_l * delta_l * [ d_P(u_i, v_k) - (1/K) sum_{k'} d_P(u_i, v_{k'}) ], with delta_l the standardised training-split behaviour-graph curvature deviation and d_P the fixed-curvature Poincare distance; the assignment minimises C_ik + b_ik subject to the exact code histogram m_k.
OBSERVABLES: (i) Hamming fraction of items whose level-l digit differs from the Euclidean argmin, per level (must be >0 for the coupling to be live; expected 5-25 percent); (ii) an in-code assertion that the level-l histogram equals m_k exactly at every step; (iii) distinct-code support 247/7414/20223 and triple collision near 0.177 (not 0.998); (iv) first-level/second-level/third-level prefix hit rates near 0.079/0.005 as in the baseline and the teacher-forced next-digit NLL per level; (v) Stage-3 test_recall@10 against 0.055537 with the 0.065 target.
ABLATION BEHAVIOR OFF: delta <- 0, so b = 0 and the swap criterion can never accept a move from the Euclidean argmin (the argmin is the unconstrained minimum of the same total cost), hence the output is exactly a0 and the measured Hamming distance to the Euclidean assignment is 0 by assertion; reported as the behaviour-off arm.
ABLATION GEOMETRY OFF: d_P is replaced by the Euclidean tangent distance ||u_i - v_k||_2 on the same tanh-projected points with lambda recomputed against that denominator, while delta and the swap rule are unchanged; this isolates the curved operator from the behaviour signal.
ABLATION BOTH ON: the full rule above with delta_l and d_P together; this is the only arm trained.
SPEC EQUATIONS: Pre-pass: W^l_{jk} = #{(t): code_l(s_t)=j, code_l(s_{t+1})=k}; m_j = 0.5 e_j + 0.5 W_j./sum(W_j); kappa(j,k) = 1 - W1(m_j,m_k)/d_G(j,k); kappa_hat_l = mean_{jk: W_jk>0} kappa(j,k); over R=20 membership shuffles pi_r: z_l = (kappa_hat_l - mean_r kappa_hat_l^{(r)})/sd_r; delta_l = z_l - mean_{l'} z_{l'}. Per step, per level: u_i = tanh(||r_i||/2) r_i/(||r_i||+eps); v_k = tanh(||c_k||/2) c_k/(||c_k||+eps); d_ik = arcosh(clamp(1 + 2||u_i-v_k||^2/((1-||u_i||^2)(1-||v_k||^2)+eps), 1, 1e6)); b_ik = lam_l * delta_l * (d_ik - mean_k d_ik); a0 = argmin_k ||r_i-c_k||^2; m = hist(a0); for i in order: j=a_i; for k != j with bucket_k non-empty: i* = argmax_{i' in bucket_k}(||r_{i'}-c_k||^2 + b_{i'k}); if (||r_i-c_k||^2+b_ik) + (||r_{i*}-c_j||^2+b_{i*j}) < (||r_i-c_j||^2+b_ij) + (||r_{i*}-c_k||^2+b_{i*k}) then swap(a_i, a_{i*}). Return a, m.
SPEC INPUTS OUTPUTS: Inputs: per-level training residual batch {r_i}, frozen codebook {c_k}, frozen scalars delta_l and lambda_l, the seed-fixed item order. Outputs: one integer digit a_i per item per level, a per-level digit vector whose histogram is exactly m_k, and the residuals for the next level. The offline input is the training transition list plus the initial codes; the offline output is the 3-vector delta and the 3-vector lambda.
SAFEGUARDS: eps=1e-9 in every norm and denominator; arcosh argument clamped to [1,1e6]; ||u||, ||v|| clamped to 1-1e-6; |delta_l| clipped to 1.0; lambda_l floored at 1e-3 and set to the measured median margin ratio (no sweep); stop_gradient on u and v so no curved gradient can move a code or a radius; the ball radius is a constant 1 and the codebook vectors are the baseline Euclidean vectors, so the curvature cannot shrink the space; per-code buckets are only exchanged, never resized, and the histogram equality is asserted each step; the offline job is a single pre-pass writing a config file (no NCCL, no rank-0 broadcast inside the loop); if the measured Hamming distance is 0 the run logs COUPLING-INERT rather than silently claiming the mechanism.
END IDEA
