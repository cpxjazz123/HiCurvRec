IDEA: QUOTAPERM-HYP
TITLE: Capacity-conserving hyperbolic behaviour permutation of RQ-VAE SID triples (the triple bag is conserved; only the item->triple bijection is curved-and-behavioural)
MOTIVATION: The SID table that the generative recommender consumes is produced by a Euclidean arg-min. That arg-min ignores the training behaviour graph, so an item and its regular successors can land in unrelated prefixes, while the quantiser's capacity is allocated by embedding geometry alone. The two measured failures of the previous rounds were (i) curvature spent as a radius, which collapsed the codebook (170 -> 56 distinct triples, recall 0.041888) and (ii) a multiplicative per-pair weight, which moved costs but moved not a single arg-min. The problem this addresses is precisely that: how to make behaviour+curvature change the actual SID indices while the codebook's resolution is untouchable, i.e. frozen as a conserved quantity rather than merely "protected" by a soft plan or a clipped loss.
NOVELTY: No prior round in this repository changes the *pairing* between items and SID labels while conserving the label multiset. Previous arms moved code vectors (Poincare-Frechet codebook updates), set per-level scaling/radius from curvature (CURVCTRL-SID, BRad-RQ), added successor smoothing or successor boosting to the residual (LORENTZ-SUCCPROFILE-SMOOTH-RQ, succboost-geoshift), used MoE/cone branch structures (BRANCHCURV-MOEB-RQ, behcone-prefix-rq, TSG-SID) or solved an assignment/transport plan whose arg-max need not reproduce its marginals (CURVCAP-SUCCPLAN, refused). Here the object is a permutation of a fixed bag of whole triples, so the conservation is algebraic, not approximate; the cost is additively rank-fused (no weight to tune); and the measured standardised curvature deviation enters with the deliberately opposite sign to the round-1 arm (kappa_l = exp(+delta_l) instead of exp(-delta_l)), because the level whose behaviour quotient is *flatter* than its size-null is the level that needs the hyperbolic metric supplied, not the level that already has hierarchy.
CHANGE: After the frozen Stage-2 RQ-VAE has produced its Euclidean SID table, run one deterministic two-pass descent that transposes whole triples between items whenever the transposition lowers C(i,T) = rank_E(i,T) + sum_l rank_H,l(i,T_l), where rank_H uses the Poincare distance between an item's behaviour anchor and the triple's code points at curvature kappa_l derived from the null-standardised training-split behaviour-graph curvature. Because every accepted move is a transposition, the multiset of triples is invariant, so per-level usage histograms, distinct-triple count and collision rate are exactly the baseline's.
SPECIFICATION: Let Z = {z_i} (frozen Stage-2 item embeddings), C^(l) = {c_k^(l)} (frozen codebooks, l = 1..3), T_i^base = (e_1(i), e_2(i), e_3(i)) the baseline Euclidean triple, K_l = 247/7414/20223 (code counts used at each level). Build from the TRAINING split the successor sets S_i with popularity-adjusted lift. For each level build the baseline quotient graph, measure its Ollivier-Ricci mean curvature kappa_hat_l, standardise it against R = 20 size-preserving member-shuffle nulls to get delta_l, and set kappa_l = exp(delta_l) clipped to [0.25, 4]. Put every used code on the Poincare ball of curvature -kappa_l by exp-map of c_k^(l)/s_l (s_l = median code norm), and put every item at exp-map of its successor-code centroid m_i^(l)/s_l. Candidate triples for item i: its own baseline triple, the baseline triples of its top-B_i successors, and the baseline triples of its 8 nearest items in embedding space, capped at 32. Rank E and the three H terms within that candidate set (+ the triple currently under evaluation), sum the four integer ranks, take the arg-min as the target, and attempt a transposition with the cheapest of up to 32 holders of that target triple; repeat for 2 passes in descending gain order. Output: a new triple per item.
COST: Training cost is 1.00x the baseline at the frozen scale: 24 steps/epoch x 3000 epochs = 72000 steps, and the mechanism adds exactly 0 operations per step (it never touches the encoder, the decoder or the codebook updates; the straight-through path is byte-identical to baseline, which is what makes collapse impossible). The one-off quantisation pass over 24556 items costs: three nearest-neighbour products 24556x(256+7414+20223)x d ~ 2e10 MACs; ~2.4e6 rank/cost evaluations for candidate construction; ~3.1e6 cost evaluations for the swap market (2 passes x 24556 items x 32 holders x 2 evaluations). Total: minutes on one card, few hundred MB chunked, fully vectorisable; measured once and cached.
HYPOTHESIS: Worth keeping iff (1) the triple multiset is bit-identical to the baseline's while a non-trivial fraction of items (report it; expected order 5-25%) receive a different triple; (2) the mean curved distance from each item to its top successors' triples falls relative to baseline; (3) Stage-3 test_recall@10 rises above 0.055537 and, if the mechanism is right, above 0.065, with the level-1 hit rates and the collision rate numerically unchanged from baseline because they are conserved by construction. If recall moves but the conserved diagnostics also move, the implementation is wrong (a real transposition cannot change them).
RISKS: The swap market is a local descent and may find few improving transpositions, so the SID table changes too little to matter; the reconstruction rank term may be dominated by a handful of hot triples so most items keep their anchor; the frozen codebook means code k's vector no longer matches its members, raising distortion (the rank_E term only bounds this locally, and a large swap gain could still buy a bad distortion); the behaviour graph is sparse and lift-adjusted top-B successors may be noisy for tail items; kappa_l = exp(+delta_l) may over-flatten level 1 (kappa = 0.72) so the coarse level contributes almost nothing; and the swap step could produce a partition that improves prefix reuse but degrades the reconstruction the encoder was trained for, leaving recall flat or slightly below baseline.
BEHAVIOR SIGNAL: Popularity-adjusted directed successor lift over training sequences, turned into a per-item successor set S_i with weights w_ij, and thence into a per-level successor-code centroid m_i^(l). Secondary (diagnostic only, never an admission gate): behaviour-conditioned successor agreement at each level.
BEHAVIOR COMPUTATION: From the TRAINING split only. For each ordered consecutive pair (u_t, u_{t+1}) in every training sequence accumulate t_ij (raw counts, no dedup, no reweighting by position). Popularity margins n_i = sum_j t_ij, m_j = sum_i t_ij. Lift w_ij = t_ij / sqrt((n_i+1)(m_j+1)). S_i = the smallest prefix of the w_ij-sorted successors whose cumulative weight reaches 50% of sum_j w_ij, capped at 16 (B_i = min(16, b_i), floor 1). Then m_i^(l) = sum_{j in S_i} w_ij c^(l)_{e_l(j)} / sum_{j in S_i} w_ij using the FROZEN BASELINE assignment e_l (this breaks the circularity: the centroid never depends on the permutation being optimised). Items with empty S_i get m_i^(l) = 0.
LEAKAGE BOUNDARY: The transition counts, the successor sets, the quotient graphs and the curvature null distribution are computed exclusively from training-split sequences; no validation or test interaction, item or session is read at any point. The item embeddings and codebooks are the frozen Stage-2 artefacts trained on the training catalogue. The curvature measurement is run ONCE, offline, before the arm starts, on a single process (not inside the training loop), and written to a JSON artifact that every rank reads at start-up, so there is no rank-0-only broadcast or in-loop export; every rank reconstructs identical kappa_l, s_l and q_k from the artifact plus the frozen codebook. Stage-3 is untouched and only measures.
HYPERBOLIC OPERATOR: Per-level trainable-free negative curvature -kappa_l with kappa_l = exp(delta_l) in [0.25, 4] (numerically ~[0.720, 0.931, 1.491] for the measured delta = [-0.328, -0.071, +0.399]), used through (i) the Poincare exponential map at the origin exp_0^kappa(v) = tanh(sqrt(kappa)||v||/2) v / (sqrt(kappa)||v||), and (ii) the Poincare distance d_kappa(x,y) = (1/sqrt(kappa)) arcosh(1 + 2 kappa ||x-y||^2 / ((1 - kappa||x||^2)(1 - kappa||y||^2))).
HYPERBOLIC LOCATION: At quantisation, in the code-assignment operator that writes the SID table, after the frozen Stage-2 codebooks exist. The curvature never enters the encoder, the decoder, the codebook update, the straight-through gradient or any radius/scale of the Euclidean code vectors; it acts only inside the ranking function that decides which item receives which already-existing triple.
COUPLING PATH: One chain: training transitions -> (w_ij, S_i) -> successor-code centroid m_i^(l) -> exp-map to the behaviour anchor p_i^(l) -> Poincare distance d_{kappa_l}(p_i^(l), q_k^(l)) with kappa_l from the null-standardised measured curvature -> per-level hyperbolic rank -> additively summed with the reconstruction rank into C(i,T) -> the arg-min of C and the transposition gate -> the item's SID triple -> what Stage 3 generates. Removing the behaviour term removes m_i and p_i, all four ranks collapse to the Euclidean rank, no transposition is accepted, and the SIDs are byte-identical to baseline; removing the curved metric (replacing d_kappa by ||p-q||_2 on the same ball coordinates) keeps every behaviour quantity identical and changes the H-orderings, hence the accepted transpositions. Neither component can be deleted without changing the emitted SID table, and the change is a top-1 (indeed top-3) index change, measurable and reportable.
COUPLING EQUATION: C(i,T) = rank_E(i,T) + sum_{l=1..3} rank_H,l( i, T_l ) with rank_H,l(i,k) = rank of H_l(i,k) = d_{kappa_l}( p_i^(l) , q_k^(l) ) within { H_l(i,k') : T' in Cand_i }, and p_i^(l) = exp_0^{kappa_l}( m_i^(l) / s_l ), q_k^(l) = exp_0^{kappa_l}( c_k^(l) / s_l ), m_i^(l) = sum_{j in S_i} w_ij c^(l)_{e_l(j)} / sum_{j in S_i} w_ij, kappa_l = exp(delta_l). The behaviour term is the w_ij/S_i-driven m_i inside p_i; the curved term is d_{kappa_l} with the measured kappa_l; they multiply/meet only inside H_l, and H_l only enters additively.
OBSERVABLES: (1) top-1/level-wise flip count and flip rate of the emitted triple per item, with behaviour on vs off (must be > 0, reported); (2) equality certificate: the triple multiset, each level's usage histogram, the count of distinct triples and the collision rate must equal the baseline's exactly (integer equality, asserted in code, printed); (3) level-1 hit rates at 0.079/0.005 and collision at 0.177 as an exact-equality check against baseline (they are conserved, so any drift is a bug); (4) mean and median d_{kappa_l}(p_i^(l), q^(l)_{T_l}) over training transitions before/after, expected to fall; (5) successor prefix agreement, i.e. the fraction of training transitions u->v whose level-l tokens now agree or share the modal successor token, recorded per level; (6) total ranked cost C summed over items before/after (monotone decrease by construction); (7) Stage-3 test_recall@10, the only judgement.
ABLATION BEHAVIOR OFF: SWITCH_BEHAVIOUR = 0 sets m_i^(l) = 0 for all i and l, hence p_i^(l) = origin, H_l(i,k) identical for all k, every rank_H ties at 0 and is broken by code index, C reduces to rank_E, every target equals the item's own triple, no transposition is accepted, and the emitted SID table equals the baseline Euclidean table element-wise. This arm is implemented and unit-tested for exact equality against the baseline SID file; it is never trained.
ABLATION GEOMETRY OFF: SWITCH_GEOMETRY = 0 keeps every behaviour quantity (w_ij, S_i, m_i, the same ball points p_i and q_k, the same candidate sets, the same ranks) and replaces only d_{kappa_l}(x,y) with the Euclidean ||x-y||_2 on the same ball coordinates, which is the kappa -> 0 limit of the Poincare distance up to the factor 2. kappa_l is then unused. This arm is implemented and exercised in a unit test on a fixed toy batch only; it is never trained.
ABLATION BOTH ON: SWITCH_BEHAVIOUR = 1 and SWITCH_GEOMETRY = 1 with the frozen kappa artifact: the full coupled assignment described above. This is the single arm that is trained and evaluated in this round; the two off-switches exist only as code paths and unit tests, no arm is launched with them off.
SPEC EQUATIONS: 1) w_ij = t_ij / sqrt((n_i+1)(m_j+1)); S_i = smallest cumulative-50%-mass prefix, cap 16. 2) delta_l = (kappa_hat_l^obs - mean_r kappa_hat_l^{null,r}) / std_r kappa_hat_l^{null,r}, over R = 20 shuffles that permute the level-l code labels among items while preserving the code-size multiset and rebuild the quotient graph with training transition masses; kappa_l = clip(exp(delta_l), 0.25, 4). 3) s_l = median_k ||c_k^(l)||. 4) exp_0^kappa(v) = tanh(sqrt(kappa)||v||/2) v/(sqrt(kappa)||v||), with exp_0^kappa(0) = 0. 5) d_kappa(x,y) = kappa^{-1/2} arcosh(1 + 2 kappa ||x-y||^2 / ((1-kappa||x||^2)(1-kappa||y||^2))). 6) Residual chain for a triple T: r_1 = z_i - c^(1)_{T_1}; r_2 = r_1 - c^(2)_{T_2}; r_3 = r_2 - c^(3)_{T_3}; E(i,T) = sum_l ||r_l - c^(l)_{T_l}||^2. 7) H_l(i,T_l) = d_{kappa_l}(p_i^(l), q^(l)_{T_l}). 8) Cand_i = {T_i^base} U {T_j^base : j in S_i} U {T_j^base : j in NN_8(i)}, capped 32 by Euclidean item distance to i. 9) C(i,T) = rank_E(i,T) + sum_l rank_H,l(i,T_l), all ranks taken within Cand_i U {T}, ties broken by (rank, triple integer id). 10) Descent pseudocode: for pass in 1..2: order items by gain_i = C(i,cur_i) - min_{T in Cand_i} C(i,T) descending, tie by item id; for each i: T* = argmin; if T* == cur_i continue; for j in the first 32 holders of T* (ordered by hash(j) fixed seed): d = C(i,T*)-C(i,cur_i) + C(j,cur_i)-C(j,T*); keep the j with the smallest d; if d < 0: swap cur_i and cur_j, update the triple->holders index. 11) Emit the final cur_i as item i's SID triple.
SPEC INPUTS OUTPUTS: Inputs: frozen item embeddings Z (24556 x d), frozen codebooks C^(1..3), the baseline Euclidean triple table, the training sequences, the cached curvature artifact {delta_l, kappa_l, s_l}. Outputs: a new triple table (24556 x 3) whose multiset of triples is identical to the baseline's, plus a JSON report with flip counts per level, the multiset equality assertion results, before/after mean d_kappa on successor pairs, and the summed cost C before/after.
SAFEGUARDS: (i) Ball-coordinate clamp: if kappa||x||^2 > 1 - 1e-6 rescale x by sqrt((1-1e-6)/kappa)/||x||; all geometry in float64. (ii) arcosh evaluated as log1p(z + sqrt(z(z+2))) with z >= 0 clamped at 0 to avoid cancellation. (iii) Empty S_i or zero total weight -> m_i = 0 -> p_i = origin -> H ties -> item keeps its Euclidean anchor (no forced move). (iv) No move is forced: a transposition is accepted only if the summed ranked cost strictly decreases, so the descent is monotone and terminating; if no improving transposition exists the baseline table is emitted unchanged and this is reported as zero flips rather than treated as an error. (v) Deterministic tie-breaking everywhere (rank, then triple id, then item id, then a fixed hash for holders) so the table is reproducible and rank-independent. (vi) Explicit integer assertions after the pass: triple multiset equality, per-level usage histogram equality, distinct-triple count equality, collision-rate equality; any failure aborts and falls back to the baseline table rather than emitting a corrupted SID set. (vii) kappa clipped to [0.25, 4] and s_l floored at 1e-6 so a degenerate codebook cannot divide by zero; if all code norms are zero the geometry switch degrades to Euclidean and the run reports it. (viii) The curvature artifact is read, never recomputed, at run time, and its producer runs once offline, so no cross-rank synchronisation exists inside the training loop.
END IDEA
