IDEA: EQVOTE-HYP-RQ
TITLE: Exact-quota hyperbolic vote assignment: an additive curvature-kernel behaviour bias that permutes RQ slots without ever touching the usage multiset
MOTIVATION: The baseline TIGER_RQ-VAE (247/7414/20223, Stage3 test_recall@10 = 0.055537) clusters items purely by content, so a fine (level-3) token says "this item looks like these items" and not "this item sits on this behavioural branch". The generative model therefore has to guess branch identity from content evidence alone. Round 1 tried to fix this by spending the measured behaviour-graph curvature on the SID space radius and the codebook collapsed (170 -> 56 distinct triples, recall 0.041888); round 2 tried to fix it with a multiplicative per-pair cost weight and the verifier measured 0 of 4 argmins moving. The problem is real (the level-3 behaviour quotient is more tree-like than its size-preserving null, delta_3 = +0.399) but it needs a mechanism whose top-1 effect is provable and whose capacity effect is zero.
NOVELTY: Three things that no earlier arm here did. (i) The behaviour term is a bounded PROBABILITY-like vote, not a distance rescale: v(i,c) in [0,1], so its top-1 effect is an absolute cost gap rather than a ratio gap and cannot be a no-op on non-equidistant codes. (ii) The assignment object is not a soft plan and not a radius: quotas are read off the Euclidean pass and then the labelling is changed only by composing transpositions of two items' labels, so the per-level usage multiset is invariant BY CONSTRUCTION with nothing to assert about marginals. (iii) The curvature is spent INSIDE the kernel metric used to spread the vote (curvature nu_l = exp(delta_l) on R-normalised coordinates), so it changes which codeword a behaviour vote lands on while leaving codebook vectors, radii and counts untouched; and the sign-gated strength s_l = [delta_l]_+ / sum [delta_l]_+ spends it only where the measured quotient is genuinely above its null, which on the evidence is level 3 alone.
CHANGE: At each RQ level the Euclidean residual argmin is computed first and its per-codeword counts are frozen as quotas; every training successor of item i then casts a weight w_ij at the level-l codeword it currently occupies, that vote is spread over codewords by a Poincare kernel exp(-d_P(v_l)^2/2) evaluated at curvature exp(delta_l) on R-normalised codebook coordinates, and the negated vote enters the assignment cost as an ADDITIVE term whose magnitude is the level's own measured median reconstruction distortion. The item-to-codeword labelling is then improved by accepted transpositions only, so the Euclidean usage multiset is reproduced exactly.
SPECIFICATION: 
Notation: level l in {1,2,3}; codebook E_l = {e_c}, c = 1..256; r_{l-1}(i) is the level-l input residual; R = median_i ||x_i|| over the 24556 training content embeddings (offline, one scalar).
Offline constants (a 3-vector shipped in the config): delta_l = kappa_hat_l - mean_l(kappa_hat_l), where kappa_hat_l is the edge-weight-weighted mean of the null-standardised Ollivier curvatures of the training behaviour quotient at the frozen baseline SIDs' level-l prefixes. On the measured evidence delta = [-0.328, -0.071, +0.399].
Per step, per level l (levels with s_l = 0 are skipped entirely and are bit-identical to the baseline):
1. Euclidean pass: cE(i) = argmin_c ||r_{l-1}(i) - e_c||^2; quotas q(c) = |{i in batch : cE(i) = c}|.
2. Ball map: nu_l = exp(delta_l); z_c = exp_0^{nu_l}(e_c / R), with exp_0^nu(v) = tanh(sqrt(nu)||v||/2) v/||v||.
3. Kernel: Khat[c,c'] = exp( -d_P^{nu_l}(z_c, z_c')^2 / 2 ), distances in R units.
4. Successor vote: v(i,c) = sum_{j in N+(i)} w_ij Khat[c, c_l^cache(j)] / sum_{j in N+(i)} w_ij, and v(i,c) = 0 if N+(i) is empty; c_l^cache is the previous-epoch-end level-l Euclidean code of j.
5. Additive cost: S(i,c) = ||r_{l-1}(i) - e_c||^2 - lambda_l * v(i,c), with lambda_l = s_l * median_i ||r_{l-1}(i) - e_{cE(i)}||^2.
6. Quota-exact permutation by swap local search (T = 3 passes, no cap on accepted swaps): described in SPEC EQUATIONS.
7. The final labelling drives the usual codebook EMA/update; the geometry and the kernel are detached (no gradient through the hyperbolic map).
COST: Only level 3 executes (s = [0,0,1] on the evidence). Added per step at 1023 x 256 x 32: cost matrix 8.4 MFLOP, codebook kernel 256x256x32 = 2.1 MFLOP, sparse vote 1023x16x256 = 4.2 MFLOP, three swap passes ~1.6 MFLOP, total ~16 MFLOP per step against the baseline's level-3 assignment of ~8.4 MFLOP, i.e. 2-3x the RQ-VAE assignment work and roughly 1.4-2x Stage-2 wall clock over 3000 epochs x 24 steps = 72,000 steps (tens of minutes, four cards). Epoch-boundary residual cache refresh over all 24556 items is 0.4 GFLOP per epoch, 1.2 TFLOP total, minutes. Offline curvature precompute: transition graph a few million edges, Ollivier W1 per edge under 32 member-shuffle draws, a few minutes to ~20 minutes once on CPU. Memory +0.3 MB (batch x C plus C x C). Stage 3 is untouched and runs the frozen protocol.
HYPOTHESIS: Worth keeping iff (i) the vote materially reorders the fine level - frac_top1_changed_3 between roughly 0.08 and 0.30 with levels 1 and 2 at exactly 0 - and (ii) that reordering raises the fine-token conditional predictability of the true next item without raising collisions. Observed as: distinct-triple count stays near 7414 (it cannot fall below the baseline level-1 pattern because that level is bit-identical), first-level hit rates stay at 0.079/0.005, collision near 0.177, and Stage3 test_recall@10 > 0.055537 with 0.065 as the target. If frac_top1_changed_3 is under 0.02 the coupling is present but inert and the idea is dead regardless of recall.
RISKS: (1) Co-consumed items are content-similar, so the vote may mostly agree with the Euclidean argmin and few swaps survive the cost test - the mechanism becomes a no-op and recall is unchanged. (2) Because the cost test includes the Euclidean distortion, the swaps may concentrate on poorly reconstructed, low-margin items and change nothing that matters. (3) The level-3-only gate makes the effect small: one token of three changes for a minor fraction of items, so even a correct mechanism may only move recall by a few thousandths. (4) The hyperbolic kernel may be numerically close to the Euclidean kernel for codewords at similar radii, making the geometry-off arm nearly identical to both-on; this is the specific comparison that must be reported, not assumed. (5) Successor votes taken from the previous epoch's cache lag by up to 24 steps and could reinforce an early accident.
BEHAVIOR SIGNAL: Popularity-adjusted directed item transitions inside training sequences - for each item i, the multiset N+(i) of items that follow it within a window of 5 positions, with per-pair weight w_ij = cnt(i->j) / sqrt(pop_i * pop_j).
BEHAVIOR COMPUTATION: Built once, offline, from the training split sequences only (user, item, timestamp ordered): cnt(i->j) counts every ordered pair at distance 1..5 in a user's training sequence; pop_i is the training interaction count; the suffix-popularity normalisation is applied at use time. Stored as a fixed successor table (top 16 by weight per item, 24556 x 16 int32 plus float32 weights). During training the table is read only, and the level-l codes of the successors are taken from the epoch-boundary residual cache, which every rank recomputes identically from the fully replicated content matrix and the replicated codebook.
LEAKAGE BOUNDARY: The successor table is built from training sequences only; no validation or test sequence is read by the offline script, and the curvature quotient uses the frozen baseline RQ-VAE whose Stage-2 fit used the training split only. The null-standardised curvature is reduced to three scalars delta_1..delta_3 that are shipped as configuration constants, so nothing about validation or test can enter the SID construction at run time, and no validation-selected constant exists: lambda comes from a measured median, R from a measured median, the strength s from the measured delta, the kernel's 1/2 is the Gaussian default, T = 3 is a documented default, and neither lambda nor T is ever varied.
HYPERBOLIC OPERATOR: Poincare-ball exponential and distance at trainable-free, measurement-derived negative curvature nu_l = exp(delta_l) (dimensionless in units of R): exp_0^nu(v) = tanh(sqrt(nu)||v||/2) v/||v||, and d_P^nu(x,y) = (1/sqrt(nu)) arcosh(1 + 2 nu ||x-y||^2 / ((1 - nu||x||^2)(1 - nu||y||^2))), with the ball radius 1/sqrt(nu).
HYPERBOLIC LOCATION: In the assignment cost only, at the level(s) with delta_l > 0, inside the codebook-to-codebook kernel that spreads the training-successor vote. It does not touch the codebook vectors, the codebook radius, the quotas, or the residual computation.
COUPLING PATH: training transitions -> per-item successor vote over codewords -> vote spread by the Poincare kernel at curvature exp(delta_l) -> additive term lambda_l * (-v(i,c)) in the assignment cost -> quota-preserving transposition -> final level-l label -> codebook sum update and SID token. Removing the behaviour empties N+(i) so the vote is identically zero and the cost collapses to the Euclidean one, which leaves no accepted transposition; removing the curved operation replaces d_P by the Euclidean distance in the kernel, which changes the spread of every vote and therefore the argmin set. Neither half is a side term: both are operands of the same kernel-weighted vote.
COUPLING EQUATION: S_l(i,c) = || r_{l-1}(i) - e_c ||^2  +  lambda_l * ( - [ sum_{j in N+(i)} w_ij * exp( - d_P^{exp(delta_l)}( e_c/R , e_{c_l(j)}/R )^2 / 2 ) ] / [ sum_{j in N+(i)} w_ij ] ), with lambda_l = s_l * median_i ||r_{l-1}(i) - e_{cE(i)}||^2 and s_l = [delta_l]_+ / sum_{l'} [delta_l']_+.
OBSERVABLES: Per level, frac_top1_changed_l = |{i : a_l(i) != cE_l(i)}| / n; expected [0, 0, 0.08-0.30]. The count of distinct used level-1 codes must stay exactly 247 (it is invariant by construction); distinct triples stay near 7414 rather than collapsing toward the 56-170 range of round 1; collision stays near 0.177; first-level hit rates stay at 0.079/0.005 because level 1 is bit-identical; the level-l codebook sum norms move away from the baseline even though the counts do not; and Stage3 test_recall@10 is read once against 0.055537.
ABLATION BEHAVIOR OFF: N+(i) := empty for every item, so v == 0, every swap gain is exactly 0, no transposition is accepted, and the labelling equals the Euclidean pass bit for bit; frac_top1_changed = 0 at every level and Stage 2 reduces to the baseline RQ-VAE.
ABLATION GEOMETRY OFF: The curved operation is replaced by the Euclidean one - delta_l := 0, d_P replaced by ||e_c - e_c'||/R in the kernel, and the Euclidean mean used wherever a curved centroid would be used - while the behaviour vote, the quotas, lambda_l and the swap search are unchanged.
ABLATION BOTH ON: The full coupled run above: curved kernel at nu_l = exp(delta_l), behaviour vote from N+(i), additive bias, quota-exact transposition. This is the only arm that is trained.
SPEC EQUATIONS: 
Offline:
  cnt(i->j) from training sequences, window 5; w_ij = cnt(i->j)/sqrt(pop_i pop_j); keep top 16.
  R = median_i ||x_i||.
  for l in 1..3: build quotient graph over baseline level-l prefix groups, W_l(alpha,beta) = sum_{i in alpha, j in beta} cnt(i->j); kappa(alpha,beta) = 1 - W1(m_alpha, m_beta)/d(alpha,beta) with lazy (1/2) walk measures;
    null: 32 draws of a size-preserving member shuffle (permute item->group membership, preserve group sizes and the edge total); kappa_hat(alpha,beta) = (kappa - mu_null)/sigma_null;
    kappa_hat_l = edge-weight-weighted mean; delta_l = kappa_hat_l - mean_l kappa_hat_l.
  s_l = [delta_l]_+ / sum_l' [delta_l']_+  (if all zero: s = one-hot at argmax delta_l).
Per step:
  for l in 1..3:
    if s_l == 0: a_l = cE_l; continue        # baseline path, unchanged
    z = tanh(sqrt(nu_l)||e/R||/2) * (e/R)/||e/R||            # [C,d]
    D = arcosh(1 + 2 nu_l ||z_c - z_c'||^2 / ((1-nu_l||z_c||^2)(1-nu_l||z_c'||^2))) / sqrt(nu_l)
    Khat = exp(-D*D/2)                                       # [C,C]
    v[i,c] = sum_j w_ij*Khat[c, cache(j)] / sum_j w_ij        # [B,C], 0 if N+(i) empty
    lambda = median_i ||r_{l-1}(i) - e_{cE(i)}||^2
    S = ||r_{l-1}(i) - e_c||^2 - lambda * v
    a = cE
    for t in 1..3:
      cs = argmin_c S; g = S[i,a[i]] - S[i,cs]                 # g >= 0
      bucket[p,q] = argmax_{i: a[i]=p, cs[i]=q, g[i]>0} g[i]    # scatter-max over p*C+q
      for each unordered pair {p,q} with both buckets filled:
        i = bucket[p,q]; j = bucket[q,p]
        if S[i,q] + S[j,p] < S[i,p] + S[j,q]: swap labels of i and j
    return a, with counts(a) == counts(cE) by the transposition lemma
SPEC INPUTS OUTPUTS: Inputs: level-l residuals r_{l-1}(batch) [B,d], codebook E_l [C,d], successor table N+ with weights [B,16], successor level-l Euclidean codes from the epoch cache [B,16], the offline constants delta_l and R, and s_l. Outputs: the final level-l label a_l(i) for every item in the batch (feeding the codebook EMA/update and the SID token), plus the diagnostics frac_top1_changed_l and the count multiset q(c). Side output for the next epoch: refreshed full-set residuals and Euclidean codes.
SAFEGUARDS: arcosh argument clamped to >= 1 + 1e-7 and the denominator to >= 1e-9; ball coordinates clipped at ||z|| <= 0.997/sqrt(nu_l), which is safe because R is chosen so the median point sits at tanh(exp(delta_l/2)/2) ~ 0.46 of the ball radius; kernel exponent floored at -60; v floored at 0 and capped at 1 (it is a convex combination, so this is only float hygiene); lambda_l floored at 1e-6 * mean_i ||x_i||^2 so a degenerate level cannot produce a zero-cost bias; if the batch has fewer than two distinct occupied codewords, or if max_c v(i,c) - min_c v(i,c) < 1e-8 for every i, the swap search exits early and the labelling equals the Euclidean pass; all reductions are over full replicated tensors so every rank computes the identical delta, R, s and cache and no broadcast, collective or rank-0 read happens inside the training loop; no random tie-breaking anywhere (ties broken by lowest codeword index) so the run is exactly reproducible.
END IDEA
