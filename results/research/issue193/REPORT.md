## P0-1 两条选码路径的不一致率

同一 checkpoint、同一份 embedding（本臂自己的 `maybe_apply_pca` + `load_embeddings`），全量 24,587 商品：

| 口径 | 不一致商品 | 比例 |
|---|---|---|
| L1 | 174 | 0.7077% |
| L2 | 224 | 0.9111% |
| L3 | 286 | 1.1632% |
| **三码（任意一层不同）** | **338** | **1.3747%** |

- **分块不是原因**（`p0_1_chunking.json`）：整库一次前向与 4096 分块给出**完全相同**的 174/224/286；两种口径下 curvature−euclidean 的差都等于 338。
- **κ 集中在高曲率商品**：不一致组 κ 中位 **1.3446**、均值 1.4759；一致组中位 0.9048、均值 0.9922（`p0_1_summary.json`）。
- **样本清单位于** `p0_1_samples.json`（25 件，按 |κ−中位| 降序），含每件的 κ、两条路径的三码。
- **导出复现残差**（`p0_1_export_check.json`）：整库 CPU 重跑本臂导出路径 `_encode_all` 与已发布 `item_sids.json` 相差 82 件（逐层 2 / 28 / 76）。这是设备精度残差（发布文件由 CUDA 产生），与两种代价矩阵的差异无关。
- 结论措辞按 Issue 规定的阈值处理：**1.3747% > 1%**，故路径不一致**成立且不可忽略**；但它同时意味着 **98.6% 的商品两条路径选码一致**，因此它不足以单独解释 #181 的读数——两项事实必须并列，不能只引用其中一项。

## P0-2 AF3 教师的三角形计数

**实现缺陷**：`af3_values` 写的是 `4 − d_i − d_j + 3.0`，常数 3 只在 `m_ij = 1` 时等于 `3·m_ij`；且该常数同时进入 `q05/q95` 归一化，在 `W = 1 + clip((AF3−q05)/(q95−q05),0,1)` 中被消掉，边权因此**只依赖度数和**。

**修正**（审计副本 `af3_teacher_fixed.py`）：`3·m_ij`，`m_ij` = 共同邻居数；`weights` / `build` / `build_sparse` 全部把邻接表传下去，避免"分位数用一套、权重用另一套"。

**红→绿**（`test_af3_teacher.py`，7 个手算用例；`AF3_TARGET=shipped|fixed`）：

| 用例 | 真值 | 现行实现 | 修正实现 |
|---|---|---|---|
| 无三角 4-环 | 全部 0 | 全部 3.0 ❌ | 0 ✅ |
| 单三角 | 全部 3 | 3 ✅ | 3 ✅ |
| K4 | 全部 4 | 4 ✅ | 4 ✅ |
| 路径+弦 (0,1)/(1,2)/(1,3)/(2,3) | 0 / 2 / 2 / 3 | 与真值不符 ❌ | 一致 ✅ |
| 4-环分位数 | (0, 0) | (3, 3) ❌ | (0, 0) ✅ |
| 同度序列下三角形必须改变权重 | 必须改变 | 不改变 ❌ | 改变 ✅ |

`AF3_TARGET=shipped`：**5 failed / 2 passed**（`red_run.txt`）；`AF3_TARGET=fixed`：**7 passed**（`green_run.txt`）。

**真实训练图上的旧/新对比**（`p0_2_quantiles.json`，`train.parquet`，396,958 行 → **323,633 条边**、24,556 个商品）：

| | 现行（常数 3） | 修正（3·m_ij） |
|---|---|---|
| q05 / q95 | −1189.0 / −18.0 | −1078.4 / −20.0 |
| u = 0 占比 | 5.001% | 5.000% |
| u = 1 占比 | 5.435% | 5.148% |
| u 均值 / 标准差 | 0.7868 / 0.2696 | 0.7798 / 0.2714 |

- **40.21% 的边三角形数为 0**，其余 1–≥6；即"常数 3"对四成边是完全错的加项。
- 但经归一化后 u 的变化很小：**Spearman(旧,新) = 0.99929**，平均 |Δu| = 0.0118（90.3% 的边有 >1e-12 的改动，但幅度约 1%）。
- 原因：该图上 AF3 被 `−(d_i + d_j)` 主导（q05 达 −1189），三角形项量级小。
- 因此**缺陷真实存在，但对教师权重近乎无关**：修正后教师权重的秩相关 0.9993。`#181` 的负结果**不能**归因于这个缺陷——这点必须写下，否则会把"实现错误"误读成"机制被证伪"。

## P0-3 教师–SID 保真度（前导指标，与 recall 并列）

方法：`T = (P + P^2)/2`（稀疏，按 anchor 行取用，不构造 24,587² 稠密矩阵），512 个 anchor 的 teacher 支撑集（≤4096/行，共 **895,540** 对），与 `item_sids.json` 的三码逐层比较。

| 指标 | 现行教师 | 修正教师 |
|---|---|---|
| Pearson(权重, 共同前缀层数) | **0.10530** | 0.10543 |
| Pearson(权重, 逐层一致比例) | 0.10530 | 0.10543 |
| Spearman(权重, 共同前缀层数) | **0.10746** | 0.10803 |
| KL(P_teacher ‖ Q_sid) 均值 | **2.03845** | 2.04468 |

分层均值（共同前缀层数 → teacher 权重均值）：

| 共同层数 | 现行 | 修正 | 支撑集占比 |
|---|---|---|---|
| 0 | 0.000396 | 0.000396 | 94.95% |
| 1 | 0.000868 | 0.000869 | 4.80% |
| 2 | 0.002221 | 0.002224 | 0.19% |
| 3 | **0.020023** | **0.020114** | 0.07% |

读法：
1. **方向正确、强度很弱**：teacher 权重随共同前缀层数**单调上升**，三码全同时均值为零层时的 **50.6 倍**；但线性/秩相关只有约 **0.105 / 0.107**，KL 2.04 说明 SID 分布与 teacher 行分布相差很大。弱相关主要来自支撑集极度偏斜（94.95% 的对零层相同）。
2. **缺陷不影响这个结论**：修正教师的两项相关与 KL 与现行几乎一致（0.10530→0.10543、KL 2.0385→2.0447），再次表明三角形计数缺陷不是 #181 读数的主因。
3. 这是**前导指标**，按 §64 不作为晋级闸门；`test_R@10` 仍是唯一判据。

## 附：#193 断言 4（曲率挂钩的层范围）

`model/layers.py` 的 `_distances` 位于**通用 `VQLayer`**，`r48k2_assign.level1_cost` 因此在**每一层**生效，而 #180 的设计只针对 L1。P0-1 的逐层不一致（174 / 224 / 286）正是该路径在**三层全部**起作用的直接证据：若只有 L1 受影响，L2/L3 的不一致应为 0。是否回灌 #181/#180 树另开 Issue，本 Issue 不改动候选树。
