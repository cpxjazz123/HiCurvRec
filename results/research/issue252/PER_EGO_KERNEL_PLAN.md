# per-ego 融合核设计草案（Issue #252 性能路线 A）

目标：把 2-hop 全体 ego 的活体 GNN 从 cuSPARSE 按边 gather 的实现，换成直接消费**静态 ego 布局**的融合核，数学不变。
当前实测：单卡单步 98.3 ms，4 卡 60 epoch 窗口 0.8032 s 均值 / 0.7415 s 中位；门槛 ≤0.5 s/轮（6 步/轮 ⇒ 单步 ≤75 ms）。

## 1. 现在慢在哪（实测，1024 件/批，2-hop）

| 项 | 值 |
|---|---|
| ego 节点数 | 1,452,365（均值 1508/件） |
| 每向边数 | 20,272,387（均值 20,878/件） |
| 装配 CSR | 9.2 ms（每步物化每批块对角 CSR：列/值/crow ≈1.5 GB 临时量） |
| 两层 GNN 前向 | 17.1 ms（cuSPARSE SpMM：每条边 gather 一个 32 维向量） |
| 反向 | 14.1 ms（伴随 SpMM，再来一遍同样的 gather） |

访存估算：每向 20.27M × 32 × 4 B ≈ 2.6 GB，正反两向 + 反向传播 ≈ **10.4 GB/step**；按 L40S 约 800 GB/s 的下限也要 13 ms，而实测 31 ms。

## 2. 融合核的做法

静态资产（`assets/v9_ego_operators`）已经按 ego 存好每件商品的完整节点表与两个方向的 CSR 行指针/列索引（int32）。因此**不需要每批拼块对角矩阵**：

- 每批的 ego 是若干条**连续区间**（每个 ego 的节点/边在布局里连续）；
- 核按 ego（或 ego 组）处理：把该 ego 的 x 块（≈1508×32 ≈ 193 KB）放进 shared memory / L2，
  按该 ego 自己的行指针与列索引做行归一化累加；
- x 每 ego 只读一次，输出写一次，边表读一次。

流量估算：前向每向 ≈ x 186 MB + 输出 186 MB + 静态边表 81 MB ≈ 0.45 GB，两向 + 反向 ≈ **1.8 GB/step**（≈6× 于现在），
并且**每批块对角 CSR 的物化完全消失**（装配 9.2 ms → ~0）。

## 3. 为什么数学不变

- 现在的 `normalized_directional_means` 就是 `D^{-1} A x`，A 是 ego 内按行度数归一化的邻接（值 = 1/deg）；
- 核做的是同一件事：按 ego 的行指针遍历该行的列、对 x[col] 求和再乘 1/deg；
- 差别只在**求和顺序**。cuSPARSE 的求和顺序本来就未指定，契约对独立参考实现只要求 rtol 1e-4；
  float32 下行内 14 项求和的误差量级 ~1e-7，落在容差内；
- 行的**值**必须逐位保持：仍是同一组 1/deg（float32）与同一组列，只是累加顺序不同。

## 4. 必须一起做的两件事

1. **精确伴随**：反向要给出 `grad_x = A^T grad_out`（同一套静态支撑，只换度数），
   不能再走现在的 `_transpose_pair`（它每步物化两份转置 CSR）；
   反向的伴随核必须与前向核共用同一支撑与同一归一化常数。
2. **四处校验重跑**：值（对独立稠密参考）、梯度（对稠密参考的 autograd）、SID（同一 checkpoint 重编码一致）、
   DDP（四卡一致）；准入凭证要按新源码哈希重生成。

## 5. 风险与备选

| 风险 | 缓解 |
|---|---|
| 自定义核的数值与 cuSPARSE 差在容差外 | 用同一 CSR 对照 cuSPARSE，逐元素比；不合格就退回“核只做装配、SpMM 仍用 cuSPARSE” |
| 伴随写错导致梯度方向反 | 与现有 `sparse_adjoint.py` 的伴随在同输入上逐元素比 |
| 工程量大、时间超预算 | 分两步：①只把**装配**改成核内直读静态布局（SpMM 仍用 cuSPARSE），约 −8 ms；②再换 SpMM |
| 数值精度不够 | 若 owner 允许，第二层 SpMM 走 fp16/bf16（误差 ~1e-3，超出当前 rtol 1e-4，需显式批准） |

## 6. 若不做路线 A

诚实现状：单步 98.3 ms，轮 0.8032 s 均值 / 0.7415 s 中位。离 ≤0.5 s 差约 40%。
此时只有两条路可走，都需要 owner 决策：

- **放宽验收门槛**到 ~0.8 s/轮（并记录理由）；
- **改机制本身**（2-hop ego 的规模/尺度、辅助总体 256 件的规模），这会改变已冻结的机制契约。

正式训练在这两条路都未决前不启动：没有 3000 轮 Stage2、没有 Stage3、没有 R2 归档。
