## 3. Inherited mechanisms

All four mechanisms listed under `ACTIVE_MECHANISMS_BEFORE` are inherited verbatim from iter18.  No loss weight, optimizer hyperparameter, dataset, or Stage3 trainer setting is changed for non-codebook parameters.

## 4. Optimizer differences (for codebook only)

`AdamW(lr=1e-3, β₁=0.9, β₂,l=frozen from c_l(0), eps=1e-8, wd=1e-4)` is the same group wiring as iter18 **but for encoder + decoder + per-layer `c_layer_scale` only**.  The codebook `layers.X.embedding.weight` is **excluded** from the optimizer entirely; `check_step5_optimizer` (iter18 strict check) is intentionally skipped because it would fail on the missing codebook.  A custom iter28 check replaces it (verifies every trainable param is either in an optimizer group OR is a codebook embedding.weight).

## 5. Loss differences

None.  `reconstruction + rqvae + 0.20·behavior + 0.005·curv_reg` is unchanged.  No new term is added.

## 6. Stage1 / Stage3 differences

None.  Stage1 reads the same `sentence_t5.npy` + `item_ids.json`.  Stage3 uses `code_path = item_sids.json` (TIGER-compatible 4-token format) generated by Stage2; the trainer T5 hyperparameters, beam, n_eval, and launcher env are identical to iter18.

## 7. One-factor statement

The only conceptual change is the **post-`optimizer.step()` Sinkhorn-weighted Riemannian EMA codebook update** introduced in iter28.  No second mechanism is introduced alongside it; no mechanism from iter18 is removed or weakened (the iter18 `β₂` mechanism still operates on `c_layer_scale` / encoder / decoder).

## 8. Stop conditions

- If `preflight_cao1.py` fails, stop before training.
- If `mvg_check.py` fails, stop before training.
- If `clip_frac` of any SREMA summary line is replaced with `saturation_max >= 1` (escape from ball), stop.
- If `median_update < 1e-12` for every layer every 1000 steps for the entire run, classify F-1 inactive (autonomous abort per SKILL.md §2.9/§2.10).
