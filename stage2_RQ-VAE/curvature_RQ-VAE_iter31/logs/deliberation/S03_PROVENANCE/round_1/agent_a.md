## Arithmetic reproduction of fixed curvature

Using only the preserved JSON decimals and registered constants (`B_ref=2.0`, `m_ref=0.1`, `c_min=0.05`, `c_max=1.5`), the mapping is:

```text
x_l = B_l / (B_l + 2.0)
y_l = m_l_raw / (m_l_raw + 0.1)
u_l = (x_l + y_l) / 2
c_l = 0.05 + (1.5 - 0.05) * u_l
```

Arithmetic gives:

```text
x = [0.9062129756321139, 0.42206034326942476, 0.3366083742817442]
```

## Geometry and interpretation limitations

`_expmap0_t` projects the exponential result to radius `(1-eps)/sqrt(c)` with default `eps=1e-6`; `_logmap0_t` clamps its `atanh` argument to at most `1-1e-5`. Thus `log0^{c_l}(exp0^{c_l}(e_l))=e_l`, and the derived pointwise simplification `q_l^0=exp0^{c0}(e_l)`, are valid only in the nonsaturated, unclipped domain. No claim is made that actual embeddings stay in that domain. Projection/clamp rates, intermediate ball validity, finite `h`/`z`, and direct Step6 effect require later adjudicated preflight/MVG evidence.

The transfer `T_{c_l→c0}(q)=exp0^{c0}(log0^{c_l}(q))` has no general Möbius-addition homomorphism guarantee. Möbius addition is not generally associative, so the exact S02 tree/order must be retained. The paper's exact HRA telescope assumes paired residual subtraction and reverse-nested aggregation in one shared curvature; Iter29 uses heterogeneous fixed curvatures and cross-layer residual transport. No exact telescope, residual inversion, or cross-curvature homomorphism is claimed.
