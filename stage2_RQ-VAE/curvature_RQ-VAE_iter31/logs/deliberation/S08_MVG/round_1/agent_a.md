DECISION: HOLD_FOR_SCOPED_REPAIR

PRIMARY REASON — missing applicable component gradient. Root `CLAUDE.md` §6 requires component-wise `torch.autograd.grad(loss_item, model.parameters(), retain_graph=True, allow_unused=True)` for each applicable mechanism loss; the canonical S06 plan repeats that requirement for each relevant existing mechanism-loss component. `modules/rqvae.py:353–377` defines `behavior_loss` as an existing train-only next-item contrastive objective: per layer it compares hyperbolic distances between source residuals and future-item candidate residuals, uses masked cross-entropy for valid rows, and averages layer losses. `modules/rqvae.py:393–402` computes it in every forward and includes it in the actual total as `BEHAVIOR_LOSS_WEIGHT * behavior_loss`; the source constant is 0.20 (`modules/rqvae.py:24–27`). It is thus an applicable existing contrastive loss, not an HRA-specific auxiliary loss. The Step6 HRA change does not replace or remove that inherited loss. The output also preserves it as `RqVaeComputedLosses.behavior_loss` (`modules/rqvae.py:49–55, 427–430`).

But `scripts/mvg_check.py:302–340` defines the component dictionary with only `reconstruction` and `quantizer`; those are checked for graph/finiteness and nonzero gradients in expected parameter prefixes. It then calls `loss.backward()` and checks total-loss gradients (`:342–359`), but never calls `autograd.grad` on `output.behavior_loss`. The returned `hra_specific_auxiliary_loss: False` (`:356–359`) correctly says HRA introduced no new auxiliary loss, but does not make the inherited contrastive loss inapplicable. Total-loss gradients cannot substitute for measuring this individual component: the weighted combination could conceal a detached/zero contrastive branch while total gradients still pass. This gap alone makes the checker incomplete under the explicit contract.

EXACT SCOPED REPAIR: after Judge C authorizes a bounded repair, extend the component-gradient check to include `output.behavior_loss` as its own component, with graph/finiteness checks and `torch.autograd.grad(..., retain_graph=True, allow_unused=True)`; require at least one finite nonzero gradient among parameters actually expected to be affected by that contrastive computation (source trace supports encoder and/or quantizer/residual-path parameters; do not assume a particular prefix without confirming the actual path). Record its nonzero parameter names separately. Preserve the existing reconstruction/quantizer checks, total `loss.backward()`, exact registered mechanism, batch/checkpoint, and no-step/no-save behavior. Then return to S08 adjudication before any MVG execution. This is a verification repair, not a change to the research mechanism.
