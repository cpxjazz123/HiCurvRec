# Iter29 S07_PREFLIGHT — Agent B

## Decision

**Overall static audit: FAIL / NOT READY for the authorized official preflight as a complete contract-enforcement claim.** The active implementation correctly uses the registered FCCR-1 formula, explicit physical input keys, and a fixed-curvature buffer; the current JSON contains the approved inputs and derived values. The material gap is that the consumer recomputes from whatever vectors are in that JSON but never checks those vectors against the canonical S03/S02 input values. Because the output mapping uses the average of two transformed inputs, a changed input pair can preserve the registered curvature while changing the registered evidence. The formula is implemented once in `scripts/compute_closed_form_curvature.py`: constants/mapping ID at `:11-15`, ordered three-value finite/type/domain validation at `:18-41`, and the registered `x=B/(B+2)`, `y=m/(m+0.1)`, `u=(x+y)/2`, `c=0.05+1.45u` calculation and output checks at `:43-61`. **Material FAIL / missing check.** `_load_closed_form_curvatures()` recomputes from the two JSON vectors and compares computed intermediates to JSON (`curvature_RQ-VAE.py:290-322`), then compares computed curvature to the contract vector (`:323-350`). It does **not** compare `payload["branching"]` and `payload["raw_residual_medians"]` to the exact S03-approved vectors at `logs/mechanism_manifest_iter29.md:25-27`. The S04 contract stores the semantic input names and final curvature, but not the input values (`logs/mechanism_contract_iter29.json:10-11`). Since `c` depends on the sum/average of the transformed x and y, compensating changes to B and m can preserve c; if the JSON intermediates are recomputed too, these checks do not establish that the approved vectors were used. That violates the one-factor requirement to retain the same input vectors, even though the present file values are correct. The shared skill-level `preflight_contract.py` also only validates contract flags/finite curvature, required files, and source AST for trainable/scheduled curvature, fixed-buffer sites, and regularization (`.claude/skills/curvature-rqvae-iter/scripts/preflight_contract.py:52-74,90-150,152-197`); it does not read or recompute the input payload/formula. Thus a future official preflight result alone would not close this input-identity gap.
