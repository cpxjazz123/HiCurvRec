# The second curvature round: the machine verification refuses the coupling

Round `round_20261102_071156_961` (issue 121), the follow-up to the first
curvature round. The framework selected `CURVCAP-SUCCPLAN`, the mechanism was
implemented, and **the launch was refused by the machine verification** — which
is the most useful thing that could have happened to this proposal.

## What the round produced

| phase | outcome |
|---|---|
| ideation (5 agents) | four proposals, all `IN_SCOPE`: `CURVCAP-SUCCPLAN`, `CURVCHART-EQUIMARGIN-RQ`, `CURVCHART-RESGUARD`, `CURVEBEND-NORM-RESIDUAL` — every one of them answers the first round's failure by protecting the resolution |
| evidence probe | train-only behaviour statistics, a small-tensor curved check, a verified literature pass |
| scoring (3 independent scorers, ranking only) | `CURVCAP-SUCCPLAN` selected (total rank 7, one first place); the other three are the backups |
| implementation (the main agent writes it) | `model/capacity_assignment.py`, the field `a_ik`, the capacity-frozen Sinkhorn plan, the offline curvature profile, the quantizer's straight-through, 12 tests — all green |
| **machine verification** | **REFUSED**: the behaviour dependency is a multiplicative per-pair weight, and the check measured that such a weight left every arg-min unchanged |
| Stage 2 / Stage 3 | not run: the candidate never passed the admission |

## Why the verification refused it, and why it was right

The proposal's cost is

```text
C_ik = d_{c_l * exp(-a_ik)}( psi(z_i^l), psi(v_k) ),   a_ik = (1/|S(i)|) * sum_j 1[euc_l(j) = k]
```

The behaviour enters as a **multiplicative factor on the cost**. The verifier
measures exactly that kind of dependency, and its witness is decisive:

```text
margins_behavior_off = [3.007, 3.738, 1.761, 4.097]
margins_both_on      = [3.007, 14.016, 1.761, 0.517]
"a codeword-dependent weight moved False of the top-1 indices"
```

The margins moved — two of the four by 1.0 and 3.6 — and **not one arg-min
moved**. A rescaling of a distance is a weak channel: it can reorder the
nearest code only when two codes are almost equidistant, which is a measure-zero
event in the verifier's instance and a rare one in practice. So the coupling
cannot be certified as a behaviour dependency, and the framework refused to spend
a GPU budget on it.

The implementation that was written against the proposal agrees with the
verifier about the weakness: the field decides a pair only when the cost gap is
small (the test had to be written that way), and the plan's arg-max does not
reproduce the capacities exactly — the resolution protection the proposal
claimed is **partial**, which the proposal itself lists as its own risk and one
of the three scorers named as the reason its capacity guarantee is unsound.

## The baseline problem this round also exposed

The round was created before the chain guard existed, so its cached baseline was
`TIGER_BRad-RQ` — a mechanism whose SID has already collapsed to 12 / 60 / 170.
On that baseline the resolution protection this round asks for cannot be
measured at all: there is no resolution left to protect. The tree was re-copied
from the resolved baseline (the frozen `TIGER_RQ-VAE`, 247 / 7,414 / 20,223)
and the round's record updated with the reason.

The guard itself is now in the framework: **a mechanism whose Stage 3 lost to
the frozen baseline, or whose SID table is gone, is skipped by the chain**, and
the chain falls back to the frozen baseline. Without it, every round after the
first curvature round would have been built on a collapsing arm.

## What the exploration has established so far

1. **The curvature profile is real and measurable.** On the frozen baseline's
   prefixes: `kappa_hat = [-2.32, -1.80, -0.86]`, i.e. the baseline's fine
   level is *less* curved than its size-preserving null, and the mean-zero
   deviation gives `delta = [-0.328, -0.071, +0.399]` and a per-level curvature
   of `[1.389, 1.074, 0.671]`. The baseline already has the flatter profile the
   correlation analysis says the recall prefers.
2. **Spending the profile on the space's radius destroys the resolution**
   (round 1: 170 → 56 distinct triples, recall 0.0446 → 0.0419).
3. **A curvature that only rescales the cost is too weak to be a dependency**
   (round 2: the machine verification refused it, correctly).
4. ⇒ **The next round must make the behaviour term additive in the assignment**
   — a bias whose top-1 effect is provable — and must protect the resolution by
   construction rather than by a plan whose arg-max may not reproduce its
   marginals.
