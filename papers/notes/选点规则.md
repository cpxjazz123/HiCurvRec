# 选点规则（写死版本，不允许训练后修改）

> 本规则在训练开始前已确定，写死版本。本文档与脚本、yaml 配置一一对应。

## 数据切分 (P3)

按 **用户** 切分训练 / 验证 / 测试集。规则：
```
user_id → sha256 → bucket[0,9]
bucket in [0..6] → train    (70%)
bucket in [7..8] → val      (20%)
bucket in [9]   → test      (10%)
```

三个 split 的用户集合**完全不重叠**。

## 选点规则 (Early Stopping)

```
每 500 步在 val set (diag_val) 上跑一次 val_R@10_Generative (next_k=1)
记录历史 best val_R@10_Generative
连续 3 次评估 (≈ 1500 步) val_R@10_Generative 不再提升 (相对 delta < 0.001)
  → 停止训练
使用 best 对应的 checkpoint 做最终 test 评估
```

**绝对不允许**：
- ❌ 用 test set 选 checkpoint
- ❌ 训练完后回头挑"看起来最好的"点
- ❌ 调 min_delta / patience 看 test 表现再改

## 验证集 (diag_val) 的使用方式

- 只用于 `val_R@10_Generative` 监控和 early stopping 判定
- 不用来调超参 / 改 yaml
- 不用来看 example / debug

## 测试集 (diag_test) 的使用方式

- **全程封存**到训练结束
- 只在最后一次性 eval 报数字
- 如果"跑出来不满意再回去调" → 视为数据泄漏，实验作废

## 复现性验证 (P4)

3 个不同随机种子 (42, 43, 44) 跑同一规则。接受标准：
- 3 个种子选出的 checkpoint 步数 ≤ 1500 步差距
- 测试集 R@10 方差 ≤ 0.005

不满足 → 选点规则不可信，回到选点规则设计阶段。

## yaml 中的实现

`configs/experiment/tiger_decoder_only_train_flat_v3.yaml`：
```yaml
callbacks:
  - model_checkpoint:
      monitor: val/recall@10_generative
      mode: max
      save_top_k: 1
  - early_stopping:
      monitor: val/recall@10_generative
      patience: 3
      min_delta: 0.001
      mode: max
      check_on_train_epoch_end: false
trainer:
  val_check_interval: 500  # 每 500 步评估一次
```
