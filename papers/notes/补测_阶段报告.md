## P1 (完成) — 现象 1 根因诊断

**结论**：用户假设 **得到证实**。val_R@10_NextK (predict position -K = predict last item, autoregressive) 与 end-to-end R@10 在 long training 后方向**反转**。

| ckpt step | val_R@10_NextK | e2e test R@10 | val/loss |
|-----------|----------------|---------------|----------|
| 1600 | 0.0788 | 0.1188 | 8.558 |
| 1800 | 0.0820 | 0.1275 | 8.553 |
| **2000** | **0.0836** | **0.1361 ← PEAK** | **8.531 ← MIN** |
| 3900 | 0.0921 ↑ | 0.1297 ↓ | 9.222 ↑ |

- val_R@10_NextK 持续 +10.2% 增长 (step 1999→3899)
- e2e R@10 在 step 2000 后下降 -4.7% (overfit)
- val/loss 在 step 2000 后反弹 +8.1%
- 文件：`task_artifacts/scripts/p1_diagnostic_tf_vs_generative.py`
- 数据：`result/p1_diagnostic/p1_diagnostic.json`

## P2 (完成) — val_R@10_Generative 是不是 e2e 的可靠代理？

**结论**：**不可靠**。即便把指标换成 autoregressive generate()，val_R@10 (on evaluation split) 与 e2e test R@10 依然在不同 step 选择最优 ckpt：

| ckpt | val_R@10_Generative | e2e test R@10 |
|------|---------------------|---------------|
| 1600 | 0.0788 | 0.1188 |
| 1800 | 0.0820 | 0.1275 |
| **2000** | 0.0836 | **0.1361 ← ACTUAL BEST** |
| 3900 | **0.0921 ← val picks** | 0.1297 (overfit) |

- **val_R@10_Generative 选了 step 3900** (val_best)，但实际 best 是 step 2000 (test_best)
- 在 step 2000→3900 之间：**val +0.0086, e2e -0.0064** → 方向反转
- 原因：`data/evaluation` 中的用户与 `data/training` **重叠**，导致 val 指标被 train 数据污染
- 文件：`task_artifacts/scripts/p2_val_recall_generative.py`
- 数据：`result/p2_val_generative/p2_val_R10_generative.json`

→ P3 必须做 user-disjoint 切分，val/test 都用训练未见过的人

## P3 (完成) — 三路 user-disjoint 数据集

**切分规则 (写死)**：
```
user_id → sha256 → bucket [0, 99]
bucket in [0..69]  → train   (70%)
bucket in [70..84] → val     (15%)
bucket in [85..99] → test    (15%)
```

**切分结果 (从 19412 用户中)**：

| Split | Users | Records |
|-------|-------|---------|
| diag_train | 13,509 (70%) | 195 MB / partition |
| diag_val | 2,898 (15%) | 39 MB / partition |
| diag_test | 3,005 (15%) | 41 MB / partition |

**Disjointness verified**:
- train ∩ val = 0
- train ∩ test = 0
- val ∩ test = 0

数据位置：`data/amazon_data/toys/diag_{train,val,test}/from_*.tfrecord.gz` (3 source splits)

**选点规则文档**：`task_artifacts/docs/选点规则.md`

**关键规则 (训练前写死，不可改)**：
- 每 500 步在 diag_val 上跑 val_R@10_Generative
- 连续 3 次评估 (1500 步跨度) 不提升 Δ < 0.001 → 停止
- best val_R@10_Generative 对应 ckpt 做 final test
- 绝对不允许：看 test 调整、改 min_delta/patience、训练后挑点

文件：
- `task_artifacts/scripts/p3_user_split.py` — 切分脚本
- `task_artifacts/docs/选点规则.md` — 规则文档

## P4 (脚本就绪) — 3-seed 复现验证

**目标**：证明显 P3 的选点规则不是巧合，是可复现的。

**接受标准**：
- 3 个种子 (42/43/44) 选出的 best step 范围 ≤ 1500 步
- test_R@10 标准差 ≤ 0.005

**训练配置 (yaml overrides 写死)**：
```bash
data_loading.train_dataloader_config.dataloader.data_folder=${DATA_DIR}/diag_train
data_loading.val_dataloader_config.dataloader.data_folder=${DATA_DIR}/diag_val
callbacks.model_checkpoint.monitor=val/recall@10
callbacks.model_checkpoint.save_top_k=1
callbacks.early_stopping.monitor=val/recall@10
callbacks.early_stopping.patience=3
callbacks.early_stopping.min_delta=0.001
trainer.val_check_interval=500
trainer.max_steps=10000
```

**启动方式** (需要 GPU 环境)：
```bash
bash task_artifacts/scripts/p4_3seed_train.sh
```

**运行时间预估**：每个 seed 训练到 early stopping (≈ 3000-5000 steps) 约 2-4 小时 on A100。
**注意**：当前 background session 受时间约束，**未运行实际训练**——脚本就绪。

```

```

如果 P4 通过：
- val_R@10_Generative + diag_val (user-disjoint) = 可信 proxy

- cross-seed 一致性 = 不是"调出来的 lucky result"

如果 P4 不通过：
- 回到选点规则设计，看 min_delta / patience 是否对超参敏感
- 考虑换 val metric (e.g. validation ranking loss with stronger smoothing)
