## 1. 用户三轮指引的演进逻辑 (2026-07-25/26)

### 1.1 第一轮: 反驳 Pair H2 (双曲 vs 欧式 碰撞率对齐)

- 用户原话: "两个 checkpoint 来自训练的完全不同阶段, 这条对比毫无意义. 跑 5 分钟 argmin 一致率诊断."
- 设计: 同 ckpt (双曲 ep19) + 同 (latent, codebook), 只换 argmin 函数 (Poincaré vs Euclidean).
- 结果: **99.91% 一致率** → 现状几何 ≈ 欧式, Pair H2 失效, **几何方向被判 close**.

### 1.2 第二轮: 反驳 β 假说

- 用户原话: "我漏了一半 — 量化损失只是天平的一端, 另一端 (重构损失) 也跟着 loss_type 变了, 而且变得更多. 下一步测两臂的 recon / quant 数值和比值."
- 设计: 在 `_train_epoch` 加 `DIAG[ep0 batchN]` 打印 recon / rq_loss / 比值.
- 结果:
  - 双曲 (β=1.0, qw=1.0): recon=4.02, rq=3.01e-3, ratio=7.50e-4
  - 欧式 (β=0.5, qw=1.0, in-code ×4): recon=1.31e-3, rq=1.67e-3, ratio=1.28
  - ratio_hyp / ratio_euc = 5.86e-4 → **欧式 qw 应该减小到 5.86e-4, 不是 β=1.0 → 0.5**

### 1.3 第三轮: 半径扫描 (用户最新指引)

- 用户原话: "在现有码本上, 不训练, 只做一个扫描: 人为把码字半径重新缩放到不同的跨度, 算 argmin 一致率. 如果推到 0.9 一致率还有 95%, 说明这条路也不通, 收."
