## 1. 对 `answer3` 三处公式的勘误（原文保留，不倒改）

| `answer3` 的写法 | 实际情况 |
|---|---|
| `c_l` 是"真实 gather，不带梯度" | 离散**索引**不可微；`gather` 对**选中码本权重**可微。两者必须分开说 |
| on 公式写成 `sg(sum sg(c_l - r_l))`，并称它提供 encoder 梯度 | 外层 `sg` 的梯度为零；该写法既不产生 encoder 梯度，也不是源码所做的事 |
| 由此把 `q` 描述为"R + 直通项" | 源码是 **`q = R + T − sg(T)`**，`T = Σ u_l`、`u_l = r_l + sg(c_l − r_l)`；前向等于 `R`，反向保留 `T` 的梯度 |

`T` 并非只依赖 encoder：`native_product.residuals` 每层都用 `z` 与前层**可微码字**重建残差，因此码字还会经前层残差产生间接梯度——这条通路被 `answer3` 漏掉了。

## 2. 实测：真实 `RQLayer` 的 E16 代理系数

执行：`probe_ste_jacobian.py`（float64、`GEOMETRY_ON=True`、3×256 码、H 全零、把三层选中码固定为 0 号，E 首坐标分别为 0.1/0.2/0.3，`z_E0=0.8`）。

| 量 | 实测 |
|---|---|
| 前向 `q_E0` | **0.6000000000000001**（= 0.1+0.2+0.3，即 `R`） |
| `d q_E0 / d z_E0` | **3.0** |
| `d q_E0 / d cE_l`（L1/L2/L3） | **−1.0 / 0.0 / +1.0** |
| 当前系数 `(z, c1, c2, c3)` | **(3, −1, 0, 1)** |
| `answer3` 声明的目标 | (1, 1, 1, 1) |

这与 `question4.md` §2 的解析表逐项一致：C2 的 E 半区代理系数为 **0**（R 的 +I 与 T 的 −I 抵消），C1 为 −I，C3 为 +I，encoder 为 3I。

**红灯（真实、可解释）**：一条断言"encoder 一次 I、每个选中码本 +I"的测试在当前源码上必然失败，实测值就是上面的 `(3, −1, 0, 1)`。本问不修改源码，故该红灯如实保留；修复需先由规格确认目标梯度。

为什么不能只看范数：C2 的 H 半区非零分量可以掩盖 E 半区的抵消——q3 里 C2 结构梯度 `7.9e-07` 正是这个现象。
