# question1 — 结构项到底有没有改变硬 SID？

**状态：已审阅归档（非验收通过；补证统一转交 `question2.md`）**　提出：2026-11-10　原协议 `main` @ `b3178d3e`　审阅：2026-11-10

---

## 1. 为什么这是第一问

我们已经把曲率接进了选码代价、Möbius 残差、右嵌套回读，并把 $\lambda$ 定为 $3.5211\text{e-}06$。但这些都只证明**机制在跑**，不证明**机制在起作用**。

Stage3 只读离散 token。若结构项在当前权重下对硬 SID 是惰性的，那么后面 3000 epoch 的冻结 Stage2 只是在重复一次基线实验，代价最高、信息量最低。所以先花 50–100 个 CPU step 判断这件事，是整条主线上最便宜的一次分叉。

同时它也回答另一个悬着的问题：$\lambda=3.5211\text{e-}06$ 相对 codebooks 块的 base 范数（$3.47\text{e-}05$）正好是 100% 预算，但 encoder 只拿到 56.7%；加上余弦 0.1175/0.0708（近正交，合成梯度 1.149×、转向约 30°），**"范数相等"完全不能推断 token 会动**。只有数出来才算。

## 3. 前置修正（否则量的是错的机制）

`tests/probe_collision_gradients.py:99-100` 仍在做
`pair_levels[-1] + (codes_to_positions(...) - codes_to_positions(...).detach())`，
即生产已删除的双计路径。用它做预检会给出与训练不一致的梯度量级。

处理：按 `training_hooks._positions` 收敛为**只取 `levels[-1]`**，或直接删掉旧探针另写预检脚本。二者选一，不能留着。

---

## 4. 协议（纯 CPU，单进程，不开 GPU）

- 数据：真实 `results/stage0_build_parquet/train.parquet` + 真实 `stage1_GeneEmbedding/output/sentence_t5.npy`。
- 模型：trainer 自己的构建路径（`_tokenizer_config` + Xavier + `init_codebook` 的 KMeans），不另写近似模型。
- 固定一个小 batch（例如 512 个 TRAIN 商品），固定 seed，**同一 batch 反复**前向，避免 batch 构成变化干扰计数。
- 超参用已冻结值：`BATCH_SIZE_PER_RANK` 规则、`STRUCT_TRIPLES`、$s=0.041920$、$\lambda=3.5211\text{e-}06$、`GEOMETRY_ON=True`、`BEHAVIOUR_ON=True`、AdamW + `LR=1e-3`、`GRADIENT_CLIP_NORM=1.0`。
- 步数：50 与 100 各报一次（同一次运行里记录两个检查点）。
- 只跑训练循环体，不写 checkpoint、不导出 SID、不调用框架启动器。

## 6. 判定（只设一条硬规则）

> **换码计数为 0（L1、L2、L3 全为 0）且同前缀比例变化 < 0.1pp ⇒ 判"结构项对硬 SID 惰性"。**

惰性即停止主线推进，回到权重/梯度通路排查，不进入 P3、不进 Stage2。

其余（重构是否抬升、结构改善在哪一层、碰撞率升降）**只如实报告，不设阈值**——目前没有依据给重构定容差，不凭空造一个。
